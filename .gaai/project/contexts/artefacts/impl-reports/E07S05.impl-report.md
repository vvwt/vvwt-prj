# Implementation Report — E07S05: Gesamtübersicht Svelte view — layout + data rendering

## Summary

- Delivered a separate Svelte 5 + Vite + TypeScript display SPA (`src/main/ui-display/`) that serves the Gesamtübersicht at `/display/overview`. The SPA reads a device token from `localStorage`, fetches tournament data from the three E07S04 display endpoints concurrently, and renders a two-column CSS Grid layout: court/match grid on the left (4fr), group standings on the right (28em).
- All assets are bundled locally via Maven (`frontend-maven-plugin` + `maven-resources-plugin`) and served from `classpath:/static/display/` — no CDN references, fully offline-compatible per DEC-16.
- 5 Java ITs + 15 vitest unit tests deliver; 272 total tests pass with zero regressions.

## Key Design Decisions

**D1 — Separate SPA, not a route in the admin SPA:** The display SPA lives in `src/main/ui-display/` with its own `vite.config.ts` (base: `/display/`). This avoids polluting the admin SPA bundle with display-specific code and allows the display SPA to run without admin authentication. The admin SPA uses hash-based routing (`svelte-spa-router`) which is unsuitable for the display surface.

**D2 — `forward:/display/index.html` pattern:** `DisplayViewController` returns `forward:/display/index.html` (same pattern as `AdminSpaController` → `forward:/static/admin/index.html`). Spring Boot's static resource handler serves `classpath:/static/display/index.html` for URL `/display/index.html`. The forward is transparent to the client.

**D3 — `Promise.all` for concurrent data fetch (AC5):** All three display endpoints (`overview`, `matches`, `groups`) are fetched concurrently at mount time. The view renders only after all three resolve. This avoids a multi-stage render flash and is acceptable for V1 (E07S06 adds real-time updates).

**D4 — Typed error hierarchy (AC9):** `displayApi.ts` defines `UnauthorizedError`, `NoActivePhaseError`, and `ApiError` as distinct classes. `App.svelte` uses `instanceof` checks to map each to a specific `errorType` state, which `ErrorPanel` then renders with an appropriate message. No generic "error occurred" messages.

**D5 — Story branch built on `story/E07S04`:** The `story/E07S05` branch was created from `story/E07S04` (not staging) because E07S04 is not yet merged to staging but E07S05 depends on its display endpoints. The PR targets staging; both stories' code will arrive via their respective PRs.

**D6 — Integration test AC11 semantics:** Sending wrong HTTP Basic credentials to a Spring Security HTTP Basic server returns 401 even for permit-all routes (Spring processes the auth header before the permit-all check). The `overviewPageIsAccessibleWithNoCredentials` test correctly tests AC11 by sending NO credentials, not wrong credentials.
