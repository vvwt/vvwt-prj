# Implementation Report — E21S06

## Summary

Reconstructed the Device aggregate in-place under `de.vvwt.tm.tournament.*` and
`de.vvwt.tm.tournament.internal.*`, strictly following the DEC-22 TDD Iron Law
(RED commit 73e73ac → GREEN commit c04a05f). 13 production classes + 6 DTOs were
created; 10 RED test files were committed first. Key decisions: JdbcTemplate
(not Spring Data JDBC CrudRepository) for DeviceRepository to avoid entity-mapping
conflict with legacy `de.vvwt.tm.domain.Device`; URL `/api/tm/devices` to avoid
RequestMappingHandlerMapping ambiguity; `@EnableMethodSecurity` added to
AuthConfiguration to activate `@PreAuthorize("hasRole('ADMIN')")` on
DeviceAdminController (DEC-24); `@ExceptionHandler(AccessDeniedException.class)`
added to GlobalExceptionHandler to prevent the catch-all handler from swallowing
403 responses with a 500.

## Design Decisions

**D1 — JdbcTemplate for DeviceRepository**: Spring Data JDBC maps repository entities by class
name. Two entities (`de.vvwt.tm.domain.Device` and `de.vvwt.tm.tournament.Device`) for the same
`devices` table causes ambiguous CrudRepository registration. JdbcTemplate avoids this conflict
during reconstruction-in-place, consistent with TournamentRepository (E21S02) precedent.

**D2 — URL /api/tm/devices**: Legacy DeviceController occupies /api/devices. Reconstruction-in-place
requires a distinct URL prefix during the parallel phase (E21S13 cutover will normalize).

**D3 — @EnableMethodSecurity + @PreAuthorize**: SecurityConfig only uses `.authenticated()` for
/api/**. Role enforcement requires method security. Added @EnableMethodSecurity to AuthConfiguration
(minimally invasive) and @PreAuthorize("hasRole('ADMIN')") on DeviceAdminController class level.

**D4 — GlobalExceptionHandler AccessDeniedException**: Spring Security's ExceptionTranslationFilter
converts AccessDeniedException to 403 only if the filter runs first. With @ControllerAdvice
catching Exception, AccessDeniedException was intercepted before the filter. Added specific
handler returning 403.

## QA Note — Pre-existing @SpringBootTest Context Failure

DeviceRepositoryIT, DeviceControllerIT, and DeviceAdminControllerIT fail with the same
`UnsatisfiedDependencyException` as TeamRepositoryIT (pre-existing on staging):
`de.vvwt.tm.domain.repo.PhaseCrudRepository` not available after Spring Data JDBC bean override
between the legacy and new PhaseBreakCrudRepository/PhaseCrudRepository registrations.
This failure was present on staging BEFORE E21S06 (verified by git stash + baseline test run).
Scope: E21S06 does not introduce or worsen this failure. It will be resolved at E21S13 atomic
cutover when legacy beans are deleted.
