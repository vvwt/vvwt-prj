## Rules Applied

- DEC-5: every entity has `tenant_id`; enforced in `TenantScopedRepository.save()` and `SetResultRepository`
- DEC-14: Spring Data JDBC CrudRepository delegates; `JdbcAggregateOperations` for explicit INSERT/UPDATE
- DEC-17: guard fires before any SQL in every public method; `SetResultRepository` uses `activeTenantId()` guard at top of each method

## Decisions Made During Implementation

1. **Delegate interfaces must be top-level.** Spring Data JDBC's component scan does not wire inner interfaces declared inside `@Repository` beans. All `*CrudRepository` interfaces were extracted as package-private top-level files.

2. **H2 `CASE_INSENSITIVE_IDENTIFIERS=TRUE` in test.** Spring Data JDBC 3.x/4.x uses ANSI-quoted lowercase identifiers. H2 default is `DATABASE_TO_UPPER=TRUE`, making quoted lowercase identifiers fail. The IT uses an isolated H2 URL with `CASE_INSENSITIVE_IDENTIFIERS=TRUE` rather than touching the shared `application-test.yml`.

3. **`JdbcAggregateOperations.insert()/update()` bypasses `isNew()`.** Spring Data JDBC's `CrudRepository.save()` detects new vs existing by null-ID check. Our entities carry pre-assigned UUIDs, so `isNew()` always returns false → UPDATE on a new row → `IncorrectUpdateSemanticsDataAccessException`. Fix: `TenantScopedRepository.save()` calls `delegate().existsById(id)`, then invokes `jdbcOperations().insert()` or `.update()` directly. Each concrete repo injects `JdbcAggregateOperations`.

4. **`TenantContext.set()/clear()` must be `public`.** `DefaultTenantContextResolver` lives in `de.vvwt.tm.web`; `TenantContext` is in `de.vvwt.tm.domain.repo`. Cross-package access requires `public` visibility.

5. **`@Param` on named-parameter queries.** Spring Data JDBC requires `@Param` annotations when the compiled bytecode does not preserve parameter names. Added to all three custom `@Query` delegate methods.

6. **`Match.memberAvatar1Id` / `memberAvatar2Id` @Column fix.** Spring Data JDBC converts `memberAvatar1Id` → `member_avatar1_id`; DDL uses `member_avatar_1_id`. Added explicit `@Column("member_avatar_1_id")` and `@Column("member_avatar_2_id")`.

7. **Test helpers must supply `createdAt` / `changedAt`.** `created_at` and `changed_at` columns are `NOT NULL DEFAULT CURRENT_TIMESTAMP`. Spring Data JDBC includes all mapped fields in the INSERT — passing `null` overrides the DB default and violates the NOT NULL constraint. Test helpers were updated to pass `LocalDateTime.now()`.

## Known Risks

- `SetResultRepository` does not extend `TenantScopedRepository` (composite PK incompatibility). The guard is still called explicitly in every method. Future refactoring could introduce a generic composite-PK base if more such entities appear.
- The `findAll()` method in `TenantScopedRepository` performs an unscoped `delegate.findAll()` followed by in-memory filtering. In V1 single-tenant mode this is safe; in a future multi-tenant deployment this must be replaced with a SQL WHERE clause.
