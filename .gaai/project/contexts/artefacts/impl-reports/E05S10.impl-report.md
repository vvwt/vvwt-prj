# Implementation Report: E05S10 — Live monitoring (REST + Svelte + WebSocket)

## Summary

- Added `LiveMonitoringService` + `MonitoringController` with 4 REST endpoints (AC1–AC4): group tables computed on read from `TeamAvatarRating` (D-24, D-33), lap-match details with set scores, current-lap summary.
- Added `PhaseCompletedEvent` + `checkPhaseCompletion` in `PhaseLifecycleService` to fill domain gap: phases were never marked COMPLETED. `DomainEventBridge` now broadcasts `LAP_ADVANCED` and `PHASE_COMPLETED` WebSocket events (AC5).
- Added `Monitoring.svelte` SPA view with group tables, lap navigation, match cards, WebSocket live refresh, connection indicator, i18n (AC6–AC12).

## Decisions Made

- **Group table fields**: Exposed `TeamAvatarRating` fields directly (points, setsWon/Lost, ballsWon/Lost, quotients) rather than computing wins/losses/draws from match history. This avoids a costly join; domain model already has all needed ranking data. Aligns with D-24 (computed-on-read, no materialized table).
- **AC9 match detail**: Shown inline in match cards (always visible) rather than requiring a click. Superior UX for real-time monitoring.
- **Phase COMPLETED gap**: Added `checkPhaseCompletion` to `PhaseLifecycleService`. Called from `DomainEventBridge.onMatchResultChanged` AFTER_COMMIT, running in a NEW transaction. This ensures the cascade chain (match → lap → phase → tournament COMPLETED) works end-to-end.
- **`@Transactional(readOnly = true)`** on `LiveMonitoringService`: correct for all-read service.
