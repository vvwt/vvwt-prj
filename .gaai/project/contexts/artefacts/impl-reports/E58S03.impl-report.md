## Design decision logged during implementation

**AC10 interpretation**: The initial implementation passed `null` as teamId in `buildProposal`. This was incorrect — `commitTransition` relies on `proposal.teamId()` to identify which team fills which slot. The correct interpretation of AC10 is that the calculator does not perform DB writes (the DB write is exclusive to `commitTransition`), but the proposal DTO carries the teamId from the previous phase avatar as a passthrough. Tests updated accordingly.
