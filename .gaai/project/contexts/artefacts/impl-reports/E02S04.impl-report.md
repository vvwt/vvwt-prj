# Implementation Report — E02S04: Default-tenant bootstrap-time UUID generation

## Summary

- Added `DefaultTenantProvider` interface and `DefaultTenantBootstrap` component to the `de.vvwt.tm.tenant` package in `vvwt-tm-web`.

## Decisions Made

- `DefaultTenantBootstrap` implements both `ApplicationRunner` and `DefaultTenantProvider` (single class for cohesion — the bootstrap both resolves the ID and exposes it). Spring wires it as the `DefaultTenantProvider` bean automatically via interface resolution.
- `@Transactional` on `insertDefaultTenantWithLocation()` is a public method (not `run()`) to allow transaction proxy interception in the Spring context. `run()` calls it directly.
- `@DirtiesContext(classMode=AFTER_EACH_TEST_METHOD)` on the IT class ensures each test gets a clean H2 in-memory DB (required because the shared `testdb` would accumulate rows across tests).
- The `concurrentStartRaceResolvesToSingleUUID` test uses a `CountDownLatch` to release both threads simultaneously and `@DirtiesContext` to clean up between tests.

## Rules Applied

- DEC-3: Java SE only (`UUID.randomUUID()`)
- DEC-5: Tenant + location created atomically in same transaction; `tenant_location_count=1`
- DEC-14: `JdbcTemplate` only; no Spring Data repository interface yet (added when domain entities need it)
