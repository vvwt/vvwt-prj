## Key Decisions

- **AFTER_COMMIT listener**: `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)` ensures the listener fires only after the cascade transaction commits, preventing a snapshot from capturing uncommitted match state. Exceptions in the listener are caught and logged — they cannot roll back the already-committed cascade.
- **Duplicate guard — first-snapshot-wins (AC5 option b)**: On detecting a duplicate `(tournament_id, phase_id, lap_number)` before INSERT, the service logs WARN and returns. This is correct for the AFTER_COMMIT path (duplicate events are rare but possible in future cluster deployments) and for `regenerate()` (which uses explicit delete+insert to achieve replace semantics).
- **`TeamAvatarRating` has no direct `phase_id` column**: The table uses `avatar_id` as PK (1:1 with `team_avatar`). The phase-level query requires a JOIN: `SELECT tar.* FROM team_avatar_rating tar INNER JOIN team_avatar ta ON ta.id = tar.avatar_id WHERE ta.phase_id = :phaseId`.
- **D-33 sort order**: `Collections.sort(ratings)` leverages `TeamAvatarRating.compareTo()` which implements points DESC → set_quotient DESC → ball_quotient DESC → `is_without_assessment=true` last.
- **JSON payload schema (AC3 Delivery decision)**: All fields are UUIDs, numeric scores, or state codes — no team names or descriptions (AC14). The `captured_at` field uses `Instant.now().toString()` (ISO-8601 UTC). `set_quotient` and `ball_quotient` are raw `double` values from the domain model.
- **`LocalDateTime.now()` for `created_at`**: Spring Data JDBC sends explicit `NULL` which overrides H2's `DEFAULT CURRENT_TIMESTAMP`. Both `writeSnapshot` and `regenerate` pass `LocalDateTime.now()` explicitly to avoid H2 `NOT NULL` violation.
- **Test isolation**: All ITs are non-`@Transactional` because `@TransactionalEventListener(phase = AFTER_COMMIT)` only fires on committed transactions. A test-managed transaction never commits, preventing the listener from running.
- **Test package**: `de.vvwt.tm.domain.repo` — required for package-private `TenantContext.set()` and `TenantContext.clear()` access (per E03S05 AC1 design).
- **DRAFT tournament status in fixture**: To avoid triggering the active-tournament-per-tenant constraint that would conflict across test methods sharing the same in-memory database.
