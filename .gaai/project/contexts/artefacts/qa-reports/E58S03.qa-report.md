## Design Decision Recorded During QA

**AC10 interpretation (confirmed correct):** The calculator passes `fromAvatar.getTeamId()` as a passthrough in `buildProposal` — this is not a DB write. The proposal DTO carries the teamId so `commitTransition` can identify which team fills which slot when the operator confirms. The "no teamId write by calculator" constraint is about DB persistence, not about the proposal DTO. This interpretation is documented in the impl-report and in the `buildProposal` Javadoc.
