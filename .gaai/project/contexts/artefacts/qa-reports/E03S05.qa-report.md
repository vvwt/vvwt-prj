## Notable Issues Resolved During Implementation

1. **Delegate interfaces must be top-level.** Spring Data JDBC component scan does not wire inner CrudRepository interfaces. Extracted to package-private top-level files.

2. **H2 case-sensitivity.** Spring Data JDBC 3.x/4.x uses ANSI-quoted lowercase identifiers; H2 default is DATABASE_TO_UPPER=TRUE. Fixed via `CASE_INSENSITIVE_IDENTIFIERS=TRUE` in IT H2 URL.

3. **`isNew()` null-ID check.** All entities carry pre-assigned UUIDs; Spring Data JDBC's `save()` would call UPDATE on new rows. Fixed by calling `JdbcAggregateOperations.insert()`/`.update()` explicitly after an existence check.

4. **`@Param` on named-parameter queries.** Three custom `@Query` methods lacked `@Param` annotations. Fixed.

5. **`Match.memberAvatar1Id` column mapping.** Spring JDBC convention `memberAvatar1Id` → `member_avatar1_id` but DDL has `member_avatar_1_id`. Fixed with `@Column` annotation.

6. **`NOT NULL DEFAULT CURRENT_TIMESTAMP` vs. null test data.** Spring Data JDBC includes null fields in INSERT, overriding DB defaults. Test helpers updated to supply `LocalDateTime.now()`.

7. **AC1 package-private enforcement.** `TenantContext.set()`/`clear()` must be package-private per AC1. `DefaultTenantContextResolver` moved from `de.vvwt.tm.web` to `de.vvwt.tm.domain.repo`; IT moved to same package.
