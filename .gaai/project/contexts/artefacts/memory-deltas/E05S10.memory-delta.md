# Memory Delta: E05S10

## New Patterns

1. **Phase COMPLETED transition**: `PhaseLifecycleService.checkPhaseCompletion(phaseId, tournamentId)` is called from `DomainEventBridge` AFTER_COMMIT to detect when all matches in a phase are terminal, marking `phase.status = COMPLETED` and publishing `PhaseCompletedEvent`. Chain: cascade → MatchResultChangedEvent → checkPhaseCompletion → PhaseCompletedEvent → checkTournamentCompletion.

2. **Monitoring service pattern**: `@Service @Transactional(readOnly = true)` for services that only read. Group tables computed from `TeamAvatarRating` (1:1 with TeamAvatar) via JOIN in `TeamAvatarRatingCrudRepository.findByPhaseIdRaw`.

3. **WebSocket event types**: `DomainEventBridge` now broadcasts 3 event types to `/topic/events`: `MATCH_RESULT_CHANGED` (entityId=matchId), `LAP_ADVANCED` (entityId=phaseId), `PHASE_COMPLETED` (entityId=phaseId).

## Decisions for Discovery Review

- **D-new**: `Double.MAX_VALUE` sentinel quotients serialized as JSON `null` (not the number) to avoid infinity-in-JSON issues. SPA renders null as "∞".
- **D-new**: Phase COMPLETED was never set before E05S10. The `checkPhaseCompletion` logic is the canonical "all matches terminal → phase COMPLETED" gate. Discovery should consider whether this warrants a new DEC entry.
