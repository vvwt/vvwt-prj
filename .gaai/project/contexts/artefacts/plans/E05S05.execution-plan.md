# Execution Plan — E05S05: Team management (REST + Svelte view)

## Objective

Deliver a complete team management API and SPA view for tournament-scoped teams, covering
CRUD + bulk create + inline editing UI with i18n and tenant ownership enforcement.

## Tier

2 (complexity 5 — clear domain, established patterns from E05S04)

## Steps

1. Extend `TeamCrudRepository` — add ORDER BY, avatar count, number conflict, max-number queries
2. Extend `TeamRepository` — add `hasTeamAvatars`, `nextTeamNumber`, `teamNumberExists` methods
3. Create `TeamService` — create/update/delete/bulkCreate with DRAFT-only guard, auto-number, tenant ownership
4. Create DTOs — TeamResponse, TeamCreateRequest, TeamUpdateRequest, TeamBulkCreateRequest/Response
5. Create `TeamController` — GET/POST/PUT/DELETE + POST /bulk at /api/tournaments/{id}/teams
6. Create `Teams.svelte` — grid view with inline editing, dirty-row indicator, add-row, delete
7. Create `teamStore.ts` — typed API client for all team endpoints
8. Update `App.svelte` — add /tournaments/:tournamentId/teams route
9. Update `Tournaments.svelte` — add "Teams" navigation button
10. Update `de.json` — add all team UI strings (AC12 i18n DoR)
11. Create `TeamControllerIT.java` — integration tests covering AC1–AC13
12. Create `teamStore.test.ts` — frontend tests covering AC12 i18n + exports
13. create-pr → ci-watch-and-fix → mark done

## Dependencies

- E05S04 (TournamentController + TournamentService patterns used as template)
- Team table exists (V2 migration — E03S01)

## DEC Validation
