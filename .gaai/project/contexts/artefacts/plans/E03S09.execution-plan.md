# Execution Plan — E03S09: MatchGenerator Strategy interface + RoundRobinMatchGenerator

## Objective

Deliver the `MatchGenerator` Strategy interface and `RoundRobinMatchGenerator` implementation (port of legacy `MatchGenerator4roundrobin`), the `MatchGeneratorRegistry`, and an extension of `TournamentRuleResolver`. All 16 AC must pass.

## DEC Compliance

- DEC-1: Java — satisfied (all code is Java)
- DEC-5/DEC-17: tenant scope — generator sets `tenant_id` on every Match from `phase.tenantId`
- DEC-9: TeamAvatar is the pairing subject, not Team
- DEC-3: No proprietary dependencies introduced
- DEC-7: Legacy algorithm ported as a clean rewrite

## Steps

### Step 1 — MatchGenerator interface (AC1)
Create `de.vvwt.tm.domain.generator.MatchGenerator` interface in the worktree:
```
vvwt-tm-web/src/main/java/de/vvwt/tm/domain/generator/MatchGenerator.java
```
Methods: `List<Match> generate(Phase phase, List<TeamAvatar> avatars)` and `String getBeanId()`.

### Step 2 — RoundRobinMatchGenerator bean (AC2, AC3, AC4, AC5, AC15, AC16)
Create `de.vvwt.tm.domain.generator.RoundRobinMatchGenerator` annotated `@Component("roundRobin")`.
- Implements the classic round-robin circle-method algorithm
- For odd N: adds phantom team to make N+1, then drops bye-matches
- Reads `MatchFormat.fromPersistedName(phase→tournament.matchFormat).getMaxSets()` via TournamentRepository
- Sets: tournamentId, phaseId, tenantId (from phase), memberAvatar1Id, memberAvatar2Id, state=0, setLimit, lapNumber=null, fieldNumber=null
- Validates inputs (null phase, null avatars, null entries, duplicate IDs) per AC13
- Returns empty list for <2 avatars per AC12
- Logs at INFO (count, beanId, avatar count) and DEBUG (each pairing) per AC15

### Step 3 — MatchGeneratorRegistry bean (AC6)
Create `de.vvwt.tm.domain.generator.MatchGeneratorRegistry` modeled exactly on `ScoringRuleRegistry`:
- Injects all MatchGenerator beans via `List<MatchGenerator>`
- Map by `getBeanId()`; `IllegalStateException` on duplicate
- `get(String beanId)` throws `IllegalArgumentException` with known IDs on miss

### Step 4 — TournamentRuleResolver extension (AC7)
Extend `TournamentRuleResolver`:
- Add `MatchGeneratorRegistry` constructor parameter
- Add `resolveMatchGenerator(Tournament tournament)` method
- Guard: null tournament, null/blank `matchGeneratorId`

### Step 5 — Unit tests (AC8, AC9, AC10)
Create `de.vvwt.tm.domain.generator.RoundRobinMatchGeneratorTest` in test source tree:
- AC8: N=4→6, N=6→15, N=8→28, N=12→66 matches; every pair (i<j) appears exactly once
- AC9: N=9→36 matches; phantom bye never appears; every pair (i<j) exactly once
- AC10: legacy parity for N=9 (known fixture from `MatchGenerator4roundrobin` behavior)

### Step 6 — Error-handling unit tests (AC12, AC13, AC14)
Add to the same or companion test class:
- AC12: 0 avatars → empty list; 1 avatar → empty list
- AC13: null phase throws; null list throws; null entry in list throws; duplicate IDs throw
- AC14: via MatchGeneratorRegistry.get("unknown") → IllegalArgumentException

### Step 7 — Integration test (AC11)
Create `de.vvwt.tm.domain.generator.RoundRobinMatchGeneratorIT`:
- `@SpringBootTest` with H2 test profile (same as E03S05 IT pattern)
- Create Tournament (BEST_OF_3), Phase, 9 Teams + 9 TeamAvatars
- Call generator via registry; persist matches via MatchRepository
- Assert 36 rows: state=0, lapNumber=null, fieldNumber=null, correct tenant, setLimit=3
