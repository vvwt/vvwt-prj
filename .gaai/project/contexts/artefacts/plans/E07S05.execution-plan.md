# Execution Plan — E07S05: Gesamtübersicht Svelte view — layout + data rendering

## Objective

Deliver a separate Svelte SPA (`/display/overview`) that reads a device token from
localStorage, fetches tournament overview data from the E07S04 display endpoints, and
renders a two-column layout matching the legacy Gesamtübersicht: courts/matches on the
left and group standings on the right.

The SPA is a **separate bundle** from the admin UI — it has its own `vite.config.ts`,
`index.html`, and `main.ts` under `src/main/ui-display/`. It is bundled to
`dist-display/` and placed in `classpath:/static/display/` by Maven.

A Spring Boot `@Controller` serves the HTML shell at `GET /display/overview` (without
authentication, per SecurityConfig — `/display/**` added to permitAll).

All acceptance criteria (AC1–AC11) map to specific implementation steps below.

## Steps

### Step 1 — Backend: serve `/display/overview` HTML shell

**Files:**
- `vvwt-tm-web/src/main/java/de/vvwt/tm/infrastructure/display/DisplayViewController.java` — new `@Controller` with `GET /display/overview` → returns Mustache view `display/overview`
- `vvwt-tm-web/src/main/resources/templates/display/overview.mustache` — minimal HTML shell that loads the Svelte bundle from `/display/assets/...`; no CDN links
- Update `SecurityConfig.java` — add `.requestMatchers("/display/**").permitAll()` before the `/admin/**` rule
- `vvwt-tm-web/src/main/java/de/vvwt/tm/infrastructure/display/DisplayViewController.java` — returns model with `locale` string

**AC8 mapping:** Route at `/display/overview`. Static bundle served from `/display/` prefix.
**AC7 + DEC-16 mapping:** Mustache shell references only local assets (`/display/assets/...`).
**AC11 mapping:** `/display/**` is read-only static; no admin actions exposed.

### Step 2 — Frontend: create display Svelte SPA scaffold

**Files:**
- `vvwt-tm-web/src/main/ui-display/` — new directory (separate from admin `ui/`)
- `vvwt-tm-web/src/main/ui-display/index.html` — entry point (references `src/main.ts`)
- `vvwt-tm-web/src/main/ui-display/vite.config.ts` — base: `/display/`, outDir: `dist-display/`
- `vvwt-tm-web/src/main/ui-display/tsconfig.json` — TypeScript config (mirrors admin SPA)
- `vvwt-tm-web/src/main/ui-display/package.json` — dependencies: svelte, vite, svelte-i18n, @sveltejs/vite-plugin-svelte, typescript
- `vvwt-tm-web/src/main/ui-display/src/main.ts` — entry: init i18n, mount OverviewApp
- `vvwt-tm-web/src/main/ui-display/src/App.svelte` — root component: token check + data loading + layout render
- `vvwt-tm-web/src/main/ui-display/src/locales/de.json` — German translations for all display strings

**AC10 mapping:** All strings in locales/de.json, accessed via svelte-i18n `$_()`.
**DEC-2 mapping:** Vite + Svelte + TypeScript, no SvelteKit.

### Step 4 — Frontend: display API client

**Files:**
- `vvwt-tm-web/src/main/ui-display/src/lib/displayApi.ts` — typed fetch functions:
  - `fetchPhaseOverview(token: string): Promise<DisplayPhaseOverview>`
  - `fetchMatches(token: string, lap?: number): Promise<DisplayMatchesResponse>`
  - `fetchGroups(token: string): Promise<DisplayGroupStandingsResponse>`
  - Types mirror E07S04 DTOs; 401 throws `UnauthorizedError`, 404 throws `NoActivePhaseError`, other non-2xx throws generic `ApiError`
  - Uses `fetch` (no credentials header needed — these endpoints are permitAll)

**AC5 mapping:** Token from localStorage passed as `?token=` query param.
**AC9 mapping:** Specific error types allow the UI to show the correct message.

### Step 5 — Frontend: token resolution

In `App.svelte` on mount:
1. Read token from `localStorage.getItem('vvwt_device_token')`
2. If absent → redirect `window.location.href = '/display/register'` (AC11)
3. If present → proceed to data loading

**AC11 mapping:** Redirect to `/display/register` if no token in localStorage.

### Step 6 — Frontend: data loading + state management

In `App.svelte`:
- State: `loading`, `error: string | null`, `errorType: 'unauthorized' | 'noPhase' | 'generic' | null`, `phase`, `matches`, `groups`
- `onMount`: call all three endpoints concurrently (`Promise.all`)
- On success: set `phase`, `matches`, `groups`, clear loading
- On `NoActivePhaseError`: set `errorType = 'noPhase'` (AC6)
- On `UnauthorizedError`: set `errorType = 'unauthorized'` (AC9)
- On generic error: set `errorType = 'generic'` (AC9)

**AC5 mapping:** All three endpoints fetched on initial load.
**AC6 mapping:** 404 → no-active-phase state shown.
**AC9 mapping:** 401 → specific message + retry redirects to re-register.

### Step 7 — Frontend: layout components

**Files:**
- `vvwt-tm-web/src/main/ui-display/src/components/OverviewLayout.svelte` — CSS Grid two-column wrapper (`grid-template-columns: 4fr 28em`)
- `vvwt-tm-web/src/main/ui-display/src/components/CourtGrid.svelte` — left column: one column per field, header "Feld {n}", match rows per lap grouped by round
- `vvwt-tm-web/src/main/ui-display/src/components/MatchRow.svelte` — single match row: team A, team B, set scores, referee
- `vvwt-tm-web/src/main/ui-display/src/components/GroupStandingsPanel.svelte` — right column: one table per group, header "Gruppe {n}", rows: rank, team, P, S, B
- `vvwt-tm-web/src/main/ui-display/src/components/ErrorPanel.svelte` — error state with retry button

**AC1 mapping:** CSS Grid two-column layout (~4fr / 28em).
**AC2 mapping:** Court grid: field columns, match rows with team names, set scores, referee.
**AC3 mapping:** Current lap matches highlighted (darker background / bold border).
**AC4 mapping:** Group standings: rank, team, P (points), S (sets won:lost), B (balls won:lost).

### Step 8 — Maven: build integration

**Files:**
- `vvwt-tm-web/pom.xml` — add `exec-maven-plugin` execution to:
  1. Run `npm ci` in `src/main/ui-display/`
  2. Run `npm run build` in `src/main/ui-display/`
  Then copy `src/main/ui-display/dist-display/` → `target/classes/static/display/` using `maven-resources-plugin` or `build-helper-maven-plugin`

Note: The admin SPA uses an existing exec-maven-plugin configuration. The display SPA adds a second execution block with a different `workingDirectory`.

**AC7 + DEC-16 mapping:** Bundle ends up inside the JAR served from the local TM instance.

## Risks / Constraints

- **Two Vite builds in one Maven module:** The admin SPA and display SPA both live in `vvwt-tm-web`. The exec-maven-plugin already has a block for the admin SPA. A second `<execution>` block must be added with a distinct `<id>` and `<workingDirectory>` pointing to `ui-display/`. The output directories must not overlap (`dist` vs `dist-display`).
- **DEC-16 offline check:** The Mustache template must reference only `/display/assets/...` paths — not CDN URLs. The integration test verifies this.
- **token localStorage key consistency:** The key `vvwt_device_token` is used in E06S04 for scoring tablets and must be the same in E07S07 for display devices. E07S05 reads the key but does not write it (E07S07 writes it). The key name is hardcoded as a constant in `displayApi.ts`.
