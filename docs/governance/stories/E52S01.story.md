# Story E52S01: Restore admin-UI access to PrintController endpoints — NEW "Zeitpläne" Tournaments-row button

## User Story

**As a** Tournament Organizer,
**I want** a "Zeitpläne" button on each tournament row in the admin tournament list (visible from PLANNED status onward) that takes me to the existing print outputs (team schedules / Laufzettel + activity schedules / Mannschaftsfoto-Übersicht),
**so that** I can reach the pre-event preparation print artefacts from the admin UI without knowing or remembering direct BE URLs.

---

## Context

The Wave-2 print module reconstruction (E24S01–S07, all done — PRs merged) rebuilt `PrintController` at `de.vvwt.tm.web.PrintController` with `@RequestMapping("/print/tournaments/{tid}")` exposing four server-rendered Mustache endpoints:

- `GET /` — printIndex (links to all sub-outputs)
- `GET /team-schedules` — Laufzettel (all teams)
- `GET /team-schedules/{teamId}` — Laufzettel (single team)
- `GET /activity-schedule/{activityTypeId}` — activity schedule (e.g., Mannschaftsfoto, breaks)

These BE endpoints are reachable directly via URL on staging today (verified empirically 2026-05-08 by reading `vvwt-prj/vvwt-tm-web/src/main/java/de/vvwt/tm/web/PrintController.java:90-411`). The admin UI in `vvwt-tm-web/src/main/ui/src/routes/Tournaments.svelte` exposes tournament-row buttons including teams, photos, certificate-template, audio, timer-link (PLANNED|ACTIVE), phases (PLANNED|ACTIVE|COMPLETED|CANCELLED), and DRAFT-only edit/draft/delete/cascade-delete plus PLANNED/ACTIVE/CANCELLED-conditional lifecycle buttons (markPlanned/activate/complete/cancel) — none invoke `PrintController`. `App.svelte` route map registers no `/tournaments/:id/print*` route.

User-observable symptom: after the operator applies a draft and the tournament becomes `PLANNED`, there is no admin-UI affordance to print the team-schedule Laufzettel — a primary pre-event document. The operator must construct the BE URL manually or open it via DB inspection.

Working hypothesis (Brief H-3, unverified): the Wave-2 atomic-cutover stories (E23S05, E23S10, E24S07) ACs did not include "restore admin-UI button + route + i18n wiring" — leaving a reachability gap. Severity does NOT depend on this being correct (Brief OUTCOME-framing): regardless of root cause, the admin-UI cannot reach the existing print outputs.

This is a **producer-side fix at the admin-UI layer** (per memory `feedback_discovery_cycle_resolution_scope_creep.md`): Tournaments.svelte is the admin-UI tournament-row entry point — adding the missing button there is the producer fix. Discovery does NOT prescribe the access shape (new-tab open, iframe-wrapper, Svelte-wrapper-route) — that decision belongs to Delivery's investigation per Brief T-3.
