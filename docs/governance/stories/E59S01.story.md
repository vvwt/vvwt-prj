# Story: Publish vvwt-prj under AGPL-3.0-or-later

## User Story

**As a** contributor, self-host operator, or commercial operator of the project,
**I want** the `vvwt-prj` repository to carry a clear, GitHub-recognised open-source license,
**so that** I know exactly what rights I have to use, modify, host, and contribute to the
code — and what source-disclosure obligations come with it.

---

## Context

`vvwt-prj` has no `LICENSE` file. Under default copyright law all rights are reserved, so
the code cannot legally be reused, modified, self-hosted, or contributed to — contradicting
the project's open-source posture (DEC-3) and blocking the intended community model.

DEC-75 selected **AGPL-3.0-or-later** as the repository license: a single repo-wide
license, copyright holder Thomas Steinke, published GitHub-conventionally as a root
`LICENSE` file. AGPL was chosen over GPL-3.0 because AGPL's Section 13 network-use clause
closes the SaaS loophole that would otherwise leave a hosted, modified Infoportal's
(DEC-42) changes unpublished.

This is the first story of Epic E59. It publishes the license and verifies that no existing
dependency's license conflicts with AGPL-3.0.

---

## Acceptance Criteria

- [ ] AC1 (governance): a file named exactly `LICENSE` exists at the `vvwt-prj` repository
  root and contains the complete, verbatim, unmodified official text of the GNU Affero
  General Public License version 3.0 (the canonical FSF text, as published at
  `https://www.gnu.org/licenses/agpl-3.0.txt`). No text is added, removed, reordered, or
  altered inside the license body.
- [ ] AC2 (governance): the `LICENSE` filename and the unmodified license text satisfy
  GitHub's Licensee classifier criteria for AGPL-3.0 (the in-cycle verifiable criterion);
  Delivery records the verification basis in the impl-report. The observable end-state —
  GitHub displaying "AGPL-3.0" in the repository sidebar — follows once the change reaches
  the default branch and is tracked as the Epic E59 success metric (DEC-75 D5).
- [ ] AC3 (governance): the standard AGPL-3.0 copyright-and-license notice (per the
  license's own "How to Apply the GNU AGPL" appendix) is present, carrying the copyright
  line `Copyright (C) 2026 Thomas Steinke` and stating the program is licensed under the
  GNU Affero General Public License version 3 or (at the licensee's option) any later
  version — the `-or-later` form (DEC-75 D2/D3).
- [ ] AC4 (governance): `vvwt-prj/README.md` states that the project is licensed under
  AGPL-3.0-or-later, names the copyright holder, and points to the `LICENSE` file. Only the
  license/copyright statement is added — the pre-existing stale README content is not
  otherwise rewritten in this story.
- [ ] AC5 (governance): a dependency-license compatibility audit is performed against
  AGPL-3.0-or-later covering every `vvwt-prj` module — the Maven dependency graph of all
  submodules under the parent POM (transitive dependencies included) and the npm/Node
  dependency graphs of the frontend sub-builds. The audit records, in the impl-report, the
  set of distinct dependency licenses found and the compatibility conclusion. The in-scope
  module and dependency set is determined by a fresh inspection of the repository at
  delivery time — not from any pre-computed list.
- [ ] AC6 (governance): if the AC5 audit finds any dependency whose license is incompatible
  with AGPL-3.0-or-later, Delivery STOPS and escalates, naming the specific dependency and
  its license — it does not remove, replace, or relicense anything and does not silently
  proceed (DEC-75 D6 — an AGPL-incompatible dependency is a governance conflict, not a
  Delivery decision).
- [ ] AC7 (governance): `mvn verify` from the `vvwt-prj` root is BUILD SUCCESS (DEC-54) —
  adding the `LICENSE` file and the README statement introduces no build regression.

> All acceptance criteria must be verifiable.

## Out of Scope

- Choosing or changing the license — settled by DEC-75.
- Per-file SPDX/AGPL license headers in source files (future E59 story).
- The AGPL §13 in-application "source code available" link in the Tournament Manager /
  Infoportal web UIs (future E59 story).
- A `CONTRIBUTING.md` / CLA — the operator chose a no-CLA community model (DEC-75 D4).
- A full README refresh of the stale Phase-1 content or its broken relative link — only
  the license/copyright statement is added here.
- Licensing the outer GAAI governance repository.

## Notes

Non-semantic repository change: adding a `LICENSE` file and a README license statement
authors no first-party code, so DEC-22's RED-first Iron Law does not apply (same
non-authoring category as the DEC-29/DEC-67 mechanical-change carve-outs); AC7's `mvn
verify` green is the regression guard. The AGPL-3.0 license text is a fixed external
document — it must be reproduced verbatim and exactly; any deviation breaks GitHub license
detection (AC2). The dependency-license audit (AC5) is an investigation recorded in the
impl-report, not a code change; per memory `feedback_no_precomputed_inventory_in_stories.md`
the story carries the audit obligation, not a dependency inventory. A material fraction of
the repository is AI-generated; the legal uncertainty about copyright in machine-generated
code is documented in DEC-75 § Impact and is explicitly out of scope here. Per DEC-13,
this work is delivered on a `story/E59S01` branch off `staging` and squash-merged back to
`staging`; AI never pushes or merges to `vvwt-prj/main` — promotion `staging` → `main` is a
human action.
