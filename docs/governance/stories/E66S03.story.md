# Story: The phase-transition page shows the ranking basis (points, sets, balls) for each team

## User Story

**As a** tournament organizer,
**I want** each team in the "Bisherige Zuordnung" pane to show the points, sets and balls that determined its ranking,
**so that** I can verify the sort is correct before I confirm the assignment.

---

## Context

On the phase-transition page the "Bisherige Zuordnung" pane shows each team and a source
label. When the teams are ranked by their previous-phase results, the operator has no way
to see *why* a team is where it is — the points, set result and ball result that drove the
ranking are not shown. DEC-77 D-3 fixes the placement comparator as points → set ratio →
ball ratio → prior group position; this story surfaces that basis so the operator can
check it (the operator must be able to verify the sort is correct).

The rating data already exists: `TeamAvatarRating` carries `points`, `setsWon` / `setsLost`
(`setQuotient`), `ballsWon` / `ballsLost` (`ballQuotient`) and a `withoutAssessment` flag.
`withoutAssessment` is a flag on an *existing* rating row — such a team still carries
points/sets/balls numbers; "a team with no rating row at all" is a separate, distinct
state. AC5 governs both.

---

## Acceptance Criteria

- [ ] AC1 (testing): TDD per DEC-22 — a failing test is authored before the production
  change, proven RED, then GREEN.
- [ ] AC2: in a Phase-2+ transition (a played predecessor phase exists), every team row
  **that has a previous-phase rating** shows the ranking basis from the previous phase —
  the team's points, its set result and its ball result — alongside the existing source
  label. This holds regardless of the configured `sortType`. Rows for teams without a
  rating are governed by AC5.
- [ ] AC3: the basis shown is exactly the data behind the DEC-77 D-3 placement comparator
  — the points, the set result (the set figures from which `setQuotient` derives) and the
  ball result (the ball figures from which `ballQuotient` derives) — so a row's displayed
  numbers explain its rank.
- [ ] AC4: for an initial (no-predecessor) transition there is no previous-phase rating to
  show — the pane omits the basis without error and without empty placeholder columns.
- [ ] AC5 (governance): the two distinct unrated states each render with a clear
  "no assessment" indication ("ohne Wertung") — never a blank value, never "undefined",
  never a runtime error: (a) a team whose `TeamAvatarRating` carries the
  `withoutAssessment` flag is clearly marked as not assessed — its rating numbers exist
  but did not count toward placement, so they may additionally be shown, but the row must
  make unmistakably clear the team was not assessed; (b) a team with no rating row at all
  carries the same clear "not assessed" indication and shows no rating numbers.
- [ ] AC6 (governance): the pane renders the teams in the order the E66S01
  `computeProposals` produced and does not re-sort — a `withoutAssessment` team ranks
  below every assessed team per DEC-77 D-3; a team with no rating row at all is positioned
  by E66S01's `computeProposals` (DEC-77 D-3 fixes the order only for the
  `withoutAssessment` case), and this pane renders E66S01's order verbatim.
- [ ] AC7 (governance): the frontend stays Vite + Svelte + TypeScript, no SvelteKit
  (DEC-2); any operator-facing string this story introduces resolves through `de.json` via
  the project's canonical fallback-aware i18n pattern (`$_(key, { default })`); no
  `teamId` UUID is rendered in the DOM (DEC-9). `mvn verify` is BUILD SUCCESS for
  `vvwt-tm-web`, including the frontend build (DEC-54).

> All acceptance criteria must be verifiable.

## Out of Scope

- The editable sort / distribution controls (E66S02).
- The decoupled `computeProposals` engine (E66S01).
- The Display overview standings (E66S04).
- Changing the placement comparator or the team order — both are defined by DEC-77 D-3 and
  implemented by E66S01; this story only displays the comparator's inputs and renders
  E66S01's order.

## Dependencies

  must travel to the page alongside the proposal. Hard prerequisite.
- DEC-77 D-3 — the placement comparator whose inputs this story surfaces.

## Notes

Acceptance criteria state behaviour, not a test mechanism — no Svelte-5 component mount is
required or implied (component mounting is infeasible in the project's Vitest+jsdom
environment, a pre-existing gap documented by E58S05). Delivery decides how the rating
values reach the page (e.g. extending the transition-proposal payload) and how they are
laid out — including whether the derived set/ball ratios are shown next to the raw figures,
and whether a `withoutAssessment` team's non-counting numbers are shown; the ACs state what
the operator must see and that the displayed numbers must explain the rank.
