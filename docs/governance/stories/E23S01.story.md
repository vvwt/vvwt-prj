# Story E23S01: Establish `de.vvwt.tm.photo` Modulith module + Q-1b relocate 7 photo-domain classes (service interface + impl + 3 exceptions + VOs + config)

## User Story

**As a** maintainer of the `vvwt-tm-web` Spring Modulith application,
**I want** the existing photo domain (`de.vvwt.tm.domain.photo.*`) relocated
into a new `de.vvwt.tm.photo` Modulith module with interfaces in the public
package and `Default*`-named implementations in `.internal`,
**so that** photo storage becomes an independently-declared bounded context
(per DEC-21 + DEC-35) and the subsequent photo stories (E23S02 PhotoUrlBuilder,
E23S04 TeamPhotoController relocation, E23S05 atomic cutover) have a
canonical target package to work against.

---

## Context

First story of the E23 photo reconstruction track. Per Brief v4 D-1 and D-4,
photo is a separate Modulith module from certificate (consumer-graph evidence:
TeamController + CertificateAssembler both consume PhotoStorageService).
Empirical verification 2026-04-23: `PhotoStorageServiceImpl.java` imports
`de.vvwt.tm.tournament.Team` + `TeamRepository` + `TournamentRepository` (lines 3-5),
therefore `photo.allowedDependencies = {tenant, tournament}`.

This story executes Q-1b whole-class relocation per DEC-22 §refactor-clause
(behavior-preserving move; existing `PhotoStorageServiceImplTest` = regression
gate; no RED-first required). Legacy `de.vvwt.tm.domain.photo.*` remains
untouched during parallel phase; deletion happens in Cutover-1 (E23S05).

## Acceptance Criteria

- [ ] **AC-PACKAGE-INFO-CREATED**: `src/main/java/de/vvwt/tm/photo/package-info.java`
  exists with `@ApplicationModule(allowedDependencies = {"tenant", "tournament"})`
  annotation. Javadoc cites DEC-21 + DEC-35 + DEC-40.
- [ ] **AC-PUBLIC-SURFACE**: Relocated to `de.vvwt.tm.photo.*` (public):
  `PhotoStorageService` (interface — already interface at source),
  `PhotoFileMetadata` (VO record), `PhotoStorageConfig` (config),
  `PhotoFormatException`, `PhotoSizeException`, `PhotoStorageException`
  (exceptions in context root per Brief v4 D-14).
- [ ] **AC-INTERNAL-SURFACE**: Relocated to `de.vvwt.tm.photo.internal.*`:
  `PhotoStorageServiceImpl` renamed to `DefaultPhotoStorageService` per
  DEC-35 naming canon.
- [ ] **AC-LEGACY-COEXISTS**: `de.vvwt.tm.domain.photo.*` legacy package
  REMAINS untouched (7 legacy files still on disk). Deletion deferred to
  E23S05 atomic cutover per DEC-21.
- [ ] **AC-TESTING-QB-NO-RED**: Per DEC-22 §refactor-clause Q-1b, NO
  RED-first tests authored for the relocation. Existing
  `PhotoStorageServiceImplTest` remains GREEN and serves as regression gate
  (test relocated to `de.vvwt.tm.photo.internal.DefaultPhotoStorageServiceTest`
  test package — same package as impl; DEC-36 permits white-box
  reference to the concrete class here, but implementer SHOULD prefer
  interface typing for future-proofing).
- [ ] **AC-TESTING-DEC36**: Any post-relocation test that lives in a
  DIFFERENT Java package than its subject (e.g., future cross-module
  consumers or a public-package test at `de.vvwt.tm.photo.PhotoStorageServiceTest`)
  references the `PhotoStorageService` interface (type + mock), NOT the
  concrete `DefaultPhotoStorageService` class — per DEC-36. Same-package
  tests are exempt from this rule per DEC-36 verbatim.
- [ ] **AC-PARALLEL-COEXISTENCE**: During parallel phase (until E23S05
  Cutover-1 deletes the legacy package), `DefaultPhotoStorageService`
  and legacy `de.vvwt.tm.domain.photo.PhotoStorageServiceImpl` BOTH
  exist on the classpath. To prevent
  `BeanDefinitionOverrideException`: the new `DefaultPhotoStorageService`
  is registered as the active `@Service` bean for the `PhotoStorageService`
  interface; the legacy `PhotoStorageServiceImpl` is excluded from
  component-scan via
  `@ComponentScan(excludeFilters = @Filter(type = FilterType.ASSIGNABLE_TYPE, classes = de.vvwt.tm.domain.photo.PhotoStorageServiceImpl.class))`
  on the tm-web `@SpringBootApplication` class (analog to E22S04/E22S05
  precedent for parallel-phase bean coexistence). The exclude-filter is
  REMOVED at E23S05 Cutover-1 when the legacy class is deleted.
  Not a DEC-21 feature-flag (DEC-21 forbids `@Profile` / `@ConditionalOnProperty`;
  exclude-filter is a structural component-scan directive, not a runtime
  flag).
- [ ] **AC-MODULITH-VERIFY-GREEN**: `ApplicationModulesTest` (`verify()`) is
  GREEN with the new photo module declared; no cross-module cycle
  (photo→tournament is DAG-valid).
- [ ] **AC-MVN-VERIFY-GREEN**: `mvn verify` is GREEN on staging PR.
  Coexistence with legacy `domain.photo.*` classes does not produce
  BeanDefinitionOverrideException (service beans are `@Service`-annotated
  in impl — only one impl active; legacy + new cannot both be `@Service`
  in same context during parallel phase — verify via exclude-filter or
  conditional; E23S05 cutover removes legacy).
- [ ] **AC-ERROR-HANDLING-UNCHANGED**: All 3 exceptions preserve their
  Javadoc + thrown-from semantics verbatim. No new exception types.
- [ ] **AC-GOVERNANCE-DEC35**: Public package contents match DEC-35 § Public
  package required content (service interface + VOs + exceptions + config).
  Internal package contains only the `Default*Service` implementation.
- [ ] **AC-SECURITY-UNCHANGED**: No REST-surface or auth-surface change in
  this story. Tenant-scoping behavior of `DefaultPhotoStorageService`
  preserved byte-equivalent: the regression-gate test
  (relocated `PhotoStorageServiceImplTest` → `DefaultPhotoStorageServiceTest`)
  exercises the tenant-resolution path via `TournamentRepository.findById`
  + `TeamRepository.findById` existence checks (both tenant-scoped via
  DEC-20 DataSource routing) and asserts the tenant-filtering behavior
  is preserved across the relocation.
- [ ] **AC-URL-UNCHANGED**: TeamPhotoController at legacy
  `infrastructure.web.photo.*` still serves OLD URL
  `/api/tournaments/{tid}/teams/{teamId}/photo` (no URL changes in this
  story; URL rename lands at E23S05 Cutover-1 atomic).
