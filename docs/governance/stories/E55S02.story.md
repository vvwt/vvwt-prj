# Story E55S02: Job-queue schema migration + DAO + Compare-and-Swap claim + DAO IT

## User Story

**As a** Tournament Manager developer (Delivery Agent),
**I want** the `phase_lifecycle_job` table created per tenant via Flyway migration AND `DefaultPhaseLifecycleJobRepository` implemented against the interface declared in E55S01, with the portable Compare-and-Swap claim mechanism working under H2 + DAO IT per DEC-26 + DEC-46,
**so that** subsequent E55 stories (E55S04 orchestrator, E55S05 cancel, E55S06 migration) have a durable per-tournament job queue + atomic claim primitive to build against, and so that DEC-49 T-6's in-memory-tracking trade-off is structurally eliminated.

## Context

DEC-64 D-4 specifies the schema + Compare-and-Swap claim mechanism. The CAS replaces `SELECT FOR UPDATE SKIP LOCKED` to remain portable across H2 versions and any future DB; the in-project precedent DEC-37 Clause B exercises only plain row-locking. Schema (per DEC-64 D-4 verbatim):

```sql
CREATE TABLE phase_lifecycle_job (
  id            UUID PRIMARY KEY,
  tournament_id UUID NOT NULL,
  phase_id      UUID NOT NULL,
  game_mode     VARCHAR NOT NULL,
  sequence      INT NOT NULL,
  status        VARCHAR NOT NULL,          -- 'PENDING' | 'RUNNING' | 'COMPLETED' | 'FAILED'
  cancelled     BOOLEAN NOT NULL DEFAULT FALSE,
  claimed_by    VARCHAR(64),
  claimed_at    TIMESTAMP,
  completed_at  TIMESTAMP,
  enqueued_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_phase_lifecycle_job_phase FOREIGN KEY (phase_id)
    REFERENCES phase(id) ON DELETE CASCADE
);
CREATE INDEX idx_phase_lifecycle_job_tournament_pending
  ON phase_lifecycle_job (tournament_id, sequence)
  WHERE status = 'PENDING';
```

The CAS claim is a two-statement protocol used by the per-tournament worker:

1. `SELECT id FROM phase_lifecycle_job WHERE tournament_id=? AND status='PENDING' ORDER BY sequence ASC, enqueued_at ASC LIMIT 1` — find next candidate for the specific tournament.
2. `UPDATE phase_lifecycle_job SET status='RUNNING', claimed_by=?, claimed_at=CURRENT_TIMESTAMP WHERE id=? AND status='PENDING'` — atomic claim; if `affectedRows == 0`, another worker already claimed it; loop to step 1.

DEC-26 (DAO IT three-rule protocol) + DEC-46 (per-module helper) apply: (a) schema-from-migration (no `@AutoConfigureTestDatabase(replace=NONE)` shortcuts), (b) independent assertj-db verifier, (c) read/write decoupling via direct JDBC for assertions. Per-module helper utility `PhaseLifecycleDaoTestSupport` follows DEC-46 pattern.

DEC-25 §no-prod-data condition applies — schema-only migration; no UPDATE-backfill SQL. The migration version follows the per-tenant Flyway runner convention (separate version sequence per tenant module).
