# Story E44S02: TM branding rollout — `<link rel="icon">` + lockup `<img>` + `ToM ·` titles in 3 Vite SPAs (admin/timer/display) + score-tablet Mustache carve-out (3 templates: lockup + favicon, no title-rebrand)

## User Story

**As a** Tournament Manager user (admin opening `/admin/`, organiser projecting `/display/`, scoring volunteer using a tablet at `/score/{field|hello|register}`, official monitoring `/timer/`),
**I want** every TM surface to show the VVW lockup in its header, the blue VVW hex-icon as its favicon, and a `ToM · {App}` title in the browser tab (where applicable),
**so that** every TM-family surface is identifiable as part of the same product family within one screen frame, and the visual identity is consistent across the admin SPA, the timer SPA, the public-display SPA, and the legacy ES5 score-entry tablet.

---

## Context

E44S01 establishes the asset-distribution mechanism and the per-module `public/` directory convention. E44S02 is the first consumer of that mechanism and rolls the brand identity into every user-facing TM surface.

`vvwt-tm-web` ships **three separate Vite-built SPAs**, each with its own `index.html`, `package.json`, and `vite.config.ts`:
- `vvwt-tm-web/src/main/ui/` (admin SPA, served at `/admin/`, current title `"Tournament Manager"`)
- `vvwt-tm-web/src/main/ui-timer/` (timer SPA, served at `/timer/`, current title `"Timer"`)
- `vvwt-tm-web/src/main/ui-display/` (Gesamtübersicht SPA, served at `/display/`, current title `"Gesamtübersicht"`)

Each Vite build outputs to its own `dist*/` directory, which `maven-resources-plugin` copies into `target/classes/static/{admin|timer|display}/` for fat-JAR self-host packaging per DEC-15.

In addition, `vvwt-tm-web` serves a **legacy score-tablet** under `/score/{field|hello|register}` via Mustache templates (`vvwt-tm-web/src/main/resources/templates/score/field.mustache`, `hello.mustache`, `register.mustache`). Per DEC-19, the score-tablet is restricted to vanilla ES5 inline JavaScript for legacy iOS Safari compatibility — but the DEC-19 restriction targets **inline JavaScript**, not HTML. `<link rel="icon">` is an HTML element, orthogonal to ES5 JS, so adding favicon links does not violate DEC-19. Empirical inspection confirmed that the 3 score Mustache templates have **no shared `<head>` partial** — each carries its own complete `<head>` block, so the favicon link must be added to all 3 files separately.

The 3 Vite SPAs receive the new `ToM · {App}` title schema (D-7) verbatim:
- admin: `"ToM · Tournament Manager"`
- timer: `"ToM · Timer"`
- display: `"ToM · Overview"` (intentional German→English translation matching the all-English `ToM · {App}` family schema; Discovery decision D-7 + D-8)

The score-tablet is **excluded** from the title schema: its existing controller-driven `{{title}}` shows match-specific context (e.g., field number, team names) and a `ToM ·` static prefix would obscure that context. The score-tablet receives the lockup + favicon only — no title rewrite.

The CSS-token rollout (`--vvw-blue: #1956a8`, `--vvw-yellow: #ffcb1f`, `--vvw-ink: #0a1f3a` per D-5) is **conditional**: an audit phase counts the existing component-local color values in the 3 Vite SPAs. If the count exceeds 20 per app, the token migration is deferred to a follow-up Story; the favicon/lockup/title rollout proceeds standalone in this Story regardless. This guard keeps E44S02's PR size bounded and prevents the rollout from being held hostage by a heavy palette migration (Brief H-2 fallback).

## Acceptance Criteria

- [ ] **AC1 (testing — RED-first per DEC-22)**: A controller integration test asserts that the **server-rendered HTML** (response body of `GET /admin/` before any client-side JavaScript executes — i.e., the Vite-built `index.html` served from `classpath:/static/admin/index.html`) contains in its `<head>`: an SVG-first favicon link `<link rel="icon" type="image/svg+xml" href="vvw-icon-blue.svg">` followed by at least one PNG fallback link (e.g., `<link rel="icon" type="image/png" sizes="32x32" href="vvw-favicon-blue-32.png">`). The test fails on current `index.html` (no favicon present per audit O-1) and passes after E44S02 modifies `vvwt-tm-web/src/main/ui/index.html` and the asset is in `public/`. Test annotation per DEC-44: `@SpringBootTest(RANDOM_PORT, classes = TournamentManagerApplication.class)` (web-module IT canon — DEC-44 retro-corrects DEC-38 / DEC-40 §Sub-Clause-3 for web-module ITs).
- [ ] **AC2 (testing — RED-first per DEC-22)**: Analogous controller integration tests assert the same favicon-link presence in the served HTML for `GET /timer/` (using same blue hex-icon assets) and `GET /display/` (same blue hex-icon assets). RED-first; one test per route.
- [ ] **AC3 (testing — RED-first per DEC-22)**: Three controller integration tests assert that the served HTML for the score-tablet endpoints (`GET /score/field?...`, `GET /score/hello?...`, `GET /score/register?...`) each contains a `<link rel="icon" type="image/svg+xml" href="vvw-icon-blue.svg">` (or equivalent under `/score/` static path served via classpath:/static/score/). RED-first; one test per Mustache file.
- [ ] **AC4 (testing — RED-first per DEC-22)**: Controller integration tests assert that the **server-rendered** HTML `<title>` (from the Vite-built `index.html`, before any client-side `document.title` mutation) for the 3 Vite SPAs is exactly `"ToM · Tournament Manager"` (admin), `"ToM · Timer"` (timer), `"ToM · Overview"` (display). The test fails on current titles (`"Tournament Manager"`, `"Timer"`, `"Gesamtübersicht"`) and passes after `index.html` is rewritten in each Vite root. The assertion is on the server-side response body, not on a JSDOM/headless-browser-rendered title (which would test the runtime layer instead).
- [ ] **AC5 (compliance)**: Each Vite SPA root component renders the brand lockup as `<img src="/${base}/vvw-tm-logo.svg" alt="Tournament Manager">` (or framework-equivalent — e.g., a Svelte `<img>` element); the `alt` text is exactly `"Tournament Manager"` (per Brief Q-4 — speaking, not generic `"logo"`). **The score-tablet (3 Mustache templates) ALSO renders the lockup** in its `<head>`-adjacent header region with the same `alt="Tournament Manager"` text — per Brief D-4 (carve-out: "Score-Tablet GETS Lockup + Favicon") which the user twice-validated (Q3=ja). The lockup placement on the score-tablet must respect the high-density data-entry context (e.g., header strip, not a full-width banner) but must be present.
- [ ] **AC6 (compliance)**: Each of the 3 TM Vite-SPA `index.html` files (admin/timer/display) declares an `<link rel="apple-touch-icon" href="vvw-favicon-blue-256.png">` (256-px PNG, **without a `sizes` attribute** — iOS scales as needed; declaring `sizes="180x180"` for a 256-px asset would be misleading metadata, and Brief S-5 forbids editing HANDOFF to add a 180-px asset). iOS still uses the 256-px asset for home-screen pinning. The score-tablet does NOT receive apple-touch-icon — Brief D-4 names the carve-out as "Lockup + Favicon" only; apple-touch-icon is a separate compliance feature that is not part of D-4 and would be agent-introduced scope creep.
- [ ] **AC7 (error-handling)**: Each of the 3 TM Vite-SPA `index.html` files (admin/timer/display) declares the favicon `<link>` tags in the order: **SVG first, then PNG sizes from largest to smallest** (browser-standard fallback order). When the SVG fails to load, the browser falls back to the next declared `<link>`. Verifiable mechanically: each `index.html` contains both an `<link rel="icon" type="image/svg+xml">` and at least one `<link rel="icon" type="image/png">`, with the SVG link declared first in document order. Score-tablet receives the same SVG-first ordering for its 3 Mustache `<head>` blocks.
- [ ] **AC8 (error-handling)**: When the brand asset SVG fails to render (file missing at runtime, e.g., asset unreachable, browser cache miss + CDN-equivalent gap), the page remains functional — the lockup `<img>` falls back to its `alt` text and the browser tab `<title>` continues to display. Verifiable via a **MockMvc test** (or equivalent) that requests `GET /admin/non-existent-asset.svg` and asserts a 404 response (Spring's static-resource handler default), establishing that asset absence does not break the application surface. The `index.html` itself never references a script that depends on the favicon SVG; verifiable by grep over the served `index.html` for any `<script>` block referencing `vvw-icon-blue.svg` (must be zero matches).
- [ ] **AC9 (governance)**: All vendored brand asset filenames in `vvwt-tm-web/src/main/{ui,ui-timer,ui-display}/public/` and `vvwt-tm-web/src/main/resources/static/score/` are **vendored copies** of the `handoff/` masters (populated via `scripts/sync-brand-assets.sh` from E44S01) — verbatim filenames per HANDOFF (`vvw-tm-logo.svg`, `vvw-icon-blue.svg`, `vvw-favicon-blue-{16,32,64,128,256}.png`); no renaming. The hash relationship to `handoff/` is enforced by E44S01's `scripts/verify-brand-assets.sh` running in `mvn verify` — Delivery does NOT re-implement the verify logic in S02. Regression check: `mvn verify` in S02's PR continues to exit 0 (i.e., the new vendored copies still match `handoff/` masters after S02's index.html / Mustache edits add the references but do NOT modify the asset bytes).
- [ ] **AC10 (governance)**: The 3 score Mustache templates retain their existing controller-driven `<title>{{title}}</title>` mechanism unchanged — no `ToM ·` prefix is added to score-tablet titles (Brief D-7 carve-out). Mustache template body content is otherwise unchanged; the only edits are `<head>` additions for the favicon `<link>` and apple-touch-icon `<link>`.
- [ ] **AC11 (compliance + testing)**: A CSS-audit phase counts component-local color values (any literal `#xxxxxx`, `rgb(...)`, named colour, or `oklch(...)`) in the 3 Vite SPAs (`*.svelte`, `*.css`, `*.ts` excluding `node_modules` and `dist*/`). If the total count is **≤20 per app**, the impl-report includes the result and the rollout adopts CSS tokens (`--vvw-blue`, `--vvw-yellow`, `--vvw-ink` declared in a shared CSS file imported by each SPA). If the count is **>20 in any app**, the impl-report explicitly notes the deferral, and a follow-up Story is escalated to Discovery for token migration; the favicon/lockup/title rollout still ships in this Story unchanged. The threshold is sharp per Brief D-5 — no grey zone.
- [ ] **AC12 (governance — surface-specific path conventions)**: Each surface references brand assets via its native path-staging mechanism — never via direct `handoff/` paths or external URLs:
  - **Vite SPAs** (admin/timer/display): assets staged under `{ui-dir}/public/` and resolved at runtime via Vite's `base` config (`/admin/`, `/timer/`, `/display/`); references in `index.html` use plain filenames (`href="vvw-icon-blue.svg"`) which Vite rewrites to base-prefixed URLs at build time.
  - **Score-tablet** (Mustache, Pattern Mustache): assets staged under `vvwt-tm-web/src/main/resources/static/score/` and served by Spring at `/score/{filename}`; references in the 3 Mustache templates are absolute paths (`href="/score/vvw-icon-blue.svg"`) — NOT Vite-resolved.
  - Verified mechanically by grep over `index.html`, Mustache templates, and Svelte components: no literal `handoff/` substring, no `https://` URL referencing brand assets.
- [ ] **AC13 (compliance — minimum render sizes per Brief C-9)**: The brand lockup `<img>` in each Vite SPA root component is rendered at ≥120px CSS width (verifiable via component test asserting computed style or via a `width` attribute / CSS class declaration). The favicon `<link>` declarations include at least the 16×16 PNG variant per Brief C-9 (`<link rel="icon" type="image/png" sizes="16x16" href="vvw-favicon-blue-16.png">`). Score-tablet lockup `<img>` also respects the ≥120px minimum.
- [ ] **AC14 (governance — no-auto-hook negative assertion per Brief D-9)**: S02 introduces no git pre-commit hook, no post-merge hook, no CI auto-sync step, no Husky / lefthook configuration, and no Maven plugin invoking `scripts/sync-brand-assets.sh` automatically. Asset refresh remains exclusively manual per Brief D-9. Verifiable by grep: no new entries in `.husky/`, `.git/hooks/`, `.github/workflows/`, or POM `<execution>` blocks reference `sync-brand-assets`.

## Notes

**Test-mechanism choice (Delivery)**: The controller integration tests in AC1–AC4 + AC8 may use existing TM-web test infrastructure. Per DEC-44, web-module controller integration tests use `@SpringBootTest(RANDOM_PORT, classes = TournamentManagerApplication.class)` rather than `@ApplicationModuleTest` — that pattern is the canon for new web-module ITs in this Story. Per DEC-44 §"2026-04-27 Empirical Refinement", web-module ITs must include `@Import({WebModuleTestConfig.class, <IT>.TestAdminCredentials.class})` for the auth-substitute chain to wire correctly under `@SpringBootTest`. Score-tablet ITs (AC3) target `/score/` endpoints and may require existing fixture controllers to render the Mustache templates against test data.

**Asset path convention (Vite)**: Vite resolves files placed in `{ui-dir}/public/` to root-level URLs at the configured `base` (e.g., `vvwt-tm-web/src/main/ui/public/vvw-icon-blue.svg` → `/admin/vvw-icon-blue.svg` in production). The `<link rel="icon" href="vvw-icon-blue.svg">` reference in `index.html` resolves correctly in dev (`vite dev`) and in production (Spring Boot serving from `classpath:/static/admin/`). Verify in dev mode before committing.

**CSS-token-deferral fallback (Brief H-2)**: The 20-value threshold is sharp per Brief D-5. The impl-report must record the audit numbers per app for traceability — Delivery does NOT introduce a grey-zone judgement: ≤20 → tokens applied, >20 → defer (no exceptions).

**ToM-acronym + brand-acronym coexistence (Brief D-8)**: `ToM` appears in the browser tab title (`ToM · Tournament Manager`); `T 🏆 M` appears in the lockup (HANDOFF brand mark). Both markers are visible simultaneously in the user's viewport — this is the intentional Discovery decision and must not be "harmonised" by Delivery during implementation.
