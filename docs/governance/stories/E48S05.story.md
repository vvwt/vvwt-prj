# Story E48S05: Phasen-Übersicht-Route + Per-Phase-Navigation (read-only display)

## User Story

**As a** Tournament Organizer of an active tournament,
**I want** a Phasen-Übersicht-Route that shows all phases of my tournament with their status, gameMode, current lap, and match counts,
**so that** I can navigate to a specific phase to manage its lifecycle and see at a glance where the tournament currently stands.

---

## Context

Per Brief S-2 + O-6: aktuell existiert keine Svelte-Route für Phasen-Anzeige oder per-Phase-Navigation. Die Tournaments-Liste bleibt der oberste Einstiegspunkt; aber sobald ein Tournament PLANNED/ACTIVE ist, muss ein Admin in eine "Phasen-Sicht" navigieren können. Diese Story liefert die read-only Foundation: eine neue Svelte-Route `/tournaments/:tournamentId/phases` mit Tabellen-Anzeige (Phase-sequenceNumber, Description, Status-Badge, gameMode aus draft_json, currentLapNumber, Match-Counts pro State); ein REST-Endpoint `GET /api/tournaments/:tournamentId/phases` der DTOs zurückgibt. Phase-Lifecycle-Buttons (Start/Finalize/Notabschluss) kommen in E48S06 — diese Story ist nur Anzeige.

Navigation-Eintritt: aus `Tournaments.svelte` Action-Spalte ein neuer Button "Phasen" (sichtbar wenn Status ∈ {PLANNED, ACTIVE, COMPLETED, CANCELLED}) der nach `/tournaments/:id/phases` navigiert. E47 Shell-Mechanism (sticky Header per E47S01) wird konsumiert für Page-Title + Back-Button.

- [ ] **AC-TEST-PHASE-LIST-ENDPOINT-RED** (testing): RED-first IT-Test: `GET /api/tournaments/:tournamentId/phases` returns Liste von Phase-DTOs mit Feldern (id, sequenceNumber, description, status, gameMode, currentLapNumber, matchCountsByState); 200 OK bei valid tournamentId, 404 bei unknown tournamentId.
- [ ] **AC-IMPL-PHASE-LIST-ENDPOINT**: Controller `TournamentPhasesController` (oder Methode auf existierendem `TournamentController`) in `de.vvwt.tm.web` per DEC-40; Service-Methode `DefaultPhaseQueryService.listPhasesWithCounts(tournamentId)` in `de.vvwt.tm.tournament.internal`; Read-only DTO `PhaseOverviewResponse` im public package.
- [ ] **AC-IMPL-GAMEMODE-FROM-DRAFT-JSON**: Phase-DTO `gameMode` Feld wird aus `tournament.draft_json` abgeleitet (parse JSON, lookup section.gameMode bei matching sectionNumber); defensive null-handling per C-14 / E48S02 (falls draft_json null/parse-error → AC-PHASE-LIST-DEFENSIVE).
- [ ] **AC-PHASE-LIST-DEFENSIVE** (error-handling): falls draft_json null oder parse-error → DTO-Feld `gameMode = null` und Response-Status bleibt 200 (kein hard fail; UI zeigt "—" oder "?").
- [ ] **AC-IMPL-MATCH-COUNTS-BY-STATE**: für jede Phase die Counts der Matches gruppiert nach State (z.B. `{OPEN: 0, ENABLED: 8, INPROGRESS: 1, ONCHECK: 0, FINISHED_WINNER1: 4, FINISHED_WINNER2: 3, FINISHED_STANDOFF: 0, CANCELED: 0}`); via einer einzigen Aggregation-Query (kein N+1).
- [ ] **AC-TEST-CONTROLLER-IT-PER-METHOD-GREEN** (testing): happy-path + security-negative IT (DEC-44 `@SpringBootTest`); DB-side verifier per assertj-db.
- [ ] **AC-FRONTEND-PHASES-ROUTE** (i18n + url-routing): neue Svelte-Route `/tournaments/:tournamentId/phases` registriert in `App.svelte` routes map; new component `PhaseList.svelte` in `src/routes/`; Page-Title aus i18n (`phases.pageTitle`); Tabellen-Spalten via i18n.
- [ ] **AC-FRONTEND-STATUS-BADGE** (i18n): Phase-Status (PENDING/ACTIVE/COMPLETED) als farbiges Badge; Color-Coding konsistent mit Brief Q-3 ("gleiches visuelles Vokabular für Tournament- und Phase-Status").
