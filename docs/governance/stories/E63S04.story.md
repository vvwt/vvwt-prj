# Story E63S04: TM embedded worker — host-protection: live-scoring auto-pause probe + inter-packet CPU throttle

## User Story

**As a** Tournament Manager operator who has enabled the embedded worker,
**I want** the worker to step aside while my server is busy with live scoring and to never
monopolize the CPU,
**so that** contributing compute to the pool never degrades the tournament-day duties my TM
server exists for.

---

## Context

E63S03 builds the embedded-worker core: it pulls, solves, and submits packets on a
background thread. But a worker that solves packets at full tilt would compete with TM's
primary, tournament-day-critical duties (live scoring, the admin UI) for CPU. Two
host-protection mechanisms close that gap:

1. **Live-scoring auto-pause.** The worker observes whether TM is actively live-scoring and,
   when it is, pauses between packets. This is the only host coupling the embedded worker
   has: a thin host-provided `HostActivityProbe` interface (`boolean isLiveScoringActive()`)
   — the pattern from the original Story E01S11. TM implements the probe; the worker reads
   it. The worker still never touches the TM database and never couples to the DEC-64
   Saga-Orchestrator (Session Brief C-5).

2. **Inter-packet CPU throttle.** A packet, once started, runs to completion at full speed
   (`PacketSolver` is not interruptible mid-packet). The throttle is enforced *between*
   packets: after solving a packet the worker sleeps proportionally so its averaged CPU
   share stays within a configured bound. This is **new design** — the standalone worker's
   `CpuThrottle` only sleeps when *no packet is available* (idle-poll pacing); it does not
   bound CPU while there is work.

Both mechanisms act between packets, never mid-packet.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-AUTO-PAUSE-ON-LIVE-SCORING** — RED-first (DEC-22): when the `HostActivityProbe`
  reports live-scoring active, the embedded worker pauses between packets — it does not pull
  the next packet — and rechecks on an interval; when live-scoring ends it resumes pulling.
- [ ] **AC-TEST-PAUSE-IS-BETWEEN-PACKETS** — a packet already being solved when live-scoring
  becomes active runs to completion; the pause takes effect before the next pull, never
  mid-packet.
- [ ] **AC-TEST-CPU-THROTTLE-RATIO** — RED-first: with the throttle configured, the worker's
  averaged compute share over a measurement window stays within the configured bound — the
  inter-packet sleep enforces it. The test fails against an un-throttled worker and passes
  with the throttle.
- [ ] **AC-TEST-THROTTLE-IS-BETWEEN-PACKETS** — the throttle sleep is applied between
  packets; a packet runs to completion uninterrupted once started.
- [ ] **AC-TEST-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for `vvwt-tm-web` (DEC-54).

### Governance

- [ ] **AC-GOV-HOST-ACTIVITY-PROBE-INTERFACE** — the worker observes host live-scoring state
  ONLY through a `HostActivityProbe` interface (`boolean isLiveScoringActive()`); TM provides
  the implementation. Reading this thin in-process interface is the permitted host coupling
  (Session Brief C-5 / DEC-64) — the worker still does not read the TM database and does not
  couple to the Saga-Orchestrator.
- [ ] **AC-GOV-INTER-PACKET-THROTTLE-IS-NEW** — the inter-packet ratio throttle is new
  design; it is NOT the standalone `CpuThrottle` (idle-poll pacing only). The impl-report
  records that this is new work, RED-first authored, not a reuse of the standalone throttle.
- [ ] **AC-GOV-CONFIG-DOCUMENTED** — the throttle bound config key and the auto-pause
  behaviour are documented in the operator-facing config reference; sensible defaults are
  set (a conservative CPU share, given the worker shares the host).
- [ ] **AC-GOV-INTERFACE-MANDATE** — new behaviour-bearing Spring components obey DEC-58 /
  DEC-72 / DEC-35 / DEC-36 (interface in the module root, `Default*` impl in `.internal`);
  the interface-mandate build guard stays green.
- [ ] **AC-GOV-RED-FIRST** — new first-party code is authored RED-first per DEC-22; the
  impl-report records RED-state evidence.
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); warning-free (DEC-29);
  Spotless / google-java-format (DEC-30); no production member exists solely for tests
  (DEC-70).
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use `chore(E63S04):` / `feat(E63S04):`
  prefixes per the close-story.sh contract.

### Error Handling

- [ ] **AC-ERR-PROBE-FAILURE-IS-CONSERVATIVE** — if the `HostActivityProbe` throws or is
  unavailable, the worker treats the host as active (pauses) rather than charging ahead — a
  fail-safe biased toward not interfering with TM's primary duties; the failure is logged.
- [ ] **AC-ERR-PAUSE-DOES-NOT-ABANDON-PACKET** — pausing does not lose, abandon, or fail a
  claimed packet: a packet claimed before a pause is still solved and submitted; a pause
  before a claim simply defers the next pull.
- [ ] **AC-ERR-RESUME-AFTER-PAUSE** — after a pause (live-scoring or throttle), the worker
  reliably resumes pulling — a pause is never terminal.

### Security

- [ ] **AC-SEC-NO-NEW-SURFACE** — the probe and the throttle introduce no new authentication,
  credential, or wire-protocol surface; the `HostActivityProbe` carries only a boolean and no
  team UUIDs or PII (DEC-9). No new dispatcher interaction is added by this story.

## Notes

The `HostActivityProbe` is the resolution of the C-5 tension: the worker must observe host
live-scoring (to auto-pause) yet must not couple to the host DB / orchestrator — a thin
host-provided interface is exactly the E01S11 pattern and is the permitted coupling. The
inter-packet ratio throttle is new work, not a reuse of the standalone `CpuThrottle`.
