# Story E51S05: Lifecycle-ASSIGNED status + Transition-Tabelle (verb-encoded) + Activation-Guard

## User Story

**As a** Tournament Operator,
**I want** the phase lifecycle to capture an explicit "Mannschaften und Schiedsrichter zugeordnet"-Status (ASSIGNED) between PREPARED and ACTIVE — and the activation step to refuse if I have not yet completed slot-optimization (when `tournament.optimize=true`),
**so that** I cannot accidentally start a phase before the upfront optimization has produced its result, and the phase status I see in PhaseList tells me exactly what step is still pending.

---

## Context

DEC-55 D-4 + D-6 mandate: phase lifecycle becomes `PENDING → PREPARED → ASSIGNED → ACTIVE → COMPLETED`. Status changes are governed by an action-verb-encoded transition table (cycle-2 reviewer F-2 fix). Activation guard: `!tournament.optimize OR phase.optimized`.

Today's `PhaseLifecycleService` (`de.vvwt.tm.tournament.internal.DefaultPhaseLifecycleService`) handles `prepare()`, `start()`, `complete()`, `forceComplete()` per E48S17 — all are simple status-flips with `IllegalStateException` on wrong source-status. There is no transition table; transition rules are scattered across `if (phase.getStatus() != PENDING) throw ...` style checks.

This story replaces the scattered checks with a single `Map<PhaseStatus, Set<TransitionEdge>>` source-of-truth, where `TransitionEdge = (target, verb)`. The verb distinguishes `complete()` from `forceComplete()` (both ACTIVE → COMPLETED — same edge in a state-only diagram, different verbs in this encoding).

Per DEC-55 D-4:

```java
record TransitionEdge(PhaseStatus target, String verb) {}

static final Map<PhaseStatus, Set<TransitionEdge>> ALLOWED = Map.of(
    PENDING,    Set.of(new TransitionEdge(PREPARED, "match-gen-done")),
    PREPARED,   Set.of(new TransitionEdge(ASSIGNED, "assign")),
    ASSIGNED,   Set.of(new TransitionEdge(ACTIVE,    "start"),
                       new TransitionEdge(ASSIGNED,  "re-assign")),
    ACTIVE,     Set.of(new TransitionEdge(COMPLETED, "complete"),
                       new TransitionEdge(COMPLETED, "force-complete"))
);
```

`PENDING → PREPARED` is invoked by the match-gen-listener (E51S03) when match-gen completes, with verb `"match-gen-done"`. `PREPARED → ASSIGNED` is invoked by `commitTransition` (E51S06) with verb `"assign"`. `ASSIGNED → ACTIVE` is the operator's "Phase aktivieren" click — gated by D-6 activation-guard.

Note: this story DOES NOT modify match-gen-listener (E51S03) or `commitTransition` (E51S06). It introduces the transition-table validator in `PhaseLifecycleService` and exposes a new method `void transition(UUID phaseId, PhaseStatus target, String verb)` that enforces the table. E51S03 and E51S06 are responsible for calling `transition(...)` instead of direct status-set; whether they call it gets verified by AC tests in their own stories. E51S05 verifies the validator + activation-guard logic in isolation.

## Acceptance Criteria

- [ ] **AC-TEST-TRANSITION-TABLE-ALLOWED-PATHS-RED** (testing): RED-first IT — for each entry in the `ALLOWED` map, invoking `transition(phaseId, target, verb)` succeeds; the phase's status is updated. Test fails before fix because the table + service method do not exist.
- [ ] **AC-TEST-TRANSITION-TABLE-DISALLOWED-REJECTED-RED** (testing): RED-first IT — for a representative set of disallowed transitions (e.g., PENDING → ACTIVE with verb "start"; ASSIGNED → PENDING with any verb; ACTIVE → PREPARED with any verb), `transition(...)` throws `IllegalStateException` with a message naming source + target + verb. No status mutation occurs. Test fails before fix.
- [ ] **AC-TEST-VERB-DISCRIMINATES-EDGES-RED** (testing): RED-first IT — `transition(phaseId, COMPLETED, "complete")` and `transition(phaseId, COMPLETED, "force-complete")` BOTH succeed from ACTIVE (both verbs are in the table for ACTIVE→COMPLETED); `transition(phaseId, COMPLETED, "phantom-verb")` fails because the verb is not in the table. Test fails before fix because today's logic is verb-agnostic.
- [ ] **AC-TEST-ACTIVATION-GUARD-OPTIMIZE-FALSE-PASSES-RED** (testing): RED-first IT — given `tournament.optimize=false`, `phase.status=ASSIGNED`, `phase.optimized=false`, calling `transition(phaseId, ACTIVE, "start")` succeeds. Test fails before fix because the guard does not exist.
- [ ] **AC-TEST-ACTIVATION-GUARD-OPTIMIZED-TRUE-PASSES-RED** (testing): RED-first IT — given `tournament.optimize=true`, `phase.status=ASSIGNED`, `phase.optimized=true`, `transition(phaseId, ACTIVE, "start")` succeeds. Test fails before fix.
- [ ] **AC-TEST-ACTIVATION-GUARD-FAIL-RED** (testing): RED-first IT — given `tournament.optimize=true`, `phase.status=ASSIGNED`, `phase.optimized=false`, `transition(phaseId, ACTIVE, "start")` throws an operator-actionable exception (e.g., `OperatorActionableException` mapped to HTTP 409) with a message naming the unmet condition. Test fails before fix.
- [ ] **AC-TEST-EXISTING-LIFECYCLE-OPERATIONS-PRESERVED-GREEN** (testing): regression — existing E48S17 lifecycle behavior for the operator-callable methods (`prepare`, `start`, `complete`, `forceComplete`) is preserved at the controller layer. The controllers may now call `transition(phaseId, target, verb)` internally instead of direct status-set. Verified by re-running the E48S17/E48S06 controller-IT suite GREEN against the post-fix code.
- [ ] **AC-TEST-PHASE-STATUS-CHANGED-EVENT-EMITTED-GREEN** (testing): regression — every successful `transition(...)` publishes `PhaseStatusChangedEvent` (existing event, unchanged). The transition table does NOT replace the event-publishing semantics. Verified by `@RecordApplicationEvents`.
- [ ] **AC-IMPL-TRANSITION-TABLE-IN-LIFECYCLE-SERVICE**: `Map<PhaseStatus, Set<TransitionEdge>>` declared as private static final in `DefaultPhaseLifecycleService` (or extracted to a `PhaseTransitionTable` constants class — Delivery's choice). Verb is a `String` constant per established Spring/Java idioms.
- [ ] **AC-IMPL-TRANSITION-METHOD-API**: new public method `void transition(UUID phaseId, PhaseStatus target, String verb)` on `PhaseLifecycleService`. Existing methods (`prepare`, `start`, `complete`, `forceComplete`) MAY delegate to `transition(...)` or remain as façades — Delivery's choice. The chosen approach documented in impl-report.
- [ ] **AC-IMPL-ACTIVATION-GUARD-INSIDE-START**: the activation-guard `!tournament.optimize OR phase.optimized` evaluates inside `transition(phaseId, ACTIVE, "start")` BEFORE the status mutation. Guard reads `tournament.optimize` via `tournamentRepository.findById(phase.getTournamentId())` and `phase.optimized` from the phase record itself.
- [ ] **AC-IMPL-DEC-37-LOCK-PRESERVED**: `transition(...)` acquires the per-tournament pessimistic row-lock (`tournamentRepository.findByIdForUpdate(tournamentId)`) as the first read in its transaction per DEC-37 Clause B. The existing E48S17 lifecycle operations also acquire this lock — preserved.
- [ ] **AC-IMPL-EXISTING-CONSUMERS-NOT-MODIFIED**: this story does NOT modify match-gen-listener (E51S03), `commitTransition` (E51S06), or any controller. Their migration to `transition(...)` calls happens in their own stories. Verified by `git diff --name-only staging...HEAD` showing only `DefaultPhaseLifecycleService.java` + new test files.
- [ ] **AC-ERROR-HANDLING-EXCEPTION-MESSAGE-OPERATOR-ACTIONABLE** (error-handling): rejection messages name the source-status, target-status, verb, AND the offending phase's UUID. Activation-guard rejection additionally names which condition failed (e.g., "phase X cannot transition to ACTIVE: tournament Y has optimize=true and this phase has optimized=false; wait for slot-opt completion or cancel the slot-opt to apply Best-So-Far").
- [ ] **AC-ERROR-HANDLING-NULL-VERB-REJECTED** (error-handling): `transition(phaseId, target, null)` throws `IllegalArgumentException` with a clear message. No NPE leakage.
- [ ] **AC-ERROR-HANDLING-PHASE-NOT-FOUND** (error-handling): `transition(unknownPhaseId, ...)` throws `IllegalArgumentException` with a message naming the unknown id, before any guard or table lookup. No NPE leakage.
- [ ] **AC-SECURITY-NO-NEW-AUTH-SURFACE** (security): no new endpoint. The internal service signature change is consumed only by callers in tournament context.
- [ ] **AC-GOVERNANCE-DEC-22-Q-1A-RED-FIRST** (governance): all 6 RED-first tests precede production-code change.
