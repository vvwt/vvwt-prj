# Story E23S05: Photo atomic cutover (Cutover-1) — delete legacy `de.vvwt.tm.domain.photo.*` + `infrastructure.web.photo.*` + atomic URL rename to `/api/photo/tournaments/{tid}/teams/{teamId}` (Java code + Svelte UI) + DefaultPhotoUrlBuilder URL-template swap via atomic RED-GREEN pair

## User Story

**As a** maintainer of the `vvwt-tm-web` application at the end of the E23
photo track,
**I want** a single atomic commit that deletes all legacy photo packages,
renames the photo URL from `/api/tournaments/{tid}/teams/{teamId}/photo` to
`/api/photo/tournaments/{tid}/teams/{teamId}`, and atomically flips
DefaultPhotoUrlBuilder's URL template in lockstep with TeamPhotoController's
@GetMapping update + Svelte UI path literals,
**so that** after Cutover-1 the photo context is fully reconstructed under
DEC-21 per-context atomic cutover semantics, no transient 404 affects
HTML-certificate rendering (D-17 decoupling ensures CertificateAssembler
picks up the new URL through PhotoUrlBuilder), and the staging branch
reflects a clean photo module.

---

## Context

Per Brief v4 D-12 + S-6 (Cutover-1), this is the first of two E23 atomic
cutover commits (photo first per Brief T-5). The cutover is atomic per
DEC-21 Line 126-133 (single commit deletes legacy + promotes new + updates
Spring wiring).

Per Brief v4 D-17 + C3-C2 (Cycle-3 Review resolution, user-chosen Option Y):
the URL template flip is an atomic RED-GREEN pair within this single
commit — test assertions are edited FIRST (RED: assert NEW URL template,
source still emits OLD → fails), then DefaultPhotoUrlBuilder source is
edited (GREEN: emit NEW URL template). All within a single atomic commit
per DEC-21 — analog to the E22S08 URL-rename pattern.

Per DEC-21 Line 148-151, deploy-pause on staging is acceptable during the
atomic switch (no production deployment).

## Acceptance Criteria

- [ ] **AC-LEGACY-DELETION**: Deletes 7 classes at `de.vvwt.tm.domain.photo.*`
  (`PhotoStorageService` interface, `PhotoStorageServiceImpl`, `PhotoFileMetadata`,
  `PhotoStorageConfig`, `PhotoFormatException`, `PhotoSizeException`,
  `PhotoStorageException`) and 2 classes at `de.vvwt.tm.infrastructure.web.photo.*`
  (`TeamPhotoController`, `PhotoMetadataResponse`) and their legacy test
  files.
- [ ] **AC-URL-RENAME-CONTROLLER**: `TeamPhotoController` at
  `de.vvwt.tm.web.photo.*` (moved in E23S04): all `@*Mapping` path
  attributes updated from `/api/tournaments/{tid}/teams/{teamId}/photo`
  to `/api/photo/tournaments/{tid}/teams/{teamId}`. The 3 endpoints
  (upload POST, retrieve GET, delete DELETE — grep actual mappings) all
  switch atomically.
- [ ] **AC-URL-RENAME-URLBUILDER**: `DefaultPhotoUrlBuilder.buildTeamPhotoUrl`
  return string template changes from
  `"/api/tournaments/" + tid + "/teams/" + teamId + "/photo"` to
  `"/api/photo/tournaments/" + tid + "/teams/" + teamId`. Single-line
  change in impl.
- [ ] **AC-ATOMIC-RED-GREEN-PAIR**: Within this commit, the following edits
  appear in sequence (commit history may be a single commit; the sequence
  is logical/reviewable not chronological):
  (1) `DefaultPhotoUrlBuilderTest` assertion updated to expect NEW URL (RED
      under pre-edit source),
  (2) `DefaultPhotoUrlBuilder` source updated to emit NEW URL (GREEN),
  (3) `TeamPhotoControllerIT` / `TeamPhotoControllerSliceTest` assertions
      updated for NEW URL (RED under pre-edit controller),
  (4) `TeamPhotoController` `@*Mapping` paths updated to NEW URL (GREEN),
  (5) `CertificateAssemblerTest` PhotoUrlBuilder mock-fixture updated to
      return NEW URL pattern (if test uses such fixture),
  (6) Svelte UI path literals updated (see AC-SVELTE-UI-ATOMIC).
- [ ] **AC-SVELTE-UI-ATOMIC**: Svelte UI consumer paths updated in the
  same commit. Files likely affected (grep during implementation):
  `src/main/ui/src/stores/` + `src/main/ui/src/routes/` searches for
  `"/api/tournaments/" + ".../photo"` or similar. All occurrences
  updated to the NEW URL template (E22 O-12 precedent — no transient 404).
- [ ] **AC-COMPONENT-SCAN-EXCLUSION-REMOVED**: If E23S01 / E23S04 introduced
  `@ComponentScan(excludeFilters = ...)` on legacy photo packages, that
  exclusion is REMOVED in this commit (legacy is gone, exclusion no longer
  needed).
- [ ] **AC-MOCKITOBEAN-FINAL-SWEEP**: Any remaining `@MockitoBean
  PhotoStorageService` declarations in web-module ITs are removed per
  DEC-38 2026-04-22 Amendment reverse-case (real bean present in web's
  allowedDeps).
- [ ] **AC-MODULITH-VERIFY-GREEN**: Post-cutover `ApplicationModulesTest`
  `verify()` GREEN. Photo module declares `allowedDependencies = {"tenant",
  "tournament"}`. Web module declares photo in its allowedDependencies.
  No cycles.
- [ ] **AC-MVN-VERIFY-GREEN**: Post-cutover `mvn verify` GREEN on the
  cutover PR. All pre-existing and relocated tests GREEN against NEW URL.
- [ ] **AC-TESTING-ALL-GREEN**: `DefaultPhotoUrlBuilderTest`,
  `TeamPhotoControllerIT`, `TeamPhotoControllerSliceTest`,
  `DefaultPhotoStorageServiceTest`, `CertificateAssemblerTest` all GREEN
  post-cutover.
- [ ] **AC-TESTING-NO-CHARACTERIZATION**: All edits maintain DEC-22 Iron
  Law: the URL template change is treated as a Q-1b surface-rename per
  DEC-40 precedent (E22S08 pattern), not Characterization. Commit message
  cites DEC-22 + DEC-34 override-by-delta + DEC-40 precedent.
- [ ] **AC-FLYWAY-NO-CHANGE**: Photo has no DB migration; no Flyway

- [ ] **AC-GOVERNANCE-DEC-21-ATOMIC**: Commit message structured per

- [ ] **AC-GOVERNANCE-DECISION-LOG**: Delivery's `decision-extraction`
  skill updates `contexts/memory/decisions/_log.md` post-QA-PASS to
  confirm DEC-32 invocation count unchanged (stays at #1 = E21S13; this
  cutover is Q-1b-DEC-40-precedent, not DEC-32).
- [ ] **AC-ERROR-HANDLING-UNCHANGED**: Exception → HTTP status mapping
