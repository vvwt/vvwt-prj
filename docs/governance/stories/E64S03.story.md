# Story: The Tournament-Manager logo links to the admin home page

## User Story

**As a** tournament organizer,
**I want** to click the Tournament-Manager logo to return to the home page,
**so that** I can get back to the "Turniere" / "Geräte" overview from anywhere in the app.

---

## Context

The Tournament-Manager logo sits in the persistent app header, visible on every page. It
is currently a plain, non-interactive image — clicking it does nothing. An operator who
has navigated deep into the app (a tournament's phase overview, the Info-Portal page, …)
expects the logo to act as a "home" affordance, the way an application logo conventionally
does.

The home page is the admin overview that shows the "Turniere" and "Geräte" buttons — the
application's root route. The app is a Vite + Svelte single-page application using a
client-side router (DEC-2). The header also contains a separate back-arrow control; that
control is unrelated to this story and is left untouched.

---

## Acceptance Criteria

- [ ] AC1 (testing): TDD per DEC-22 — a failing test for the logo's navigation behaviour
  (activating the logo navigates to the home route) is authored before the production
  change. The navigation behaviour is tested at a level feasible in the project's test
  environment; mounting the Svelte header component is **not** required (Svelte 5 component
  mounting is infeasible in the project's Vitest+jsdom environment — pre-existing gap,
  E58S05).
- [ ] AC2: activating the Tournament-Manager logo in the app header navigates to the admin
  home route — the page that shows the "Turniere" and "Geräte" buttons — and this works
  from any page in the app.
- [ ] AC3: the logo is an accessible, keyboard-operable control — it is focusable,
  activatable by keyboard, and has an accessible name — not a bare non-interactive image.
  The accessible name may be the product/brand name ("Tournament Manager") or a German
  label (e.g. "Startseite"); either is acceptable. Any translatable label is German per
  C-5.
- [ ] AC4: the existing header back-arrow control is unchanged. The logo "home" link and
  the back-arrow coexist as two distinct header controls; they are not merged or
  consolidated.
- [ ] AC5 (governance): the navigation uses the application's existing client-side router;
  the frontend stays Vite + Svelte + TypeScript, no SvelteKit (DEC-2). `mvn verify` is
  BUILD SUCCESS for `vvwt-tm-web`, including the frontend build via `frontend-maven-plugin`
  (DEC-54).

> All acceptance criteria must be verifiable.

---

## Out of Scope

- The header back-arrow control and the `parentRouteMap` back-navigation behaviour — the
  logo link is a separate, additional "always to home" control; the back-arrow is
  untouched.
- Any change to the home page itself or to other header content.
- Fixing the project's infeasible Svelte-5 / Vitest+jsdom component-mount test environment
  (pre-existing gap, E58S05).

---

## Dependencies

- None — the home route and the header logo already exist. Independently deliverable.

---

## Notes

Delivery decides the implementation form (an anchor, a button, a click handler) and the
testable seam — the ACs state the behaviour (logo activation navigates home, the control
is accessible) rather than prescribing a component-mount test, because mounting is
infeasible in the project's test environment (E58S05). DEC-2 forbids SvelteKit; navigation
must use the app's existing Svelte client-side router.
