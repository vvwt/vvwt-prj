# Story: Rename the German domain term "siegerehrung" to the English "awardCeremony"

## User Story

**As a** developer maintaining the codebase,
**I want** the German domain term `siegerehrung` replaced by the English `awardCeremony`,
**so that** the codebase uses one consistent language for all keys, identifiers and i18n message keys.

---

## Context

All terms and constants in `vvwt-prj` code are English except one: `siegerehrung` (German for "award
ceremony") — the game-mode key for the no-play closing ranking phase. It appears as a registry-key / wire
string, as code identifiers (e.g. the `MatchGenerator` implementation class and bean, orchestrator
constants), in the frontend, in i18n message keys, and in tests. DEC-73 (D-7) renames it to the camelCase
English `awardCeremony`, consistent with the existing `roundRobin` key style.

After E58S01 the `gameMode` field is a String registry-key (the `GameMode` enum is gone), so this rename is a
string/identifier rename, not an enum-constant change.

---

## Acceptance Criteria

- [ ] AC1 (governance): every occurrence of `siegerehrung` in `vvwt-prj` that is a registry-key / wire-format string, a code identifier (class / field / constant / method-name fragment), or an i18n message **key** is renamed to `awardCeremony` (camelCase, matching `roundRobin`). The complete occurrence set is determined by a fresh audit at delivery HEAD — this story carries no pre-computed occurrence list.
- [ ] AC2 (governance): i18n translation **values** — the human-readable label strings, including the German display label — are NOT renamed; only keys and code identifiers are anglicized.
- [ ] AC3 (governance): the `gameMode` registry-key value for the award-ceremony match generator is `awardCeremony`, and the corresponding `MatchGenerator` implementation class and its registry key reflect the new name.
- [ ] AC4 (governance): the DEC-59 Clause E/F award-ceremony lifecycle is behaviour-unchanged — the empty-match-list dispatch and the phase-activation guard now key on the string value `"awardCeremony"`; the lifecycle behaviour (PENDING→PREPARED, activation) is verified unchanged.
- [ ] AC5 (testing): all tests referencing the old term are updated to the new identifiers and pass; `mvn verify` is BUILD SUCCESS for `vvwt-tm-web` (DEC-54), including the frontend build.
- [ ] AC6 (testing): TDD per DEC-22 — the rename is a mechanical refactor with no behaviour change; the updated existing test suite is the regression gate.
- [ ] AC7 (governance): after the story, a fresh audit confirms zero occurrences of `siegerehrung` as a code key, identifier, or i18n message key in `vvwt-prj`; `.gaai/` governance documents are NOT modified by this story.
- [ ] AC8 (governance): the rename introduces no compiler warnings or unused imports (DEC-29 / DEC-30).

> All acceptance criteria must be verifiable.
