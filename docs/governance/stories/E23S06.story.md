# Story E23S06: Establish `de.vvwt.tm.certificate` Modulith module + Q-1b relocate certificate domain bundle (service interface + impl + repository impl + 3 exceptions + VOs + config) + per-module Flyway `db/migration/certificate/V1__*.sql` consolidating V15

## User Story

**As a** maintainer of the `vvwt-tm-web` Spring Modulith application,
**I want** the existing certificate domain (`de.vvwt.tm.domain.certificate.*`
+ `de.vvwt.tm.domain.repo.CertificateTemplateRepository`) relocated into a
new `de.vvwt.tm.certificate` Modulith module with interfaces in public and
`Default*` impls in `.internal`, plus a new per-module Flyway directory
`db/migration/certificate/V1__*.sql` consolidating the root `V15__e12s04_certificate_template.sql`,
**so that** certificate becomes an independently-declared bounded context
(per DEC-21 + DEC-25 + DEC-35) and the subsequent certificate stories
(E23S07 repo interface extraction + DAO test, E23S08 CertificateAssembler
interface + impl relocation, E23S09 controller relocation, E23S10 atomic
cutover) have a canonical target package + migration path to work against.

---

## Context

First story of the E23 certificate reconstruction track. Per Brief v4 D-5,
`certificate.allowedDependencies = {tournament, photo}` — tenant NOT needed
after the C2=β decision removed `resolveLocationDisplayName` concern from
certificate module (multi-tenancy via DEC-20 DataSource routing is
transparent to certificate code). Photo dependency is needed because
CertificateAssembler (to relocate here at E23S08) consumes PhotoUrlBuilder +
PhotoStorageService.

Per Brief D-9: CertificateTemplateService is ALREADY a public interface
(empirically verified 2026-04-23 at
`src/main/java/de/vvwt/tm/domain/certificate/CertificateTemplateService.java:30`)
— so Q-1b relocation, not Q-1a extraction. CertificateTemplateRepository
is a concrete `@Repository` class; its interface extraction is DEFERRED to
E23S07.

Per Brief C-3 + DEC-25, the root `V15__e12s04_certificate_template.sql`
migration is retired in the Wave-2 Big-Bang-Reset; E23 introduces the
per-module replacement at `db/migration/certificate/V1__*.sql`.

  `CertificateTemplateService` (interface — already interface at source),

  `CertificateTemplateServiceImpl` renamed to `DefaultCertificateTemplateService`
  (DEC-35 naming canon); `CertificateTemplateRepository` (concrete @Repository
  class from legacy `de.vvwt.tm.domain.repo.*`) relocated to

- [ ] **AC-LEGACY-COEXISTS**: `de.vvwt.tm.domain.certificate.*` (8 classes)
  and `de.vvwt.tm.domain.repo.CertificateTemplateRepository` REMAIN

- [ ] **AC-FLYWAY-PER-MODULE-V1**: New file
  `src/main/resources/db/migration/certificate/V1__initial_schema.sql`
