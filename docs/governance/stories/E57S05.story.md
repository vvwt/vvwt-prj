# Story: Remediate the `@Bean`-produced interface-mandate gap and land the machine-checked enforcement guard

## User Story

**As a** maintainer of the `vvwt-prj` codebase and of GAAI governance,
**I want** the DEC-58/DEC-72 interface mandate fully honoured for `@Bean`-factory-produced service beans, and the machine-checked enforcement guard live inside `mvn verify`,
**so that** the mandate is both complete and self-enforcing — no `@Bean`-produced service bean escapes it, and a future violation fails the build before it reaches `staging`.

---

## Context

DEC-58 (as amended by DEC-72) mandates that every self-created Spring component be addressable through a public interface. Epic E57 operationalizes it: E57S01–S03 remediated the three `vvwt-prj` Maven modules (`vvwt-tm-web`, `vvwt-info-server`, `vvwt-slotopt-dispatcher`); E57S04 was to install a build-time enforcement guard (DEC-72 Clause E-ext).

E57S04 built that guard and ran it — and it caught a remediation gap. E57S01–S03 remediated the **stereotype-annotated** classes (`@Service` / `@Component` / hand-authored `@Repository`), but did not remediate **first-party service beans produced by `@Bean` factory methods** — the trigger DEC-72 Clause A-ext brings into the mandate. E57S04 correctly STOPped and escalated this gap per its own `AC-GOV-PREDICATE-CONSISTENCY` (it did not weaken the guard to go green). E57S04 is **superseded by this story**.

This story closes the `@Bean`-produced remediation gap **and** lands the machine-checked guard. The two are inseparable: the guard's "GREEN on the delivery HEAD" criterion is only satisfiable once the `@Bean`-path remediation is complete, so a guard-only story (E57S04's shape) could never reach `done` on its own. E57S05 delivers both in one atomic story — the guard is GREEN by construction at this story's HEAD.

The complete in-scope violation set is **re-derived fresh by Delivery at the delivery HEAD** — the guard itself is the audit mechanism. No starting-point bean list is reproduced in this story (per memory `feedback_no_precomputed_inventory_in_stories.md`; the E57 stories already burned review cycles on embedded inventories). This story is a **structural refactor** (interface extraction; implementation bodies unchanged) plus **build-time test code** (the guard); it changes no production runtime behaviour.

---

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-REMEDIATION-GREEN** — the full existing test suite of every touched module remains GREEN: `mvn verify` is BUILD SUCCESS (DEC-54). Interface extraction changes no production logic; the existing suite is the regression gate.
- [ ] **AC-TEST-AOP-PROXY-SHIFT** — interface extraction shifts Spring AOP proxying from a CGLIB subclass proxy to a JDK interface proxy. For each remediated `@Bean`-produced bean advised by Spring AOP (`@Transactional` / `@Async` / `@Scheduled` / `@Cacheable` / etc.), Delivery verifies the **specific** proxied behaviour still holds after extraction — an existing test exercising that behaviour staying green, or, where none exists, a fresh Q-1a RED-first test asserting the concrete proxied behaviour (a genuine failing state, not a vacuous "no change" assertion). The impl-report lists the advised targets and the per-target evidence.
- [ ] **AC-TEST-CROSS-PACKAGE-INTERFACE** — every test class in a Java package different from a remediated target type-references and mocks the **public interface**, not the `Default{Foo}` implementation class (DEC-36); `@MockitoBean(name=...)` and qualifier references to renamed beans are updated.
- [ ] **AC-TEST-GUARD-PROVEN-TO-FAIL** — the guard is demonstrated to FAIL on each non-trivial violator shape: Delivery temporarily adds, one at a time, (a) a stereotype-annotated `@Component` with no interface; (b) a `@Component` implementing a Spring-framework config interface that **also** declares a first-party public service method, with no first-party interface (the DEC-72 Clause D-ext-3 composite — it must NOT be excluded); (c) a `@Component` listener / executor / `ApplicationRunner` host with no interface (DEC-58 Clause E); (d) a `@Bean`-factory-produced first-party service bean whose implementation class implements no public interface — runs the guard, observes and records each FAIL (with the failure message) in the impl-report, then removes the fixture. A guard never shown to fail guards nothing.
- [ ] **AC-TEST-GUARD-PROVEN-TO-EXCLUDE** — symmetrically, the guard is demonstrated NOT to false-FAIL on an excluded bean: Delivery temporarily adds a bean of each Clause D-ext kind with no interface — a `@ConfigurationProperties` holder, a class carrying **both** `@Component` and `@ConfigurationProperties`, a `@ControllerAdvice` bean, and a framework-config-only adapter `@Component` (implements a Spring-framework config interface, no first-party public service method) — runs the guard, records that it stays GREEN, then removes the fixtures. This proves the exclusion predicate actually fires.
- [ ] **AC-TEST-GUARD-IN-MVN-VERIFY** — the guard runs inside `mvn verify` (DEC-54): each covered module's own `mvn verify` invocation executes the guard against that module's compiled classes. It is not a standalone or manually-invoked test. `mvn verify` is BUILD SUCCESS.

### Governance

- [ ] **AC-GOV-FRESH-AUDIT** — Delivery re-derives, at the delivery HEAD across the three E57 Maven modules, the complete set of **first-party service-shaped beans produced by an `@Bean` factory method** (DEC-72 Clause A-ext) that lack a public first-party interface, **minus** the exclusion set — DEC-58 Clause C (Spring Data ports), DEC-58 Clause D (`@RestController` / `@Controller` / `@Configuration`), and DEC-72 Clause D-ext (`@ConfigurationProperties` holders incl. the composite `@Component`+`@ConfigurationProperties` case; `@ControllerAdvice` / `@RestControllerAdvice`; framework-config-only adapter beans) — the exclusions applied to the **produced bean's shape**. DEC-58 Clause E listener / executor / `@Scheduled` / `ApplicationRunner` host beans remain **covered**. No starting-point list is reproduced in this story; the qa-report enumerates the final set with a per-bean verdict (remediated / excluded-with-clause / already-compliant).
- [ ] **AC-GOV-BEAN-INTERFACE-EXTRACTION** — every in-scope `@Bean`-produced violator gets a `{Foo}` interface in the public root package of its owning bounded context and a `Default{Foo}` implementation in that context's `.internal` package, per the DEC-35 / DEC-58 naming canon (`I`-prefix forbidden). The `@Bean` factory method's declared return type becomes the interface, and the produced implementation class implements it (DEC-72 Clause A-ext).
- [ ] **AC-GOV-CONSUMER-REWIRING** — production-side injection sites of each remediated bean (across packages and across Modulith bounded-context modules) switch to the interface type in the **same commit** as the extraction, so no intermediate broken-compilation state is left; `@Qualifier` and explicit bean-name wiring is audited and updated; no autowiring ambiguity is introduced. `ApplicationModules.verify()` passes within `mvn verify` (DEC-21) — no new `allowedDependencies` edge is expected; if re-typing a consumer would in fact require one, Delivery STOPs and escalates to Discovery rather than adding it silently.
- [ ] **AC-GOV-NO-BEHAVIOUR-CHANGE** — no production logic changes: the diff shows interface extraction, class rename to `Default{Foo}`, package move, and consumer re-typing only — no change inside any implementation method body. The AOP proxy-type shift (AC-TEST-AOP-PROXY-SHIFT) is the one mechanism change. Delivery classifies each extraction per DEC-22 — Q-1b mechanical refactor where a trustworthy TDD-authored test oracle already covers the surface, otherwise Q-1a fresh RED-first against the new interface contract — and records the per-bean classification in the impl-report (the Q-1a/Q-1b vocabulary is from memory `feedback_dec22_refactor_phase_first.md`, an informational pointer; the governing artefacts are the DECs).
- [ ] **AC-GOV-GUARD-PREDICATE** — the build-time architecture test's predicate encodes the **full** DEC-72 Clause A-ext trigger (stereotype-annotated `@Service` / `@Component` / hand-authored concrete `@Repository` classes — incl. DEC-58 Clause E listener / executor / `@Scheduled` / `@EventListener` / `ApplicationRunner` host beans — **AND** first-party service-shaped beans produced by a `@Bean` factory method) and the full exclusion set (DEC-58 Clause C + Clause D + DEC-72 Clause D-ext, incl. the composite `@Component`+`@ConfigurationProperties` case and the **structural** D-ext-3 test: a `@Component` is excluded iff it implements a Spring-framework-supplied config interface AND declares no `public` method beyond that framework interface's contract). A `@Bean`-produced bean is compliant iff its produced implementation class implements a public non-`.internal` first-party interface. A false-negative on a `@Bean`-produced violator, or a false-FAIL on a genuinely excluded bean, is a guard defect.
- [ ] **AC-GOV-GUARD-CONSISTENCY** — the guard predicate is the machine-checked encoding of the *same* DEC-72 Clause A-ext / Clause C / Clause D / Clause D-ext rule this story's remediation applies. The guard is GREEN on the delivery HEAD of this story. If the guard FAILs on HEAD, that signals a residual remediation gap or a guard-predicate defect: Delivery STOPs, does **not** weaken the guard to go green, does **not** mark the story `done`, and escalates to Discovery / the operator.
- [ ] **AC-GOV-TOOL-HOW** — the concrete guard mechanism (ArchUnit, a Spring Modulith verification extension, a reflection-based test, or equivalent) is a Delivery decision; the impl-report records the choice, explains how it satisfies AC-GOV-GUARD-PREDICATE, and records the guard's treatment of non-instantiable stereotyped types (an abstract `@Component` base class is not a bean and is not flagged). Any new test-scoped dependency is declared in the appropriate module build descriptor. If Delivery finds the structural D-ext-3 predicate genuinely not expressible by the chosen tool, it STOPs and escalates to Discovery rather than shipping a guard with an unsound exclusion.
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); all Java touches compile warning-free (DEC-29) and pass Spotless / google-java-format (DEC-30); no test-only production member is introduced (DEC-70).
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use the `E57S05` story-id prefix per the close-story.sh contract: `chore(E57S05):` for RED tests, the guard test code, build-descriptor (`pom.xml`) wiring, and refactor housekeeping; `feat(E57S05):` for any GREEN production change (e.g. a new interface type). This story deliberately carries both production code (interface extraction) and test code (the guard) — the accepted combined-story trade-off (see Notes).

> All acceptance criteria must be verifiable.

## Out of Scope

- Re-remediating the stereotype-annotated `@Service` / `@Component` / hand-authored `@Repository` classes — E57S01–S03 already remediated those (`done`); only the `@Bean`-produced path remains. (If the fresh audit finds a stereotype-annotated violator E57S01–S03 missed, the guard will flag it and AC-GOV-GUARD-CONSISTENCY governs — STOP and escalate; this story does not silently absorb a separate remediation class.)
- The DEC-72 Clause D-ext config/adapter-shaped beans (`@ConfigurationProperties` holders, `@ControllerAdvice` beans, framework-config-only adapters) — NOT interface-extracted; the guard must NOT flag them (AC-TEST-GUARD-PROVEN-TO-EXCLUDE).
- Upgrading any hand-authored `@Repository` to a Spring Data repository interface (DEC-58 Clause C option a).
- Any change to production runtime behaviour.
- The Epic E58 registry/strategy work (DEC-73) — a separate epic that depends on this story for the guard.

## Notes

- **This story supersedes E57S04.** E57S04 is set to `superseded` in the backlog as part of the Discovery commit that registers this story; its QA-FAIL `notes` are preserved verbatim as the historical record, with a supersession pointer to E57S05 appended.
- **Discovery Brief**: `discovery-2026-05-16-e57s05-bean-remediation-and-guard` (human-validated 2026-05-16; Brief review[tier-2]: cycle-1 FAIL on an incomplete repoint target list, cycle-2 PASS; the `failed`→`superseded` reclassification of E57S04 was an explicit operator decision at Brief validation).
- **Combined-story rationale** — a guard-only story (E57S04's shape) cannot reach `done` until the remediation is complete: the guard's "GREEN on HEAD" criterion is contingent on it. E57S04 demonstrated exactly this. E57S05 delivers the remediation and the guard in one atomic story so the guard is GREEN by construction at this story's HEAD; re-splitting into two stories would recreate the coupling that made E57S04 fail.
- **No starting-point violator list — by design.** Per memory `feedback_no_precomputed_inventory_in_stories.md`, `feedback_subagent_no_precomputed_findings.md`, and `feedback_daemon_concurrency_staleness.md`, the contract is the rule + `AC-GOV-FRESH-AUDIT`. The superseded E57S04 backlog `notes` name candidate beans as a **non-authoritative pointer only**; Delivery re-derives the complete in-scope set fresh at the delivery HEAD.
- **Module expectation** — the `@Bean`-path remediation is expected to be concentrated in whichever module(s) host `@Bean`-factory service beans; E57S04's guard run pointed at `vvwt-tm-web`, but the module attribution is not independently verified. Delivery's fresh audit across all three modules is authoritative; the guard must be GREEN across every module it scans regardless of where the violators land.
- **Downstream consumer** — E58S01 (Epic E58) depends on this story for the interface-mandate guard: the guard must be on `staging` and GREEN so that E58S01's own `mvn verify` includes it. E58S01's dependency, previously on E57S04, is repointed to E57S05 in the same Discovery commit.
- **`I`-prefix forbidden** (DEC-35 / DEC-58 naming canon). Interface `{Foo}`, implementation `Default{Foo}`.
- **DEC-22 classification** — interface extraction with no behaviour change is a mechanical (Q-1b) refactor where a trustworthy TDD-authored test oracle exists, else Q-1a fresh RED-first (AC-GOV-NO-BEHAVIOUR-CHANGE). The guard is build-time test code, not production runtime code — DEC-22's Iron Law governs the authoring of production code and does not apply to the guard; `AC-TEST-GUARD-PROVEN-TO-FAIL` is a guard-efficacy demonstration (the rule has teeth), not a RED-first TDD sequence.
- **`ApplicationModules.verify()` is not sufficient** — it checks module-dependency edges, not interface-vs-concrete consumer types (DEC-58 § Scope). The guard is a separate, additional check.
- Discovery defines WHAT (every `@Bean`-produced first-party service bean is interface-addressable; the guard runs inside `mvn verify`, fails on any interface-mandate violation, does not false-FAIL on excluded beans, and is GREEN on this story's HEAD); Delivery defines HOW (the per-bean refactor classification, the guard tool and predicate implementation, the per-module wiring, and whether to recover the guard code from the `story/E57S04` branch or re-author it).
