# Story E36S04: Certificate domain Q-1a TDD rebuild — CertificateTemplateService + DefaultCertificateTemplateService + 3 exceptions + 2 VOs + CertificateTemplateStorageConfig (D-7 Option γ at canonical FQN de.vvwt.tm.certificate.*)

## User Story

**As a** maintainer of `vvwt-tm-web` opening Track 2 (Certificate) of Epic E36,
**I want** the legacy certificate-domain Q-1b artefacts at
`de.vvwt.tm.certificate.*` (in-scope subset) deleted and rebuilt under DEC-22
Iron Law Q-1a TDD RED-first authorship at the same canonical FQNs (D-7
Coexistence Option γ), with the preserved `CertificateTemplateRepository`
interface and `DefaultCertificateTemplateRepository` impl untouched per audit (iii)
verdict,
**so that** the certificate domain carries a trustworthy correctness oracle and
Track 2 advances toward assembler + controller rebuild + Cutover-2.

---

## Context

Per Session Brief `discovery-2026-04-26-e36-retro-correction` D-7 Option γ +
audit `E36-discovery-legacy-inventory.md` Certificate Domain (E23S06) group: 7
public-API in-scope artefacts under `de.vvwt.tm.certificate.*` (~272 LOC public API)
plus 1 impl in `.internal` (`DefaultCertificateTemplateService`) — 8 production
files total deleted by AC-DELETE-LEGACY-FIRST.

Per audit `E36-discovery-dec26-dao-coverage.md` PASS verdict: the
`CertificateTemplateRepository` interface, `DefaultCertificateTemplateRepository`
impl, and `DefaultCertificateTemplateRepositoryIT` are **out-of-scope and
preserved**. The IT satisfies all three DEC-26 rules (schema from production
migration, independent persistence verifier, read/write decoupling) and achieves
100% branch coverage on the impl. No conditional impl rebuild is needed; the
story count for E36 dropped from 9 to 8.

Per audit `E36-discovery-dec41-test-classification.md`:
`DefaultCertificateTemplateServiceTest` (27 methods, count flagged for
delivery-time re-verification per Brief Q-7) is 100% Snapshot-Driven; zero
Contract Test reuse candidates.

Per Brief C-3, signature-preservation is the default; deviations on records
(`CertificateTemplateMetadata`, `CertificateTemplateVariable`), exception
constructors, or config getters/setters trigger stop-and-escalate. This is a
high-risk story for C-3 because it carries TWO records with consumer counts of
5 and 3 respectively.

## Notes

- **Constraint** (Brief C-3 — high-risk story): TWO records (`CertificateTemplateMetadata`,
  `CertificateTemplateVariable`) + 3 exception constructors + config
  getters/setters are signature-preservation candidates. Any unavoidable
  signature evolution triggers stop-and-escalate to Discovery before GREEN
  code lands.
- **Risk** (Brief C-11): If during RED-first authoring a pre-existing
  behavioral characteristic (specific exception messages consumed by
  CertificateExceptionAdvice, specific MERGE semantics consumed by repository,
  specific assembler-driven embedding behavior) cannot be reproduced verbatim,
  this is a behavioral-divergence trigger and MUST stop-and-escalate.
- **Escalation triggers**: C-3 (signature evolution, especially records),
  C-11 (behavioral divergence), C-2 (consumer-import change would invalidate
  Option γ).
- **Modulith placement** (per audit (i)): public API stays under
  `de.vvwt.tm.certificate`; `DefaultCertificateTemplateService` impl stays
  under `de.vvwt.tm.certificate.internal` per DEC-35.
- **Special note on Spring bean naming** (per audit (i) note):
  `certificateModuleStorageConfig` is the preserved bean name on
  `CertificateTemplateStorageConfig`. Bean name change would break injection
  consumers and is a C-3 trigger.
- **CertificateExceptionAdvice still resident**: This story does NOT delete
  `CertificateExceptionAdvice`. That deletion happens in E36S08 Phase 2.
- **Per Brief C-2**: DEC-32 invocation count remains 1 (E21S13 only).
