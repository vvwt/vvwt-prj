# Story E43S01: Convenience redirect — `GET /` → `302 Found Location: /admin/` via new `LandingController`

## User Story

**As a** Tournament Manager organizer (or any end user) who types `http://<host>:8080/` into a browser address bar without remembering the `/admin/` path,
**I want** the application to forward me with a `302 Found` redirect to `/admin/`,
**so that** I land on the administration UI's login dialog without needing to know the application's URL convention.

---

## Context

`vvwt-tm-web` currently has no controller or static resource bound to the exact path `/`, so a typed root URL returns Spring Boot's default `HTTP 404`. The Tournament Manager is intended for technically non-savvy users (volunteer organizers at sports venues per DEC-5 default-tenant LAN-mode); a 404 at the platform's root URL is a usability regression even though it is technically correct. Discovery investigation 2026-05-02 confirmed that `/admin/` is the only end-user-suitable typed-URL entry point in the system — `/score/`, `/display/`, `/timer/`, `/print/` all require device pairing, login, or a tournament-id parameter and are unsuitable for direct user-typed entry.

This Story ships the V1 redirect: a single new `LandingController` class in the `de.vvwt.tm.web` Modulith module per DEC-40 Clause A. The controller's sole responsibility is to map exact path `/` to a `302 Found` response with `Location: /admin/`. Unknown URLs (e.g., `/foo`, `/anything-else`) continue to return `HTTP 404` — no catch-all routing.

**HTTP 302 (Found, temporary) was chosen over 301 (Permanent)** to preserve the future option of evolving `/` into a real informational landing page (per E43 Epic Scope) without browser-cache lock-in. The marginal extra HTTP roundtrip per visit is negligible on LAN-mode (DEC-16) and on admin-login frequency.

This Story `depends_on: [E42S02]` because the redirect target `/admin/` is currently broken (HTTP 404 — see E42S02). Shipping this redirect before E42S02 lands would route users from a working 404-on-`/` to a broken 404-on-`/admin/`, delivering negative value. The dependency is functional, not merely sequential.

## Acceptance Criteria

### Behavior contract

- [ ] **AC1 (Redirect contract — RED-first IT)**: Add a failing integration test in `vvwt-tm-web/src/test/java/de/vvwt/tm/web/` (annotation per DEC-38 amended by DEC-44 — `@SpringBootTest(webEnvironment = RANDOM_PORT, classes = TournamentManagerApplication.class)`) that performs an unauthenticated `GET /` (HTTP client configured to NOT follow redirects) and asserts:
  - response status is `HTTP 302`, AND
  - response header `Location` equals exactly `/admin/` (trailing slash included; case-sensitive).
  Test MUST be authored, committed, and observed RED in the impl-report's git log BEFORE any controller code lands (per DEC-22 Iron Law Q-1a — new code).

- [ ] **AC2 (End-to-end redirect chain)**: A second test method in the same IT class performs `GET /` with redirect-following enabled and asserts that the followed request reaches `/admin/` and returns a non-404 response. (The body assertion `<div id="app">` is owned by E42S02 AC2 — this Story does NOT re-test the SPA shell content; it only verifies the redirect chain completes against a reachable target.)

- [ ] **AC3 (Exact-path matcher — no catch-all)**: A third test method in the same IT class performs `GET /unknown-path-that-should-404` (without redirect-following) and asserts `HTTP 404`. This guards against accidentally introducing a catch-all matcher that would mask broken bookmarks or typos.

### Implementation contract

- [ ] **AC4 (New `LandingController` class)**: A NEW Java class `de.vvwt.tm.web.LandingController` is authored in `vvwt-tm-web/src/main/java/de/vvwt/tm/web/`. The class is annotated `@Controller`. It exposes exactly ONE handler method mapped to `@GetMapping("/")` that returns a Spring-idiomatic redirect (`"redirect:/admin/"` view name OR an equivalent `RedirectView` / `ResponseEntity` construct that produces `HTTP 302` with `Location: /admin/`).

- [ ] **AC5 (Module placement — DEC-40 Clause A)**: The class lives in `de.vvwt.tm.web` (NOT in any bounded-context module; NOT in `de.vvwt.tm.web.internal`). No `web.allowedDependencies` expansion is required (the controller depends on no bounded-context module).

- [ ] **AC6 (No method on `AdminSpaController`)**: The redirect MUST NOT be added as an additional `@GetMapping` on the existing `AdminSpaController`. `AdminSpaController` serves SPA shells; `/` redirect is a different concern (single-responsibility per Discovery brief T-5).

### Security contract

- [ ] **AC7 (`permitAll` on `/` BEFORE `anyRequest().authenticated()`)**: `SecurityConfig.java` matcher chain is updated to add `requestMatchers("/").permitAll()` placed **before** the existing `anyRequest().authenticated()` clause (currently at line 162-163). Spring Security matcher-order semantics evaluate matchers in declaration order — the `permitAll` for `/` MUST precede the catch-all `authenticated` clause, otherwise the catch-all swallows it and the redirect would itself trigger an HTTP Basic challenge before the controller fires (breaking the convenience contract).

- [ ] **AC8 (Auth state at `/`)**: An unauthenticated `GET /` returns `HTTP 302 + Location: /admin/` (NOT `401 + WWW-Authenticate`). After following the redirect, the `/admin/` request is subject to its existing `.authenticated()` rule (line 158-159) — the user sees the HTTP Basic dialog at `/admin/`, not at `/`. AC1 and AC2 both verify this without supplying credentials.

### Regression preservation

- [ ] **AC9 (Existing security rules preserved)**: All existing `SecurityConfig` matcher rules (lines 128-163) remain unchanged in semantics. The only modification is the insertion of `requestMatchers("/").permitAll()` at the appropriate position in the chain. Existing security tests (auth-protected paths still 401 without auth, public paths still reachable) continue to PASS.

- [ ] **AC10 (No regression on `/admin/` etc.)**: Running `mvn -pl vvwt-tm-web verify` after the change shows: existing `AdminSpaControllerTest` + slice tests continue to PASS, and the new redirect tests (AC1 + AC2 + AC3) also PASS. The full test suite delta is +3 new tests; 0 existing tests deleted or weakened.

### Build/governance

- [ ] **AC11 (Compiler hygiene + format)**: `mvn -pl vvwt-tm-web verify` passes with `-Xlint:all,-serial` + `failOnWarning=true` per DEC-29 and Spotless `google-java-format` AOSP-style per DEC-30 across all modified/added files (`LandingController.java`, `SecurityConfig.java`, new test class).

- [ ] **AC12 (DEC-22 RED-first git log evidence)**: The impl-report includes a `git log --oneline story/E43S01` excerpt showing the RED-first commit sequence — failing test commit precedes the controller + SecurityConfig commits.

## Notes

**Risk for Delivery — matcher-order silent failure.** AC7 explicitly mandates the `permitAll("/")` placement BEFORE `anyRequest().authenticated()`. A common Spring Security mistake is to append the new matcher at the end, after the catch-all — this silently defeats the rule. The reviewer of any PR for this Story should diff the SecurityConfig matcher chain visually and verify ordering, in addition to AC8's runtime assertion.

**Risk for Delivery — Vorzeitiges Mergen.** Story B (this Story) merging before Story A (E42S02) is ON STAGING delivers negative value (302 to broken 404). The daemon should respect `depends_on` and refuse to pick up E43S01 until E42S02 is `done`. If the daemon's scheduler does not enforce this, the human gates the merge manually.
