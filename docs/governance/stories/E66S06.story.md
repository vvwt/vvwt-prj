# Story: The Display overview shows the refereeing team and reads clearly at a glance

## User Story

**As a** spectator or referee reading the public Display overview,
**I want** each match to show which team referees it, beneath the score, with the playing teams' names clearly legible,
**so that** the refereeing team knows to go to the court and everyone can read the match at a glance.

---

## Context

On the Display overview each match shows the two playing teams and the score, but never the
refereeing team. The data is available — a match carries `Match.refereeTeamId` (set once
the referee assignment has run; `null` before that), and the print/Laufzettel path already
resolves a referee team id to a team name. The Display overview's data structure already
has a `refereeTeamName` field, and the match-row component already renders it conditionally
— but the backend always sends `null`, so nothing appears.

The playing-team names on the overview use the inherited default text colour. The operator
finds them too light on the venue display and wants them darker, with the refereeing team
shown in a lighter, subordinate shade beneath the score.

This story sits under Epic E66, whose governing decision is DEC-77; the referee row and
the colour change are not behaviourally constrained by DEC-77's sort/distribution clauses,
but DEC-77 is listed for epic-level traceability.

---

## Acceptance Criteria

- [ ] AC1 (testing): TDD per DEC-22 — failing tests are authored before the production
  change, proven RED, then GREEN. Both production parts are covered: the backend
  referee-name resolution is tested at the logic level, and the frontend placement +
  colour change is covered by a RED-first test at a level feasible in the project's
  environment (no Svelte-5 component mount — that is infeasible per E58S05; Delivery
  selects the feasible mechanism). The frontend test asserts the placement and the
  colour-relationship outcome, not merely the presence of a source string. No production
  part is left without a test.
- [ ] AC2: on the Display overview, a match whose `Match.refereeTeamId` is set shows the
  refereeing team's name; a match with no referee assigned shows nothing referee-related —
  no blank line, no placeholder, no runtime error.
- [ ] AC3: the Display overview backend data is populated with the refereeing team's name,
  resolved from `Match.refereeTeamId` — it is currently always `null`.
- [ ] AC4: the refereeing team's name appears **beneath the score** of the match, not
  inline with the playing-team names.
- [ ] AC5: the refereeing team is visually subordinate to the playing teams — the
  playing-team names render in a darker text colour than today, and the referee line in a
  lighter, subdued shade.
- [ ] AC6 (governance): the colour change is verifiably legible. Delivery resolves the
  Display overview's actual background colour and the current inherited playing-team text
  colour; the new playing-team text colour is demonstrably darker than the current
  inherited colour; and both the playing-team text and the referee line meet at least the
  WCAG 2.1 AA contrast ratio against the resolved Display overview background (4.5:1 for
  normal-size text, 3:1 for large text) — checkable from the resolved colour values
  without venue display hardware. The Display SPA still functions offline with no new
  external dependency (DEC-16); the frontend stays Vite + Svelte + TypeScript, no
  SvelteKit (DEC-2); no `teamId` UUID is rendered in the DOM (DEC-9). `mvn verify` is
  BUILD SUCCESS for `vvwt-tm-web`, including the frontend build (DEC-54).

> All acceptance criteria must be verifiable.

## Out of Scope

- The Display overview group-standings ranking (E66S04).
- The referee-assignment logic itself — this story only displays an already-assigned
  referee; it does not change when or how `Match.refereeTeamId` is set.
- Any Display page other than the overview, and live-score propagation (Epic E65).

## Dependencies

- None — independently deliverable. `Match.refereeTeamId` exists and the referee-name

- DEC-16 — the Display SPA must function without internet.
- Epic E65 concurrently touches the Display overview (live scores) — logically independent;
  any file-level overlap is resolved at delivery time.

## Notes

Acceptance criteria state behaviour, not a test mechanism. Delivery decides the exact
colour values (AC5 / AC6 state the relative treatment — playing teams darker, referee
lighter — and a verifiable contrast floor against resolved colour values, not specific hex
codes) and how the referee team id is resolved to a name in the Display context (the
print/Laufzettel path is an existing reference). The match-row component already has a
conditional render for the referee name; the gap is the backend always sending `null`,
plus the placement and colour treatment.
