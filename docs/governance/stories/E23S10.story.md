# Story E23S10: Certificate atomic cutover (Cutover-2) — delete legacy certificate + print.CertificateAssembler packages + atomic URL renames (5 logical endpoints / 5 @*Mapping annotations + Svelte UI) + Q-1a resolveLocationDisplayName migration to PrintController + Q-1b PrintController FQN-rewrite + empirical-coverage-gated CertificateRenderingSpikeTest deletion + web.allowedDeps += certificate

## User Story

**As a** maintainer of the `vvwt-tm-web` application at the end of the E23
certificate track,
**I want** a single atomic commit that deletes all legacy certificate
packages (8 domain classes + 1 repo class + 3 web classes + 2 print classes
+ spike test) + atomically renames certificate URLs (5 logical endpoints
= 5 `@*Mapping` annotations) + migrates `resolveLocationDisplayName` (Q-1a:
new JdbcTemplate field + constructor param + method in PrintController) +
rewrites PrintController FQN-imports (Q-1b, 14 call-sites empirically
verified) + finalizes `web.allowedDependencies` with certificate,
**so that** after Cutover-2 the certificate context is fully reconstructed
under DEC-21 per-context atomic cutover semantics, PrintController (still
legacy but updated) correctly resolves location display names without
depending on certificate-internal code, and the staging branch reflects a
clean certificate module ready for E24 print-context reconstruction.

### resolveLocationDisplayName migration (Q-1a + Q-1b per Brief D-13)

- [ ] **AC-PRINTCONTROLLER-JDBCTEMPLATE-FIELD**: `PrintController` at
  `de.vvwt.tm.infrastructure.print.*` gains
  `private final JdbcTemplate jdbcTemplate;` field.
- [ ] **AC-PRINTCONTROLLER-CTOR-PARAM**: PrintController constructor
  (line 156) gains new `JdbcTemplate jdbcTemplate` parameter.
- [ ] **AC-PRINTCONTROLLER-METHOD-ADDED**: PrintController gains new
  method body BYTE-EQUIVALENT to the legacy
  `CertificateAssembler.resolveLocationDisplayName(UUID tenantId)`
  (preserved verbatim, including the `tenant_id = ?` discriminator —
  see AC-TENANCY-LOCATIONS-PRE-BIG-BANG below for DEC-20/DEC-39
  justification):
  ```java
  String resolveLocationDisplayName(UUID tenantId) {
      List<String> names = jdbcTemplate.query(
          "SELECT display_name FROM locations WHERE tenant_id = ? LIMIT 1",
          (rs, rowNum) -> rs.getString(1), tenantId);
      return names.isEmpty() ? "" : names.get(0);
  }
  ```
- [ ] **AC-TENANCY-LOCATIONS-PRE-BIG-BANG**: The `tenant_id = ?` WHERE
  predicate is PRESERVED pre-Big-Bang. Per DEC-39, `tenant_id` removal
  from tenant-scoped tables (including `locations`) is codified as target
  state but APPLIED AT DEC-25 Wave-2 Big-Bang-Reset — NOT during E23.
  The SQL preserved here matches the legacy
  `CertificateAssembler.resolveLocationDisplayName` behavior byte-equivalent
  (Q-1b behavior-preservation). Post-Big-Bang, the predicate will be
  removed and DataSource routing (DEC-20 DB-per-Tenant) alone will enforce
  tenant scoping. This AC documents that the apparent DEC-20 redundancy
  is the known transition state codified by DEC-39.
- [ ] **AC-PRINTCONTROLLER-CALLSITES**: Call sites at PrintController.java:885
  + 1006 (grep-verify any other occurrences during implementation) updated
  from `certificateAssembler.resolveLocationDisplayName(tenantContext.current())`
  to `this.resolveLocationDisplayName(tenantContext.current())`.
- [ ] **AC-PRINTCONTROLLER-REDFIRST-TEST**: RED-first test for the new
  PrintController method authored per DEC-22 Iron Law. DEC-26 applicability:
  because the new method IS a data-access operation at the controller
  layer (controller-embedded DAO-shape), all 3 DEC-26 rules apply to the
  test:
  - Rule 1 (schema from production migration): `locations` table schema
    loaded from whichever Flyway migration currently creates the
    `locations` table (likely pre-Big-Bang root `V*.sql` — grep
    `src/main/resources/db/migration/` for `CREATE TABLE locations` and
    cite the resource path in the test) via `ScriptUtils.executeSqlScript`.
  - Rule 2 (assertj-db independent verifier): not strictly needed here —
    the test's subject IS a read-query returning a value, and the
    assertion is on the returned value, not on DB state after a write.
    Rule 2 applies to write-path tests; this is a read-path test. No
    DEC-26 Rule 2 artefact required.
  - Rule 3 (read/write decoupling): fixture `locations` row inserted via
    direct JDBC (or `TenantDaoTestSupport.insertDirectly(...)` if the
    utility evolved to cover tenant-shared tables by E23 time),
    NOT by calling a DAO's own write methods.
  `resolveLocationDisplayName` call returns the inserted `display_name`.
  Test lives at `PrintControllerTest` or equivalent. RED → GREEN commit
  history.
- [ ] **AC-PRINTCERTIFICATEIT-REGRESSION**: Existing `PrintCertificateIT`
  (partial regression gate per DEC-41) remains GREEN post-migration.
