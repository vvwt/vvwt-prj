# Story E15S08: Pilot retrospective note

## User Story

**As a** human evaluator at the Wave-1 gate,
**I want** a short retrospective note capturing what worked and what hurt in the E15 Pilot,
**so that** the Wave-2 Discovery round starts from concrete Pilot observations rather than abstract assumptions.

---

## Context

Per the Epic scope, E15 ends with a retrospective note at `.gaai/project/contexts/artefacts/reports/E15-pilot-retrospective.md`. The note is the evaluation input for the Wave-1 gate decision ("proceed to Wave 2" vs "adjust approach"). It is deliberately lightweight: process-oriented, not a full postmortem.

Per the mission brief, this story does NOT write the retrospective content itself — the retrospective is composed by the human (or by Discovery during Wave-1 gate review). This story produces the AC framework so that the note's existence, location, and minimum content are non-negotiable.

The note is committed TOGETHER with the cutover commit in E15S07. Treating it as a separate late-landing artefact risks it being forgotten; pinning it to the cutover ensures the Pilot is not declared "done" without the retrospective artefact existing.

---

## Acceptance Criteria

- [ ] AC1 (governance — retrospective file exists): A markdown file exists at `.gaai/project/contexts/artefacts/reports/E15-pilot-retrospective.md` at the time of E15 completion. Missing file fails the Epic.

- [ ] AC2 (governance — commit-with-cutover): The retrospective file is committed in the SAME commit as E15S07's atomic cutover (per mission brief: "committed together with cutover"). If E15S07 lands without the retrospective, E15S07 itself fails AC and must be revised.

- [ ] AC3 (testing — minimum content structure): The retrospective includes at minimum: (a) "What went well" section with at least one concrete observation, (b) "What was painful" section with at least one concrete observation, (c) "Wave-2 adjustment proposals" section — may be empty if the Pilot ran without adjustment need, but the section exists with an explicit "None" declaration rather than being absent.

- [ ] AC4 (governance — references specific observations): The retrospective references at least one specific observation tied to a Wave-1 mechanism — Modulith `verify()` behaviour, TDD reconstruction-in-place, atomic cutover, per-tenant Flyway runner, or the tenant::api contract. Generic statements ("it went well") without a concrete anchor fail AC.

- [ ] AC5 (error-handling — missing retrospective is a cutover failure): If at E15S07 commit time the retrospective file does not exist at the specified path, the E15S07 cutover commit fails its own AC (the inter-lock is explicit in E15S07 dependencies). This prevents silent Epic closure without the retrospective — the only error mode for this story is "retrospective is absent at cutover", and it produces a hard stop in E15S07 rather than a soft warning.

- [ ] AC6 (security — no leakage of operational secrets, preventive authoring): The retrospective is composed in a deliberately-generic register — no operational data is accessed by the author during composition. Specifically, the retrospective MUST NOT include: actual admin-password plaintext from any dev/test/staging run, actual tenant UUIDs or file paths from operational environments, bcrypt-hash values, database contents, or any credential-adjacent sample. Author protocol: compose from memory/notes ONLY, not by reading dev-environment logs or staging output. A preventive review BEFORE the cutover commit (either human or Discovery) confirms compliance — post-commit leakage is in git history and cannot be remediated, so the check is a pre-commit gate, not a gate-time afterthought.

## Notes

This is intentionally a lightweight story (6 ACs after validation-gate expansion — originally drafted at 4). Its value is in the existence guarantee + operational-safety constraints, not in elaborate structure. The mission brief's "lightweight" intent stands; AC5 and AC6 were added to satisfy Epic E15's mandatory_ac_categories (error-handling + security) as required by the format gate.

The Wave-2 gate itself is not this story's concern — it is an out-of-band human step. This story ends when the retrospective file exists and is committed alongside cutover. Whether Wave-2 proceeds is the human's call downstream.
