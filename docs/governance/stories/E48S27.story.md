# Story: Loading indicator on the match-overview and match-correction pages — replace the bare "…" placeholder

## User Story

**As a** tournament operator opening the "Spiele der Phase" overview or the "Match-Korrektur" page,
**I want** the page to tell me that the games / the game-results are being loaded,
**so that** I can see the page is working rather than facing a bare "…" that is indistinguishable from a glitch or a stuck screen.

---

## Context

Two admin-SPA pages — both reached from the Phasenübersicht via the **"Spiele anzeigen"** button on an ACTIVE phase row — render a **literal "…" ellipsis character** as their loading placeholder while data is fetched:

- **`MatchOverview.svelte`** (the "Spiele der Phase" match-overview page, route `/tournaments/:tournamentId/phases/:phaseId/matches`, shipped by E48S26) — renders `…` in its `{#if loading}` branch while the phase match list loads.
- **`MatchCorrection.svelte`** (the "Match-Korrektur" page, shipped by E48S25) — renders `…` in its `{#if preloading}` branch while the match's recorded set results pre-load.

The placeholder is **not localized**, gives the operator no indication of what is happening, and is visually indistinguishable from a rendering glitch. Operator-reported 2026-05-16: the placeholder should be a clear message stating that the games / the game-results are currently being loaded.

This is a pure-frontend presentation defect in the admin SPA (`vvwt-prj/vvwt-tm-web/src/main/ui/`). It does not touch data loading, error handling, the empty state, or any backend.

---

## Acceptance Criteria

### Testing (DEC-22 RED-first; DEC-54 `mvn verify` gate)

- [ ] **AC-TEST-MATCH-OVERVIEW-LOADING-MESSAGE-RED**: A RED-first Svelte test asserts that while `MatchOverview` is in its loading state, the page renders a **localized loading message** — a resolved i18n string, non-empty, and not the bare literal "…" — that tells the operator the matches are being loaded. The test MUST fail on current HEAD (which renders "…") and pass after the fix; the RED commit precedes the GREEN commit in `git log`.
- [ ] **AC-TEST-MATCH-CORRECTION-LOADING-MESSAGE-RED**: A RED-first Svelte test asserts that while `MatchCorrection` is in its pre-loading state, the page renders a **localized loading message** (resolved i18n string, non-empty, not "…") telling the operator the match results are being loaded. RED on current HEAD, GREEN after the fix; RED commit precedes GREEN.
- [ ] **AC-TEST-LOADED-AND-OTHER-STATES-GREEN**: Regression — once the data has loaded, the loading message is gone and the existing match table / correction form renders; the existing **error state** and **empty state** of each page continue to render their existing messages unchanged. The other existing `MatchOverview` / `MatchCorrection` test cases remain GREEN.

### Governance (DEC-2 Svelte+TS stack; DEC-22; DEC-54; i18n; scope; commit format; attestation)

- [ ] **AC-GOVERNANCE-I18N-KEYS**: The loading-message text is supplied by **i18n keys** added to the `matchOverview.*` and `correction.*` namespaces in both `de.json` and `en.json` (the namespaces each page already uses). No hard-coded user-facing string is introduced. The German text states what is loading (e.g. "Spiele werden geladen…" / "Spielergebnisse werden geladen…"); the English text is the equivalent.
- [ ] **AC-GOVERNANCE-DEC-22-RED-FIRST**: Both message tests are authored fresh RED-first per `feedback_dec22_refactor_phase_first.md`; each RED commit precedes its GREEN commit in `git log`.
- [ ] **AC-GOVERNANCE-DEC-54-MVN-VERIFY**: `mvn verify` for `vvwt-tm-web` exits 0 (BUILD SUCCESS); the qa-report cites the exit code and timestamp. The Svelte compiler (invoked by `frontend-maven-plugin`) is clean.
- [ ] **AC-GOVERNANCE-NO-BACKEND-CHANGES**: `git diff --name-only` for the implementation branch contains **zero `.java` files** and no `pom.xml` change. No new REST endpoint, no backend code.
- [ ] **AC-GOVERNANCE-NO-OUT-OF-SCOPE-REFACTOR**: Implementation changes are limited to `MatchOverview.svelte`, `MatchCorrection.svelte`, the two locale files (`de.json`, `en.json`), and the test file(s). The data-loading logic, the error-state branch, the empty-state branch, and the table/form markup of each page are not otherwise modified.
- [ ] **AC-GOVERNANCE-COMMIT-MESSAGE-FORMAT**: Commit subjects use `chore(E48S27):` (RED tests / housekeeping) and `feat(E48S27):` (GREEN) prefixes per the close-story.sh contract.

### Error Handling

- [ ] **AC-ERROR-MESSAGE-SCOPED-TO-LOADING-ONLY**: The loading message appears **only** during the in-flight load. When the load fails, the page shows its existing **error** message (not the loading message); when the load returns zero matches, `MatchOverview` shows its existing **empty-state** message (not the loading message). The loading, error, and empty states remain mutually exclusive.

### Security

- [ ] **AC-SECURITY-NO-NEW-SURFACE**: Presentational change only — no new fetch call, no new REST endpoint, no authentication or authorization change, no new device-token handling. Existing endpoint contracts are unchanged.
