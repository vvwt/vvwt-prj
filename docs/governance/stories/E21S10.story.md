# Story E21S10: Cross-cutting web infrastructure + TournamentRulesController — reconstruction-in-place with TDD

## User Story

**As a** maintainer of the `tournament` context's cross-cutting web layer (exception mapping, JSON serialization, WebSocket bridge, rule-registry REST endpoint),
**I want** the seven cross-cutting web-infrastructure classes reconstructed at their final DEC-21 package coordinates with real Spring integration tests,
**so that** the boundary-API exceptions authored in E21S09 surface as well-formed HTTP responses, domain events authored in E21S09 flow to WebSocket subscribers, and the tournament rule registries are queryable via REST — all without retarget-rework when downstream Track-3 reconstruction starts.

---

## Context

Per Session Brief `discovery-2026-04-20-e21-full-refinement` D-8, `tournament`-context classes split into public API (`.tournament.*`) and implementation (`.tournament.internal.*`). This story authors the **seven cross-cutting web-infrastructure classes**:

1. **`GlobalExceptionHandler`** (inventory line 450 — `tournament-boundary-API`). `@ControllerAdvice` mapping the five boundary-API exceptions (S09) + tournament-internal exceptions to HTTP responses via `ApiErrorResponse`. Lives at `de.vvwt.tm.tournament.internal.web.*` because while its effects cross contexts, its implementation is tournament-internal (per D-8 — only the contract, i.e. `ApiErrorResponse`, is public).
2. **`ApiErrorResponse`** (inventory line 412 — `tournament-boundary-API`). Shared DTO embedded in HTTP error bodies, consumed cross-context. Placed at public root `de.vvwt.tm.tournament.*`.
3. **`JacksonConfig`** (inventory line 451 — `tournament-boundary-API`). Global `ObjectMapper` configuration (JSR-310, etc.). Tournament-internal per D-8 (its effects are global but the class is not an API surface). Lives at `.tournament.internal.web.*`.
4. **`WebSocketConfig`** (inventory line 462 — `tournament-core`). Spring WebSocket + STOMP configuration. Tournament-internal.
5. **`DomainEventBridge`** (inventory line 423 — `tournament-core`). `@EventListener` forwarding the four domain events from S09 to WebSocket topics. Tournament-internal.
6. **`EventMessage`** (inventory line 449 — `tournament-core`). WebSocket event-message DTO used by `DomainEventBridge`. Tournament-internal (consumed only by the bridge, not exposed to other Java contexts — the JSON wire format is the consumer contract, not the Java type).
7. **`TournamentRulesController`** (inventory line 461 — `tournament-boundary-API`). REST endpoint exposing match-generator, scoring-rule, and set-validation-rule registries. Moved to S10 per Review-Cycle-2 Q-1(a) (2026-04-20) because it depends on E21S08's `MatchGeneratorRegistry` (reconstructed tournament) and references scoring-context registries that remain at legacy paths during E21 (mechanically rewired to new scoring::api at E22 cutover per DEC-32).

**TmStartupLogger removed from E21 scope (2026-04-20).** The Session Brief H-4 hypothesis was falsified by empirical read of the legacy class: `de.vvwt.tm.infrastructure.TmStartupLogger` subscribes to `ApplicationReadyEvent` and emits H2 database version + Flyway version + applied-migration count + Spring-Boot version (via `DatabaseMetaData` and `Flyway.info().applied()` and `SpringBootVersion.getVersion()`) — this is shared-infrastructure diagnostics, NOT tournament-domain. The class stays untouched at its legacy coordinate and is addressed in future tenant-context work or the DEC-25 Flyway Big-Bang-Reset. An erratum on inventory row 356 documents this correction.

Per DEC-22 every class is test-first. Per DEC-29/DEC-30, the `GlobalExceptionHandler` — though implementation-internal — is tested via real `MockMvc` integration against a minimal test controller that throws each of the five S09 exceptions, confirming end-to-end HTTP status + body wiring. `TournamentRulesController` follows C-13 Hybrid-Split-Minimalist-IT methodology (E20S02 canon) — `@WebMvcTest` slice + `@SpringBootTest(webEnvironment=RANDOM_PORT)` IT.

## Acceptance Criteria

> Every AC below is testable by a command, a file-path check, or a pattern match. Vague criteria are invalid.

### Testing ACs (mandatory category: `testing`)

- [ ] **AC-TDD-GlobalExceptionHandler** / **AC-TDD-ApiErrorResponse** / **AC-TDD-JacksonConfig** / **AC-TDD-WebSocketConfig** / **AC-TDD-DomainEventBridge** / **AC-TDD-EventMessage** / **AC-TDD-TournamentRulesController**: for each class, git history shows a failing test committed BEFORE the class implementation. Red-then-green per DEC-22. Characterization tests against the legacy classes are forbidden.

- [ ] **AC-CONFIG-TDD-PATTERN** (testing — DEC-22 @Configuration carve-out): `JacksonConfig` and `WebSocketConfig` are `@Configuration` classes whose RED-first test MUST prove configuration absence. For `JacksonConfig`: the RED test uses a bare `@TestConfiguration` with a vanilla `ObjectMapper` (no JSR-310 module) and asserts a serialization invariant that FAILS (e.g., `Instant.now()` serialises to epoch-long or throws), then GREEN is achieved by adding `JacksonConfig` to the context. For `WebSocketConfig`: RED starts from a `@SpringBootTest` with all `WebSocketConfigurer` beans excluded via bean-excludes or a minimal context, asserts a STOMP endpoint connect FAILS, then GREEN is achieved by adding `WebSocketConfig`. This pattern distinguishes config-class TDD from characterization tests (which assert against the legacy's current behaviour, forbidden per DEC-22).

- [ ] **AC-GLOBAL-EXCEPTION-HANDLER-INTEGRATION**: the `GlobalExceptionHandler` test uses a real `MockMvc` `@SpringBootTest` (or a `@WebMvcTest` slice with the handler + a minimal test-only controller that throws each S09 exception). The test asserts, for each of the five S09 exceptions, exactly this mapping:
    - `ForbiddenException` → HTTP 403
    - `TooManyRequestsException` → HTTP 429
    - `UnauthorizedException` → HTTP 401
    - `ValidationException` → HTTP 400
    - `ConflictException` → HTTP 409
  AND that the response body deserialises to an `ApiErrorResponse` with populated `message`, `status`, and `timestamp` fields. Exceptions imported from `de.vvwt.tm.tournament.exceptions.*` (S09 public package) — a test importing from `de.vvwt.tm.tournament.internal.exceptions.*` fails this AC.

- [ ] **AC-JACKSON-CONFIG-INTEGRATION**: a `@SpringBootTest` serialises a `java.time.Instant` and a `java.time.LocalDate` through the configured `ObjectMapper` and asserts ISO-8601 output (JSR-310 active, no `long`-epoch fallback, no `[YYYY,MM,DD]` array form). Verified by a concrete expected-string assertion, not a structural match.

- [ ] **AC-WEBSOCKET-CONFIG-INTEGRATION**: a `@SpringBootTest` with a STOMP client connects to the configured endpoint, subscribes to the configured topic prefix, and verifies a test message round-trip succeeds. The test documents the endpoint path + topic prefix — these MUST match the legacy `WebSocketConfig` (inventory line 462) exactly; deviation requires escalation.

- [ ] **AC-DOMAIN-EVENT-BRIDGE-INTEGRATION**: a `@SpringBootTest` with a STOMP client subscribes to the topic for one of the four S09 events, the test then publishes that event via `ApplicationEventPublisher`, and the test asserts the STOMP client receives an `EventMessage` with the expected payload within a bounded timeout (e.g., 2s). Wire-format round-trip — event → bridge → WebSocket topic → subscriber — is proven end-to-end, not mocked at the bridge boundary.

- [ ] **AC-REST-SLICE-TournamentRulesController** (testing — C-13): `@WebMvcTest(TournamentRulesController.class)` slice at `vvwt-tm-web/src/test/java/de/vvwt/tm/tournament/TournamentRulesControllerSliceTest.java`. `@MockitoBean` for `MatchGeneratorRegistry` (S08) and scoring-rule-registry collaborators. `TenantContextSliceTestSupport.configureMock()` in `@BeforeEach` per C-13. `MockMvc` configured with `SecurityMockMvcConfigurers.springSecurity()`. Slice covers: happy-path rule-registry GET (returns expected JSON list shape), at least one authorization-deny path (unauthenticated GET → 401 or 403 per legacy policy). Slice does NOT touch the database.

- [ ] **AC-REST-IT-HAPPY-TournamentRulesController** (testing — C-13): 1 happy-path IT at `vvwt-tm-web/src/test/java/de/vvwt/tm/tournament/TournamentRulesControllerIT.java` annotated `@SpringBootTest(webEnvironment = RANDOM_PORT, classes = {TournamentManagerApplication.class, ...TestConfig.class})` per conventions.md (d). Exercises GET of rule registries with the full Spring context; real `MatchGeneratorRegistry` from S08 is wired; legacy scoring-rule-registry consumed via its current `de.vvwt.tm.domain.rules.*` location (mechanical rewire in S13).

- [ ] **AC-REST-IT-SEC-TournamentRulesController** (security — C-13): 1 security-negative IT — anonymous or wrong-role access denied per the legacy controller's authorization policy (inspect once as reference, do not import).

### Error-handling ACs (mandatory category: `error-handling`)

- [ ] **AC-GLOBAL-EXCEPTION-HANDLER-UNKNOWN**: an unknown `RuntimeException` (e.g., `NullPointerException`) thrown from a test controller surfaces as HTTP 500 with an `ApiErrorResponse` body — NOT a raw stack trace, NOT an empty body. Message content does NOT leak the stack trace (security); test asserts the `message` field is a generic string and the body does not contain `NullPointerException` or `\tat `.

- [ ] **AC-GLOBAL-EXCEPTION-HANDLER-SCOPE-BOUNDED**: the new `GlobalExceptionHandler` at `de.vvwt.tm.tournament.internal.web.*` MUST NOT catch exceptions owned by other Track-3 contexts — specifically, the legacy `@ExceptionHandler` methods for `de.vvwt.tm.domain.timer.InvalidTimerUrlException`, `de.vvwt.tm.domain.timer.NoActiveTournamentException`, and `de.vvwt.tm.infrastructure.display.NoActivePhaseException` (classified `not-tournament:timer` and `not-tournament:display` in inventory rows 344, 345, 365) MUST NOT be migrated to the new handler. A test verifies: if one of these legacy-owned exceptions is thrown from a test controller, the new `GlobalExceptionHandler` does NOT catch it (either the legacy handler catches it during parallel phase, or the test asserts the new handler's scope is bounded via `basePackages` or class-allowlist). Migration of these three exceptions to their respective contexts is E22 / E24 / E25 scope, NOT E21.

- [ ] **AC-WEBSOCKET-BROKEN-CLIENT**: if a STOMP client drops mid-broadcast, `DomainEventBridge` does not throw (test simulates disconnected session; asserts no uncaught exception propagates to `ApplicationEventPublisher`).

- [ ] **AC-Q7-SAFETY-VALVE** (error-handling, governance — Brief Q-7): if during Delivery the scope materially expands (e.g., `GlobalExceptionHandler` requires mapping a sixth tournament-owned exception type, or `TournamentRulesController` exposes an unexpected registry type outside MatchGeneratorRegistry + scoring-rule + set-validation-rule), Delivery STOPS and escalates per Brief Q-7. Partial delivery with explicit scope-split escalation is a valid PASS; silent scope creep is a FAIL. Error-handling facet: this AC converts "session capacity or scope exceeded" into an explicit `blocked` error-state rather than a silent incomplete delivery.

## Notes

**For the Delivery Agent.**

- The seven classes split naturally into three commit waves: (1) `ApiErrorResponse` + `GlobalExceptionHandler` (depends on S09 exceptions), (2) `JacksonConfig`, (3) `WebSocketConfig` + `EventMessage` + `DomainEventBridge` (depends on S09 events), plus `TournamentRulesController` as an independent commit gated by S08 `MatchGeneratorRegistry` availability. Within each wave, strict red-then-green per DEC-22.
- `@ControllerAdvice` scope: the new `GlobalExceptionHandler` at `.tournament.internal.web.*` WILL collide with the legacy `@ControllerAdvice` at `.infrastructure.web.*` during parallel phase unless deliberately scoped. Use the E15S04 pattern (Option B — the new class is NOT `@ControllerAdvice`-annotated during parallel phase, annotation added in the atomic cutover commit) OR scope the new advice with `@ControllerAdvice(basePackages = "de.vvwt.tm.tournament")` so it does not catch legacy-package exceptions. Delivery picks one and documents. Feature flags (`@Profile`, `@ConditionalOnProperty`) are forbidden per DEC-21.
- `DomainEventBridge` depends on the four S09 events at their PUBLIC coordinates (`de.vvwt.tm.tournament.events.*`). A grep of the authored `DomainEventBridge.java` must show these imports; an import from `.internal.events.*` indicates a package-placement bug in S09.
- `TournamentRulesController` exposes three rule-kind registries via REST. During E21, `MatchGeneratorRegistry` is the NEW tournament one (S08); `ScoringRuleRegistry` and `SetValidationRuleRegistry` are legacy scoring-context imports (inventory rows 319, 322). At S13 cutover, only `MatchGeneratorRegistry` is mechanically rewired (it's tournament-owned). The scoring registries remain legacy imports until E22 scoring reconstruction, where E22's own cutover performs the mechanical rewire per DEC-32.
- **@Configuration TDD pattern (AC-CONFIG-TDD-PATTERN).** `@Configuration` classes resist classic red-green because their effect is "the ObjectMapper / WebSocket broker is configured a certain way". To prove RED-first without characterization, the RED test asserts a configuration is ABSENT (e.g., `Instant` serialises wrong; STOMP endpoint unreachable). GREEN is achieved by adding the `@Configuration` class to the context. This distinguishes the test from a characterization test against the legacy's current observed behaviour.

**Scope-split hint (Q-7).** Seven classes is at the upper edge of one Delivery session. Natural split if needed: S10a = `GlobalExceptionHandler` + `ApiErrorResponse` + `JacksonConfig` (3 classes), S10b = `WebSocketConfig` + `DomainEventBridge` + `EventMessage` (3 classes), S10c = `TournamentRulesController` (1 class, gated by S08). Flag early.
