# Story E48S26: Operator Match Score Correction — discoverable entry point (dedicated match-overview page) + correction-form pre-load of existing set results

## User Story

**As a** Tournament Organizer (Admin),
**I want** a visible, navigable way to reach the match-score-correction screen, and that screen to open pre-filled with the match's recorded set results,
**so that** I can find and correct an entered score without hand-typing a URL and without re-entering the whole match from scratch — while a fresh entry (Nacherfassung) of a not-yet-recorded match still remains possible.

---

## Context

### Bug-Triage Provenance — two defects in the shipped E48S25 feature

Story **E48S25** ("Operator Match Score Correction + Nacherfassung", PR #279, commit `ca7fea1`, QA verdict PASS, merged 2026-05-14) delivered the correction backend (`MatchCorrectionService`, `POST /api/matches/{matchId}/correction`), the read endpoint `GET /api/phases/{phaseId}/matches`, the SPA route registration, and the destination page `MatchCorrection.svelte`. Two defects make the feature operationally unusable:

**Defect 1 — no UI entry point (the reported bug).** The E48S25 diff to `PhaseList.svelte` added 41 lines, **all inside the `<script>` block** (one import, four `$state` variables, two functions `toggleMatchList` / `isCorrectionEligible`). **Zero template/markup lines.** No expand toggle, no match list and no "Korrigieren" link render. Those symbols are referenced only inside the `<script>` block — dead code (verified by full-UI grep). The correction page is reachable today only by hand-typing the hash URL `#/tournaments/<id>/phases/<id>/matches/<matchId>/correction` including the match UUID — operationally unreachable. E48S25 had no acceptance criterion requiring or testing the entry-point link to render; the only frontend test AC covered the destination page in isolation, so the QA PASS verdict was consistent with the ACs as written. The AC id `AC-FE-PHASELIST-CORRECTION-LINKS` cited in the delivered code comments and Javadoc **does not exist in the E48S25 story** — a traceability falsehood baked into merged code.

**Defect 2 — the correction form does not pre-load existing scores.** `MatchCorrection.svelte` initializes its set-score form to two empty `0:0` rows and does not load the match's recorded set results. "Correcting" therefore forces the operator to re-enter every set from scratch. Correcting is not the same as re-entering (user mandate 2026-05-15).

### Resolution shape (Discovery 2026-05-15, human-validated Brief v4)

- The entry point is a **new dedicated match-overview page** (own route `/tournaments/:tournamentId/phases/:phaseId/matches`), reached from `PhaseList.svelte` — each `ACTIVE` phase row gains a navigation link to the new route. The inline-expand approach E48S25 half-built is **not** finished; its dead `<script>` code is removed.
- The match-overview page lists every match of the phase with round, field, both team names, the per-set scores, the localized match state, and a "Korrigieren" link for correction-eligible matches.
- `MatchCorrection.svelte` pre-loads the match's existing set results into its editable form. A match with no recorded sets (`OPEN` / `ENABLED` Nacherfassung) opens with an empty form. The pre-loaded values are an **editable starting point, not a lock** — fresh entry (add/remove set rows, overwrite any value) remains fully possible.

### Scope-discipline anchors

This story does **not** modify the correction backend (`MatchCorrectionService`, the `POST` endpoint, the cascade-recompute) — it works. It does **not** operationalize DEC-65 and must **not** touch `phase.currentLapNumber` (DEC-65 §D-8 defers operationalization post-Epic-E55). The active-phase-only correction window (DEC-65 §D-7, established by E48S25) stands: the entry link appears on `ACTIVE` phase rows only.

- [ ] **AC-ERR-TEAM-NAME-FALLBACK**: If a team name cannot be resolved (null `TeamAvatar.teamId` or blank `Team.description` — an edge case; in an `ACTIVE` phase team assignment is normally complete per DEC-59, see Notes), the endpoint projection and the match-overview page render a non-empty fallback label rather than an empty cell, a `null`, or an error.
- [ ] **AC-ERR-MATCHOVERVIEW-EMPTY-PHASE**: The match-overview page for a phase with zero matches renders an explicit empty-state message — not a blank page and not an error.
- [ ] **AC-ERR-MATCHOVERVIEW-LOAD-FAILURE**: A failed match-list fetch on the match-overview page renders a descriptive error message (mirroring the existing `PhaseList.svelte` `loadError` pattern), not a silent blank.
- [ ] **AC-ERR-CORRECTION-PRELOAD-MATCH-NOT-FOUND**: `MatchCorrection.svelte` sources its pre-load data by reusing `correctionStore.listPhaseMatches(phaseId)` — its route carries `phaseId` + `matchId` — and selecting the entry whose `matchId` matches (the canonical `MatchSummary` projection of D-6/D-7; no single-match endpoint). - [ ] **AC-ERR-MATCHLIST-UNKNOWN-PHASE**: `GET /api/phases/{phaseId}/matches` for an unknown `phaseId` returns the established behavior (an empty list, consistent with the current `matchRepository.findByPhaseId` contract); the chosen behavior is asserted by IT and documented in the impl-report.

## Notes

### Architectural anchors (verified 2026-05-15)

- **`PhaseTransitionController.java:150`** `listPhaseMatches` — hosts `GET /api/phases/{phaseId}/matches`; today maps `Match` → `MatchSummaryResponse(matchId, state, lapNumber, fieldNumber)` purely from `Match` fields. The extension adds the team-name join (`Match.memberAvatar1Id`/`memberAvatar2Id` → `TeamAvatar.teamId` → `Team.description`) and the per-set score read (`SetResult` rows by `matchId`, ordered by `setIndex`). This is a multi-join projection — a `Match` carries no team or score fields.
- **`MatchSummaryResponse.java`** (`de.vvwt.tm.web.internal.dto`) — record extended with the two team names + a per-set score collection. **`MatchSummary`** in `correctionStore.ts` is its TypeScript mirror — extended in lockstep (new production code, RED-first per DEC-22).
- **`correctionStore.ts`** — `listPhaseMatches()` is reused by the new match-overview page (one canonical FE match-list projection); after `PhaseList.svelte` drops its import, `correctionStore.ts` is not orphaned.
- **`App.svelte`** route table — a new route `/tournaments/:tournamentId/phases/:phaseId/matches` → the new match-overview component is registered (the correction route `…/matches/:matchId/correction` is already registered).
- **`parentRouteMap.ts`** — back-navigation per memory `feedback_e48s15_back_nav_principle` (back-target follows the calling page): the new match-overview page → the phase list; the correction page → the new match-overview page (its new calling page).
- **`PhaseList.svelte`** — gains a navigation link on `ACTIVE` phase rows; loses the dead inline-expand `<script>` code.
- **`MatchCorrection.svelte`** — gains a mount-time pre-load of the match's recorded set results. It obtains them by reusing `correctionStore.listPhaseMatches(phaseId)` (its route carries `phaseId` + `matchId`) and selecting the entry whose `matchId` matches — the same canonical `MatchSummary` projection the match-overview page consumes (D-6/D-7); no single-match endpoint is introduced. Its set-score form remains fully editable (add/remove rows, overwrite values).
- **`locales/de.json` + `en.json`** — new i18n keys, including localized match-state labels (mirroring the existing `PhaseList` status-badge i18n pattern).
- **In an `ACTIVE` phase** every match's member avatars have a non-null `teamId` — verified against DEC-59 (the operator-confirmation team-assignment workflow writes `TeamAvatar.teamId` in the same transaction as the `PREPARED → ASSIGNED` transition, and `ACTIVE` follows `ASSIGNED`). `AC-ERR-TEAM-NAME-FALLBACK` is defensive for the residual edge case (e.g. blank `Team.description`).
