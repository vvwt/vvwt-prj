# Story: Extend `build-image.sh` pre-flight to catch FullPageOS's undocumented Python dependencies (python3-git + python3-yaml) before the chroot phase

## User Story

**As a** tournament operator,
**I want** `./build-image.sh` to fail fast at pre-flight time with an
actionable English message when the Python deps that FullPageOS's
`build_dist` requires (`python3-git`, `python3-yaml`) are missing,
**so that** I don't have to debug a `ModuleNotFoundError` deep inside
the FullPageOS chroot's `execution_order.py` after the script has
already downloaded the ~550 MB Raspbian image and run for several
minutes.

---

## Context

Discovery's Bug-Triage chain under Epic E69 continued past E69S04's
`update-custompios-paths`-argument fix. The 2026-05-27 live operator-
attest progressed past CustomPiOS clone + symlink-helper + Raspbian
image download + overlay-apply, and entered the FullPageOS `build_dist`
phase. There, CustomPiOS's `execution_order.py` (invoked by FullPageOS
via `custompios` shell on `python3 ${CUSTOM_PI_OS_PATH}/custompios_core/execution_order.py`)
failed at module-load time:

```
File "…/execution_order.py", line 6, in <module>
    from get_remote_modules import get_remote_module
File "…/get_remote_modules.py", line 5, in <module>
    import git
ModuleNotFoundError: No module named 'git'
```

Root cause is empirically established. Two non-stdlib Python packages
that the CustomPiOS `execution_order.py` import chain eagerly loads at
script-load time:

- **`git`** (GitPython, apt: `python3-git`) — imported by
  `get_remote_modules.py`. NOT a default Debian/Ubuntu package.
- **`yaml`** (PyYAML, apt: `python3-yaml`) — imported by both
  `get_remote_modules.py` and `common.py`. Typically pre-installed on
  Ubuntu/Debian as a core dependency.

These dependencies are NOT enumerated in the FullPageOS 0.14.0 README's
"Developing" prerequisites section (which lists only `coreutils`,
`p7zip-full`, `qemu-user-static`, root privileges, bash, realpath,
sudo, jq). The gap is in upstream documentation; this story closes it
operator-facing by extending the wrapper's pre-flight check.

E69S03 AC5 Escalation-Clause governs the pattern: gap → new story
(`track: bug-triage`, single-class) → fix → re-attest. E69S05 is the
third such retrofit under Epic E69.

The fix is a script-level retrofit: extend the non-dry-run pre-flight
check (currently `build-image.sh:142-176`) to verify both Python
imports via per-dep `python3 -c 'import <name>'` invocations, each
producing an actionable English message on failure; extend the
`pi-display/README.md` Prerequisites section with the two `python3-*`
apt packages; bats RED-first source-grep verifying the pre-flight
check covers both deps. No upstream contract change, no fork, no new
CLI surface. Wrapper identity preserved per E69S01 Brief T-3.

This story is `track: bug-triage` per the Discovery Bug-Triage Flow.
Like E69S04 and E69S06, it is a single-class retrofit on the wrapper —
not a feature expansion. E69S05 is statically independent of E69S04
(different code regions: pre-flight vs `update-custompios-paths`
invocation) and E69S06 (different code regions: pre-flight vs wget
URL); either can land before or after E69S05 without affecting its
correctness.

## Root Cause Analysis

Single-class defect: missing pre-flight coverage of two FullPageOS-
upstream-required Python imports in `vvwt-prj/pi-display/build-image.sh`.

**Upstream contract** — Static read of CustomPiOS devel branch HEAD
2026-05-27 (the branch the wrapper script clones by default via
`git clone https://github.com/guysoft/CustomPiOS.git` — no `--branch`
specified, defaults to remote HEAD = devel):

```
custompios_core/execution_order.py
  └── imports: argparse, os, subprocess, typing (stdlib)
  └── from get_remote_modules import get_remote_module
      (eager import at module load; line 6)

custompios_core/get_remote_modules.py
  └── imports: os, pathlib, typing (stdlib)
  └── imports: yaml (PyYAML; apt: python3-yaml)
  └── imports: git, from git import RemoteProgress (GitPython; apt: python3-git)
  └── from common import get_custompios_folder (sibling)

custompios_core/common.py
  └── imports: typing, os, pathlib (stdlib)
  └── imports: yaml (PyYAML; apt: python3-yaml)
```

Complete set of non-stdlib Python imports loaded at `execution_order.py`
script-load time: **`git`** + **`yaml`** — verified by reading the full
import block of each file at devel HEAD 2026-05-27. No additional
non-stdlib deps; the static enumeration is bounded.

**Both deps are eager imports** — loaded regardless of whether the
build configuration uses remote modules. Both are HARD requirements for
ANY FullPageOS build via CustomPiOS, not optional.

**License audit:** `python3-git` (BSD-3-Clause), `python3-yaml` (MIT).
Both AGPL-forward-compatible per the FSF license-compatibility matrix.
No DEC-3 or DEC-75 §D6 implication.

**Pre-flight check design — per-dep invocation:**

The naive single-invocation `python3 -c 'import git, yaml'` would raise
`ModuleNotFoundError` on the FIRST failing import and exit — the second
dep is never checked. To emit per-dep messages when both deps are
missing (Q-3 contract), each dep is checked in its own `python3 -c`
invocation. A naive sequential pair under `set -euo pipefail`
(`build-image.sh:87`) would also short-circuit (the script aborts on
the first non-zero exit before the second check runs). The fix uses a
**collect-and-exit** guard pattern: each dep's check is wrapped in
`|| { echo "ERROR: …"; MISSING_PYTHON=true; }` so the compound
expression always succeeds (under `set -e`); after both checks run, if
`MISSING_PYTHON=true` then the script exits non-zero with both error
messages already emitted.

**Why it slipped past E69S03** — E69S03 AC2 bats are fixture-based
against a mock FullPageOS-source-tree (per E69S03 O-8: Delivery has no
Docker / sudo / network-clone in `mvn verify`); the fixture-based
assertions verify the overlay-apply step against directory structure,
not the FullPageOS upstream's Python-deps preflight. E69S03 AC5
operator-attestation runs post-merge; the 2026-05-27 operator log is
that first live attest, by construction the gap-discovery vehicle.

## Acceptance Criteria

- [ ] **AC1 [testing — reproduction scenario, Given/When/Then]:**
  **Given** a Linux host with the prerequisites listed in E69S03 AC6
  (Docker or `podman+podman-docker`, `qemu-user-static`, `git`,
  `wget`, `sudo`, `modprobe loop` capability) BUT **without** the two
  Python packages `python3-git` and/or `python3-yaml` installed, and
  an internet connection, **when** the operator runs from
  `vvwt-prj/pi-display/`:
  `sudo ./build-image.sh --server-url=https://tm.example.test/`,
  **then** the script exits non-zero at pre-flight time (before any
  network clone or wget download) and the stderr output contains
  actionable English messages naming each missing Python module + the
  apt-install remediation hint. Against the pre-story script
  (E69S04-merged HEAD), the same invocation does NOT detect the
  missing deps at pre-flight time and instead proceeds through clone /
  download / overlay-apply to the FullPageOS chroot phase where the
  inner `execution_order.py` raises `ModuleNotFoundError` after
  significant work has been done. The reproduction-vs-fix evidence is
  recorded in the impl-report per AC4.

- [ ] **AC2 [testing — fixture-based bats RED-first source-grep on
  per-dep pre-flight checks, no Docker, no live Python invocation]:**
  The bats test suite under `vvwt-prj/pi-display/src/test/sh/` is
  extended with assertions that perform static `grep -q` on
  `${BUILD_SCRIPT}` matching the per-dep pre-flight check shape — at
  minimum: one grep for the executable invocation
  `python3 -c 'import git'` (anchored to the executable line, not a
  comment line — recommended anchor shape: a regex including
  `python3 -c` immediately preceding the import-name token), AND a
  separate adjacent grep for `python3 -c 'import yaml'`. The grep
  asserts EXISTENCE of both per-dep invocations in the source. The
  assertion runs by static source inspection only — no live Python
  invocation, no `docker`/`podman`, no `sudo`. Each grep fails against
  the pre-story script (which carries neither invocation) and passes
  after the fix. Per memory `feedback_ac_behavioural_what_not_test_how`,
  the AC names the verification surface (static grep on the
  invocation line); Delivery chooses the exact regex.

- [ ] **AC3 [error-handling — collect-and-exit guard pattern for
  per-dep failure-message emission under `set -euo pipefail`]:**
  The pre-flight check uses a collect-and-exit guard pattern: each
  per-dep `python3 -c` invocation is wrapped in
  `|| { echo "ERROR: …" >&2; MISSING_PYTHON=true; }` (or equivalent
  pattern that prevents `set -e` short-circuit), so both checks
  execute even when the first fails. After both checks run, if any
  failed (`MISSING_PYTHON=true` or equivalent flag), the script exits
  non-zero. The per-dep error message names the specific missing
  module (e.g., `python3-git`) and the apt-install remediation hint
  (`sudo apt-get install python3-git` for Debian/Ubuntu, with a
  generic "or your distro's equivalent" note for non-Debian operators).
  A bats assertion (in addition to AC2's existence checks) verifies
  the source contains the collect-and-exit guard pattern — at minimum
  by grep'ing for the literal flag-variable name (or equivalent
  guard-pattern token chosen by Delivery) on the wget+pre-flight
  section. Per E69S01 AC7 actionable-English convention.

## Out of Scope

- **Comprehensive audit of all CustomPiOS Python modules** — the
  static inventory bounded by AC2/AC3 covers the two non-stdlib
  imports reachable from `execution_order.py`'s module-load chain at
  devel HEAD 2026-05-27. Future Python-dep gaps surfaced by upstream
  changes each escalate to a new story per the E69S03 AC5
  Escalation-Clause; speculative comprehensive coverage would add
  Delivery effort proportional to upstream code surface + staleness
  risk.
- **Distro-specific package-manager wrappers in the script** — the
  pre-flight check is Python-import-based (distro-portable); the
  error message lists the apt-install command + a generic "or your
  distro's equivalent" hint. Operators on non-Debian systems
  translate manually.
- **Single-pass `python3 -c 'import git, yaml'` pre-flight** —
  rejected because Python's import machinery raises on the FIRST
  failing import and does not collect all missing imports;
  incompatible with the per-dep error-message contract (both missing
  → both named).
- **CI full Docker build** — still untestable per E69S03 O-8 + T-1.
- **FullPageOS / CustomPiOS internal-contract changes** — the fix
  conforms `build-image.sh` to upstream's existing contract; no
  contract change.
- **FullPageOS tag bumps beyond 0.14.0** — separate stories per
  E69S01 Brief D-9.
- **`pi-display/pom.xml` modification** — entirely shell script +
  bats + README; POM unchanged per AC6.
- **In-runbook authoring of new systemd drop-ins or HTML fallback
