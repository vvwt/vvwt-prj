# Story E21S03: Phase + PhaseBreak + RoundSnapshot Aggregates — reconstruction-in-place with TDD

## User Story

**As a** maintainer of the `tournament` bounded context,
**I want** the `Phase`, `PhaseBreak`, and `RoundSnapshot` entities + their six repositories + the `PhaseBreakService` reconstructed under `de.vvwt.tm.tournament.*` / `.tournament.internal.*` with a failing test preceding every implementation,
**so that** the phase-lifecycle aggregates sit cleanly on the new Modulith boundary and the slotopt integration, timer context, and display context can target the new `Phase`/`PhaseRepository` public surface without retargeting later.

---

## Context

Epic E21 is the hub-first Track-3 reconstruction (Brief D-10 Approach C). After E21S02 delivers the `Tournament` root + the DAO-schema helper, this story reconstructs the three non-root entities that model a tournament's **phase structure**: `Phase` (phases within a tournament — group stage, knockout, etc.), `PhaseBreak` (scheduled breaks between laps within a phase), and `RoundSnapshot` (point-in-time snapshot of match state per round, used for display and recovery).

Per Session Brief D-4 (aggregate-oriented DDD decomposition), these three cluster naturally: Phase is the parent aggregate in the phase cluster, PhaseBreak is a dependent child, and RoundSnapshot is a read-model alongside. Per Brief D-8 and inventory evidence: `Phase` (inventory line 177, 12 importers — boundary-API), `PhaseRepository` (line 298, boundary-API — consumed by `slotopt/DirectSlotOptimizationClient`), `PhaseBreak` (line 178 — boundary-API candidate, consumed by `timer/TimerDataService`), and `RoundSnapshot` (line 181) all become public-API entities; the `CrudRepository` twins, `PhaseBreakService`, and any internal helpers land at `de.vvwt.tm.tournament.internal.*`.

Per Brief O-8, `PhasePreparationService` (inventory line 180 — phase preparation + referee assignment + match generation, substantial logic) is deferred to later stories (S08). THIS story scopes strictly to entities, their repositories, and the thin `PhaseBreakService` CRUD. Per DEC-22, RED-first TDD per class. Per DEC-26, DAO tests use the `TenantDaoTestSupport.applyTournamentSchema()` helper delivered by E21S02. No REST controller in this story (there is no dedicated Phase REST controller in legacy — phase operations are exposed via `TournamentController` / later draft controller).

Legacy FQNs untouched until S13 atomic cutover. No consumer-context edits (slotopt, timer, display rewire → S13 per DEC-32).

- **Scope-split trigger (Q-7):** Total 10 classes + 6 IT tests + 3 unit tests ≈ moderate scope. If execution pushes past session capacity (>8h continuous / >4000 LOC), STOP and flag split. Candidate split line: Phase cluster vs RoundSnapshot.
- **No REST, no DTOs, no slice-tests:** This story is purely domain + DAO. REST methodology (C-13) is N/A here; `mandatory_ac_categories` intentionally excludes `security` (no controller-layer security surface).
- **FK note:** `Phase` has `tournament_id` FK → `tournament.id`; the S02 helper loads V2 which defines both tables. `PhaseBreak` has `phase_id` FK → `phase.id` (V7). `RoundSnapshot` links to phase (V11). The helper's version-order guarantee (from E21S02) makes FK constraints satisfiable during IT setup.
- **Phase state + MatchState:** `Phase` has a state/lifecycle field; the enum types (`MatchState`, `SetState`) live with match-context in legacy (inventory lines 176, 184). `Phase` references `MatchState` only indirectly — its own state is a distinct enum. If `Phase` requires a state enum value at construction for testing, use a minimal inline enum type until S05 delivers the full match enums, OR import legacy `de.vvwt.tm.domain.MatchState` transitionally (documented in impl-report). Prefer the local enum approach.
