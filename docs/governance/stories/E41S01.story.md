# Story E41S01: NEW module skeleton vvwt-slotopt-standalone-worker + parent-POM atomic edit (legacy `<module>` REMOVE + new ADD per Coexistence δ-c′) + Picocli dep + greenfield package layout

## User Story

**As a** maintainer of the vvwt-prj reactor enabling the greenfield slot-opt-standalone-worker development per Session Brief D-1,
**I want** a NEW Maven module `vvwt-slotopt-standalone-worker` created with Picocli + worker-lib + slf4j dependencies + greenfield package layout under `de.vvwt.slotopt.standalone.*` (root + `.internal` sub-package per DEC-35-by-analogy from E35S04), AND the parent `pom.xml` atomically edited to REMOVE the legacy `<module>vvwt-standalone-worker</module>` entry at line 25 + ADD `<module>vvwt-slotopt-standalone-worker</module>` line in the same commit (per Brief D-3 Coexistence δ-c′),
**so that** subsequent E41 stories (S02 Config/CLI, S03 Crypto, S04 HTTP, S05 Runtime, S06 Integration) have a working module skeleton to build on, AND legacy `vvwt-standalone-worker/` filesystem stays UNTOUCHED (per Brief C-23) but is excluded from the reactor build.

---

## Context

Per Brief D-1: greenfield TDD authoring of NEW module — NOT a rebuild/rewrite of legacy. Per Brief D-2: module name `vvwt-slotopt-standalone-worker` + Java package root `de.vvwt.slotopt.standalone.*` per E37 D-6b naming convention. Per Brief D-3 Coexistence δ-c′: parent POM atomic edit (line REMOVED + line ADDED), legacy filesystem UNTOUCHED.

Per Brief C-23: parent `pom.xml` MUST receive exactly TWO line-level changes at this story's atomic commit:
- One line REMOVED: `<module>vvwt-standalone-worker</module>` (current line 25, verified at session start)
- One line ADDED: `<module>vvwt-slotopt-standalone-worker</module>`

No reordering, no comment changes, no whitespace changes to surrounding `<module>` entries permitted. qa-review verifies via diff hunks.

This is the FOUNDATIONAL story for E41 — every subsequent story carries `depends_on` including E41S01.
