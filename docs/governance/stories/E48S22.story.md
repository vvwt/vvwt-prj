# Story E48S22: Atomic apply() — DRAFT precondition + draft_json persist + DRAFT→PLANNED transition (delegate to TournamentLifecycleService) + markPlanned public-surface removal + DraftAlreadyAppliedException collapse + E48-Epic-narrative amendment + saveDraft multi-call regression

## User Story

**As a** Tournament Organizer,
**I want** clicking "Phasenplan anwenden" to be the single, final commit of my plan — creating phases, persisting the plan as the source of truth, AND transitioning the tournament to GEPLANT in one atomic operation,
**so that** the post-Apply success message is truthful (status really is GEPLANT), the Phasen-Übersicht shows the Spielmodus column, the "Vorbereiten" button on Phase 1 actually works, and I do not need to click a second "Planen"-button afterwards.

---

## Context

This Story closes the bug class observed by the user on 2026-05-08 (tournament `be12b52a-648d-4580-a13c-e492dcd573df`, "31. Frühjahrsturnier"). Three observable symptoms converge on a single architectural inconsistency in `DefaultDraftService.apply()`:

1. **Vorbereiten on Phase 1 throws HTTP 400 `AC-ERROR-HANDLING-DRAFT-JSON-NULL`** — `DefaultPhaseTransitionService.java:493-507` requires `tournament.draft_json` non-null; `apply()` does not persist it.
2. **Spielmodus column shows "—"** — `PhaseOverviewResponse.java:22-24` derives `gameMode` from `draft_json` per `AC-PHASE-LIST-DEFENSIVE`; null `draft_json` → null `gameMode` → "—".
3. **Tournaments listing shows "Entwurf" + Planen-button after Apply** — `apply()` does not transition `tournament.status`; the FE `applySuccess` message at `de.json:119` ("Das Turnier hat jetzt den Status GEPLANT") is unfounded; user must click Planen separately to invoke `DefaultTournamentLifecycleService.markPlanned()` (line 57-71) which is the sole DRAFT→PLANNED authority.

The fix is atomic: `apply()` becomes the single commitment that requires DRAFT, creates phases (existing), persists draft_json (new), and transitions DRAFT→PLANNED via `TournamentLifecycleService.markPlanned()` delegation (new — preserves DEC-35 modulith authority-locality; same `@Transactional` boundary, REQUIRED propagation joins outer TX, re-entrant `findByIdForUpdate` permitted under H2).

**Public-surface decoupling (User-decision P-1):** since `markPlanned()` is now invoked only internally by `apply()`, its public surface is removed end-to-end (REST endpoint + FE Planen-button + i18n keys + tournamentStore client + controller-IT cases). The service method + impl + service-level IT remain — invoked only from `apply()`.

**Idempotency collapse:** under the new invariant "phases exist iff status=PLANNED", the existing `DraftAlreadyAppliedException` / `AC-DRAFT-APPLY-IDEMPOTENCY` phases-exist guard at `DefaultDraftService.java:189-193` becomes redundant (re-Apply on PLANNED fails on the new DRAFT-precondition first). The exception class is removed; the typed-409 messageKey contract migrates to a new `AC-DRAFT-APPLY-NON-DRAFT-STATUS-409`.

**Epic narrative amendment:** E48 Epic at lines 25, 79, 97 references the now-removed two-step Apply→markPlanned user journey. Discovery commits the amendment atomically with this Story's backlog registration; line 42 (historical E48S03 reference) retained.

**Pre-existing stuck-DRAFT-with-phases tournaments:** Reset-Plan (E48S13) requires PLANNED status — does NOT apply. Recovery: Cascade-Delete (E48S13 widened DELETE accepts DRAFT) + recreate. User accepts (1 tournament, dev environment).

This Story is a **producer-fix in `DefaultDraftService.apply()`** (per memory `feedback_discovery_cycle_resolution_scope_creep.md`). Public-surface deletion is end-to-end atomic in a single PR (DEC-21 atomic-cutover spirit) — no live window where the FE Planen-button can hit a removed BE endpoint.
