# Story: Scoring-tablet field-page layout redesign — logo removed, match identity in the header, bottom wordmark + version + field number, one score field per team

## User Story

**As a** referee scoring a match courtside on the tablet,
**I want** the field page to show the two teams and the current round and set in the header,
the score for each team in a single clear field, and only minimal branding chrome,
**so that** I can identify the current match at a glance and have more of the screen for score
entry.

---

## Context

This is the first story of Epic E61. The scoring-tablet field page (`/score/field/{n}`,
template `templates/score/field.mustache`) today renders a large brand logo lockup in a top
header strip, shows the match identity (team names, round, set) low in the page body, and gives
each team two score widgets — a large read-only display plus a separate small numeric input.

Per the Discovery session of 2026-05-16, the layout is reworked so the match identity moves to
the header, the logo is dropped to free vertical space, the brand is re-expressed as a small
bottom wordmark, and each team gets a single score field. This story is pure presentation; it
does not change the match API (Epic story E61S02) and does not add the team-position swap
(E61S03).

---

## Acceptance Criteria

- [ ] AC1 (layout): the brand logo lockup image (`vvw-tm-logo.svg`, currently in the top header
  strip of the field page) is removed from the field page. The favicon `<link rel="icon">`
  tags are left unchanged.
- [ ] AC2 (header): the field-page header displays the active match's two team names as
  "{team1} vs. {team2}" and the current round and set as "Runde {n} — Satz {m}".
- [ ] AC3 (branding): a "Scoring Tablet" wordmark is placed at the bottom-left of the page, with
  the letter "o" in "Scoring" rendered as the blue icon (`vvw-icon-blue.svg`) integrated inline
  as that letter; the application version (e.g. "Version: dev") is shown immediately beside the
  wordmark.
- [ ] AC4 (layout): the field number is displayed centred at the bottom of the page, as
  "Feld {n}".
- [ ] AC5 (score field): each team has exactly one score field — a single editable input field,
  sized like the former large score display — replacing the former separate read-only display
  and small numeric input. The +/− buttons are retained and operate on this single field.
- [ ] AC6 (error-handling): when no active match is present on the field, the header shows no
  team / round / set values — no raw UUIDs, no stale or placeholder text — and the existing
  "no active match" state is shown.
- [ ] AC7 (i18n): every user-facing string on the page is sourced from a message key — no
  hardcoded display string is introduced; any new label (e.g. for the field number) uses a
  message key consistent with the existing `score.field.*` keys.
- [ ] AC8 (governance): the field page remains Mustache + inline vanilla ES5 JavaScript only —
  no Svelte or other framework, no ES2015+ syntax, no bundler (DEC-19); the changed template
  and inline script introduce no ES2015+ constructs.
- [ ] AC9 (testing): the change is covered by tests — authored failing-first for any first-party
  logic per DEC-22 — asserting on the rendered field page that the logo image is absent and
  that the header (teams + round/set), the bottom wordmark + version, the bottom-centred field
  number, and exactly one score input per team are present, and that the +/− buttons update
  that single score field. Page behaviour not reachable by the project's existing test surface
  for this Mustache + ES5 page is verified and recorded in the impl-report.
- [ ] AC10 (governance): `mvn verify` from the `vvwt-prj` root is BUILD SUCCESS (DEC-54,
  DEC-71).

> All acceptance criteria must be verifiable.

## Notes

This is the first story to touch the scoring-tablet field page in Epic E61 — it cites DEC-19
(Mustache + inline ES5 carve-out for legacy iOS 9 Safari) per that DEC's first-touch rule. The
header's team / round / set values are populated client-side from the existing match API; with
the API currently reporting a hardcoded set index (fixed by E61S02), the displayed "Satz" value
remains 1 until E61S02 lands — this story builds the header structure, not the API. Per memory
`feedback_ac_behavioural_what_not_test_how`, AC9 states the behavioural requirement and points
at the project's existing test surface for this page rather than prescribing a test mechanism
the Mustache + ES5 environment may not support. `mvn verify` is the build gate per DEC-54 /
DEC-71.
