# Story E44S04: Brand-lockup oversize fix — `.brand-lockup` adopts `height: 2em` with `min-width: 120px` removed across 4 Vite SPAs (TM admin/timer/display + Info)

## User Story

**As a** user opening any of the 4 VVW Vite SPAs (TM admin, TM timer, TM display, Info portal),
**I want** the brand lockup in the page header to render at a moderate size (~32 px tall) that does not visually dominate the page,
**so that** the page content immediately commands attention while the brand lockup remains visible and recognisable as a VVW-family identifier.

---

## Context

E44S02 (TM-side rollout, PR #168) and E44S03 (Info-side rollout, PR #169) shipped on 2026-05-03. Both stories enforced `min-width: 120 px` on `.brand-lockup` per Brief C-9 of the original `discovery-2026-05-02-vvw-brand-rollout-phase1` Brief, but neither story declared a height ceiling. As a result, all 4 SPA `.brand-lockup` rules render at the SVG asset's intrinsic dimensions, producing an oversized lockup observed by the human on the Admin SPA on 2026-05-04.

Empirical analysis during Discovery (Brief v3 O-3): `vvw-tm-logo.svg` ships with viewBox `552.5 × 240` (aspect ratio ≈ 2.30:1); `vvw-info-logo.svg` ships with viewBox `441.8 × 240` (aspect ratio ≈ 1.84:1). The user's empirically validated target value is `height: 2em` (≈ 32 px). At that height, the lockup naturally renders at ~74 px wide (TM) / ~59 px wide (Info) — both below the 120 px floor that AC12 of E44S03 / AC13 of E44S02 had imposed.

Discovery cycle-1 review (Tier-2 Reviewer, rubric_version 2026-03-30) flagged the conflict as CRITICAL F1: enforcing both `height: 2em` and `min-width: 120px` simultaneously would force the browser to horizontally stretch the `<img>` element, breaking its aspect ratio. The human resolved F1 by choosing option (a): **drop `min-width: 120px` for the 4 SPA surfaces**. Quote from the Discovery session: "mit 120px nimmt es in der aktuellen Umsetzung zu viel Platz weg." This is a deliberate per-surface relaxation of Brief C-9; the original Brief's C-9 remains intact at the E44 phase-1 level (governs Score-Tablet Mustache templates, which keep their 120 px width via `<img width="120">` HTML attribute — different mechanism, unaffected).

This story does NOT amend the AC text of E44S02 / E44S03 in their respective story files or backlog notes. Done-story artefacts are historical records of what shipped at PR-merge time; their AC text remains intact as such. The new ACs in this story describe the new scope of work and supersede the prior `min-width: 120px` enforcement only at the live-codebase level. Existing test assertions that encoded the obsolete invariant (`InfoBranding.test.ts` lines 71–91) are mutated as part of this story's test-file scope — normal TDD-driven test mutation, not "AC deprecation by successor story" (a governance-novel concept explicitly avoided per cycle-2 Reviewer N-2 finding + human option (a) resolution).

A pre-existing client-side branding test exists only for the Info SPA (`InfoBranding.test.ts`); the 3 TM SPAs shipped E44S02 without dedicated client-side `.brand-lockup` vitest tests (verified via empty grep across `vvwt-tm-web/src/main/ui*/src/**/*.test.ts` and `vvwt-tm-web/src/test/**/*.java` for `brand-lockup` / `BrandLockup` / `min-width.*120`). Therefore: Info SPA gets a test-file edit; the 3 TM SPAs get new test files added.

**Aspect-ratio empirical math (Brief v3 O-3)**: at `height: 2em` (~32 px), TM logo (552.5×240, ratio 2.30:1) renders ~73.6 px wide; Info logo (441.8×240, ratio 1.84:1) renders ~58.9 px wide. Both naturally below 120 px → user accepts the smaller render width per option (a).

**Test mechanism rationale (Brief v3 C-4 + AC1–AC4)**: jsdom does NOT compute CSS from `<style>` blocks, so `window.getComputedStyle` is NOT viable for asserting `.brand-lockup` declarations. Postcss-AST parsing introduces build-time complexity disproportionate to the bug-fix scope. Playwright/Puppeteer headless rendering introduces test-runtime infrastructure not present in the project today. The committed strategy — `fs.readFileSync` source + comment-strip + permissive regex — is brittle to spelling but falsifiable, value-locked, and zero-infrastructure. The selector pattern `(?::global\()?\.brand-lockup\)?` accepts both `.brand-lockup` (TM admin/display, Info) and `:global(.brand-lockup)` (TM timer) without per-SPA test-pattern divergence.

**Brief C-9 relaxation scope (Brief v3 C-7 + AC12)**: Brief C-9 of `discovery-2026-05-02-vvw-brand-rollout-phase1` mandated `min-width: 120 px` as the brand-lockup minimum render size. This story relaxes that enforcement for the 4 SPA surfaces only. Score-Tablet retains 120 px width via the `<img width="120">` HTML attribute (different mechanism, unaffected by CSS edits in the 4 SPAs). The original Brief's C-9 remains intact at the E44 phase-1 level; this story's Brief v3 C-7 documents the per-surface deviation as session-scoped, not a framework-level rule change.

**Cross-SPA visual coherence (Q-2) scope (Brief v3 Q-2)**: Coherence is achieved at the lockup-element level across the 4 SPAs (uniform `height: 2em` declaration, uniform regex-tested invariant). Coherence is NOT achieved at the full-SPA-presentation level — TM SPAs wrap the lockup in `<header class="brand-header">` chrome (padding, white background, bottom border) whereas Info SPA renders the lockup as a direct child of `<main class="app">` with no wrapper. This structural divergence is OUT of scope for this fix (Brief S-5).
