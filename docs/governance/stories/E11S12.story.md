# Story E11S12: Timer SPA inline transport controls per schedule row + audio-activity indicator + manual time-shift + ephemeral phase-config inline editing

## User Story

**As a** tournament organizer using the Timer SPA at a venue,
**I want** (a) small play / pause / stop controls in every schedule row (round and audio-playing break) with a visual "is audio playing right now for this row?" cue, (b) the ability to click a row's inline play to "skip to" that row immediately (shifting the wall-clock times of this and all subsequent rows by the same delta), and (c) the configured lap duration, lap break, inter-phase pause, and intra-phase breaks editable inline in the schedule so I can correct misconfigurations on the day without going back to the admin tournament-setup page,
**so that** I can manually drive or correct the timer flow during a live tournament without context-switching away from the timer page — and quickly try out a different lap-time without committing the change to the persisted plan.

---

## Context

After E11S11 reorganises the layout (sticky header + scrollable schedule), the Timer SPA still lacks per-row interaction. The operator's UX needs (Brief D-10, D-11) are:

- **Inline per-row transport controls (B.3).** Each schedule row that triggers audio (ROUND rows that play start / end sounds; `breakType=REGULAR` rows that play pause music) should carry its own small play / pause / stop control set. The inline play icon's colour saturation should reflect whether that row's audio is *currently* playing (bright green when active for this row; pale green otherwise). The main controls in the header (E11S11 AC2) remain — they drive the global engine state.

- **Manual time-shift via inline play (B.3).** Clicking the inline play of a row "skips to" that row: the engine stays `PLAYING`, the row's effective wall-clock time becomes "now", and every subsequent row's effective time advances by the same delta. The shift uses the existing `timeOverrides` Map pattern introduced by E11S04 AC7 (manual time edit per row); the same semantic that "WS LAP_ADVANCED reload wipes manual overrides" applies — operator's manual time-shift does not survive a WS-driven schedule reload.

- **Ephemeral phase-config inline editing (B.4).** Each phase carries a config row positioned directly above its Round 1, exposing the operator-configured `lapTimeMinutes`, `lapBreakTimeMinutes`, `sectionBreakTimeMinutes` as inline-editable numeric inputs. Intra-phase breaks (`DraftSection.breaks`) are inline-editable at their respective break-row's display area (duration + optional label). **Edits are ephemeral — operator-decision (Brief D-11 clarification round): no `DraftService.saveDraft` call, no persistence, no backend status-guard interaction.** The new values trigger a schedule recompute, the recomputed schedule is visible immediately in the table + countdown, and a page reload reverts to the backend-served (persistent) schedule. This sidesteps the `DefaultDraftService.saveDraft` 409-on-non-DRAFT guard entirely.

Discovery Session Brief `discovery-2026-05-28-timer-post-e11s09-bugs-and-ux-evolution` (operator-validated 2026-05-28 after Tier-2 cycle-2 en-bloc resolution of 3 escalated findings; rubric_version 2026-03-30) drives the scope. The Brief's E-8 finding (Delivery architecture asymmetry for the recompute path) is resolved by recommending the FE-port option in the § Notes section — Delivery may choose differently with rationale.

## Acceptance Criteria

> All acceptance criteria are observable behaviour. Implementation approach (FE-local recompute vs. non-persisting backend call) is Delivery's choice; this Story specifies the WHAT.

### Inline transport controls per row (Brief D-10 — B.3)

- [ ] **AC1 — Inline play / pause / stop controls in every audio-triggering row.** Every schedule row of type `ROUND` and every row of type `BREAK` with `breakType=REGULAR` (i.e. every row that triggers audio per the existing E11S04 classification) renders a compact set of inline play / pause / stop micro-controls. Rows of `breakType=ADDITIONAL` (no audio) do NOT render the controls. Icon style matches the existing main-controls icon family (Brief Q-4) — Delivery may reuse the same icon component, scaled down. **Inline pause / stop semantics:** clicking the inline-pause or inline-stop forwards to the global transport state (i.e. behaves equivalently to the main header-strip Pause / Stop button). Discovery does not introduce per-row paused-but-others-playing semantics; one engine, one transport state. Inline-play remains the row-specific "skip-to" action defined by AC3.
- [ ] **AC2 — Audio-activity indicator via inline-play colour saturation.** The inline play icon of a row is **bright green** when (a) audio playback is currently active for this row's audio category AND (b) `snapshot.playingIndex` equals this row's index. Otherwise the icon is **pale green** (a desaturated variant of the same green; visually inactive but available). Two states only — no animation / pulsing required (Brief Q-5). Delivery picks (i) the source of the (a)-signal (inferred from `snapshot.playingIndex` + entry-type combined with the existing engine fire/stop cadence, OR a thin public accessor added to the audio engine), and (ii) the specific pale and bright tones consistent with the existing button-enabled / button-disabled palette. The impl-report attests the chosen (a)-signal source.
- [ ] **AC3 — Manual time-shift via inline play "skip-to".** When the operator clicks the inline play icon of a row whose effective wall-clock time is in the future, the engine stays `PLAYING` (no transport-state change), and the schedule's wall-clock times shift so that THIS row's effective time becomes the current Hallenuhr-Now. Every subsequent row's effective time advances by the same delta `Δ = HallenuhrNow − row.originalEffective`. The shift uses the existing `timeOverrides` Map per E11S04 AC7 pattern. Currently-running audio of the previous row (if any) is NOT cancelled; it plays out naturally or is deactivated by the next event boundary (Brief Q-7).
- [ ] **AC4 — Manual time-shift documented WS-reload behaviour.** Consistent with E11S04 AC7: the operator's manual time-shift is wiped by a WS-driven `loadTimerDataSilent` (LAP_ADVANCED / PHASE_CHANGED). This Story does not change that behaviour and explicitly documents it for the operator. Persistent skip-to is OUT OF SCOPE.

### Ephemeral phase-config inline edit (Brief D-11 — B.4)

- [ ] **AC5 — Phase-config row above Round 1 of each phase.** For every phase in the schedule, a non-row config strip is inserted immediately above the first ROUND row of that phase. The strip exposes (a) `lapTimeMinutes`, (b) `lapBreakTimeMinutes`, (c) `sectionBreakTimeMinutes` (the per-phase Phase-Pause that follows this phase) as inline-editable numeric inputs (Brief Q-6). For the final phase, the `sectionBreakTimeMinutes` input is shown but its edits have no effect (or is hidden — Delivery's UX choice, impl-report attested).
- [ ] **AC6 — Intra-phase break inline-edit.** Each schedule row of type `BREAK` with `breakType=ADDITIONAL` (i.e. an intra-phase break per the existing E11S04 classification) becomes inline-editable: its duration becomes a numeric input; its optional `label` becomes a text input. (`sectionBreakTimeMinutes`-driven inter-phase breaks ALSO render as `ADDITIONAL` per E11S10 AC7; they are editable via AC5's phase-config strip, NOT via this AC6 row-level edit — Delivery's UX call: either visually distinguish the two ADDITIONAL-break sub-categories OR allow both edit paths to converge on the same underlying value.)
- [ ] **AC7 — Edits are ephemeral (no persistence).** Inline-edited values DO NOT trigger `DraftService.saveDraft` and DO NOT write to `tournament.draftJson`. They live in client-side state only. A full page reload (operator presses F5 / re-navigates) reverts to the backend-served schedule (= persisted `DraftConfig` values). This invariant is enforceable via source-inspection: no `saveDraft` call may appear in the edit-handler path.
- [ ] **AC8 — Schedule recomputes live on edit.** When an inline-edit value is committed (Delivery's UX choice: on blur, on Enter, or on debounced input — impl-report attested), the schedule table's wall-clock times update immediately to reflect the new values, and the countdown / next-event computation uses the new values. The operator-visible behaviour: type a new `lapTimeMinutes`, blur the field, see the schedule re-render. Delivery's architecture choice: **(a) FE-port the existing `DefaultDraftService.buildTimeline` Strategy-i logic into TypeScript** (Discovery recommends — parameter-free because operator edits don't change lap-count per phase; lap-count derivable from current schedule's MATCH_ROUND entries per phase), OR **(b) call a non-persisting backend endpoint** (e.g. `DraftService.preview` — note that this signature requires `participatingTeamCount`, `fieldCount`, `plannedStartTime` which are NOT present in `TimerData` today; Delivery would need to plumb these through `TimerDataResponse` or introduce a wrapper endpoint that derives them from `Tournament`). Discovery does NOT mandate the choice; AC asserts the behavioural outcome. The chosen path is impl-report attested with rationale.

### Error-handling (mandatory category)

- [ ] **AC9 — Invalid inline-edit input.** When the operator enters an invalid value (`lapTimeMinutes <= 0`, `lapBreakTimeMinutes < 0`, `sectionBreakTimeMinutes < 0`, or non-numeric input — matching `DraftSection` validation), a validation error renders inline near the offending input. The schedule does NOT recompute against invalid values; the previous-valid schedule remains until the operator either fixes the input or reverts the change (Delivery's UX choice on revert mechanism).
- [ ] **AC10 — WS-driven schedule reload during edit.** If a WS LAP_ADVANCED or PHASE_CHANGED arrives while the operator has open inline-edits, the existing `loadTimerDataSilent` reload (which resets `timeOverrides = new Map()` per `App.svelte:263`) ALSO resets any ephemeral phase-config-edit state — consistent with AC4's manual-time-shift semantic. The operator's in-flight edits are lost; the schedule re-renders against backend-served values. Operator-acceptable per Brief D-10 documented limitation (Q-7 carryover principle).
- [ ] **AC11 — Inline-trigger for a row in the past.** When the operator clicks the inline play of a row whose effective wall-clock time is ALREADY in the past (i.e. `row.effective <= HallenuhrNow`), Delivery picks one of: (a) skip-to-this-row still applies (effective becomes HallenuhrNow, all subsequent shift), OR (b) the click is a no-op (already past, nothing to skip), OR (c) the click rewinds (effective becomes HallenuhrNow, prior rows already-done state preserved). The chosen rule is impl-report attested. Discovery's preference is (a) — uniform skip-to-now semantic — but Delivery may pick a different rule with rationale.

## Notes

**Track:** `feature` — UX evolution. Operator-stated priority `MEDIUM` (Brief T-4). Sequenced after E11S10 + E11S11 (Brief E-10 resolution accepted by operator 2026-05-28).

**Ephemeral edit semantic (Brief D-11 + T-5 + operator clarification):** `saveDraft` is hard-blocked at `DefaultDraftService.java:463` for non-DRAFT tournaments (ConflictException, HTTP 409). Operator chose to sidestep this entirely via ephemeral FE-only override semantic. Future Story may revisit persistent edits with appropriate runtime-mutation safeguards.

**Recompute architecture (Brief T-6 / E-8 resolution):**
- *(a) FE-port (Discovery recommendation).* TypeScript port of `DefaultDraftService.buildTimeline` Strategy-i logic. Parameter-free because operator inline-edits do NOT change `lapCount` per phase — they change `lapTimeMinutes`, `lapBreakTimeMinutes`, `sectionBreakTimeMinutes`, `breaks` (duration + label). `lapCount` is derivable from the current backend-served schedule (count of `type=ROUND` entries per phaseNumber). Logic-duplication risk between Java `DefaultDraftService.buildTimeline` and TS port is acknowledged; the duplication scope is bounded.
- *(b) Backend non-persisting call.* `DraftService.preview(DraftConfig, int, int, LocalTime)` is a pure computation (no DB side-effect; line 249 of `DefaultDraftService.java`) and accepts any DraftConfig. BUT the signature requires `participatingTeamCount` + `fieldCount` + `plannedStartTime` — none present in `TimerData` today. Delivery would plumb these through `TimerDataResponse` (DTO extension) OR introduce a thin wrapper backend endpoint that derives them from `Tournament`. Plumbing cost surfaces an architecture decision.
- Discovery recommends (a) for the contained-scope reason; Delivery may pick (b) with rationale in impl-report.

**Audio-activity indicator (Brief Q-5):** two-state colour swap, no animation. Pale-green ≈ existing button-enabled-but-desaturated; bright-green ≈ saturated. Delivery picks the specific tones consistent with existing palette.

**Manual time-shift via inline play (Brief D-10 / Q-7):** existing E11S04 `timeOverrides` Map pattern; currently-running audio is NOT cancelled (plays out naturally); WS-reload wipes overrides per existing semantic.

**Past-row inline-click (AC11):** Discovery preference is "uniform skip-to-now"; Delivery may pick differently. Impl-report attests the choice.

**i18n convention (Brief C-5):** `de.json` + `$_('key')` per project frontend convention. **Do NOT cite DEC-52** (Memory `feedback_tm_i18n_pattern_not_dec52.md`). Numeric input labels ("Lap-Zeit", "Lap-Pause", "Phasen-Pause") use new i18n keys; literal German text not embedded in `.svelte` source.

**Test harness reality:** source-inspection only (`AppBranding.test.ts` precedent). The runtime-mount click-handler-observation case is not testable on the existing harness; ACs are enforced via source-inspection of the wiring (existence of the handler, the class-binding, the absence of `saveDraft` call, etc.).
