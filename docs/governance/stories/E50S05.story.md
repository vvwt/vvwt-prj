# Story: Display SPA Vertical-Fill Regression — CourtGrid Body Row-Distribution Defect (E50S04 follow-up)

## User Story

**As a** tournament operator and audience member viewing the public Display screen at venue,
**I want** the round-row grid for each court column to fill the available vertical space of the body area equally,
**so that** the screen real estate is used efficiently and round rows are large enough to be read from far away in the venue.

---

## Context

E50S04 (PR #254, merged 2026-05-10) introduced multi-round display (T3) + vertical-fill (T4) + active-round-highlight (T5) for the `/display/overview` SPA. T3 functions correctly — all rounds are visible per court column. T4 (vertical-fill) is **visually broken**: round-rows collapse to content-height instead of distributing the available `.court-grid__body` height equally, leaving large empty white space below the rendered rows (operator screenshot `Bildschirmfoto_2026-05-11_23-41-25.png`).

**Empirical root cause** (Brief O-5, verified against `CourtGrid.svelte:189–195`): the CSS chain stops distributing height at `.court-grid__body`. The body has `display: grid; grid-template-columns: repeat(var(--field-count), 1fr); flex: 1; overflow: hidden` but **no `grid-template-rows`** and no `grid-auto-rows` declaration. The implicit grid row defaults to `auto` (content-sized). Children `.court-grid__field-column` (which themselves declare `grid-template-rows: repeat(var(--lap-count, 1), 1fr)`) therefore do NOT receive a definite parent height, so their internal `1fr` distribution collapses to content-height.

The chain that IS definite up to the failure point:

```
body (100vh) → #app (100vh flex column) → .display-app (flex: 1)
  → OverviewLayout (height: 100%; grid rows: auto 1fr)
    → .overview-layout__main (in row 2: 1fr)
      → CourtGrid (height: 100%; flex column)
        → .court-grid__body (flex: 1) — DEFINITE up to here
          → .court-grid__field-column — UNBESTIMMT (no row-distribution from body)
```

**E50S04 false-PASS class** (Brief D-4): E50S04 introduced the AC `AC-TEST-VERTICAL-FILL-EQUAL-DISTRIBUTION-RED` and verified it via vitest+jsdom source-inspection — the test asserted the string `grid-template-rows: repeat(var(--lap-count, 1), 1fr)` is present in `CourtGrid.svelte`. The string IS present (on `.court-grid__field-column`), and the test passed, but the body-level row-distribution was missing — the test was structurally insufficient. `mvn verify` did not catch the visual regression because jsdom has no layout engine. This is the **E48S11 class** of false-PASS (DEC-54 gap for jsdom).

This story replaces the structurally-insufficient AC with a **structurally necessary-AND-sufficient** AC per Brief C-6: the test asserts the CSSOM-property whose absence is the chain defect (a row-distribution mechanism on `.court-grid__body`). The test MUST fail on the current production code and become GREEN only after a fix that materially closes the chain.

Out-of-scope for this story: the Active-Round-Highlight (T5) regression — that bug stems from `Phase.currentLapNumber` 0-based semantic divergence with DEC-60 1-based `Match.lapNumber` and is operationalized post-Epic-E55 per DEC-65 D-8. Post-E50S05 delivery, the screen will fill vertically but the active round remains visually unmarked until the post-E55 follow-up Bug-Triage Story ships. User-accepted per Brief D-1 split decision.

## Acceptance Criteria

### Testing (DEC-22 RED-first; DEC-54 mvn verify gate; vitest+jsdom)

- [ ] **AC-TEST-COURT-GRID-BODY-ROW-DISTRIBUTION-RED**: New vitest case in `CourtGrid.test.ts` (or equivalent) asserts via CSSOM/stylesheet inspection on the rendered `.court-grid__body` selector that the CSS rule declares a row-distribution mechanism that allows child `.court-grid__field-column` to receive a definite portion of the body's height. Acceptable forms (Delivery picks one — equivalence definition):
  - `grid-template-rows: 1fr` (or `repeat(N, 1fr)` for any N ≥ 1)
  - `grid-auto-rows: 1fr` (or non-`auto` non-`min-content` non-`max-content` row-size)
  - `display: flex` with `flex-direction: column` AND CSS rule on `.court-grid__field-column` declaring `flex: 1` (or equivalent flex-grow that consumes body height)
  - Any other declared mechanism that documentably distributes body height to child columns
  The test MUST fail on the current production code (`.court-grid__body` declares only `display: grid; grid-template-columns: ...; flex: 1; overflow: hidden` — none of the above row-distribution mechanisms). RED commit precedes GREEN commit in git log. The test verifies the structural property that is **necessary** (without it, the chain breaks) AND **sufficient** (with it, jsdom's CSSOM correctly carries the property even though jsdom cannot compute pixel layout).

- [ ] **AC-TEST-COURT-GRID-FIELD-COLUMN-1FR-PER-LAP-PRESERVED-GREEN**: Existing E50S04 source-inspection assertion on `.court-grid__field-column` (`grid-template-rows: repeat(var(--lap-count, 1), 1fr)`) remains GREEN after the fix — the field-column's internal 1fr distribution is preserved per E50S04 T4 contract. - **jsdom limitation**: per Brief C-6 + E50S03/E50S04 lessons-learned, vitest+jsdom CANNOT do bounding-box geometry; tests verify DOM structure (parentElement, closest, querySelector) and CSSOM/style-attribute properties (`style.gridTemplateRows`, `getComputedStyle` on jsdom supported subset, CSS rule presence on selector via `document.styleSheets` introspection), NOT pixel positions. - **Visual equivalence definition for AC-TEST-COURT-GRID-BODY-ROW-DISTRIBUTION-RED**: Delivery picks the row-distribution mechanism (grid-template-rows: 1fr, grid-auto-rows: 1fr, flex column with children flex: 1, or other). Discovery defines the WHAT (body distributes height to field-columns); Delivery defines the HOW.
- **DEC-44 cited in `related_decs`**: defensive inclusion — if Delivery introduces a web-module integration test (unlikely for this FE-only story but permissible), `@SpringBootTest(RANDOM_PORT, classes=TournamentManagerApplication.class)` is the canonical framework. - **Asymmetric-error preference** (Brief Q-1): if the row-distribution mechanism produces edge cases (e.g., zero laps), Delivery prefers the conservative behavior (empty render, no broken layout) over the maximalist behavior (force a phantom row).
