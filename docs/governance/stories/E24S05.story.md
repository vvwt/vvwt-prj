# Story E24S05: Q-1a TDD RED-first NEW `CertificateRenderController` at `de.vvwt.tm.web.certificate.*` covering SVG+HTML+ZIP+error paths (E23 scope-gap closure) + NEW `handleTournamentNotFound` method added to existing `GlobalExceptionHandler` (RED-first) + `templates/certificate/print*.mustache` new templates + SecurityConfig `/certificate/**` pattern

## User Story

**As a** maintainer of `vvwt-tm-web` closing the E23 scope-gap for
certificate HTML-rendering controllers under strict DEC-22 Iron Law,
**I want** a NEW `CertificateRenderController` at
`de.vvwt.tm.web.certificate.*` (TDD RED-first, 4 branches: SVG byte-response
+ HTML Mustache view + ZIP archive + error-400 plaintext — Path A fat-
controller per Brief v6 E-5), a NEW `handleTournamentNotFound` method
added to existing `tournament.internal.web.GlobalExceptionHandler`
(RED-first, covering web-tier TNFE for fresh S05/S06 controllers), fresh
Mustache templates at `templates/certificate/print*.mustache`, and
SecurityConfig `/certificate/**` pattern added atomic — with **no migration
of GlobalExceptionHandler** and **no consolidation of Photo/Cert advice
files** (both deferred to E34 retro-correction epic),
**so that** E23 scope-gap is closed with full functional parity and zero
Iron Law violations in E24.

- [ ] **AC-TNFE-HANDLER-ADD**: In existing file
  `vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/internal/web/GlobalExceptionHandler.java`
  ADD NEW method named `handleTournamentNotFound` (or implementer-chosen
  name; the name is internal — Spring routes by `@ExceptionHandler` type).
  **Behavioral contract** (NOT an implementation snippet — implementer
  drives shape RED-first from AC-REDFIRST-TNFE-HANDLER-TEST):
  - **Annotation**: `@ExceptionHandler(TournamentNotFoundException.class)`
    where the class FQN is `de.vvwt.tm.tournament.exceptions.TournamentNotFoundException`
    (S01 public exception). Imports updated accordingly.
  - **HTTP response status**: HTTP 404 (Not Found).
  - **Response body**: `ApiErrorResponse` JSON with the following field
    contract — matches existing handler-method patterns in this same
    class (e.g., `handleConflict`, `handleValidation`):
    - `status` = 404
    - `reason` = `HttpStatus.NOT_FOUND.getReasonPhrase()` (or equivalent
      "Not Found" string)
    - `message` = the exception's `getMessage()` value (which contains
      the tournament UUID per S01 message contract)
    - `errorKey` = `"error.tournament.notFound"` (i18n message-bundle key
      following the project's existing `error.{domain}.{condition}` pattern)
    - `path` = the request URI (from injected `HttpServletRequest`)
  - **Logging**: emit a debug-level log entry on entry, including the
    exception message; do NOT log at WARN/ERROR (this is an expected
    business-condition 404, not a system error).
  - **Method signature**: matches the existing handler-method convention
    in this class: `(TournamentNotFoundException, HttpServletRequest) →
    ResponseEntity<ApiErrorResponse>`.
  - **NO other modification** to `GlobalExceptionHandler` (basePackages
    UNCHANGED; class location UNCHANGED; existing handler methods
    UNCHANGED). The only diff is: 1 new import + 1 new method.
  All shape decisions beyond the above (variable names, formatter style,
  Builder vs constructor instantiation of ApiErrorResponse) are
  implementer's call, driven RED-first by the test in
  AC-REDFIRST-TNFE-HANDLER-TEST.
