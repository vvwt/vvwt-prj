# Story E21S17: Refactor — migrate cross-context consumers from legacy `TenantContext` bridge to `de.vvwt.tm.tenant::api`; clean dangling Javadoc; delete unused test helper

## User Story

**As a** reviewer of the Wave-2 Track-3 pre-cutover consolidation,
**I want** every survive-S13 consumer outside the tournament-context tree that currently depends on the legacy `de.vvwt.tm.domain.repo.TenantContext` bridge migrated to use `de.vvwt.tm.tenant.TenantContext`, plus all dangling `{@link}`/`{@code}` references to the bridge cleaned up, plus the no-longer-called `TenantContextTestHelper` test-only utility deleted,
**so that** after α (E21S16) and β (this story) complete, no consumer anywhere in `vvwt-tm-web` survives E21S13's bridge deletion with a broken reference, and E21S13 can proceed to its atomic cutover.

---

## Context

β is the second of the two-step pre-flight (α → β) that prepares the tree for E21S13's bridge deletion. α (E21S16) migrates the tournament-context tree. β handles everything else that survives the S13 cutover:

- Cross-context production code with code-level legacy-bridge usage — `infrastructure/web/WebSocketSecurityConfig.java`, `infrastructure/web/DeviceTokenHandshakeInterceptor.java` (WebSocket auth infrastructure — NOT tournament-scoped), `infrastructure/print/PrintController.java` (print context, one of the 6 DEC-32 consumer contexts but with code-level TenantContext use that DEC-32's (a) mechanical-rewrite scope does not cover).
- Dangling `{@link}`/`{@code}` references that will become build-breakers under DEC-29 `failOnWarning=true` once the bridge class is deleted. These live in a small number of production classes and one test-support class outside the tournament tree.
- Cross-context integration tests that reference the legacy bridge via `@Autowired`, `.set()/.clear()`, or the companion `TenantContextTestHelper` utility.
- The `TenantContextTestHelper` test-only utility itself, which loses its last caller once the associated IT is migrated and has no remaining reason to exist.

**Refactor-phase governance (same as α).** Per Session Brief v7 §O-1, the legacy bridge's `.getTenantId()` already delegates to `de.vvwt.tm.tenant.TenantContext.current()`. β is behavior-preserving refactor under DEC-22's Red-Green-Refactor "refactor as needed" clause (DEC-22 §Decision, line 89). Existing tests are the regression oracle; no new red-first tests per migrated file; characterization-test prohibition (DEC-22 line 95–98) not implicated because assertions in existing tests are unchanged.

**Structural scaffolding removal.** Unlike α (which is primarily method-rename + import-swap), β's two `infrastructure/web/*` targets (`WebSocketSecurityConfig`, `DeviceTokenHandshakeInterceptor`) carry parallel-phase scaffolding — legacy `TenantContext` fields + constructor parameters + pass-through wiring + `.set()/.clear()` call sites. β removes these entirely. Per Session Brief O-1/O-2, the scaffolding is redundant: the new `TenantContext.bind(…)` call already wraps the DB-lookup scope in `DeviceTokenHandshakeInterceptor` (the `try (Scope s = ctx.bind(tenantUuid))` construct around `deviceRepository.findByDeviceToken(…)`), and is the actual DB router post-E14S11. The legacy field in `WebSocketSecurityConfig` is pure pass-through storage.

**DEC-24 behavioral invariant preserved.** The WebSocket handshake's device-token resolution semantics (DEC-24 D2), admin Basic auth (DEC-24 D3), timer-client path (E11S05 D-7) are all preserved. β removes parallel-phase indirection; it does not change the authentication contract visible to clients. This is a security-adjacent change — the `security` category appears in `mandatory_ac_categories`.

## Notes

**Scope determined by grep, not Brief enumeration.** Session Brief v7 explicitly defers enumeration to Delivery (AC-GREP-BASELINE + AC-CLASSIFICATION-TABLE). Discovery-time enumeration was attempted in Brief v4 (FQN grep) and v5 (package-local sweep); both were found incomplete during review. Delivery-time grep against the actual tree at migration commit time is the authoritative inventory.

**Parallel-phase scaffolding in WebSocketSecurityConfig / DeviceTokenHandshakeInterceptor.** Both files hold legacy `TenantContext` fields + constructor parameters that are redundant given the new `TenantContext.bind()` is the actual DB router post-E14S11. Field removal + constructor-signature change is permissible under DEC-22's refactor phase (no behavior change; existing WebSocket auth ITs are the regression oracle). This is refactor, not new development.

**PrintController is in the DEC-32 consumer set already.** `infrastructure/print/PrintController.java` appears in E21S13's execution plan Step 2 "Consumer Files to Rewrite" list. DEC-32's scope covers `Device`/`DeviceRepository` (and other tournament types) FQN substitutions in PrintController at cutover. But DEC-32 condition (a) forbids method renames, so the `TenantContext.getTenantId()` → `.current()` rename in PrintController is β's job, NOT S13's. β handles the method-rename refactor; S13 handles the FQN substitution for Device-adjacent types. Both commits touch the same file; sequencing (β → S13) is straightforward because β precedes S13 per the dependency chain.

**DEC-26 applicability in β.** β touches WebSocket/display/print infrastructure primarily, not DAO-boundary tests. The DAO-IT three rules (DEC-26) apply only if a migrated test IS a DAO IT. For β's expected scope, no DAO IT is touched — α already migrated all tournament DAO ITs. But AC-STOP-ON-AMBIGUITY covers the edge case where an unexpected DAO IT surfaces in β's scope.

**DisplayOverviewControllerIT + TenantContextTestHelper disposition.** The earlier Brief v5 inventory noted `DisplayOverviewControllerIT` as the sole caller of `TenantContextTestHelper`. β migrates the IT to use `TenantContextTestSupport.Binder` (or direct `.bind()` scope if lifecycle requires) in a single atomic step, then deletes `TenantContextTestHelper.java`. If the grep reveals additional callers at baseline (unlikely per prior inspection, but possible), AC-DELETE-UNUSED requires migrating them all first, then deleting the helper.

**E21S13 amendment follows β.** After both α and β land, E21S13's scope amendment adds `WebSocketSecurityConfig.java` + `DeviceTokenHandshakeInterceptor.java` to its DEC-32 mechanical consumer set for `Device`/`DeviceRepository` FQN substitutions at cutover. The amendment is additive; no DEC-32 condition is relaxed.

**Review-simplicity ordering.** Session Brief §T-2: β depends on α for review simplicity, not technical necessity. Delivery is free to pipeline α and β if capacity allows, but each story reviews + closes before the next enters `in_progress`.
