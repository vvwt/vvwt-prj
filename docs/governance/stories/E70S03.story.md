# Story E70S03: Activate PMD Cyclomatic + Cognitive Complexity + Method/Class Size + Dead-Code rules in `mvn verify`

## User Story

**As an** operator + every Delivery agent,
**I want** Java methods that exceed complexity / size thresholds AND unused production code (private methods / fields / locals) to fail the build mechanically,
**so that** KISS-structural and YAGNI-code violations are caught at build time, surfaced as candidates for review per `clean-code.rules.md` §Application Discipline Clauses 3, 4.

---

## Context

DEC-78 classifies KISS-structural and YAGNI-code as hard-gated. Both are enforced via the same `maven-pmd-plugin` family configured in E70S01 for PMD CPD — this Story adds the rule-set for:

- **Cyclomatic Complexity** (PMD rule `CyclomaticComplexity` — Java built-in)
- **Cognitive Complexity** (PMD rule `CognitiveComplexity`)
- **Method Size** (PMD `NcssCount` / `ExcessiveMethodLength`)
- **Class Size** (PMD `NcssCount` / `ExcessiveClassLength`)
- **Dead Code** (PMD `UnusedFormalParameter`, `UnusedLocalVariable`, `UnusedAssignment`, `UnusedPrivateField`, `UnusedPrivateMethod`)

Per `clean-code.rules.md` §Application Discipline Clause 4 (KISS = clarity, NOT primitivity), complexity gate findings are **candidates for review**, not mandates to split. The mechanical gate trips; the developer / reviewer applies judgment per the Anti-Patterns Reference. The hard-gated classification means the gate FAILS the build on findings above threshold; the Wisdom-Frage does NOT downgrade hard-gated FAILs (per Clause 7 scoping, DEC-71 alignment). The downstream judgment is recorded via threshold tuning at activation time and via the suppression-baseline strategy at first-run.

**H-4 (DEC-78 §Hypotheses — UNVERIFIED, Delivery-time empirical):** Activating PMD Cyclomatic + Cognitive defaults (cyclomatic=10, cognitive=15) on vvwt-prj will produce ~M findings of unknown magnitude. vvwt-prj contains several legitimately-complex methods (slot-optimization algorithm internals per DEC-4 / DEC-49 / DEC-55 / DEC-64) that may exceed defaults. Baseline strategy at activation is suppress-with-tracking (DEC-78 Clause E); per-Story empirical observation is recorded in `impl-report.md` per AC6.

## Notes

**Rule selection rationale**: The five PMD rule families above are the conventional set for KISS-structural + YAGNI-code mechanical detection. PMD's catalogue contains many more rules; activating beyond this set risks false-FAIL flood — a separate scope, deferred. The Story may activate further PMD rules with explicit per-rule rationale in `impl-report.md` if the operator approves at story-time.

**Threshold tuning is the load-bearing decision**: vvwt-prj contains several legitimately-complex methods (slot-optimization algorithm internals per DEC-4 / DEC-49 / DEC-55 / DEC-64) that may exceed default cyclomatic thresholds. Threshold tuning + suppression baseline together ensure those known-complex sites do NOT block new development. The activation MUST NOT silently raise thresholds to "find zero pre-existing findings" — that would weaken the gate. Per `clean-code.rules.md` §Application Discipline Clause 4, complexity gates surface candidates for review; the suppression baseline absorbs known-legitimate complexity, and the gate fires on NEW violations.

**Anti-dogma — Wisdom-Frage NOT applicable**: KISS-structural is hard-gated. A hard-gated FAIL escalates per DEC-71; it does NOT downgrade via Reviewer-Wisdom-Frage. The legitimate path on a disputed hard-gated FAIL is: (i) tune threshold (with documented justification), (ii) add suppression baseline entry (with documented justification), or (iii) refactor — never silent override.

**Asymmetric-error preference**: Per DEC-47-F / DEC-71 — when in doubt on threshold, prefer stricter; suppression baseline absorbs noise without weakening detection of new violations.
