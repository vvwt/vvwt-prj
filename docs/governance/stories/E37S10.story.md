# Story E37S10: cache package — CacheController + CachedResult + CachedResultEntity + CachedResultId + CachedResultRepository + ResultsCacheService + CacheCorruptionException (Q-1a TDD RED-first against spec)

## User Story

**As a** Tournament Manager submitting an optimization job whose structural fingerprint matches a previously-completed job (community cache hit per DEC-9 § Impact "Cross-organizer cache works as designed"),
**I want** the dispatcher to short-circuit packet decomposition and return the cached result immediately,
**so that** community-wide compute amortization works as designed and repeated tournament structures don't re-pay the compute cost.

---

## Context

The cache package owns the cross-organizer structural-fingerprint result cache per DEC-9. It owns: CacheController (HTTP `GET /api/cache/{structuralFingerprint}` for direct cache lookups), CachedResult (DTO), CachedResultEntity (JDBC entity), CachedResultId (composite key on structural fingerprint + game-mode), CachedResultRepository, ResultsCacheService (cache write on first-accepted-result + cache read on submit-job short-circuit + on cache GET), CacheCorruptionException (raised when cache hit but stored payload fails canonical re-verification).

Per DEC-9 § Impact: structurally-identical tournaments from different organizers produce identical cache keys (lexicographic position-tuple sort + dense integer assignment + per-row sort + serialize + hash). The Brief does not introduce a new D-item for the cross-organizer cache value-prop — DEC-9 is the sole authoritative source.

This story is authored against E37S02 spec sections (a) shared, (b) dispatcher contract cache + structural-fingerprint algorithm. No legacy inspection.
