# Story E11S11: Timer SPA layout consolidation — main display in header, scrollable schedule with sticky header and auto-scroll-to-current-row

## User Story

**As a** tournament organizer using the Timer SPA on a venue screen,
**I want** the main timer display (round number, countdown, transport controls) to live in the page header next to the tournament name, the Hallenuhr-Now reading to sit compactly under the tournament name on the same header strip, and the schedule table below to scroll while the header stays visible — auto-scrolling smoothly to the current / next-upcoming row,
**so that** I can always see what is happening "right now" without losing the in-progress / next-upcoming row in a long schedule.

---

## Context

After E11S10 ships and the audio engine + timeline math behave correctly, the Timer SPA's information density is still suboptimal: the main display (countdown + transport controls) takes a full row above the schedule, the Hallenuhr-Now reading is at the right edge of the brand strip, and the schedule table grows unbounded — a 16-round, 2-phase tournament can produce ≥35 schedule rows that push the active row off the bottom of the screen, requiring manual scroll to see what is currently playing.

Operator-requested consolidation (Brief D-8, D-9):
- **Header row reorganisation:** tournament name (e.g. "31. Frühjahrsturnier") spans the left half of the header; the main display block (round indicator + countdown + visible countdown-label + transport controls) sits in the right half. A second row below the header (still part of the sticky strip) shows the Hallenuhr-Now reading under the tournament name on the left. The right half spans both rows visually so that `height(header row) + height(Hallenuhr row) = height(main display block)`.
- **Scrollable schedule with sticky header strip:** the schedule table sits in a scrollable container below the sticky header strip; the header strip stays visible during scroll.
- **Auto-scroll to current / next-upcoming row:** when `playingIndex` changes (WS LAP_ADVANCED, PHASE_CHANGED, or operator's local time-override per E11S04 AC7 / Story E11S12 AC3), the schedule table smoothly scrolls so the playing row is visible plus a small lookahead margin (the next-upcoming row is also visible).

Discovery Session Brief `discovery-2026-05-28-timer-post-e11s09-bugs-and-ux-evolution` (operator-validated 2026-05-28 after Tier-2 cycle-2 en-bloc resolution of 3 escalated findings; rubric_version 2026-03-30) drives the scope of this Story.

Visual identity (font, color palette, brand-lockup placement) preserved — this Story is reorganisation, not redesign (Brief Q-2).

## Acceptance Criteria

> All acceptance criteria are observable behaviour. Implementation approach (CSS grid vs flex, scroll mechanism) is Delivery's choice.

### Layout consolidation (Brief D-8)

- [ ] **AC1 — Tournament name renders in the header's left side.** The tournament's `description` value renders as a heading in the left portion of the page's sticky header strip, replacing the existing centred / above-controls placement. Font size and weight match (or are intentionally adjusted from) the existing tournament-name styling — visual identity preserved (Brief Q-2).
- [ ] **AC2 — Main display block renders in the header's right side.** The round-indicator (currentRound / totalRounds), the large countdown numerals, the visible countdown-label (per E11S09 AC6), and the transport controls (Play / Pause / Stop) render together as one cohesive block in the right portion of the sticky header strip. This block spans the full vertical height of the header strip (i.e. it spans BOTH the tournament-name row AND the Hallenuhr-Now row visually on the right).
- [ ] **AC3 — Hallenuhr-Now reading renders under the tournament name.** The Hallenuhr-Now display (introduced by E11S09 AC7) renders in a row beneath the tournament name in the left portion of the header strip. It continues to update at one-second resolution (E11S09 AC7 behaviour preserved). It is NOT relocated into the brand-lockup strip or elsewhere.
- [ ] **AC4 — Header strip height invariant.** The total vertical height of `(tournament-name row) + (Hallenuhr-Now row)` equals the height of the main display block on the right. The visual effect is a balanced two-column header strip without left/right vertical mismatch.

### Sticky header + scrollable schedule (Brief D-9)

- [ ] **AC5 — Header strip is sticky during schedule scroll.** When the schedule table is scrolled vertically, the header strip (tournament name + Hallenuhr-Now + main display block) remains visible at the top of the viewport. The brand-lockup strip's behaviour above the header (E44S02 / E59S03 carryover) is not affected by this Story.
- [ ] **AC6 — Schedule table renders inside a scrollable container.** When the schedule contains more rows than fit in the viewport below the sticky header, the schedule rows scroll within their container while the header strip stays fixed.
- [ ] **AC7 — Auto-scroll to playing row on `playingIndex` change.** When the engine's `snapshot.playingIndex` changes (driven by WS LAP_ADVANCED, PHASE_CHANGED, or local `timeOverrides` update), the schedule table smoothly scrolls so the playing row is positioned with a small lookahead margin (the next-upcoming row is also visible above the fold). The scroll is smooth, not snap (Brief Q-3).
- [ ] **AC8 — Auto-scroll does not interfere with operator manual scroll.** If the operator manually scrolls the schedule (e.g. to inspect an earlier round), the auto-scroll behaviour does not yank the view back instantly. Delivery picks the specific UX rule — e.g. (a) auto-scroll suppressed for N seconds after a manual scroll, OR (b) auto-scroll fires only when the playing row leaves the visible area. Either is acceptable; the chosen rule is impl-report attested.

### Error-handling (mandatory category)

- [ ] **AC9 — Empty-schedule case.** When the tournament has no schedule entries (e.g. `emptySchedule: true` per E11S02 / E26S01), the layout renders cleanly: header strip with tournament name + Hallenuhr-Now + main display block (countdown shows `--:--` or `00:00` per the existing E11S04 finished-state), and an empty / placeholder schedule area below. No layout collapse.
- [ ] **AC10 — Very-long-schedule case.** When the schedule contains many entries (e.g. ≥40 rows representing a multi-phase tournament with many rounds and breaks), the scroll container handles it without horizontal overflow, the sticky header remains stable, and auto-scroll-to-playing-row works for any row index.
- [ ] **AC11 — Narrow-viewport graceful degradation.** When the viewport width is too narrow for the two-column header layout (e.g. portrait mobile phone, Delivery picks the breakpoint), the layout degrades gracefully — the main display block may move below the tournament-name row, the Hallenuhr-Now may stack vertically, or another responsive strategy is applied. The schedule table remains usable. The exact responsive rule is impl-report attested.
