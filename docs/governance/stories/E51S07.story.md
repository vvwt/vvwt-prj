# Story E51S07: Operator-UI + Restart-Recovery + TournamentForm.optimize-checkbox + DEC-31 governance propagation

## User Story

**As a** Tournament Operator,
**I want** to see at a glance which phase is currently being optimized in the background, to be able to cancel an in-progress slot-optimization, to control whether slot-optimization runs at all (per-tournament checkbox), and to trust that a server restart does not lose my queued optimization work,
**so that** I have visibility into the upfront-pipeline, control to cancel if it's taking too long, the option to skip slot-opt for time-critical tournaments, and reliability across server restarts.

---

## Context

This is the closing story of E51 — wires the user-facing surfaces and the operational-resilience layer. Six sub-deliverables:

1. **`TournamentForm.svelte` checkbox** for `tournament.optimize` (DEC-55 D-5). Default `true`. Label DE: *"Slot-Optimierung berechnen"*; tooltip *"Langsamer für große Phasen, bessere Spielzeitausnutzung. Bei `aus` startet die Phase ohne berechnete Spielreihenfolge."*. The new field flows into the existing tournament-create / tournament-edit POST/PUT payload + Java service + entity + JDBC mapping.
2. **`PhaseList.svelte` per-phase status icon** showing `phase.last_job_state` (DEC-55 D-2 + D-9): spinner if `'match_gen_running'` or `'slot_opt_running'`; check-mark if `'idle'` AND `phase.optimized=true`; warning if `'cancelled'` or `'failed'`. Click on running spinner navigates to `SlotOptimization.svelte` for the corresponding tournament. The "Phase aktivieren" button is disabled with a tooltip when D-6 activation-guard fails (`tournament.optimize=true && phase.optimized=false`).
3. **`SlotOptimization.svelte` updated** (E27S02) to display `phase.last_job_state` + `bestSoFarVarietyScore` (existing) + Cancel button (existing). NO start button; NO manual re-trigger. Polling stays at 2 s cadence (E27S02 precedent unchanged). The route URL `/tournaments/:tournamentId/slot-optimization` remains; navigation to it is via the PhaseList icon-click (new).
4. **`JobQueueRecoveryService` `@EventListener(ApplicationReadyEvent.class)`** in tournament context (DEC-55 D-8). On Spring application-ready, scans `phase.last_job_state` and reconciles per the rules in DEC-55 D-8 (re-publish `MatchGenJobScheduledEvent` for stuck-in-PENDING-with-avatars-no-matches; re-publish `SlotOptJobScheduledEvent` for stuck-in-PREPARED-with-optimize-true-not-optimized).
5. **Status response shape extension**: existing `GET /api/slotopt/tournaments/{tournamentId}/status` response gains an explicit `lastJobState` field (matching `phase.last_job_state`). PhaseList GET endpoint response gains `jobStatus` per phase row. Backward-compatibility: existing fields untouched; new field is additive.
6. **DEC-31 governance-snapshot propagation** to `vvwt-prj/docs/governance/`: new DEC-55 file is propagated; updated DEC-49 file is re-snapshotted; all 7 stories E51S01–S07 + Epic E51 are propagated as point-in-time snapshots per E25S03/E26S04/E27S04 precedent (Cutover-pattern). Two-commit pattern per DEC-31 §(c): commit-1 = snapshot files; commit-2 = docs metadata if needed.
