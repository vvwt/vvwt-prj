# Story E21S09: Tournament domain events + boundary-API exceptions + AdminSpaController — reconstruction-in-place with TDD

## User Story

**As a** consumer of the `de.vvwt.tm.tournament::api` surface (WebSocket bridge, `GlobalExceptionHandler`, Admin SPA runtime),
**I want** the four cross-context domain events, the five boundary-API HTTP exceptions, and the Admin-SPA forwarder reconstructed at their final DEC-21 package coordinates with real-integration tests,
**so that** downstream contexts can publish/subscribe events against a stable `tournament::api` contract from day one and the Admin UI is served at its existing URL without regression.

---

## Context

Per Session Brief `discovery-2026-04-20-e21-full-refinement` D-8, the `tournament` reconstruction bifurcates into public API at `de.vvwt.tm.tournament.*` (consumable by other contexts) and implementation at `de.vvwt.tm.tournament.internal.*` (hidden). This story authors the **ten boundary-adjacent classes** whose contracts are consumed from OUTSIDE the tournament context and therefore must land at the public root:

1. **Four Spring `ApplicationEvent`s** at `de.vvwt.tm.tournament.events.*` — published by tournament-core services and consumed cross-context by `DomainEventBridge` (S10) and potentially by `scoring`/`display`/`timer` reconstruction: `DeviceRegisteredEvent`, `LapAdvancedEvent`, `MatchResultChangedEvent`, `PhaseStatusChangedEvent`.
2. **Five boundary-API exceptions** at `de.vvwt.tm.tournament.exceptions.*` — thrown across context boundaries and mapped to HTTP responses by `GlobalExceptionHandler` (S10): `ForbiddenException` (403), `TooManyRequestsException` (429), `UnauthorizedException` (401), `ValidationException` (400), `ConflictException` (409). Per inventory lines 418+ (`ConflictException` cross-context).
3. **AdminSpaController** at `de.vvwt.tm.tournament.*` — static-resource forwarder serving the Svelte Admin SPA at `/admin/**` (inventory line 353, `tournament-core` classification). Placed at the public root because it is the externally-addressable tournament-UI entry point; no internal subpackage is appropriate for a top-level HTTP-path controller consumed by browsers.

Per DEC-22, every class is test-first (failing test committed before implementation). Per DEC-29/DEC-30 (boundary-API discipline), public-package classes are tested via real Spring integration (`@SpringBootTest` for event publication; `MockMvc`-slice for the controller) — not mocked.

`AdminSpaController` is a static-resource forwarder, NOT a CRUD controller — the E20 Controller-TDD methodology (DEC-29) applies in its **integration-test form**: an `@SpringBootTest` / `MockMvc` test verifying HTTP 200 on `/admin/` and appropriate behaviour on missing paths. A slice test (`@WebMvcTest`) is OPTIONAL and not required to satisfy DEC-29 for a static-forwarder (Session Brief C-13 scope — CRUD methodology does not govern static forwarders verbatim).

Legacy `de.vvwt.tm.infrastructure.AdminSpaController` and legacy exception/event types remain live at their original coordinates until the atomic cutover story; this story adds the new types alongside.

## Acceptance Criteria

> Every AC below is testable by a command, a file-path check, or a pattern match. Vague criteria are invalid.

### Testing ACs (mandatory category: `testing`)

- [ ] **AC-TDD-DeviceRegisteredEvent** / **AC-TDD-LapAdvancedEvent** / **AC-TDD-MatchResultChangedEvent** / **AC-TDD-PhaseStatusChangedEvent**: for each event, git history shows a failing test authored BEFORE the event class (red-then-green per DEC-22). Each test publishes the event via `ApplicationEventPublisher` in a `@SpringBootTest` context and asserts a registered `@EventListener` receives it with preserved payload fields. Characterization tests against the legacy event types are forbidden.

- [ ] **AC-TDD-ForbiddenException** / **AC-TDD-TooManyRequestsException** / **AC-TDD-UnauthorizedException** / **AC-TDD-ValidationException** / **AC-TDD-ConflictException**: for each exception, a failing JUnit test (pure — no Spring) is committed BEFORE the class. Tests verify: (a) extends `RuntimeException` (unchecked), (b) message preservation via typed constructors, (c) `Throwable cause` chaining preserved, (d) class hierarchy (direct parent is `RuntimeException`, not a checked sibling).

- [ ] **AC-TDD-AdminSpaController**: a failing integration test (`@SpringBootTest` with `MockMvc`) is committed BEFORE the controller. The test asserts HTTP 200 + `Content-Type: text/html` for `GET /admin/` and returns 404 for `GET /admin/nonexistent.file.html` (OR whatever SPA-fallback behaviour the implementation chooses; either behaviour is acceptable but MUST be documented in the class Javadoc AND asserted by the test). Delivery chooses and documents.

- [ ] **AC-SPRING-EVENT-CONTRACT**: all four events extend `org.springframework.context.ApplicationEvent`. A `@SpringBootTest` publishes each event, and an in-test `@EventListener`-annotated bean captures and asserts payload integrity. Event contract is verified end-to-end via Spring's publisher — no unit-test `new Event(...).getXxx()` substitution.

### Error-handling ACs (mandatory category: `error-handling`)

- [ ] **AC-EXCEPTION-CONTRACT**: each of the five exceptions provides at minimum: `Exception(String message)` and `Exception(String message, Throwable cause)` constructors. Tests verify `getMessage()` and `getCause()` pass-through. No checked exceptions. A test attempting to compile a `throws ForbiddenException` declaration without `throws` succeeds (unchecked) — verified by the test passing compilation.

- [ ] **AC-EVENT-NULL-GUARD**: each event constructor rejects `null` for its `source` (Spring `ApplicationEvent` contract) with the built-in `IllegalArgumentException` — test asserts this standard Spring behaviour is preserved (no silencing in subclass constructors).

- [ ] **AC-SPA-404**: `AdminSpaController` handling of a nonexistent `/admin/**` path returns HTTP 404 (or the SPA-fallback 200+index behaviour — whichever is chosen, Javadoc and test must agree); does NOT surface a cryptic `ResourceNotFoundException` stack trace; `MockMvc` test asserts the response body is either the SPA index.html OR an `ApiErrorResponse` (S10) — never a raw stack trace.

### Security ACs (mandatory category: `security`)

- [ ] **AC-SEC-NO-AUTH-BYPASS**: the `/admin/**` route under `AdminSpaController` does NOT introduce a Spring Security bypass. Integration test asserts `GET /admin/` without credentials returns 401 (or the appropriate redirect to login) under the production `SecurityConfig` profile — the controller MUST NOT be `@PermitAll`-annotated or otherwise weaken the existing filter chain. If the legacy `AdminSpaController` was already public, document this explicitly and preserve the legacy behaviour — never silently tighten OR silently loosen.

- [ ] **AC-SEC-EXCEPTION-NO-LEAK**: the five exception classes do not carry sensitive payloads by contract; their Javadoc states they MUST NOT embed credentials, session tokens, or raw SQL. A grep-based test (or a static-check) confirms no exception constructor signature accepts a `char[] password`, `String token`, or `ResultSet` parameter.

### Governance ACs (mandatory category: `governance`)

- [ ] **AC-PKG-DeviceRegisteredEvent** / **AC-PKG-LapAdvancedEvent** / **AC-PKG-MatchResultChangedEvent** / **AC-PKG-PhaseStatusChangedEvent**: each event file is at `vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/events/<ClassName>.java` (public boundary-API per D-8). NOT at `.tournament.internal.events.*`. Verified by `test -f` on each path.

- [ ] **AC-PKG-ForbiddenException** / **AC-PKG-TooManyRequestsException** / **AC-PKG-UnauthorizedException** / **AC-PKG-ValidationException** / **AC-PKG-ConflictException**: each exception file is at `vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/exceptions/<ClassName>.java` (public boundary-API per D-8). NOT at `.tournament.internal.exceptions.*`.

- [ ] **AC-PKG-AdminSpaController**: file is at `vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/AdminSpaController.java` (public root per D-8 and D-2 — boundary-addressable URL entry point).

- [ ] **AC-NO-LEGACY-TOUCH**: `git diff --name-only origin/staging..HEAD -- 'vvwt-prj/vvwt-tm-web/src/main/java/de/vvwt/tm/infrastructure/**' 'vvwt-prj/vvwt-tm-web/src/main/java/de/vvwt/tm/domain/**'` returns zero lines. Legacy `de.vvwt.tm.infrastructure.AdminSpaController`, `de.vvwt.tm.infrastructure.web.ConflictException`, and any legacy event types at `de.vvwt.tm.domain.event.*` remain untouched; atomic cutover handles removal in a later story.

- [ ] **AC-GOV-DEC-REFS**: impl-report references DEC-21 (package split), DEC-22 (TDD), DEC-29 (boundary-API discipline), DEC-30 (public vs internal test discipline) and explains how each was satisfied.

- [ ] **AC-INVENTORY-CITATION**: the impl-report cites the inventory rows (`E21-tournament-legacy-inventory.md` lines 353, 418+, and the four `domain/event/*` rows) that scoped the ten classes authored here. A class authored here without a matching inventory row is a failed AC.

- [ ] **AC-Q7-SAFETY-VALVE**: if during Delivery the scope materially expands beyond these ten classes (e.g., a fifth ApplicationEvent surfaces via grep, or an additional exception type is discovered cross-context), Delivery STOPS and escalates per Session Brief Q-7 rather than silently expanding the story. A partial delivery accompanied by an explicit scope-split escalation is a valid PASS; a silent scope creep is a FAIL.

## Notes

**For the Delivery Agent.**

- The ten classes split naturally into three commit groups: (1) events with `@SpringBootTest` event-capture tests, (2) exceptions with pure-JUnit tests, (3) controller with `MockMvc` integration test. Within each group, strict red-then-green per DEC-22.
- The events are SIMPLE value-carrying `ApplicationEvent` subclasses; resist the urge to add domain logic. Payload fields match the legacy event types 1:1 unless a deliberate refinement is planned AND documented in impl-report with rationale.
- For AdminSpaController: the legacy controller (inventory line 353) is likely a ~15-line class forwarding `/admin/**` to `classpath:/static/admin/index.html`. Read the legacy source before authoring the test to confirm forwarding semantics — but do NOT copy-paste; re-author under TDD.
- Session-management / auth behaviour of `/admin/**` MUST match legacy exactly. If the legacy is public (no auth), preserve that and flag it. If the legacy is auth-gated, preserve the gating. Deviation requires escalation, not silent change.

**Scope-split hint (Q-7).** Ten classes is already near the upper end of a single Delivery session. If fatigue or context bloat appears, the natural split is: S09a = events (4 classes), S09b = exceptions (5 classes), S09c = AdminSpaController (1 class). Flag early — the cost of escalating is far lower than the cost of a rushed merge.
