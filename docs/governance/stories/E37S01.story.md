# Story E37S01: Slot-Opt naming convention DEC (D-6b) + vvwt-worker-lib rename + legacy vvwt-dispatcher parent-POM exclusion (atomic mechanical FQN-rewrite)

## User Story

**As a** maintainer of the vvwt-prj slot-optimization service preparing for E37 dispatcher reconstruction,
**I want** the new `vvwt-slotopt-*` artifactId + `de.vvwt.slotopt.*` package naming convention authored as a fresh DEC (D-6b), the vvwt-worker-lib module mechanically renamed to vvwt-slotopt-worker-lib (artifactId + directory + Java packages), all consumer imports rewritten in the same atomic commit, AND the legacy vvwt-dispatcher module excluded from the parent POM,
**so that** every subsequent E37 story authors against renamed FQNs only (no mixed-naming imports), the legacy dispatcher is mechanically isolated from the new module's compile/test classpath (no false-positive RED-test risk per Brief T-8), and the convention is established for forward-looking slot-opt service module migrations.

---

## Context

Per Brief D-6b: the new naming convention `vvwt-slotopt-*` (artifactId) + `de.vvwt.slotopt.*` (Java package root) is authored as a separate DEC from D-6 (algorithm-agility). D-6b includes a self-authorization clause for mechanical FQN-rewrite operations applying the convention to existing modules; conditions analogous to DEC-32 (no behavior change; atomic commit; qa-review verifies rename-only diff). DEC-32 itself is NOT amended.

Per Brief D-7 + T-8: Coexistence Option γ (delete-then-rebuild) was REJECTED based on empirical Delivery-track-record from past Epics. Option δ-c (Maven-module-level mechanical isolation) is chosen instead. Legacy `vvwt-dispatcher` is excluded from the parent POM in this same atomic commit; physical directory remains on filesystem (untouched) until E37S11 cleanup.

worker-lib is consumed by FOUR modules in the reactor (verified via pom.xml + import-grep at session-start): vvwt-dispatcher (legacy, excluded in this commit), vvwt-benchmark, vvwt-standalone-worker, vvwt-tm-web. All non-legacy consumers receive mechanical import-rewrites (`de.vvwt.worker.*` → `de.vvwt.slotopt.worker.*`) in the same atomic commit.

This story is a hard prerequisite for E37S03+ (which reference renamed FQNs). E37S02 (spec extraction) can run in parallel — it only references E01 stories + DECs + planung; it does not import worker-lib types directly.
