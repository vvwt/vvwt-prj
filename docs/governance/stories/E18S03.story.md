# Story E18S03: Fix three Vite SPAs blank on load — `ReferenceError: global is not defined` from sockjs-client bundle (Vite global→globalThis shim)

## User Story

**As an** organizer (admin SPA), display device user (display SPA), or timer operator (timer SPA),
**I want** each `vvwt-tm-web` SPA to render its first screen on a clean app start,
**so that** I can use the application instead of seeing a blank page with a `ReferenceError: global is not defined` in the browser console.

---

## Context

Bug report (verbatim, DE): "Nach dem Starten von vvwt-tm-web zeigt mir die Admin-Seite nur eine leere Seite. In der Console wird folgender Fehler angezeigt: ReferenceError: global is not defined".

Discovery 2026-05-04 reproduced the symptom empirically on all three SPAs: `/admin/`, `/display/register`, and `/timer/tournaments/<any-uuid>` each render a blank `<div id="app">` with the same `ReferenceError: global is not defined` in the browser console. The error fires at module-evaluation time, before `mount()` runs — no UI is rendered, no API call is made.

Root cause (verified on disk):

1. All three SPAs have a static top-level import of `sockjs-client` on a path that is reachable from the entry module:
   - admin: `src/main/ui/src/App.svelte` imports `routes/Devices.svelte:27` which does `import SockJS from 'sockjs-client'`.
   - timer: `src/main/ui-timer/src/App.svelte` imports `lib/timerWs.ts:31` which does the same.
   - display: `src/main/ui-display/src/App.svelte` imports `lib/websocket.ts:27` which does the same.
2. `sockjs-client@1.6.1` references the Node.js builtin `global` at module-evaluation time. The built admin bundle (`src/main/ui/dist/assets/index-BfrRnMkA.js`) contains many direct `global.*` references (`typeof global`, `global.WebSocket`, `global.XMLHttpRequest`, `global.document`, `global._sockjs_onload`, `global.crypto`, etc.). `global` is unbound in browsers.
3. Vite ≥ 5 (the project uses `vite ^8.0.8`) does not auto-shim `global`. None of the three `vite.config.ts` files (`ui`, `ui-timer`, `ui-display`) declare a `define: { global: ... }` entry — the configs are otherwise structurally identical.
4. Server-side `de.vvwt.tm.tournament.internal.web.WebSocketConfig:55` registers `/ws` with `.withSockJS()`. The SockJS transport is load-bearing on the server side and is preserved by this story.

Per DEC-22 (TDD Iron Law): the surface of this fix is build configuration (`vite.config.ts`), not application logic. A RED-first Vitest on production code is structurally inapplicable. The acceptable RED-first form for this Story is a build-output assertion (or equivalent headless module-evaluation check) that fails on the unfixed build and passes on the fixed build — Delivery picks the form. The Brief is the oracle: "blank page + `ReferenceError: global is not defined`" is the failure mode the regression test must encode.

This Story is housed under E18 (Code Hygiene Enforcement) per the human's parent-Epic decision on 2026-05-04. E18's literal scope (DEC-29/DEC-30 Java compiler+formatter hygiene) is extended de facto to frontend build hygiene by this Story — analogous to how E16S03 extended E16's DAO-IT scope to test-config mode without a DEC amendment. No DEC amendment is requested by this Story.

## Acceptance Criteria

- [ ] **AC1 (testing — reproduction Given/When/Then):** A reproduction scenario is documented in the impl-report or QA report covering all three SPAs:
  - **Given** `vvwt-tm-web` is started against a clean H2 + freshly installed Vite dist (no service worker cache),
  - **When** the user opens any of `http://<host>:<port>/admin/`, `http://<host>:<port>/display/register`, `http://<host>:<port>/timer/tournaments/00000000-0000-0000-0000-000000000000` in a recent Chromium- or Firefox-based browser,
  - **Then** before the fix the page is blank and the browser console shows `ReferenceError: global is not defined`; after the fix none of the three URLs surfaces a `ReferenceError: global is not defined` in the browser console, and each SPA's root component is mounted (the admin SPA shows the brand header + router shell; the display SPA shows the registration page; the timer SPA progresses to the clock-sync dialog or to its `invalid-url` branch — neither is a blank page).

- [ ] **AC2 (build — Vite shim added in all three configs):** A `define` entry that maps `global` to a browser-valid identity is added inside the `defineConfig({...})` block of each of the three files, exactly:
  - `vvwt-tm-web/src/main/ui/vite.config.ts`
  - `vvwt-tm-web/src/main/ui-timer/vite.config.ts`
  - `vvwt-tm-web/src/main/ui-display/vite.config.ts`

  No other Vite-config-level keys are introduced or removed. No new top-level dependencies are added to any of the three `package.json` files (the shim is a built-in Vite mechanism). The entry mechanism (e.g., `define: { global: 'globalThis' }`) is Delivery's choice as long as it satisfies AC1, AC4, and AC6 and does not introduce CDN-loaded code per DEC-16.

- [ ] **AC3 (governance — symmetric form):** The `define` entry has the IDENTICAL form (same key, same value, same position relative to neighbouring keys) in all three `vite.config.ts` files. A single mechanical diff that produces three structurally identical hunks is the expected shape. Asymmetry across the three files fails this AC.

- [ ] **AC4 (governance — explanatory comment):** Each modified `vite.config.ts` has a short comment immediately above or alongside the `define` entry that explains WHY the shim exists — minimally: that `sockjs-client` references the Node.js builtin `global` at module-evaluation time, and that Vite no longer auto-shims it, so removing this entry will re-break all three SPAs. The comment must be present in all three files.

- [ ] **AC5 (testing — RED-first regression test per DEC-22):** A regression test exists that fails on the unfixed build and passes on the fixed build. The test encodes the failure mode "loading the entry bundle in a browser-like environment throws `ReferenceError: global is not defined`". Acceptable forms (Delivery's choice):
  - a Vitest under `src/main/ui*/src/` that loads or evaluates the built entry bundle in a `jsdom` environment and asserts no `ReferenceError`; or
  - a build-output assertion that the produced bundle does not contain bare `global` identifier references unguarded by a `define` substitution; or
  - any equivalent automated check that demonstrably FAILED before the shim was introduced and PASSES after.

  Evidence in the impl-report: a transcript showing the test FAILing with the unfixed `vite.config.ts`, then PASSing after the shim is restored. The test covers at least one of the three SPAs; a single test over one bundle is sufficient because the symmetry constraint (AC3) reduces the failure modes to one root cause for all three.

- [ ] **AC6 (testing — existing test suite green per DEC-22):** All existing tests across `vvwt-tm-web` Java modules and the three Vite SPAs (`vitest run` per SPA, `mvn verify` for the Maven build) remain green on a fresh checkout of `staging` after merge. No test is removed or weakened. If a pre-existing flake surfaces, it is documented in the impl-report and explicitly out-of-scope; only NEW failures attributable to this fix block this AC.

- [ ] **AC7 (governance — server-side WebSocketConfig untouched):** The diff between `staging` pre- and post-merge introduces no changes to `vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/internal/web/WebSocketConfig.java`. In particular, `.withSockJS()` on `/ws` is preserved verbatim. The fix is client-side build configuration only.

- [ ] **AC8 (governance — no out-of-scope drift):** The diff between `staging` pre- and post-merge does NOT:
  - remove the `sockjs-client` dependency from any `package.json`,
  - bump the `sockjs-client` or `vite` version in any `package.json`,
  - convert any of the three `import SockJS from 'sockjs-client'` static imports into a dynamic `await import(...)` form,
  - introduce a polyfill for any other Node builtin (`process`, `Buffer`, `__dirname`, `__filename`).

  If during Delivery a separate `ReferenceError` for one of those identifiers surfaces, Delivery escalates to Discovery rather than expanding scope inline.

## Out of Scope

- Removing the `sockjs-client` dependency or migrating any of the three SPAs to native `WebSocket`. (Larger blast radius — server-side `withSockJS()` would also need to change, plus a DEC-16 re-evaluation under the self-host LAN posture. Tracked as a possible separate Discovery; not this Story.)
- Converting the three static `import SockJS from 'sockjs-client'` imports into dynamic / lazy imports. (Symptom displacement, not a root-cause fix; would leave the same failure mode latent for the next contributor who static-imports a Node-tied module.)
- Polyfilling other Node builtins (`process`, `Buffer`, `__dirname`, `__filename`). (Out of scope per S-6; if surfaced empirically during Delivery, escalate to Discovery.)
- Bumping the `vite` or `sockjs-client` version in any `package.json`. (Version-bump risk separate from this fix.)
- Modifying `vvwt-info-client/src/main/ui/vite.config.ts` (the public Info Portal SPA — not part of the user-reported symptom and not verified to depend on `sockjs-client`; out of scope for this bug-triage).
- Changes to `WebSocketConfig.java` server-side, `WebSocketSecurityConfig.java`, or any other Java module.
- Any DEC amendment. E18's parent-Epic scope is extended de facto by this Story; if a future Story formalizes a "Frontend Build Hygiene" line of work, a DEC amendment may be appropriate at that point.

## Notes

- **Empirical evidence collected during Discovery (2026-05-04):**
  - Admin bundle `src/main/ui/dist/assets/index-BfrRnMkA.js` contains many direct `global.*` references (the reviewer counted 62 occurrences during Tier-2 review). The exact count is informational; the existence of any unguarded `global.*` reference in a browser-loaded bundle is sufficient to reproduce the symptom.
  - `WebSocketConfig.java:55` `registry.addEndpoint("/ws").setAllowedOriginPatterns("*").withSockJS()` — confirms server-side SockJS dependence.
  - `package.json` for all three SPAs lists `"sockjs-client": "^1.6.1"`; all three `vite.config.ts` files lack any `define` block.
  - User-confirmed empirical symptom on all three URLs (admin, display/register, timer/tournaments/<fake-uuid>) on 2026-05-04.

- **DEC-22 form rationale (build-config TDD):** The Iron Law expects a RED-first test on TDD-authored code. This Story authors no production code — it modifies build configuration. The regression test must therefore act on the build OUTPUT (the bundle) or on the build's runtime behaviour (jsdom evaluation), not on the build configuration itself. AC5 codifies this form choice. See user-memory entry `feedback_dec22_refactor_phase_first.md` for the broader "legacy code/tests are not a trustworthy oracle" framing — here the oracle is the empirical browser failure, encoded by the regression test.

- **Single-Story-three-SPAs rationale:** identical root cause + identical fix shape + identical regression risk → atomic delivery + single regression-test contract. Three independent Stories would add bureaucratic overhead without quality gain (Brief T-2). The symmetry AC (AC3) is the structural guarantee that the three sub-fixes stay coupled.

- **Reviewer informational notes (Brief Tier-2):** `WebSocketConfig.java`'s javadoc references a "legacy `de.vvwt.tm.infrastructure.web.WebSocketConfig`" that no longer exists on disk. Out of scope for this bug-triage; flagged for a future cross-cutting Discovery.
