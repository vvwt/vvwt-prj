# Story E21S08: Match-generation strategies + Referee assignment + PhasePreparationService — CRITICAL-PATH-CONVERGENCE (reconstruction-in-place with TDD)

## User Story

**As a** tournament operator preparing a Phase for play (match pairings + referee assignment),
**I want** the match-generation SPI (`MatchGenerator` interface + `MatchGeneratorRegistry` + `RoundRobinMatchGenerator` concrete strategy), the referee-assignment subsystem (`RefereeAssigner` + `RefereeAssignmentReport` + `RefereePreferenceConfig`), and the orchestrating `PhasePreparationService` reconstructed under `de.vvwt.tm.tournament.*` with DEC-22 TDD,
**so that** Phase preparation is a clean orchestrated operation over tested match-generation + referee collaborators, the `MatchGeneratorRegistry` boundary-API is stable (REST-exposed via S02's `TournamentRulesController`), and the critical-path convergence of the tournament domain is anchored before cross-cutting stories (S11 timeline, S12 `@ApplicationModule`).

## Notes

**Critical-path-convergence (O-8).** This is the single most structurally-fragile story in E21. `PhasePreparationService` could not live in S03 (per the original plan) because three of its four collaborators (generators + referees + match-persistence) did not yet exist. Moving it to S08 at the convergence point is the correct DAG topology — but it concentrates risk. Mitigations baked into the ACs: AC-ORCHESTRATION-CONVERGENCE forces a convergence check in the test; the daemon-side four-upstream ready-gate prevents premature start.

**RoundRobinMatchGenerator fairness (AC-FAIRNESS-PROPERTY).** The algorithm must produce a round-robin schedule for N teams — N\*(N−1)/2 matches, each team playing N−1 matches. A property-based test (jqwik preferred) with a sweep over N ∈ [2, 16] is the right shape; a hand-rolled single-N enumeration misses odd-N edge cases (N=3 has rest-slots; N=5 exercises the pairing-rotation algorithm). Reference inventory row 258.

**MatchGeneratorRegistry as boundary-API.** The registry is public surface (root package `de.vvwt.tm.tournament.MatchGeneratorRegistry`). The `TournamentRulesController` in S02 consumes the registry to expose available generator strategies over REST — changes to the registry's method signatures are cross-context-visible and must be treated as API changes. If Delivery finds an S02 test fail against the new registry signature, re-align the signature BEFORE green.

**RefereePreferenceConfig parsing.** Per inventory row 278, the config is parsed from a match-JSON blob. The parsing logic is domain behaviour — test it with representative legacy JSON fixtures (copy from legacy test resources or legacy `@Sql` seeds). Do NOT characterise against legacy bytes (DEC-22); extract the behavioural contract (what inputs produce what configs) and test against that.

**Why this is the convergence gate.** Every tournament Phase preparation goes through `PhasePreparationService`. If this service is incorrect, every downstream feature (timeline, scoring kickoff, display updates) is built on sand. AC-TDD-PhasePreparationService is the most consequential single AC in E21 — do not cut corners.
