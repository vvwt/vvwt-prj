# Story: An ephemeral per-print override for the organizer and venue at certificate generation

## User Story

**As a** tournament organizer generating certificates,
**I want** to adjust the organizer and the venue shown on the certificates just
for this print,
**so that** the printed awards show the correct names even for a tournament I
can no longer edit.

---

## Context

When the operator generates certificates, they have no way to influence two of
the values printed on the certificate:

- the **organizer** subtitle — from `tournament.organizer`;
- the **venue** line in the footer — from the location's stored label
  `locations.display_name`, resolved live at render time (currently the
  bootstrap literal *"Default Location"*).

A completed tournament cannot be edited — the tournament form is reachable for
DRAFT tournaments only — so for an already-finished tournament the operator
cannot correct a wrong organizer or venue at all. Even the organizer field on
the tournament form (story E68S01) only helps while the tournament is still
DRAFT.

This story adds an **ephemeral override** at the certificate-generation screen:
the operator can adjust the organizer and the venue for the current print run.
The override is never persisted — it changes no stored data — consistent with
the operator's decision that the certificate-time override is a print-time
correction, not a saved setting.

A field the operator does not change is **not** an override: the certificate
then shows exactly today's value, resolved the same way (and the venue stays a
live read at render time). The override never produces an empty certificate
line — a printed award always shows a real organizer and venue (Brief Q-1).

Persistent editing of the stored venue label is out of scope and deferred:
location management as a whole is not yet implemented in the application. Until
it is, this override is the only way to put a real venue name on a certificate.

## Acceptance Criteria

- [ ] **AC1 [override fields]:** The certificate-generation screen presents,
  before the certificate is generated, two editable fields — **organizer** and
  **venue** — each pre-filled with the value that would otherwise appear on the
  certificate: the organizer pre-filled from the tournament's stored
  `organizer`, the venue pre-filled from the location label the certificate
  resolves today.
- [ ] **AC2 [override applied]:** When the operator changes the organizer
  and/or venue field to a new value and generates the certificate(s), the
  generated certificate shows the changed organizer as the subtitle and/or the
  changed venue in the footer line.
- [ ] **AC3 [both certificate documents]:** The override applies equally to the
  single-team certificate and to the all-teams certificate document — both
  honour the supplied override values.
- [ ] **AC4 [ephemeral — nothing persisted]:** A certificate generation that
  uses an override issues no `INSERT` or `UPDATE` to the database. After such a
  generation, `tournament.organizer` and the location's stored `display_name`
  are unchanged. Re-opening the certificate-generation screen afterwards shows
  the original pre-filled values again, not the previously-entered override.
- [ ] **AC5 [no override — today's output, unchanged]:** Generating without
  supplying an override produces exactly today's certificate output. A field
  counts as "overridden" only when the operator supplies a value that differs
  from the current resolved value; a field left at its pre-filled value is not
  an override. For a non-overridden field the certificate resolves it exactly
  as today: the organizer from `tournament.organizer`, and the venue from
  `locations.display_name` resolved **live at render time** — the venue is
  never frozen to a value captured when the certificate screen was opened.
- [ ] **AC6 [error-handling]:** A blank or whitespace-only override field is
  treated as "no override" — the corresponding certificate line falls back to
  the default resolved value of AC5 (organizer from `tournament.organizer`,
  venue from the live `locations.display_name`). The override never causes an
  empty organizer subtitle or empty venue line (Brief Q-1). Generation is not
  blocked and no error is shown.
- [ ] **AC7 [i18n]:** The override fields' labels and any helper text are
  rendered through the project's German-first i18n mechanism
  (`$_(key, { default })` with German default strings). No hardcoded display
  string is introduced. The certificate's own labels and locale-resolved date
  are unaffected.
- [ ] **AC8 [testing — TDD/RED-first]:** The behavior is authored RED-first per
  DEC-22. Tests cover: (a) a supplied organizer/venue override reaching the
  rendered certificate (single-team and all-teams); (b) the no-override path
  producing today's output — including the venue resolved live at render time,
  not frozen at screen-open; (c) the ephemeral guarantee — a generation issues
  no `INSERT`/`UPDATE` and leaves `tournament.organizer` and
  `locations.display_name` unchanged. Each fails against the pre-story code and
  passes after. The RED→GREEN cadence is recorded in the impl-report.
- [ ] **AC9 [testing — build gate]:** `mvn verify` for `vvwt-tm-web` is BUILD
  SUCCESS after the story (DEC-54) — no regression in the certificate or
  tournament test suites, frontend build included.
- [ ] **AC10 [governance]:** No new DEC is created. The override is threaded
  UI → controller → assembler: new request parameters on the existing
  certificate render endpoints in the `de.vvwt.tm.web` controller module
  (DEC-40), and a signature extension of the `CertificateAssembler` public
  interface and its `DefaultCertificateAssembler` implementation (DEC-35) so the
  assembler accepts optional organizer/venue overrides instead of always
  deriving them internally. Server-side Mustache rendering is unchanged
  (DEC-12); the rendered certificate stays self-contained / offline (DEC-16).
  No change is made to the authentication/authorization of the
  `/certificate/**` surface — no new endpoint, no `SecurityConfig` change. No
  test-only or orphan production code — method, constructor, or field — is
  introduced (DEC-70). `related_decs` cites the constraining DECs.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Out of Scope

- Persisting the override / writing it back to the tournament or the location
  — the override is explicitly ephemeral (operator decision, 2026-05-18).
- A Settings / Configuration page, and persistent editing of the location's
  stored label — deferred with location management.
- Editing the organizer on the tournament form — that is story E68S01.
- The tournament name and the certificate date shown on the certificate — both
  are already editable via the tournament form and are not part of this
  override.
- Changing the certificate template's visual design / layout.
- The COMPLETED-status gate on certificate generation, the no-uploaded-template
  fallback (Epic E67), and placement computation (E12S09) — all unchanged.

## Notes

- This story defines the behavioral outcome. Delivery chooses the
  implementation — including how the override values travel from the
  certificate screen to the render endpoints (the endpoints are currently GET
  with path variables only; query parameters or another mechanism are
  Delivery's choice), and how a field is recognized as "overridden" vs left at
  its pre-filled value (AC5) — for example by sending the override parameter
  only for a changed field, so an unchanged field carries no parameter and the
  endpoint resolves it exactly as today.
- The no-override path must keep the venue a **live** `locations.display_name`
  read performed at render time (Brief D-5 / O-2 / O-3). It must not be
  satisfied by passing the screen-load pre-fill value through as a parameter —
  that would silently convert the live read into a screen-time snapshot.
- Pre-fill sources: the organizer from `tournament.organizer`; the venue from
  the same location label the certificate resolves today (via
  `LocationDisplayResolver`).
- The certificate render endpoints derive the organizer internally today; this
  story makes the organizer (and the venue) optional, override-able inputs of
  the render — absent/blank override ⇒ today's resolution.
