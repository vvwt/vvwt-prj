# Story E24S03: Q-1a TDD RED-first fresh reconstruction of `ActivityScheduleAssembler` — new public interface + `DefaultActivityScheduleAssembler` impl + `ActivityScheduleRow` VO + `ActivityScheduleModel` DTO + fresh deep-behaviour tests

## User Story

**As a** maintainer of `vvwt-tm-web` reconstructing the print bounded context
under strict DEC-22 Iron Law,
**I want** a fresh `ActivityScheduleAssembler` public interface +
`DefaultActivityScheduleAssembler` impl + `ActivityScheduleRow` VO +
`ActivityScheduleModel` DTO authored TDD RED-first at `de.vvwt.tm.print.*`,
with behaviour coverage for photo-schedule assembly (activity assignments,
break interleaving, unassigned-team warnings),
**so that** the second print-domain assembler meets DEC-22 Iron Law; legacy
remains untouched through cutover.

## Context

Per Brief v6 Seq-C + Q-1a full. Legacy
`de.vvwt.tm.infrastructure.print.ActivityScheduleAssembler` (413 LoC, plus
`ActivityScheduleRow` 141 LoC + `ActivityScheduleModel` 45 LoC) stays
untouched. Fresh reconstruction at `de.vvwt.tm.print.*`.

Parallel to S02 (LaufzettelAssembler reconstruction) — same pattern,
different domain (photo-schedule vs team-schedule).

Empirical 2026-04-23: `ActivityScheduleAssembler` uses same import surface
as `LaufzettelAssembler` (`Tournament`, `Match`, `Phase`, `PhaseBreak`,
etc.; `ActivityAssignmentService` from unassigned `domain.activity.*`).
Deleted legacy `ActivityScheduleAssemblerTest` had 10 `@Test` methods —
scenario set mined as black-box reference.
