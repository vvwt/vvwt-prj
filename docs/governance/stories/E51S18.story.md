# Story E51S18: Operationalize DEC-59 — uniform avatar persistence at apply (N per phase incl. siegerehrung; teamId=NULL universal) + operator-confirmation team-assignment workflow + distributionMode-as-source + siegerehrung lifecycle uniform via vacuous L1+L2 + activation-guard gameMode-OR-term

## User Story

**As the** Tournament Operator,
**I want** the team-assignment workflow to behave uniformly across all phases (Phase 1, intermediate phases, and siegerehrung) — with team-IDs written ONLY after I review and confirm a system-computed proposal at the right lifecycle moment (PREPARED + previous-phase-COMPLETED), and with avatar slots existing in equal count per phase (including siegerehrung) so I can rank teams in the ceremony,
**so that** the system aligns with my stated workflow intent (operator-confirmation gate on team assignment), avoids hardcoded distribution-shapes that ignore my `DraftSection.distributionMode` configuration, and codifies siegerehrung as a first-class phase with its own avatar slots — eliminating the K-1/K-3/K-4/K-6 contract violations identified in the 2026-05-09 Discovery audit.

## Context

DEC-59 (commit `ab727af` on staging) amends DEC-55 D-1 + D-6 to codify the uniform-avatar-persistence and operator-confirmation team-assignment workflow:
- **Clause A:** N avatars per phase including siegerehrung (replaces `groupCount × ceil(N/groupCount)` formula for Phase 2+ and `0 for siegerehrung`).
- **Clause B:** teamId=NULL universally at apply-time, including Phase 1 (removes the DEC-55 D-1 *"Phase 1 MAY be populated immediately"* carve-out).
- **Clause C:** operator-confirmation team-assignment workflow — proposal computed → operator views/corrects/confirms → teamId-write + PREPARED→ASSIGNED in same TX. Confirmation is the SOLE trigger for teamId population.
- **Clause D:** `DraftSection.distributionMode` (E51S15) is the sole source of truth for Phase-N team-assignment-shape. Apply-time hardcoded Round-Robin removed.
- **Clause E:** siegerehrung lifecycle uniform via vacuous L1+L2 execution. Per-gameMode `MatchGenerator` returns empty match list for `gameMode == "siegerehrung"`. DEC-55 D-3 step 1 + D-4 + DEC-56 D-1 textually preserved.
- **Clause F:** DEC-55 D-6 activation-guard amended: `!tournament.optimize OR phase.optimized OR section.gameMode == 'siegerehrung'`.

This Story operationalizes DEC-59 in production code + test code. Four originally-distinct concerns (K-1, K-3, K-4, K-6) are bundled because they all touch the same code path (`DefaultDraftService.apply()` lines ≈575-673 per user IDE) and split-delivery would create intermediate broken states.
