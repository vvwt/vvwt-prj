# Story: Per-packet result retention + Flyway migration

## User Story

**As** the slot-optimization dispatcher,
**I want** every accepted packet result retained in a queryable, durable form,
**so that** a job's global optimum can later be aggregated across all of its packets instead
of being lost.

---

## Context

When a worker submits a packet result, `DefaultSubmitResultService` verifies the signature,
enforces the algorithm match, applies first-valid-wins, marks the `PacketRecord`
`RESULT_RECEIVED`, and writes that packet's `resultPayloadJson` to the fingerprint-keyed
result cache. The `PacketRecord` itself retains **no result** — its fields are
`{id, packetId, jobId, packetPayloadJson, status, claimedByWorkerId, claimedAt, timeoutAt}`.
The worker's computed `bestRank` / `bestScore` survive only inside the cache's
`resultPayloadJson` blob, and — because the cache is keyed by the *job* structural
fingerprint and is INSERT-only — only for whichever packet of the job wrote first; every
later packet of the same job collides on that key and its result is discarded.

There is therefore no substrate from which a job's global optimum can be computed. This
story adds one: each accepted packet's result (`bestRank` + `bestScore`) is retained in a
queryable, durable persistence store, with the supporting Flyway migration. This is the
substrate the finalization/aggregation story (E60S03) consumes.

The substrate shape is a Delivery design choice — result columns added to `PacketRecord`, a
dedicated packet-result table, or a row model analogous to the existing `LateResult` table.
Whichever is chosen, per-packet results are individually queryable by `jobId`.

The signature-verification, algorithm-match, and first-valid-wins intake behaviour
(DEC-6 / DEC-43) is preserved exactly — retention is additive to it.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-RESULT-RETAINED-ON-ACCEPT** — RED-first (DEC-22): when `submit-result`
  accepts a packet's first valid result, that packet's `bestRank` and `bestScore` are
  retained in the persistence store; a query for that packet's result returns the submitted
  `bestRank` / `bestScore`. The test fails on current `HEAD` (no retention store) and passes
  after the change.
- [ ] **AC-TEST-RETENTION-DURABLE** — the retained result is durable: it is read back
  correctly from a freshly-loaded repository / persistence context (it is persisted, not
  held in memory), so it survives a dispatcher restart.
- [ ] **AC-TEST-RETAINED-RESULTS-QUERYABLE-BY-JOB** — all retained packet results for a
  given `jobId` are queryable as a set (the access path E60S03 aggregation needs).
- [ ] **AC-TEST-LATE-RESULT-DOES-NOT-OVERWRITE** — a late (superseded) result for a packet
  that already has a first-valid result does not overwrite the retained first-valid result;
  first-valid-wins (DEC-6) is preserved end-to-end including retention.
- [ ] **AC-TEST-MIGRATION-APPLIES-CLEAN** — the Flyway migration applies cleanly on a fresh
  `vvwt-slotopt-dispatcher` database and yields a schema that supports the retention store.
- [ ] **AC-TEST-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for `vvwt-slotopt-dispatcher`
  (DEC-54); the existing E37/E40 suite remains GREEN.

### Governance

- [ ] **AC-GOV-QUERYABLE-SUBSTRATE** — per-packet results are retained in a queryable,
  durable persistence substrate keyed/associated such that all results for one `jobId` can
  be retrieved together. The substrate mechanism (result columns on `PacketRecord`, a
  dedicated packet-result table, or a `LateResult`-analogous row model) is Delivery's design
  choice; the impl-report records and justifies the chosen substrate.
- [ ] **AC-GOV-INTAKE-BEHAVIOUR-PRESERVED** — the existing per-packet intake behaviour —
  signature verification, algorithm match, first-valid-wins, the `RESULT_RECEIVED`
  transition, the `LateResult` logging of superseded results (DEC-6 / DEC-43) — is preserved
  unchanged; retention is strictly additive.
- [ ] **AC-GOV-DAO-IT-THREE-RULE** — the retention store's DAO integration tests follow the
  DEC-26 / DEC-46 three-rule generator/evaluator-separation pattern: schema-from-migration,
  an independent persistence verifier, read/write decoupling — using the dispatcher's
  per-module DAO test support utility.
- [ ] **AC-GOV-NO-BACKFILL** — the Flyway migration introduces new structure only and
  requires no data backfill: DEC-25 records the human confirmation that no production data
  exists anywhere, so no existing rows need migrating.
- [ ] **AC-GOV-DEC9-STRUCTURAL-ONLY** — the retained result carries only structural
  optimization data (`bestRank` / `bestScore` and packet/job association keys) — no team
  UUIDs, names, or other identity-bearing attributes (DEC-9).
- [ ] **AC-GOV-INTERFACE-MANDATE** — any new behaviour-bearing first-party Spring component
  is addressable through an interface in its module-root package with a `Default*`
  implementation in `.internal` (DEC-58 / DEC-72 / DEC-35 / DEC-36); the interface-mandate
  build guard stays green.
- [ ] **AC-GOV-RED-FIRST** — new first-party code is authored RED-first per DEC-22; changes
  to E37S09-delivered `DefaultSubmitResultService` follow reconstruction-in-place /
  §refactor-clause; the impl-report records RED-state evidence and the per-change
  classification.
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); Java touches compile
  warning-free (DEC-29) and pass Spotless / google-java-format (DEC-30); no production
  member exists solely for tests (DEC-70).
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use `chore(E60S02):` / `feat(E60S02):`
  prefixes per the close-story.sh contract.

### Error Handling

- [ ] **AC-ERR-RETENTION-ATOMIC-WITH-ACCEPT** — retaining the packet result and marking the
  `PacketRecord` `RESULT_RECEIVED` are atomic: either both succeed or neither does. A
  retention-store write failure does not leave a packet marked `RESULT_RECEIVED` with no
  retained result (which would make the job permanently un-aggregatable). On such a failure
  the packet remains claimable/reissuable as before.
- [ ] **AC-ERR-DUPLICATE-RESULT-NO-CORRUPTION** — a worker re-submitting the identical
  packet result (idempotent duplicate) does not create a duplicate retention row and does
  not corrupt or replace the retained first-valid result.
- [ ] **AC-ERR-RETENTION-REJECTS-MALFORMED-RESULT** — a result payload from which a
  `bestRank` / `bestScore` cannot be extracted is handled with a defined error response and
  is not retained as a valid result (it cannot silently poison a later aggregation).
