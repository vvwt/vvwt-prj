# Story: The Display overview group-standings rank teams by the placement comparator

## User Story

**As a** spectator or organizer reading the public Display overview,
**I want** the group standings ranked by points, then set ratio, then ball ratio, then prior group position,
**so that** the standings agree with how teams are actually seeded into the next phase.

---

## Context

The Display overview shows a group-standings panel. The phase-transition sort and the
Display standings are two views of the same question — "which team ranks higher" — and they
must not disagree. DEC-77 D-3 fixes that ranking as points → set ratio (`setQuotient`) →
ball ratio (`ballQuotient`) → prior group position (`TeamAvatar.groupPosition`), with
unrated teams (`withoutAssessment`) last; D-6 requires the Display standings to use that
same comparator. E66S01 implements the comparator as a single shared piece — this story
makes the Display standings use it, so the two screens cannot drift apart.

Whether the Display standings currently rank by the full comparator is not assumed — this
story carries a fresh-audit acceptance criterion rather than a pre-stated defect claim.

---

## Acceptance Criteria

- [ ] AC1 (testing): TDD per DEC-22 — a failing test is authored before the production
  change, proven RED, then GREEN; the standings ranking is tested at the logic level. The
  test verifies the no-divergence property: for the same set of teams and ratings, the
  Display standings order and the phase-transition proposal order are identical — not
  merely that the standings are sorted in some plausible order.
- [ ] AC2: the Display overview group-standings rank teams by points descending → set
  ratio (`setQuotient`) descending → ball ratio (`ballQuotient`) descending → group
  position (`TeamAvatar.groupPosition`) ascending; a team flagged `withoutAssessment`
  ranks below every assessed team — the same order as the phase-transition sort
  (DEC-77 D-3 / D-6). Group position 1 is the top slot (the project convention — the
  proposal calculators assign the highest-ranked team to position 1).
- [ ] AC3: the standings ranking uses the single shared placement comparator introduced by
  E66S01 — it does not re-implement a separate sort, so the standings and the
  phase-transition proposal cannot drift apart. At delivery the standings ordering is
  audited (fresh audit) so that it matches the DEC-77 D-3 order; this AC is satisfied by
  the rule (the standings match D-3), not by matching a pre-computed current-state claim.
- [ ] AC4 (governance): tie and unrated cases resolve deterministically with no runtime
  error — teams equal on points, `setQuotient` and `ballQuotient` are ordered by group
  position ascending; two teams that are both `withoutAssessment` are likewise ordered by
  group position ascending. No arbitrary or unstable order.
- [ ] AC5 (governance): the frontend stays Vite + Svelte + TypeScript, no SvelteKit
  (DEC-2); no `teamId` UUID is rendered in the DOM (DEC-9). `mvn verify` is BUILD SUCCESS
  for `vvwt-tm-web`, including the frontend build (DEC-54). TDD per DEC-22.

> All acceptance criteria must be verifiable.

## Notes

Acceptance criteria state behaviour, not a test mechanism — no Svelte-5 component mount is
required (infeasible in the project's Vitest+jsdom environment, E58S05). Delivery decides
whether the shared comparator is reused directly or exposed through a thin query the
Display context calls; AC1's no-divergence test is what guarantees one source of truth
(DEC-77 D-6) — a test of "the standings are sorted" alone would not catch a re-implemented
parallel sort drifting from the phase-transition order.
