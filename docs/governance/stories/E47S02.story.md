# Story E47S02: Special-pattern routes migration (Home, TournamentForm-new, TournamentForm-edit, SlotOptimization) with back-arrow on 3 non-top-level routes, tournament-name on SlotOptimization, addition of `slotopt.title` i18n key, removal of TournamentForm's existing per-page back-button (form-footer Save/Cancel preserved per D-13)

## User Story

**As a** Tournament Manager admin (landing on `/`, creating a new tournament at `/tournaments/new`, editing an existing tournament at `/tournaments/:id/edit`, monitoring slot-optimization at `/tournaments/:tournamentId/slot-optimization`),
**I want** these 4 special-pattern routes to follow the same persistent-header layout as the other 8 admin routes — page title in the sticky header, back-arrow where the route is non-top-level, tournament name where I am inside a tournament, and (for SlotOptimization specifically) a proper German title sourced from i18n instead of the current hardcoded English `<h2>Slot Optimization</h2>`,
**so that** the entire admin SPA presents a single consistent navigation chrome regardless of which route I open, and SlotOptimization in particular stops being the lone English-text page in an otherwise German UI.

---

## Context

E47S01 establishes the shell mechanism (per-page header registration), the sticky brand-header, the responsive collapse rule, the Overflow-Menu pattern, and the parent-route map. S01 migrates the 8 routes that today follow Pattern-(a) (`__header` flex container with `<h1>` + actions, per Brief O-3a).

S02 migrates the remaining 4 routes that DO NOT follow Pattern-(a). Each requires a per-pattern adaptation (Brief O-3 b/c/d):

- **Home (`/`)** — Pattern-(b): bare `<h1>{$_('home.heading')}</h1>` at `Home.svelte:13`. Note: uses `home.heading` not `home.title` (Brief D-15) — the shell consumes the existing key as-is, no i18n schema change. Top-level route (no back-arrow per D-5), no tournament context (no tournament-name per D-6), no primary action button — header action area stays empty per Brief D-4. The migration is the simplest of the 4: just relocate the `<h1>`'s i18n key into the shell registration; remove the in-page `<h1>`.

- **TournamentForm-new (`/tournaments/new`)** — Pattern-(c): bare `<h1>` (`TournamentForm.svelte:???` — Delivery confirms the exact line; the file uses `tournaments.new.title` or `tournaments.create.title`-style key — verify in `de.json`) above a `<form>` containing the form fields and a `form__actions` footer with `<button type="submit">` + Cancel. Sub-route of `/tournaments` (back-arrow added per D-5; parent path is `/tournaments`); no tournament context (no tournament-name per D-6 — the tournament does not exist yet). No primary header action button — header action area stays empty per D-4. **Save/Cancel STAY in `form__actions` footer per D-13**: they are HTML form-association elements (`<button type="submit">`) — moving them outside `<form>` breaks form semantics and the implicit Enter-key-submits behaviour. The existing per-page back-button on TournamentForm is removed (Brief D-10).

- **TournamentForm-edit (`/tournaments/:id/edit`)** — Pattern-(c): same shape as TournamentForm-new but for editing an existing tournament. Sub-route (back-arrow added; parent path is `/tournaments`); the tournament IS the subject of the page (form contains the name) — no header tournament-name per Brief D-6 ("On `/tournaments/:id/edit`, the form contains the name → no header-name"). Save/Cancel STAY in `form__actions` per D-13. Existing per-page back-button removed.

- **SlotOptimization (`/tournaments/:tournamentId/slot-optimization`)** — Pattern-(d): bare `<h2>Slot Optimization</h2>` hardcoded English at `SlotOptimization.svelte:74`, plus an inline `<button class="btn btn--cancel" on:click={cancelOptimization}>` at line 93. Sub-route with tournament context (back-arrow + tournament-name added per D-5/D-6). The `<h2>` is HARDCODED — no i18n key exists today. **S02 adds a NEW i18n key `slotopt.title` to `de.json` with German text "Slot-Optimierung"** (Brief D-14). The shell consumes `slotopt.title`. The inline cancel button is NOT a page-level CTA — it is an in-flight-job control bound to job state (`status === 'RUNNING'` or similar). It stays where it is; the header action area is empty per D-4.

After S02 the Epic is complete: all 12 admin routes follow the unified header pattern, all redundant per-page back-buttons are removed, and SlotOptimization carries a proper German title sourced from i18n.

S02's parent-route map additions (Brief D-12 — declared in code per S01 AC15(ii)):
- TournamentForm-new (`/tournaments/new`) → `/tournaments`
- TournamentForm-edit (`/tournaments/:id/edit`) → `/tournaments`
- SlotOptimization (`/tournaments/:tournamentId/slot-optimization`) → `/tournaments/:tournamentId/edit`
- Home (`/`) is top-level — not in the parent map.

**`slotopt.title` German translation choice (per Brief D-14)**: "Slot-Optimierung" is the natural German rendering. Delivery may consult existing project glossary (if any) for consistency with related terms (`tm.slotopt.exhaustive-max-n` is a property name, not a UI string — irrelevant to translation). If a different rendering is preferred (e.g., "Spielplan-Optimierung", "Belegungs-Optimierung"), Delivery records the choice in impl-report AC14(i) — Discovery does not constrain beyond "valid German + matches the page's purpose".

**TournamentForm i18n key names — Delivery verifies (per Context paragraph 3)**: The exact title keys for `/tournaments/new` and `/tournaments/:id/edit` may be `tournaments.new.title`, `tournaments.create.title`, `tournaments.edit.title`, or some other shape. Delivery `grep`s `de.json` and the existing `<h1>` template binding to confirm. AC14(i) records the verbatim keys consumed.

**Home title key reuse (per Brief D-15)**: Home uses `home.heading` not `home.title`. Discovery considered renaming for consistency but explicitly REJECTED renaming (Brief D-15) — string-content changes are out of scope per Brief S-4. The header consumes `home.heading` as-is; the route's i18n contract is unchanged.

**Form-button preservation (per Brief D-13)**: TournamentForm Save/Cancel cannot move to the header without breaking HTML form-association semantics. Specifically: `<button type="submit">` outside its `<form>` ancestor does NOT submit the form on click, and the Enter-key-submits keyboard contract is broken. AC4 codifies this — the buttons remain in `form__actions` footer.

**SlotOptimization Cancel button — NOT a page-level CTA**: The inline button at `SlotOptimization.svelte:93` is a job-state-bound control. It only appears (or is enabled) when an optimization job is running; clicking it cancels the in-flight job. Relocating it to the header would (a) make it visible when there is no job to cancel (visual noise + confusion) or (b) require complex header-state plumbing tied to the route's job-state, which is out of scope. AC10 protects against accidental relocation.

**Epic-closure AC13**: S02 is the last Story in E47. AC13 explicitly closes the Epic Success Metric ("no per-page `__header` block remaining") — by re-running S01 AC11's grep after S02 merges and observing zero matches. This is not a new check; it is a delegation to S01's grep that S02 cannot regress.

**RED-first test density (per DEC-22 §Iron Law)**: AC1 (×1), AC2 (×1), AC3 (×4), AC4 (×2), AC5 (×3), AC6 (×2), AC7 (×4), AC11 (×1) = 18 RED-first tests in S02. Smaller scope than S01 because the shell and overflow infrastructure are reused.

**Single new i18n key in the entire Epic**: `slotopt.title` is the only new key. All other header text consumes existing keys (Brief C-4 + S-4). No string content changes — only structural relocations and the one i18n addition.
