# Story E35S03: Replace Snapshot-Driven tests in utility packages — fresh TDD per audit findings

## User Story

**As a** Delivery Agent (and the human reviewing the test corpus),
**I want** every Snapshot-Driven test (FORBIDDEN per DEC-41 § hierarchy clause 3) identified in the E35S01 audit replaced with a fresh TDD test under DEC-22 Iron Law (RED-first per § Decision item 4, activated project-wide per § item 1), while leaving utility-class production code in `codec` / `solver` / `score` / `types` UNTOUCHED per the Brief T-7 X-scoping decision,
**so that** the FORBIDDEN-test gap that motivated X-scoping over W is closed without retrofitting Slot-Opt utility-class production code (DEC-22 § item 5 explicitly defers that choice to a Wave-2 Epic scope decision — E35 makes the choice via Brief T-7), and the test corpus for `vvwt-worker-lib` becomes fully DEC-41-admissible.

---

## Context

E35S01's audit table identifies which existing test methods qualify as Spec-Anchored (per DEC-41 D-4 a/b/c/d) and which are Snapshot-Driven (none of the four observable criteria). DEC-41 § hierarchy clause 3 explicitly FORBIDS reuse of Snapshot-Driven tests against new code; per Brief Q-8, dropped behavioural coverage MUST be preserved by replacement TDD tests (not just deleted).

This story executes the test-corpus remediation half of E35's quality-lift work. Production code in utility packages (`LehmerCodec`, `PacketSolver`, `StructuralFingerprint`, `VarietyScorer`, all 7 `types` records) is NOT touched per Brief D-2(c) / S-10 / T-7 X-scoping rationale, authorized by DEC-22 § Decision item 5's deferral clause ("reconstruction of previously-delivered code is a separate Wave-2 Epic scope decision, not this DEC's concern"). Identity-package tests are addressed in E35S02; this story covers codec / solver / score / types only.

## Acceptance Criteria

- [ ] **AC1 — Snapshot-Driven test replacement under DEC-22 Iron Law (RED-first per § Decision item 4, activated per § item 1).** For each Snapshot-Driven test (entire file OR individual method per E35S01 audit AC3 Mixed sub-table) in codec / solver / score / types: write a fresh replacement test that demonstrably goes RED first (against the absent or minimal new test). The replacement test MUST exhibit at least one of the DEC-41 D-4 observable criteria (a/b/c/d) so it is itself admissible going forward. The impl-report cites per-test RED state evidence (test name + RED-state condition) for every new test. (Testing, governance.)

- [ ] **AC2 — Behavioural coverage of dropped Snapshot-Driven tests preserved (Brief Q-8).** For each Snapshot-Driven test replaced under AC1, the impl-report includes a "Coverage Preservation" entry stating: (i) the dropped test's behavioural assertion (what concrete case it asserted), (ii) which AC1-replacement test (or which existing Spec-Anchored test) covers that case after the replacement, (iii) explicit confirmation that the case is covered (NOT silently dropped). If the implementer determines that a dropped Snapshot-Driven test asserted a case that no Spec-Anchored test (existing or new) covers, the implementer either (a) authors an additional fresh TDD test to cover the case, OR (b) STOPs and escalates per Conflict Protocol — a case cannot be silently dropped. (Testing, governance.)

- [ ] **AC3 — Production code in utility packages UNTOUCHED.** No file under `vvwt-prj/vvwt-worker-lib/src/main/java/de/vvwt/worker/codec/`, `.../solver/`, `.../score/`, or `.../types/` is modified by this story. The implementer verifies via `git diff --stat` post-implementation that only files under `src/test/java/de/vvwt/worker/{codec,solver,score,types}/` are touched (plus any necessary test-helper additions in test-source tree). The impl-report includes the `git diff --stat` output as evidence. (Governance.)

- [ ] **AC4 — DEC-41 audit-classification table in impl-report.** Per Brief Q-4 + `patterns/conventions.md` § "Spec-Anchored Test Reuse (DEC-41)" Audit Obligation, the impl-report includes the per-test classification table for every new replacement test: file path, test class, test method name, qualifying observable criterion (a/b/c/d), criterion evidence (annotation presence / assertion shape / citation locator / invariant naming + body lines). Old (replaced) tests are not in the table — only the new ones. (Testing, governance.)

- [ ] **AC5 — Atomic per-package commits (no atomic cutover required for test-only changes).** Test corrections are committed in per-package commits (e.g., one commit for codec corrections, one for solver, one for score, one for types). Commits are titled `test(E35S03/{package}): replace Snapshot-Driven tests with fresh TDD per E35S01 audit`. There is NO production-code cutover (AC3) so the DEC-21 atomic-cutover principle does NOT apply to this story (per Brief T-3 / SC.5 reviewer note). (Governance.)

- [ ] **AC6 — `mvn verify` green at every commit boundary.** Each per-package commit (AC5) leaves `mvn -pl vvwt-worker-lib verify` (and `mvn -pl vvwt-worker-lib,vvwt-dispatcher,vvwt-benchmark,vvwt-standalone-worker,vvwt-tm-web -am verify` for the final commit) BUILD SUCCESS. `ban-spring-boot-in-worker-lib` enforcer green; DEC-29 `failOnWarning=true` and DEC-30 `spotless:check` both pass. (Testing.)

- [ ] **AC7 — Mixed-form test files handled per E35S01 AC3 sub-table.** For test files that E35S01 audit classified as `Mixed` (per AC3 sub-table — some Spec-Anchored methods, some Snapshot-Driven), only the Snapshot-Driven methods are replaced; Spec-Anchored methods within the same file are LEFT UNCHANGED. The impl-report explicitly enumerates per-Mixed-file: (i) which methods were replaced, (ii) which methods were preserved unchanged. (Testing.)

- [ ] **AC8 — JMH benchmarks NOT touched (DEC-22 § Decision item 2 — vvwt-benchmark JMH carve-out).** No JMH benchmark file (`LehmerCodecBenchmark`, `VarietyScorerBenchmark`, `PacketSolverBenchmark`) is modified by this story. The DEC-22 § item 2 JMH carve-out applies. The impl-report confirms via `git diff` that no `*Benchmark.java` file was touched. (Governance.)

- [ ] **AC9 — Commit & push to vvwt-prj `staging`.** All per-package commits (AC5) pushed to `staging` per DEC-13. PR opened per `coordinate-handoffs`. Outer-repo edits (this story file) committed separately to outer repo and pushed to outer-repo `staging`. (Governance.)
