# Story E48S07: Drag&Drop Phase-Transition Backend — Initial Assignment per sortType + Propose/Commit Endpoints

## User Story

**As a** Backend Service supporting the Drag&Drop Phase-Transition UI,
**I want** an algorithm that proposes an initial Team-zu-(Gruppe, Platz)-Zuordnung based on the next phase's sortType, plus endpoints to fetch the proposal and to commit a (possibly admin-corrected) assignment as TeamAvatars,
**so that** the admin gets a sensible starting point, can correct it via drag-and-drop, and the corrected assignment is persisted with referential and concurrency safety.

---

## Context

Per Brief D-6 + O-16: Drag&Drop ist generisches Phase-Übergangs-Pattern für jeden N→N+1 (nicht Phase-2-spezifisch). Backend muss anhand Phase N+1's `sortType` (∈ {team_number, placement_group, group_placement}) eine initiale Zuordnung der Teams aus Phase N's Endstand zu (groupNumber, groupPosition)-Tupeln in Phase N+1 berechnen. Algorithmus-Referenz: Legacy `vvw-tournaments/vvw-tournaments-admin-ui/controls/lifecycle/lifecycle.js` `MappingSuggestion.get()` + zugehöriger Backend-Endpoint (Delivery findet exakte FQN). Story-AC zitiert Legacy als read-only-Referenz, neue Implementation TDD-RED-first per DEC-22 (Q-1a).

3 sortType-Algorithmen (high-level, exakter Legacy-Code wird gelesen):
- `team_number`: Round-Robin nach Team-Nummer aufsteigend in N Gruppen
- `placement_group`: Teams behalten ihre Gruppen-Zugehörigkeit; innerhalb jeder Gruppe sortiert nach Platzierung der vorigen Phase
- `group_placement`: Cross-Group-Distribution — alle 1. Plätze in Gruppe 1, alle 2. Plätze in Gruppe 2, etc.

Bei Phase N+1's gameMode = siegerehrung läuft derselbe Drag&Drop-Workflow (initiale Zuordnung berechnet, Admin korrigiert), aber nach Commit werden KEINE Matches generiert (E48S02 No-op-Generator-Bean handhabt das).

DEC-37 Clause B Lock essential: Commit schreibt TeamAvatars + ggf. Matches → mehrere Aggregat-Members → Tournament Row-Lock.

## Acceptance Criteria

- [ ] **AC-TEST-PROPOSE-TEAM-NUMBER-RED** (testing): RED-first JUnit für `proposeTransition(fromPhaseId, toPhaseId)` mit `sortType=team_number`: gegeben 8 Teams, 2 Gruppen → returns 4 Teams pro Gruppe, Round-Robin nach Team-Nummer (Team 1 → Gruppe 1 Pos 1, Team 2 → Gruppe 2 Pos 1, Team 3 → Gruppe 1 Pos 2, etc.).
- [ ] **AC-TEST-PROPOSE-PLACEMENT-GROUP-RED** (testing): RED-first für `sortType=placement_group`: Teams behalten Gruppe (aus Phase N), neu-sortiert nach Platzierung innerhalb derselben Gruppe. **Konkretes Fixture**: gegeben Phase N mit 2 Gruppen (Gruppe 1: TeamAvatars A[rank 1], B[rank 2], C[rank 3]; Gruppe 2: D[rank 1], E[rank 2], F[rank 3]; rank source = `TeamAvatarRating.compareTo()` sort order) → erwartet Phase N+1 Gruppe 1: A Pos 1, B Pos 2, C Pos 3; Gruppe 2: D Pos 1, E Pos 2, F Pos 3.
- [ ] **AC-TEST-PROPOSE-GROUP-PLACEMENT-RED** (testing): RED-first für `sortType=group_placement`: 1. Plätze aller Phase-N-Gruppen → Phase N+1 Gruppe 1, 2. Plätze → Gruppe 2, etc. **Konkretes Fixture**: gegeben Phase N mit 2 Gruppen, je 4 Teams (Gruppe 1: A1[1], A2[2], A3[3], A4[4]; Gruppe 2: B1[1], B2[2], B3[3], B4[4]) → erwartet Phase N+1 (4 Gruppen): Gruppe 1: A1, B1; Gruppe 2: A2, B2; Gruppe 3: A3, B3; Gruppe 4: A4, B4. Edge-Case (ungleiche Gruppengrößen) ist **eigene Sub-AC RED-first** in der gleichen Story: Delivery wählt Algo (z.B. "kleinste Gruppe truncated") + dokumentiert in impl-report; **RED-Test PRECEDED Implementation** auch für die Edge-Case-Sub-AC, kein impl-first für Edge-Cases (DEC-22 Iron Law gilt auch hier).
- [ ] **AC-IMPL-PHASE-TRANSITION-SERVICE-INTERFACE** (governance): NEUE Service-Schnittstelle `PhaseTransitionService` im public package `de.vvwt.tm.tournament` (DEC-35 interface-first canon); deklariert beide Methoden `proposeTransition(UUID toPhaseId)` und `commitTransition(UUID toPhaseId, List<TeamAvatarAssignment> assignments)`. **Service löst `fromPhaseId` intern auf** via PhaseRepository.findByTournamentIdAndSequenceNumber(toPhase.tournamentId, toPhase.sequenceNumber - 1) — Controller liefert nur die toPhase-UUID aus dem Pfad. Implementation `DefaultPhaseTransitionService` in `de.vvwt.tm.tournament.internal`. Web-Module-Konsumenten (Controller + ITs) referenzieren nur das Interface (DEC-36 cross-package-test-typing).
- [ ] **AC-IMPL-DTO-PLACEMENT** (governance): `TeamAvatarProposal` (Service-Return + GET-Response) ist als Java-Record im public package `de.vvwt.tm.tournament.*` platziert (Pattern A per DEC-40 Clause B 2026-04-27 Clarification — bounded-context-owned query-shape, projection == wire shape). `TeamAvatarAssignment` (POST-commit Request-Body) ist als Web-Tier DTO im Package `de.vvwt.tm.web.internal.dto.*` platziert (request bodies sind always web-tier DTOs per DEC-40 Clause B).
- [ ] **AC-IMPL-PROPOSE-TRANSITION**: `DefaultPhaseTransitionService.proposeTransition(UUID toPhaseId)` löst intern fromPhase auf (sequenceNumber - 1 within same tournamentId) und returns `List<TeamAvatarProposal>` mit (teamId, groupNumber, groupPosition); Lookup von `tournament.draft_json` für toPhase.sortType; Lookup von TeamAvatarRating (sort order via existing `TeamAvatarRating implements Comparable<TeamAvatarRating>`) für Phase N's Platzierungen.
- [ ] **AC-IMPL-PROPOSE-IS-READ-ONLY**: `proposeTransition` ist pure read-only (berechnet, persistiert nichts) — kein Lock erforderlich.
- [ ] **AC-IMPL-COMMIT-TRANSITION**: `commitTransition(UUID toPhaseId, List<TeamAvatarAssignment> assignments)` persistiert TeamAvatars für Phase N+1; akquiriert per-tournament row-lock (DEC-37 Clause B / C-13) als ersten Read; ruft `phasePreparationService.generateMatches(toPhaseId, gameMode)` (skipt für siegerehrung via E48S02 No-op-Bean).
- [ ] **AC-TEST-COMMIT-TRANSITION-WITH-MATCHES-RED** (testing): RED-first IT: `commitTransition` für eine Phase mit gameMode=roundrobin → TeamAvatars + Matches persistiert; assertj-db verifies Match.phaseId, TeamAvatar.(group, position).
- [ ] **AC-TEST-COMMIT-TRANSITION-SIEGEREHRUNG-RED** (testing): RED-first IT: `commitTransition` für eine Phase mit gameMode=siegerehrung → TeamAvatars persistiert ABER NULL Matches; assertj-db count.
- [ ] **AC-TEST-DEC-37-LOCK-COMMIT-RED** (testing): RED-first concurrency IT: zwei parallele Threads rufen `commitTransition(samePhaseId)`; einer succeeds, andere wirft IllegalStateException oder lock-timeout-Exception; CascadeLockIT-Pattern.
- [ ] **AC-IMPL-CONTROLLER**: `PhaseTransitionController` in `de.vvwt.tm.web` per DEC-40; Endpoints `GET /api/phases/:phaseId/transition-proposal` (returns proposed assignments für phase mit phaseId als toPhase), `POST /api/phases/:phaseId/transition-commit` (mit body = List<TeamAvatarAssignment>).
- [ ] **AC-TEST-CONTROLLER-IT-PER-METHOD-GREEN** (testing): happy-path + security-negative IT per Endpoint (DEC-44 `@SpringBootTest`).
- [ ] **AC-IMPL-DEC-9-TEAMAVATAR-IDENTITY** (governance): TeamAvatar-Persistierung respektiert DEC-9 — identity = (phaseId, groupNumber, groupPosition); kein UUID-cross-boundary-leak in der Optimizer-Layer-Wire (kein Optimizer involved hier, aber das domain-pattern bleibt erhalten).
- [ ] **AC-ERROR-HANDLING-INVALID-ASSIGNMENT** (error-handling): commitTransition validiert assignments: keine Duplicate-(group, position)-Tupel, keine Team-IDs außerhalb Phase-N's TeamAvatars, group/position-Werte ≥ 1 und ≤ konfigurierten max; bei Verletzung HTTP 400 mit operator-actionable Message.
- [ ] **AC-ERROR-HANDLING-DRAFT-JSON-NULL** (error-handling): falls toPhase's tournament hat draft_json=null oder parse-error → HTTP 400 mit Message ("Tournament has invalid draft_json — apply a draft first"); per C-14.
- [ ] **AC-SECURITY-TRANSITION-ENDPOINTS-AUTH** (security): beide Endpoints erfordern authenticated Admin; ITs verifizieren.
- [ ] **AC-GOVERNANCE-DEC-22-RED-FIRST** (governance): alle 3 sortType-Algorithmen + commitTransition + Controller-Endpoints sind RED-first (Q-1a frische TDD); Legacy-MappingSuggestion-Code ist read-only Referenz, KEIN Reuse via shared-abstract-type per DEC-41 (Snapshot-Driven, nicht Spec-Anchored).
