# Story E37S06: audit package — AuditEntry + AuditRepository + AuditService (Q-1a TDD RED-first against spec)

## User Story

**As a** dispatcher operator and a slot-optimization service auditor,
**I want** an audit log that records key lifecycle events (registration, role changes, registration attempts that hit conflicts) with source IP and timestamp per DEC-6,
**so that** abuse vectors against the asymmetric-key registration boundary are observable and forensically reconstructible.

---

## Context

The audit package owns the dispatcher-wide event-audit infrastructure consumed by the identity package (key registration audits) and later by the result package (result-audit per DEC-6 first-valid-result-wins logging — owned by ResultAuditService in E37S09's result package, not this audit package).

This package's audit scope is the IDENTITY/REGISTRATION audit log — distinct from the RESULT audit (which is a separate concern in result/ per E37S09). Source: E37S02 spec section (a) auth flow per DEC-6.

### Story-specific ACs

- [ ] **AC-AUDIT-ENTRY-ENTITY**: `de.vvwt.slotopt.dispatcher.audit.AuditEntry` Spring Data JDBC POJO with fields: `Long id`, `Instant occurredAt`, `String eventType` (e.g., `KEY_REGISTERED`, `KEY_ROLE_CONFLICT`, `KEY_RE_REGISTRATION_IDEMPOTENT`), `UUID workerId` (nullable when event has no worker context), `String sourceIp`, `String detailJson` (free-form structured event payload).
- [ ] **AC-AUDIT-REPOSITORY**: `de.vvwt.slotopt.dispatcher.audit.AuditRepository extends CrudRepository<AuditEntry, Long>` per DEC-35 Spring-Data carve-out. Optional finders: `List<AuditEntry> findByWorkerIdOrderByOccurredAtDesc(UUID workerId)`, `List<AuditEntry> findByEventTypeOrderByOccurredAtDesc(String eventType)`.
- [ ] **AC-AUDIT-SERVICE**: `de.vvwt.slotopt.dispatcher.audit.AuditService` interface + `de.vvwt.slotopt.dispatcher.audit.internal.DefaultAuditService` impl per DEC-35. Methods: `void recordEvent(String eventType, UUID workerId, String sourceIp, String detailJson)`. RED-first authored.
- [ ] **AC-DEC26-COMPLIANT-DAO-IT**: `AuditRepositoryIT` follows DEC-26 three-rule pattern **applied analogously to vvwt-slotopt-dispatcher** (DEC-26 §Decision is textually scoped to vvwt-tm-web; the principle — generator/evaluator separation at the data-access boundary — generalizes to any module hosting DAO ITs and is adopted here by analogy without invoking a DEC-26 scope-extension amendment). Tests cover: persist + retrieve roundtrip; findByWorkerId hit + empty; findByEventType hit + empty.
- [ ] **AC-IDENTITY-INTEGRATION-WIRING**: This story IS in scope for the cross-package integration of KeyRegistrationService → AuditService.recordEvent (per Brief Q-1 minimalism — defer no work that the audit package's reason-for-existing already requires). Concrete integration: KeyRegistrationService invokes AuditService.recordEvent on (a) successful new registration → eventType=`KEY_REGISTERED`; (b) idempotent re-registration → eventType=`KEY_RE_REGISTRATION_IDEMPOTENT`; (c) RoleConflictException → eventType=`KEY_ROLE_CONFLICT`. Integration test asserts that each path produces the expected AuditEntry row (verified via direct JDBC per DEC-26 Rule 2).
- [ ] **AC-FLYWAY-MIGRATION**: New Flyway migration (e.g., `V2__create_audit_entry_table.sql` or per per-module Flyway path) creates `audit_entry` table. Per DEC-26 Rule 1 schema-from-migration (analogously applied per AC-DEC26-COMPLIANT-DAO-IT).
- [ ] **AC-AUDIT-FAILURE-MODE** (error-handling category coverage): `AuditService.recordEvent` failure semantics are explicitly defined and tested:
  - Database persist failure (e.g., transient DB unavailability, FK violation) → AuditService logs the failure at WARN level with structured payload (eventType, workerId, sourceIp, exception class) and **does NOT rethrow** — audit failures must NEVER block the originating registration/operation. This is the user-facing impact decision: prefer dropped audit entry (with WARN-log evidence) over failed user-facing operation. Test: mock the repository to throw `DataAccessException`; assert recordEvent returns normally + WARN log captured.
  - Null-or-empty `eventType` parameter → throw `IllegalArgumentException` (programmer-error class; not for runtime user-facing flows). Test asserts the exception class.
  - Oversize `detailJson` (configurable bound, e.g., 64 KB) → truncate-with-marker rather than reject, to preserve at least partial forensics. Test asserts truncation behavior + log marker.
