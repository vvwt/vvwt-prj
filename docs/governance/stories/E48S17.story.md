# Story E48S17: PREPARED-Status Enum + Lifecycle-Refactor (prepare() + start() Predecessor-Check) + Apply-Phase-1-Distribution-Removal + Display-Branch-Erweiterung Pfad α + Phase-Übersicht-UI-Erweiterung

## User Story

**As a** Tournament Organizer,
**I want** a deliberate two-step phase activation (Vorbereiten → Aktivieren) with backend-enforced predecessor-completion check,
**so that** I can review the team-to-group assignment for every phase before it starts AND I cannot accidentally start a phase before its predecessor is completed.

---

## Context

Per Brief D-1 + D-2 + D-5 + D-6 + D-8 + O-2 .. O-8. Diese Story bildet das strukturelle Rückgrat des PREPARED-Step-Refactors:

1. **PREPARED-Enum-Wert** wird zu `Phase.PhaseStatus` hinzugefügt (PENDING/PREPARED/ACTIVE/COMPLETED). Phase.status ist VARCHAR ohne CHECK-Constraint — keine V*-Migration nötig (O-2). AC-ENUM-VALUES-STABLE gilt nicht für PhaseStatus (nur für MatchState per E21S05/DEC-22).
2. **`prepare(phaseId)`** Service-Methode in `DefaultPhaseLifecycleService` (PENDING→PREPARED). Idempotent auf PREPARED-Phase (re-prepare erlaubt — H-1 confirmed). DEC-37 Clause B Lock.
3. **`start(phaseId)`** Refactor: requires (status==PREPARED) AND (predecessor.status==COMPLETED OR predecessor==null). Backend-enforced HTTP 409. Race-safe via DEC-37 Lock. (Closes Bug von Brief-Q-C: heute prüft `start()` nur status==PENDING ohne Predecessor-Check.)
4. **Apply-Phase-1-Distribution-Removal**: `DefaultDraftService.apply:165-202` `if (isFirstPhase && !participatingTeams.isEmpty())`-Branch wird entfernt. Apply erzeugt nur Phase-Records (alle PENDING, alle ohne TeamAvatars). Vorbereiten ist alleiniger TeamAvatar-Creation-Punkt. Behavior-change → DEC-22 RED-first Tests.
5. **Display-Branch-Erweiterung Pfad α**: `DefaultDisplayOverviewService` (Lines **145, 391** — Line 384 ist ACTIVE-Filter und betrifft NICHT PREPARED) + `ActivityAssignmentPreviewController` (Lines 250, 258) PENDING-Branches umfassen ab jetzt PREPARED. **4 Code-Branches** insgesamt. Display behandelt PREPARED visuell wie PENDING (Brief D-8). KEINE Score-Tablet- oder Timer-Modifikation (filtern auf ACTIVE — PREPARED ignoriert wie PENDING).
6. **Phase-Übersicht-UI-Erweiterung**: PREPARED-Badge (gleiche Visualisierung wie PENDING aber distinkter Label "Vorbereitet"); Button-Logik: in PENDING zeige "Phase vorbereiten" (navigiert zur Vorbereiten-Route — implementiert in E48S18); in PREPARED zeige "Phase aktivieren" (disabled solange Predecessor nicht COMPLETED) + optional "Zuordnung erneut prüfen" für Re-prepare.
