# Story E11S13: Fix — Timer audio activate-fire wrong-index + schedule column-width regression + blue-marker on playing row (drop `--next`)

## User Story

**As a** tournament organizer using the Timer SPA during a live tournament,
**I want** the round-start, round-end, pause-start, and pause-stop sounds to fire at the right moments (matching the schedule transitions I see), the schedule table to fill the page width with headers correctly aligned over their cells, and the visible "current row" marker (blue stripe) to be on the round that is actually playing — not one row ahead,
**so that** the audio cues are trustworthy during play, the schedule is readable at a glance, and I can locate the currently-playing row instantly without reading the right-side badges.

---

## Context

After E11S10–E11S12 shipped, operator empirically reproduced three remaining Timer-SPA defects on 2026-05-28:

**Symptom 1 — Audio activate-fire shifted by one entry.** At tournament start (Hallenuhr = 10:00, Phase-1-Round-1 begins), the pause music plays instead of the round-start sound. At round end, no sound plays at all. At pause start, the round-start sound plays. At the next round's start, the pause music plays again. The end-of-round sound is never audible. Root cause: `App.svelte` `onTick` (line 448) reads `effectiveSchedule()[activeEventIndex]` for the activate-fire — but `activeEventIndex` is the NEXT-upcoming entry, not the entry that JUST started playing (`playingIndex`). The fire-trigger gate at line 432 fires correctly when `activeEventIndex` transitions, but the entry it looks up is one ahead of the entry whose audio should activate. The deactivate side (via `lastPlayingIndex`) is correct and does not need changing.

**Symptom 2 — Schedule table no longer fills page width.** After E11S11's header / sticky-strip reorganization, the schedule table renders constrained to a narrow column on the left, with the right portion of the page below the sticky header empty. The "RUNDE", "HALLENUHR-ZEIT", and "STATUS" column headers no longer align over their respective cells in the data rows. This is a CSS regression in the schedule-container scope only — the sticky header, brand-lockup, audio warnings, and WS-disconnect indicator are unaffected.

**Symptom 3 — Blue marker (vertical left-edge stripe) is on the next-upcoming row, not on the actually-playing row.** E11S09 AC8 introduced `.schedule-row--next` with a `border-left: 3px solid #2980b9` + light-blue background tint to signal the next-upcoming entry. `.schedule-row--playing` carries only a background fill + bold text (no left-border stripe). Operator's mental model: the blue stripe = "this row is the current one." Operator reads the next-row stripe as one row ahead of the playing-row badge and finds this confusing ("Sinn nicht erfassen"). Operator's decision: remove `.schedule-row--next` entirely; only the playing-row gets the visual marker.

Discovery Session Brief `discovery-2026-05-28-timer-post-e11s10-s12-bugs` (Tier-2 cycle-2 PASS, rubric_version 2026-03-30; operator-validated 2026-05-28) drives the per-symptom DEC-22 routing.

This Story ships **before** Story E11S14 to keep the changes to `ScheduleRow.svelte` strictly subtractive (no merge conflict with E11S14's label-rendering additions; see § Notes).

## Acceptance Criteria

> All acceptance criteria are observable behaviour. Implementation approach is Delivery's choice; this Story specifies the WHAT.

### Symptom 1 — Audio activate-fire correctness

- [ ] **AC1 — Audio activate fires for the entry that just started playing.** Whenever the engine detects that the playing entry has changed (the audio-fire gate triggers on `activeEventIndex` transition during a running tick stream), the activate-audio event corresponds to the entry at the new `playingIndex`, NOT the entry at `activeEventIndex`. Specifically: when Phase-1-Round-1 starts at its scheduled wall-clock time, the start-sound (per the existing `getAudioEventOnActivate` classification for ROUND entries) fires. When the round-following pause becomes playing, the pause music starts (per the existing classification for REGULAR-BREAK entries).
- [ ] **AC2 — Audio deactivate continues to fire for the previously-playing entry.** The existing deactivate path (via `lastPlayingIndex`) is preserved unchanged. When Phase-1-Round-1 ends and the playing index transitions to the following pause, the round-end-sound (per the existing `getAudioEventOnDeactivate` classification for ROUND entries) fires for Phase-1-Round-1.
- [ ] **AC3 — Audio classification is unchanged.** `getAudioEventOnActivate` and `getAudioEventOnDeactivate` return the same audio event types they returned before this Story (ROUND → START / END sound, REGULAR-BREAK → PAUSE music start / stop, ADDITIONAL break → silent). Only the index used to look up the entry whose audio fires changes.
- [ ] **AC4 — First-tick init-suppression preserved.** E11S10's first-tick baseline behavior is preserved: when the engine transitions from a non-running state into the running mode, the first tick records `lastFiredActiveIndex` and `lastPlayingIndex` without firing any audio. AC1–AC3 take effect on the second and subsequent ticks.

### Symptom 2 — Schedule column-width regression

- [ ] **AC5 — Schedule table fills the available container width.** Below the sticky header strip, the schedule table renders across the full available width of the page (or the schedule-container, if E11S11 nested it). The right portion of the page is not visually empty next to the schedule data rows.
- [ ] **AC6 — Column headers align over their cells.** The "RUNDE", "HALLENUHR-ZEIT", and "STATUS" column headers in the schedule table header row are horizontally positioned directly above their respective data-cell content in each schedule row. The header row and the data rows share the same column structure.

### Symptom 3 — Blue marker on playing row (drop `--next`)

- [ ] **AC7 — `.schedule-row--next` CSS class and visual treatment are removed.** The schedule table no longer applies the `.schedule-row--next` left-border + light-blue background combination to the next-upcoming row. No row in the table renders the previous "one-ahead" blue stripe.
- [ ] **AC8 — `isNext` prop and binding chain are removed.** The `isNext` prop on `ScheduleRow.svelte`, the `isNext` binding at the `App.svelte` call-site, and the next-upcoming index derivation (e.g. `getNextUpcomingIndex` in `App.svelte`) are removed. The data flow no longer carries a "which row is next" signal at all.
- [ ] **AC9 — `.schedule-row--playing` keeps its visual prominence; Delivery may optionally add a left-border stripe.** The playing row's existing background tint + bold text are preserved. Delivery MAY add a left-border stripe on `.schedule-row--playing` to match the operator's "blue stripe = current row" mental model. Whether the stripe is added is Delivery's UX choice; the impl-report attests the choice.

### Error-handling (mandatory category)

- [ ] **AC10 — Silent activate when no entry is currently playing.** When the audio-fire gate triggers but `playingIndex === -1` (the only normal-operation case is the pre-tournament-start gap before any scheduled entry has been reached), no activate-audio fires; the existing `if (entry)` guard at `App.svelte:449` handles this silently because `effectiveSchedule()[-1]` is `undefined`. The deactivate path is unaffected.
- [ ] **AC11 — Regression guard on the previously-correct deactivate behaviour.** The deactivate-audio flow that was working correctly before this Story (round-end fires when transitioning to the following pause, pause-stop fires when transitioning to the next round) is asserted by a fresh test so AC1's fix does not regress it.
- [ ] **AC12 — Audio-events not fired for ADDITIONAL break entries.** Entries with `breakType === 'ADDITIONAL'` (intra-phase breaks AND inter-phase Phasen-Pause entries) continue to be silent: no activate-audio and no deactivate-audio fires when transitioning into or out of them. (This invariant is unchanged from E11S04 classification per AC3, but is asserted as a regression guard.)

## Out of Scope

- **Last-ROUND END_SOUND at tournament end.** When the last ROUND finishes (the entry whose `effectiveTime <= now` and which has no successor entry), the existing `countdownEngine.resolveActiveEvent` semantics keep `playingIndex` on the last entry (it does not transition to `-1`) AND `activeEventIndex` becomes `-1` BEFORE the last entry ends, which causes the `App.svelte:432` activate-fire gate (`activeEventIndex !== -1`) to be already blocked at the moment the last entry ends — so no `END_SOUND` deactivate fires for the last ROUND today. This Story is minimal-invasive and does NOT change the `countdownEngine` semantics or add a tail-detector at `onTick`. A future Story may address tournament-end audio if operator priority demands; this Story's AC1–AC3 audio-fix is sound for every event boundary EXCEPT the very last one. Documented limitation.
- **Auto-PLAYING after Dialog confirm** (E11S10 D-1 shipped — preserved unchanged).
