# Story E42S02: Fix — `GET /admin/` returns HTTP 404 after Spring Boot 4 migration; restore SPA delivery + close end-to-end test gap

## User Story

**As a** Tournament Manager organizer (or any end user) typing `http://<host>:8080/admin/` into a browser after authenticating via HTTP Basic,
**I want** the request to be answered with `HTTP 200` carrying the Vite-built Admin-SPA shell HTML,
**so that** the administration UI loads and I can manage tournaments — instead of an HTTP 404 that blocks the only end-user entry point into the application.

---

## Context

### Incident

On 2026-05-02, immediately after the Spring Boot 4 / Spring Framework 7 migration (E42S01, commit `5dc6802`, merged same day) and on the user's first NetBeans `spring-boot:run` debug start, `http://127.0.0.1:8080/admin/` returned HTTP 404. Empirical curls (with valid HTTP Basic credentials) reproduced the symptom:

| Request | Status | Notes |
|---|---|---|
| `GET /admin/` (auth) | **404** | Reproduction case |
| `GET /admin/index.html` (auth) | **404** | Direct static path — bypasses `AdminSpaController` forward |
| `GET /score/test` (public) | **200** | Static-resource handler functional generally |
| `GET /display/overview` (public) | **200** | Different controller, different forward pattern |
| `GET /timer/tournaments/<uuid>` (public) | **200** | Direct `ClassPathResource` read |

All five surfaces (`/admin/`, `/admin/index.html`, `/score/test`, `/display/overview`, `/timer/tournaments/{id}`) hit the same running Spring Boot 4 instance. Auth wall is not the cause: `SecurityConfig.java:158` declares `/admin/** .authenticated()` and HTTP Basic returns `401` for missing credentials, not `404` — the user reproduced after a successful login dialog.

### Empirical pattern divergence (Discovery investigation seed — non-prescriptive)

Three controllers serve Vite-built SPA shells in `vvwt-tm-web`:

- `AdminSpaController` (`de.vvwt.tm.web.AdminSpaController:60-77`) returns `forward:/static/admin/index.html` — **fails** with 404.
- `DisplayViewController` (`de.vvwt.tm.web.DisplayViewController:67-90`) returns `forward:/display/index.html` (no `/static/` prefix) — **works** with 200.
- `TimerViewController` (`de.vvwt.tm.web.timer.TimerViewController`) returns the file via `ResponseEntity.body(new ClassPathResource("static/timer/index.html"))` — **works** with 200.

Spring Boot mounts `classpath:/static/` on URL `/` (NOT `/static/`); the Display controller's Javadoc lines 60-65 explicitly document this. The `/static/` prefix in `AdminSpaController`'s forward target is therefore semantically incorrect against the URL space exposed by the static-resource handler. Whether this construct ever resolved correctly under Spring Boot 3 (and was tightened in Spring Framework 7) or whether it was always-fragile-but-tolerated is a question for Delivery — the root-cause confirmation, the candidate fix shape selection, and the actual fix all belong to Delivery per Bug-Triage discipline.

### Test gap that allowed this to ship

Existing `AdminSpaController` tests (slice + IT pair per DEC-38 / DEC-44) verify the controller method returns the expected forward string but do NOT exercise actual SPA delivery (HTTP request → forward resolution → static-resource serving → HTML body). E42S01's PR #165 merged with these tests passing because the contract being tested was the controller-method-return value — not the end-user-observable behavior. Closing this test gap is mandated by AC2 below.

### Delivery investigation toolbox (non-prescriptive)

Discovery does not prescribe the fix shape. Candidate diagnostic + fix mechanisms Delivery may consider (without obligation to use any specific one):

- Mirror DisplayViewController's pattern (`forward:/admin/index.html` without `/static/` prefix).
- Reconfigure `spring-boot-maven-plugin:run` `addResources` or Spring `static-locations`.
- Use `ClassPathResource` direct read like `TimerViewController`.
- **Bisection via revert of E42S01** is an explicitly allowed Bug-Triage tool (same-day-regression standard practice; per Discovery brief Trade-off T-7).

The empirical pattern divergence above is a strong investigation seed but is NOT the answer.

## Acceptance Criteria

### Behavior contract

- [ ] **AC1 (Reproduction RED-first)**: Add a failing integration test in `vvwt-tm-web/src/test/java/de/vvwt/tm/web/` (annotation per DEC-38 amended by DEC-44 — `@SpringBootTest(webEnvironment = RANDOM_PORT, classes = TournamentManagerApplication.class)`) that, with valid HTTP Basic credentials, performs `GET /admin/` and asserts `HTTP 200`. Test MUST be authored, committed, and observed RED in the impl-report's git log BEFORE any fix code lands (per DEC-22 Iron Law). Same RED-first sequence applies to AC2.

- [ ] **AC2 (End-user-observable behavior — closing the test gap)**: The same test (or a sibling test in the same IT class) MUST retrieve the HTTP response body and assert that it contains:
  - the literal substring `<div id="app">` (verified empirically present in `target/classes/static/admin/index.html` line 11), AND
  - a substring matching the regex `/admin/assets/index-.*\.js` (Vite-emitted script reference).
  Asserting only the controller-method return value (`"forward:/static/admin/index.html"` or whatever replaces it) is INSUFFICIENT and does NOT satisfy AC2. The test MUST exercise the full HTTP request → response cycle.

- [ ] **AC3 (Pre-controller direct static resolution)**: A second test method in the same IT class performs `GET /admin/index.html` (with valid auth) and asserts `HTTP 200`. This bypasses the `AdminSpaController` forward and verifies that the underlying static resource is reachable through Spring's resource handler chain. Both AC2 and AC3 must PASS post-fix.

### Regression preservation

- [ ] **AC4 (Existing tests preserved)**: All existing `AdminSpaController` tests (`AdminSpaControllerTest` + any controller-slice tests) continue to PASS after the fix. The fix MUST NOT delete or weaken existing coverage; if existing coverage is incompatible with the fix (e.g., asserts the now-incorrect forward string literal), the existing assertion is updated in the same commit, with the change explained in the impl-report.

- [ ] **AC5 (No regression on adjacent surfaces)**: A smoke verification in the impl-report confirms that `GET /score/test` (public) still returns `HTTP 200`, `GET /display/overview` (public) still returns `HTTP 200`, and `GET /timer/tournaments/{id}` (public, any UUID) still returns `HTTP 200`. This is a **read-only verification**, not a new automated test — the existing E25/E26 test suites already cover these paths; the impl-report cites the relevant test classes by name and confirms their PASS status in the same Maven run as the fix.

### Security & governance

- [ ] **AC6 (Auth wall preserved)**: `SecurityConfig.java:158-163` `/admin/** .authenticated()` rule remains unchanged. Story scope does NOT permit relaxing the `/admin/` auth requirement as a workaround. Unauthenticated `GET /admin/` continues to return `HTTP 401` with HTTP Basic challenge.

- [ ] **AC7 (Module boundary)**: Any code change is confined to the `de.vvwt.tm.web` Modulith module per DEC-40 Clause A (or to `vvwt-tm-web/pom.xml` / `vvwt-tm-web/src/main/resources/` if a build-config or static-resource fix is selected). No new entry is added to `web.allowedDependencies` (the `LandingController` of E43S01 is the only other web change in this Discovery; that story is separately scoped).

- [ ] **AC8 (Compiler hygiene + format)**: `mvn -pl vvwt-tm-web verify` passes with `-Xlint:all,-serial` + `failOnWarning=true` per DEC-29 and Spotless `google-java-format` AOSP-style per DEC-30 across all modified files.

### Bug-Triage governance

- [ ] **AC9 (Root-cause analysis in impl-report per DEC-27)**: The impl-report (`contexts/artefacts/impl-reports/E42S02.impl-report.md`) MUST include a **Root Cause** section documenting (a) what mechanism actually caused the 404 (confirmed empirically, not hypothesized), (b) which candidate fix shape was chosen and why over alternatives (Display-pattern mirror, Timer-pattern, build-config, revert-bisection-confirmed-then-forward-fix, or other), and (c) whether the bug was a Spring-Boot-4-migration regression (forward construct stopped working) or a pre-existing latent defect (forward construct never worked but happened to be tolerated). An impl-report without a substantive Root Cause section fails AC9.

- [ ] **AC10 (Test gap explanation)**: The impl-report explicitly identifies the prior test gap (existing tests asserted controller-method-return-string only, did not exercise SPA delivery end-to-end) and states how AC2 + AC3 close this gap such that an analogous defect cannot ship undetected through future framework migrations.

## Notes

**Risk for Delivery — false-PASS via insufficient assertion.** AC1 + AC2 + AC3 MUST be authored such that AC2 cannot be satisfied by stubbing the response body or by re-pointing the test fixture at a hand-written HTML file in `src/test/resources/`. The test must hit the actual ApplicationContext-served static resource. If the test infrastructure makes this difficult, escalate rather than weakening the AC.

**Risk for Delivery — partial fix masking cluster regressions.** AC5's smoke verification of `/score/`, `/display/`, `/timer/` is the cluster-no-regression safeguard. If any of those three surfaces is also broken on the fix branch (Discovery's empirical baseline 2026-05-02 says they are not — but Delivery may be on a different commit), the fix is incomplete and the Story scope must be reconsidered (escalate to Discovery rather than silently expanding scope).

**Discovery investigation seed (NOT prescription).** The empirical observation that `DisplayViewController` works with `forward:/{name}/index.html` (no `/static/` prefix) while `AdminSpaController` fails with `forward:/static/admin/index.html` strongly suggests the `/static/` prefix is the operative anomaly. Delivery is free to confirm or refute this hypothesis as part of root-cause investigation. Mirroring the Display pattern is one valid fix shape among several; Discovery does not mandate it. The Display controller's Javadoc lines 60-65 explicitly document the URL-mount semantics that may be relevant.

**Bisection allowed.** Per Discovery brief Trade-off T-7, reverting E42S01 (commit `5dc6802`) on a throwaway branch to confirm whether `/admin/` worked under the prior Spring Boot 3.4.7 baseline is an explicitly allowed Bug-Triage diagnostic. If revert restores `/admin/`, the regression is in Spring Boot 4's view-resolution behavior; if revert does NOT restore `/admin/`, the bug is a pre-existing latent defect that the Spring 3 fallback chain happened to tolerate. Either result is informative; neither prescribes the fix.
