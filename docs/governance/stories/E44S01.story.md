# Story E44S01: Brand-asset distribution mechanism — per-Vite-app `public/` directories, sync + verify scripts, Maven `verify` wiring, gitignore migration for `vvwt-info-server/static/info/`

## User Story

**As a** Tournament Manager developer who needs to deploy or refresh VVW brand assets across the multi-module project,
**I want** a single shell command (`scripts/sync-brand-assets.sh`) that mirrors `handoff/` masters into all consuming Vite-app `public/` directories plus the score-tablet static directory, plus an automated build-time check (`scripts/verify-brand-assets.sh` wired into Maven `verify`) that fails the build when any vendored copy drifts from its master,
**so that** every consumer module ships byte-identical brand assets without manual file-by-file copying, drift between modules is mechanically prevented, and HANDOFF refreshes (a future Discovery Story will ingest HANDOFF v2) propagate via one explicit invocation rather than via 4+ silent edits.

---

## Context

E44 is the VVW Brand Rollout (Phase 1). The Discovery Session Brief established that the asset-hosting mechanism is **per-module vendored** (Brief D-1, T-1 alternative analysis): each Vite app owns a `public/` directory that holds its brand assets, and the score-tablet (legacy Mustache + DEC-19 ES5 carve-out) gets its own `vvwt-tm-web/src/main/resources/static/score/` directory. The alternative of a central `vvwt-brand-assets` Maven module was evaluated and rejected (Vite/npm impedance, anti-Modulith signal); the alternative of using `handoff/` directly via Vite aliases was also evaluated and rejected (`handoff/` is semantically a designer-handoff folder, not a runtime source).

The per-module-vendored choice creates a structural drift risk: 4+ copies of the same asset must stay byte-identical to the `handoff/` master, and HANDOFF refreshes (manual per Brief D-9 — no auto-hook) must be propagated explicitly. E44S01 closes this risk by establishing the one-time mechanism that all subsequent brand-asset work (E44S02, E44S03, future print/certificate Story, future SOD Story) consumes.

E44S01 is also the natural home for a one-shot housekeeping fix that empirical Discovery audit revealed: `vvwt-info-client/src/main/ui/vite.config.ts` writes its `outDir` directly to `vvwt-info-server/src/main/resources/static/info/` with `emptyOutDir: true` — this means every `npm run build` in `vvwt-info-client` wipes the entire `static/info/` directory of `vvwt-info-server`. Today, three files are committed there (`assets/index-CpLogeDW.css`, `assets/index-DD-if4wq.js`, `index.html`) — committed build output that the next build will silently destroy. The Discovery decision (human-validated) is to make `vvwt-info-server/src/main/resources/static/info/` a gitignored build-output directory; E44S01 deletes the currently committed files in the same commit that adds the gitignore entry, completing the migration atomically.

The story is the **prerequisite** for E44S02 (TM rollout) and E44S03 (Info rollout) — both parallelisable after E44S01 completes. Without E44S01's `public/` directories and verify mechanism, E44S02/E44S03 would have to invent the convention ad-hoc and ship the verify-script as a side effect of one of them, defeating the "one-time clean mechanism" benefit (Brief T-5).

## Acceptance Criteria

- [ ] **AC1 (testing — RED-first per DEC-22)**: A test asserts the existence of `public/` directories in all 4 Vite roots **plus** the score-tablet static directory: `vvwt-tm-web/src/main/ui/public/`, `vvwt-tm-web/src/main/ui-timer/public/`, `vvwt-tm-web/src/main/ui-display/public/`, `vvwt-info-client/src/main/ui/public/`, `vvwt-tm-web/src/main/resources/static/score/` (Brief S-3 (a) + (b) — both directory conventions are S01 deliverables). The test fails before S01's directory-creation step runs (RED) and passes after (GREEN). Test mechanism is Delivery's choice (Maven plugin, Java IT, bash test in `scripts/`); the test must be invoked as part of `mvn verify`.
- [ ] **AC2 (testing — RED-first per DEC-22)**: A test asserts that `vvwt-prj/scripts/sync-brand-assets.sh` and `vvwt-prj/scripts/verify-brand-assets.sh` exist and are executable. RED before S01 creates them, GREEN after.
- [ ] **AC3 (testing — RED-first per DEC-22)**: A test asserts the behavioural contract of `scripts/verify-brand-assets.sh`: when every vendored asset's sha256 matches its `handoff/` master, exit 0; when at least one vendored asset's sha256 differs from its master, exit 1 with the diverging path printed to stderr. The test sets up both pass and fail fixtures; both branches are covered.
- [ ] **AC4 (governance)**: `scripts/sync-brand-assets.sh` reads from `handoff/` (logos, icons, favicons subdirectories) and copies into the 4 Vite `public/` directories plus `vvwt-tm-web/src/main/resources/static/score/`, **preserving the original filenames verbatim per Brief Q-1 (no renaming, no normalisation, no extension change)**. Output to stdout lists every synchronised file with its destination module-relative path (per Brief Q-5). The script is idempotent: re-running on an already-synchronised tree modifies no file content (file mtime updates are acceptable; content changes are not).
- [ ] **AC5 (governance)**: The `vvwt-info-server/src/main/resources/static/info/` directory is gitignored in the same commit that deletes the currently committed contents (`assets/index-CpLogeDW.css`, `assets/index-DD-if4wq.js`, `index.html`). An optional `README.md` may be added inside the directory and excluded from the gitignore to document the build-output convention; this is a Delivery choice. After S01, `git status` shows no tracked files under `vvwt-info-server/src/main/resources/static/info/` other than the optional README.
- [ ] **AC6 (governance)**: No file under `handoff/` is modified, added, or deleted by S01 (Brief S-5 — HANDOFF.md is single source of truth). `git diff handoff/` is empty after S01.
- [ ] **AC7 (governance)**: `scripts/verify-brand-assets.sh` is wired into `mvn verify` at parent-POM level (e.g., via `exec-maven-plugin` bound to the `verify` phase). On verification failure, the Maven build fails with a non-zero exit code; the failure surfaces the diverging path so a developer can run `scripts/sync-brand-assets.sh` to repair.
- [ ] **AC8 (error-handling)**: When `scripts/sync-brand-assets.sh` is invoked and any required source is missing (the `handoff/` directory itself, the `HANDOFF.md` file, OR any of the three required subdirectories `handoff/logos/`, `handoff/icons/`, `handoff/favicons/` is missing or empty), the script exits with a non-zero status and prints a clear actionable error message to stderr (e.g., `"handoff/icons/ missing or empty — re-add the brand-asset handoff folder before syncing"`). Likewise: if any destination write fails (destination directory read-only, disk full, permission denied), the script exits non-zero with an actionable error message naming the failed path. Silent failure or zero-exit-with-no-output is a defect.
- [ ] **AC9 (compliance)**: Two compliance dimensions are addressed:
  - **(a) Cross-platform shell portability** — both shell scripts are POSIX-compatible bash (no `bashism`s like `[[ ]]` arithmetic-context-dependent semantics, no Linux-only `readlink -f` without macOS fallback). The scripts run on both Linux and macOS without modification (verifiable via `shellcheck` clean run if Delivery chooses that mechanism).
  - **(b) No internet-facing build-output residue** (DEC-42 internet-facing posture per Brief C-7) — the gitignore entry added in AC5 is the **mechanical primary gate**: `vvwt-info-server/src/main/resources/static/info/` is excluded from version control, so subsequent `npm run build` invocations (which `emptyOutDir: true` wipes the directory before each build) cannot leave committed residue. Verifiable post-S01 by `git ls-files vvwt-info-server/src/main/resources/static/info/` returning empty (or only the optional README). A commit-hook that rejects `*.css` / `*.js` / `index.html` additions under that path is OPTIONAL hardening (Delivery's choice), not a mandatory compliance gate — the gitignore is sufficient.
- [ ] **AC10 (testing)**: After S01 completes, running `scripts/sync-brand-assets.sh` on a fresh checkout populates each destination directory with the appropriate brand-asset subset:
  - **vvwt-tm-web/src/main/{ui,ui-timer,ui-display}/public/** (3 directories): TM lockup `vvw-tm-logo.svg` + 2 SVG hex icons + 10 PNG favicons (13 files each)
  - **vvwt-info-client/src/main/ui/public/**: Info lockup `vvw-info-logo.svg` + 2 SVG hex icons + 10 PNG favicons (13 files)
  - **vvwt-tm-web/src/main/resources/static/score/**: 2 SVG hex icons + 10 PNG favicons (12 files; no lockup `<img>` is required by the Mustache score-tablet — it gets only favicons; if S02 later adds a lockup `<img>` per Brief D-4, the asset can be added in S02's PR)
  - The SOD lockup `vvw-sod-logo.svg` (per Epic Out-of-Scope) MAY be mirrored uniformly to all destinations (harmless dead-weight) OR skipped — Delivery's choice; the impl-report records which choice was made.
  
  Re-running `scripts/verify-brand-assets.sh` immediately afterwards exits 0. This end-to-end behaviour is verifiable via a single manual or scripted invocation pair.
- [ ] **AC11 (governance)**: The `.gitignore` (root or `vvwt-tm-web/.gitignore`, whichever is current convention — verify before edit) confirms `dist/`, `dist-timer/`, `dist-display/` are excluded from version control (Brief S-3 (f)). If they are already gitignored (the empirical Discovery audit indicates yes — they are at root `.gitignore` lines 30/35/40), no edit is required and the impl-report records the audit confirmation. If any of the three is NOT gitignored, S01 adds the missing pattern in the same commit as the static/info/ migration (AC5).
- [ ] **AC12 (testing — RED-first per DEC-22, H-1 spike verification)**: For at least one Vite root (Delivery's choice — recommend `vvwt-info-client/src/main/ui/` because its end-to-end flow involves the cross-module emptyOutDir behaviour and therefore exercises the most fragile path), running `npm run build` after `scripts/sync-brand-assets.sh` produces a build output (the configured Vite `outDir` for that root) that contains the brand assets at their expected output paths, empirically confirming the Vite `public/`-directory propagation convention (Brief H-1 verification path). Result documented in the impl-report (which root, which assets verified, what paths they appeared at). If H-1 turns out to be FALSE (Vite does NOT auto-propagate `public/`), Delivery escalates to Discovery before completing S01 — the asset-distribution mechanism would need a different shape.
- [ ] **AC13 (error-handling — symmetric to AC8)**: When `scripts/verify-brand-assets.sh` is invoked and the `handoff/` directory or `HANDOFF.md` is absent, the script exits with a non-zero status and prints a clear actionable error message to stderr (e.g., `"handoff/ directory missing — verify cannot proceed; re-add the brand-asset handoff folder before verifying"`). This mirrors AC8's contract for `sync-brand-assets.sh`. Both scripts have symmetric missing-source error handling.

## Out of Scope

- Adding any `<link rel="icon">` markup to any HTML/Mustache file (E44S02 + E44S03).
- Adding any lockup `<img>` references in any UI component (E44S02 + E44S03).
- Modifying any `<title>` element in any `index.html` or Mustache template (E44S02 + E44S03).
- CSS-token introduction (`--vvw-blue`, `--vvw-yellow`, `--vvw-ink`) — the tokens themselves are introduced at the consumer level in E44S02/E44S03 conditional on the H-2/H-3 audit.
- SOD (`vvwt-slotopt-dispatcher`) asset distribution — out of E44 scope per D-3.
- Mustache print/certificate template asset distribution — out of E44 scope per D-4.
- Any modification of `handoff/` itself.
- Auto-hook installation (pre-commit, post-merge) for refresh — explicitly forbidden per D-9.
- Cross-platform Windows support for the bash scripts (Discovery did not require it; if needed later, a separate Story).

## Notes

**Parent-POM hygiene inheritance**: AC7 wires `verify-brand-assets.sh` via `exec-maven-plugin` (or equivalent) at parent-POM level. The wiring introduces no new Java code — `exec-maven-plugin` is config-only. If Delivery chooses a custom-Mojo route instead, the new Mojo inherits parent-POM baselines DEC-29 (`-Xlint:all,-serial` + `failOnWarning=true`) and DEC-30 (Spotless AOSP) without per-module override.

**Mechanism choices left to Delivery** (Story is behavioural, not prescriptive):
- The exact RED-first test mechanism for AC1/AC2/AC3 (Maven plugin, JUnit IT, bash test, `shellcheck` integration) is Delivery's choice as long as the test is executed by `mvn verify` and visibly fails before S01 implementation lands.
- The exact Maven plugin used for AC7 wiring (`exec-maven-plugin`, `frontend-maven-plugin`, `maven-antrun-plugin`, custom plugin) is Delivery's choice; the contract is "shell script runs in `verify` phase, non-zero exit fails the build, error message identifies the diverging path".
- The location of an optional `README.md` inside `vvwt-info-server/src/main/resources/static/info/` (AC5) is Delivery's choice; it is purely documentation of the gitignore convention and may be omitted if Delivery prefers a leaner directory.

**Brief context** (Discovery Session Brief, validated by human 2026-05-02): per-module-vendored mechanism is the chosen asset-hosting model (D-1); refresh is manual (D-9); two structurally different Vite output patterns exist (TM = vite outDir → `dist*/` → maven-resources copy; Info = vite outDir → sibling-module `static/info/` directly with `emptyOutDir: true`); the Info-pattern emptyOutDir behaviour is the empirical reason for the gitignore migration in AC5.

**Daemon-pull risk note** (Discovery memory `feedback_daemon_overwrites_untracked.md`): If the Delivery daemon pulls `origin/staging` mid-session and the `handoff/` directory is reverted by the pull, the build will fail at `mvn verify` (AC8 surface). Recovery is the same as Discovery used: re-add `handoff/`, commit, push.
