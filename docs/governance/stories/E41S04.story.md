# Story E41S04: HTTP client + bootstrap (DispatcherClient + GET /api/algorithms query + POST /api/register-key flow + DEC-43 D3 admin warning surface on stderr + WARN-log)

## User Story

**As a** newly-launched standalone-worker process at startup, before keypair generation,
**I want** to query `GET /api/algorithms` against the configured dispatcher (DEC-43 D2 announcement endpoint), validate that my configured `--signing-algorithm` (default `Ed25519`) is in the announced non-deprecated list, surface a DEC-43 D3 admin warning via stderr + WARN-log if the chosen algorithm has a non-null `deprecation_date`, then register my public key via `POST /api/register-key` with the chosen `algorithm` field set per the delivered RegisterKeyRequest DTO,
**so that** I am DEC-43 D2/D3 compliant on the client side and successfully registered with the delivered E37/E40 dispatcher.

---

## Context

Per Brief D-5 (option X): full DEC-43 D2/D3 client-side scope at V1. Worker queries announcement endpoint at startup; picks per CLI flag; surfaces D3 admin warning when applicable.

Per Brief D-6 (option β): CLI flag `--signing-algorithm <id>` default `Ed25519`. Validation against announced non-deprecated list; mismatch → fail-fast.

Per Brief D-7 (option ii): D3 warning channel = stderr + WARN-log. Both channels populated. No advisory exit code.

Per Brief D-10 + O-6 (iii): RegisterKey delivered request body carries `algorithm` field. Implementer reads `vvwt-slotopt-dispatcher/src/main/java/de/vvwt/slotopt/dispatcher/identity/RegisterKeyRequest.java` source for exact DTO shape.

Per Brief C-21 + D-9: this story depends on E40S02 (algorithm announcement endpoint — delivered, PR 140 merged 2026-04-27) — DEC-43 D2 query lands on the dispatcher's `GET /api/algorithms` endpoint.

This story does NOT yet author the runtime polling loop or result submission — those are E41S05 scope.

### Story-specific ACs

- [ ] **AC-DISPATCHER-CLIENT-INTERFACE**: `de.vvwt.slotopt.standalone.http.DispatcherClient` interface declared with methods:
  ```java
  AnnouncedAlgorithmsResponse fetchAnnouncedAlgorithms() throws DispatcherException;
  RegisterKeyResponse registerKey(RegisterKeyRequest request) throws DispatcherException;
  ```
  Both methods return DTOs that mirror the delivered dispatcher DTO field shapes (per Brief D-10). Authored RED-first.
- [ ] **AC-DEFAULT-DISPATCHER-CLIENT**: `de.vvwt.slotopt.standalone.http.internal.DefaultDispatcherClient` impl per DEC-35-by-analogy. Uses JDK 11+ `java.net.http.HttpClient` (no third-party HTTP lib needed; per Brief C-2 minimal-dependency). Constructor receives `URI dispatcherUrl` + `Duration httpTimeout` from `WorkerConfig`. RED-first authored.
- [ ] **AC-DISPATCHER-EXCEPTION** (error-handling category): `de.vvwt.slotopt.standalone.http.DispatcherException extends RuntimeException` with `(int httpStatus, String message, Throwable cause)` constructor. Captures non-2xx HTTP responses + IOExceptions. RED-first authored.
- [ ] **AC-FETCH-ALGORITHMS-WIRE**: `fetchAnnouncedAlgorithms()` performs `GET /api/algorithms` and parses response per the delivered E40S02 wire shape (JSON array of `{algorithm_id, display_name, deprecation_date, parameters}`). Implementer reads `vvwt-slotopt-dispatcher/src/main/java/de/vvwt/slotopt/dispatcher/crypto/AnnouncedAlgorithm.java` for exact field shape (per Brief D-4). RED test mocks HTTP transport + asserts deserialization round-trip.
- [ ] **AC-ALGORITHM-VALIDATION** (error-handling category): At startup, after `fetchAnnouncedAlgorithms()`, validates that `WorkerConfig.signingAlgorithm` (default `Ed25519`) is present in the announced list AND that its `deprecation_date` is null OR in the future per DEC-43 D2 free-choice rule. Mismatch (algorithm not announced, or deprecated past deadline) → fail-fast with explicit error before keypair generation. RED test scenarios:
  - chosen = `Ed25519`; announced = `[{Ed25519, null}]` → SUCCESS
  - chosen = `ML-DSA-65`; announced = `[{Ed25519, null}]` → fail-fast: "algorithm not in announced list"
  - chosen = `Ed25519`; announced = `[{Ed25519, deprecation_date: "2020-01-01"}]` → fail-fast: "algorithm deprecated past deadline"
- [ ] **AC-DEC43-D3-ADMIN-WARNING-SURFACE** (per Brief D-7 option ii): When chosen algorithm has `deprecation_date != null` AND in the future (warning, not fail), emit:
  - One WARN-level structured log line via slf4j with fields: `event=algorithm_deprecation_warning, algorithm=<id>, deprecation_date=<date>, recommended_migration=<comma-separated-non-deprecated-algos>`
  - One stderr line in human-readable form: `WARNING: Signature algorithm '<id>' will be deprecated on <date>. Recommended migration targets: <list>. Please plan migration before deadline.`
  Worker continues running normally. RED test asserts both channels are populated when warning triggers; neither populated when warning does not trigger (deprecation_date null).
- [ ] **AC-RECOMMENDED-MIGRATION-DERIVATION** (per Brief C-14 + DEC-43 D3 boundary): The "recommended migration target" in the D3 warning is derived as: the announced non-deprecated algorithms (excluding the chosen-but-deprecated one). RED test asserts derivation logic with mock announced lists.
- [ ] **AC-REGISTER-KEY-WITH-ALGORITHM**: After algorithm validation + optional D3 warning, `registerKey(RegisterKeyRequest)` is invoked with the chosen algorithm in the `algorithm` field per delivered RegisterKeyRequest DTO (per Brief O-6 (iii)). Implementer reads `vvwt-slotopt-dispatcher/src/main/java/de/vvwt/slotopt/dispatcher/identity/RegisterKeyRequest.java` for exact field shape. RED test asserts request body shape.
- [ ] **AC-FAIL-FAST-DISPATCHER-UNREACHABLE** (error-handling): When `GET /api/algorithms` fails (network error, HTTP 5xx, JSON parse error), `DispatcherException` is thrown with explicit cause; worker exits with non-zero code (no retries at startup — operator must verify dispatcher availability). RED test asserts exit-code matrix.
- [ ] **AC-DEC43-PAST-DEPRECATION-FAIL-FAST** (per Brief Q-5 defensive fail-safe; consumer-side enforcement complementing dispatcher's HTTP 410 per DEC-43 D3): When `fetchAnnouncedAlgorithms()` returns chosen algorithm with `deprecation_date != null` AND `deprecation_date.atTime(LocalTime.MAX).atZone(ZoneOffset.UTC)` is in the past per worker's clock, worker fails-fast at startup BEFORE keypair generation OR register-key invocation: emits ERROR-level log + stderr line naming the deprecated algorithm + past deprecation date + exits non-zero. Avoids round-trip with dispatcher to learn the same fact. RED test scenarios: (a) Ed25519 with past deprecation_date → fail-fast at startup; (b) Ed25519 with future deprecation_date → WARN per AC-DEC43-D3-ADMIN-WARNING-SURFACE + continue; (c) Ed25519 with null deprecation_date → continue normally.
- [ ] **AC-OBSERVABILITY-EVENTS-BOOTSTRAP** (per E37S02 spec § (c) "Observability"): Bootstrap path emits structured slf4j events at INFO level for each milestone:
  - `event=worker_started` (at OptimizerWorkerMain entry; included keys: workerId may be null at this stage, configHash from WorkerConfig)
  - `event=algorithms_announced` (after fetchAnnouncedAlgorithms; included keys: count, algorithm_ids list)
  - `event=algorithm_picked` (after validation pass; included keys: algorithm_id, deprecation_date_iso-or-null)
  - `event=algorithm_deprecation_warning` (only if deprecation_date is non-null and future; included keys: algorithm_id, deprecation_date_iso, recommended_migration_targets list) — already covered by AC-DEC43-D3-ADMIN-WARNING-SURFACE
  - `event=key_registered` (after successful register-key response; included keys: workerId, algorithm_id)
  Each event has explicit RED test asserting log shape via slf4j test-binding (e.g., logback-test or memory appender).
- [ ] **AC-EXIT-CODE-BOOTSTRAP** (per E37S02 spec § (c) "Exit Codes"): Bootstrap-stage error exit codes follow E37S02 spec § (c) matrix; specifically:
  - dispatcher unreachable → exit code per spec § (c) "Exit Codes" entry for "dispatcher_unreachable"
  - chosen algorithm not in announced list → exit code per "algorithm_not_announced"
  - chosen algorithm past deprecation deadline → exit code per "algorithm_deprecated_past_deadline"
  - register-key returns HTTP 410 (race-condition deprecation crossing) → exit code per "registration_rejected_deprecated"
  Implementer reads E37S02 spec § (c) "Exit Codes" verbatim for the canonical matrix; RED tests assert each exit-code path.

## Notes

- JDK 11+ `java.net.http.HttpClient` is used to avoid third-party HTTP-client dependency (per DEC-3 minimal-dependency philosophy).
- Jackson is the Java JSON library of choice (already used by dispatcher); add as module-level dep.
- `AnnouncedAlgorithm` field shape on the wire uses snake_case (per E40S02 spec — `algorithm_id`, `display_name`, `deprecation_date`, `parameters`). Worker-side DTO uses camelCase Java fields with `@JsonProperty` annotations OR snake-case-naming-strategy on the ObjectMapper.
- Per Brief Q-5 fail-fast philosophy: any startup error (dispatcher unreachable, algorithm validation failure, HTTP 410 at registration) causes immediate exit. No retries at startup. Operator's responsibility to verify dispatcher availability before launching worker.
- The DEC-43 D3 stderr line uses plain-language phrasing for operator visibility (per Brief Q-6 visibility-without-blocking); the WARN log uses structured key-value fields for log-aggregation pipelines.
