# Story: Fix: Mustache DRY gate fails on staging — remove duplicated document skeleton (and other duplication) from the print templates

## User Story

**As a** developer and as the Delivery pipeline,
**I want** the print templates to share their common HTML document skeleton instead of repeating it in every page,
**so that** the Mustache jscpd DRY gate passes, `mvn verify` on staging is green again, and future print pages cannot drift apart in their skeleton.

---

## Context

**Symptom (reproduced 2026-10-04 on staging HEAD fb2e0f08):** `npm run check-jscpd-mustache` (wired into `mvn verify` of `vvwt-tm-web`, E70S02) reports `BUILD FAILURE: 1 Mustache clone` — `print/activity-schedule.mustache` [lines 1–17] ↔ `print/laufzettel-no-matches.mustache` [lines 1–17], 103 tokens against `minTokens=100`. Because DEC-71 admits no pre-existing-failure allowance, every story's QA `mvn verify` FAILs (E58S07 was escalated on this).

**Root cause analysis:** the duplicated block is the HTML document skeleton (SPDX header comment, DOCTYPE, `<html lang>`, `<head>` with meta/title/stylesheet link, `<body>` opening, `{{> print-header}}`). All 7 templates under `templates/print/` repeat such a skeleton, in two variants:
- Variant A (index, error, print-layout): no viewport meta, plain `<body>`, `print-footer` with `v{{appVersion}}`.
- Variant B (activity-schedule, laufzettel, laufzettel-all, laufzettel-no-matches): viewport meta, `<body class="print-body">`; only activity-schedule has the `print-footer`.

`print/print-layout.mustache` is an unused skeleton copy. Neither the templates nor the jscpd configuration changed since the gate was activated (2026-05-31, jscpd 4.2.4 unchanged); why the gate was green earlier is not investigated (out of scope) — it is red at HEAD.

The E70S02 baseline additionally suppresses a pre-existing print duplicate pair (`print/laufzettel.mustache` ↔ `print/laufzettel-all.mustache`). Epic E70's Out of Scope defers pre-existing-duplicate remediation to a follow-up Discovery; this story is that sanctioned follow-up for the print templates (DEC-78 Clause G, operator decision D-6).

**Operator decisions (Discovery Session Brief 2026-10-04, human-validated):** fix by **refactoring**, not by adding a baseline suppression (D-2, T-1); rendered output stays unchanged (D-3); no new ignore entries (D-4); and while refactoring, the print templates are audited for further duplication, which is removed too (D-6, DRY).

---

## Acceptance Criteria

- [ ] AC1 (build-gate): After the story, `check-jscpd-mustache` (the `jscpd-mustache-templates` execution of `mvn verify`) reports zero unignored clones, and `templates/.jscpd.json` contains **no new or widened ignore entries** and no change to `minTokens` or other detection settings (DEC-78 Layer-C gate stays at full strength). The only permitted `.jscpd.json` edits are removing ignore entries that become stale through AC3 and updating the file's `"comment"` baseline documentation accordingly — a tightening, consistent with Brief S-2 ("no jscpd config changes" read as "no loosening") and D-4.
- [ ] AC2 (governance): The common HTML document skeleton of the print pages (DOCTYPE, `<html>`/`<head>` with meta, title and stylesheet link, body opening, print-header include, footer where present) is defined **once** and shared by every page template under `templates/print/`, using the Mustache mechanisms available in the project (partials or parent/block inheritance — Delivery's choice). No print **page** template — the six view templates listed in AC4 — contains its own copy of the skeleton anymore; the shared layout/partial itself (which may live under `templates/print/`) is excluded from this check.
- [ ] AC3 (governance): DRY audit (operator decision D-6): Delivery audits all templates under `templates/print/` for further duplicated markup (beyond the skeleton), using jscpd and manual review, and removes the duplication found by sharing it. **Every duplicate jscpd detects at the configured threshold (≥ minTokens) when run without the print ignore entries is removed** — this explicitly includes the baseline-suppressed pair `print/laufzettel.mustache` ↔ `print/laufzettel-all.mustache`, whose two ignore entries are then deleted from `templates/.jscpd.json`. If such a jscpd-detected duplicate cannot be shared without changing rendered output (AC4), Delivery STOPs and escalates (as in AC7) — it may not keep it on its own authority. Only below-threshold duplication found by manual review may be left in place, listed in the impl-report with the reason (e.g. sharing would make a template harder to understand — DEC-78 §Application Discipline). The audit result is determined fresh at delivery HEAD; this story carries no pre-computed duplication list.
- [ ] AC4 (governance): The rendered HTML of every print page (index, error, laufzettel, laufzettel-all, laufzettel-no-matches, activity-schedule) is unchanged apart from collapsed whitespace runs (whitespace between inline elements is not removed) and HTML comments (e.g. an additional SPDX header comment from a shared template file) — including the per-page differences that exist today (viewport meta, body class, presence/absence of the footer). Delivery verifies this by comparing the rendered output before and after the refactor for each page and documents the comparison in the impl-report. This comparison is a verification record in the impl-report, **not** a committed golden-master/snapshot test (characterization tests are forbidden — AC5).
- [ ] AC5 (testing): DEC-22 — new tests are written RED-first (they fail against the unmodified templates and pass after the change); characterization tests are forbidden (tdd.rules.md). At minimum, a test fails while any of the six print page templates (AC4) carries its own document skeleton and passes once the skeleton is shared (AC2). The jscpd gate itself is the RED artefact for AC1 (red at HEAD, green after). All existing print tests (e.g. PrintControllerIT, PrintControllerCommentLeakIT, PrintControllerSliceTest, LaufzettelPhase2EmptyRowsIT, PrintCssRulesTest) pass with their assertion intent unchanged. A source-reading guard whose target markup moves into a shared template (e.g. `PrintCssRulesTest`'s "no `{{> print-page-break}}` in laufzettel-all" check) is retargeted so it still guards the markup it protected — it must not pass vacuously.
- [ ] AC6 (build-gate): `mvn verify` run from the vvwt-prj root is BUILD SUCCESS (DEC-54 / DEC-71), with all jscpd, PMD and Spotless gates green — including the per-file SPDX license header on any new template file (DEC-76).
- [ ] AC7 (governance): The impl-report documents: the sharing mechanism chosen, what happened to `print/print-layout.mustache` (reused, or removed as dead code), the DRY-audit findings (AC3) and the `.jscpd.json` diff (only removals allowed). If sharing the skeleton is impossible without changing rendered output (AC4), Delivery STOPs and escalates instead of changing output or adding a suppression.

> All acceptance criteria must be verifiable.
