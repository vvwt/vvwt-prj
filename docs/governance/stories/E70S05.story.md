# Story E70S05: `qa-review` rubric-extension fixture validation — synthetic SRP / KISS-conceptual / YAGNI-feature / TDA violations

## User Story

**As an** operator + every Delivery agent + every Review Sub-Agent invocation,
**I want** the `qa-review` Step 10 (Clean Code Principles Compliance) rubric extension to be validated by RED-first fixtures asserting that each review-gated principle's check correctly FAILs a synthetic violation,
**so that** the rubric's extension is mechanically verified (not just prose-claimed), the Reviewer-Wisdom-Frage protocol is observable in practice, and a regression that silently weakens the rubric is detected at build time.

---

## Context

DEC-78 + Discovery-direct skill edits (S-2 in the Session Brief) add **Step 10** to `qa-review/SKILL.md` covering the review-gated principles: SRP, OCP, KISS-conceptual, YAGNI-feature, TDA. The skill text is binding for every qa-review invocation per DEC-78 Clause D. The framework rule §Application Discipline Clause 7 mandates a Reviewer-Wisdom-Frage before issuing FAIL on review-gated principles, scoped to review-gated principles only (NOT hard-gated, NOT guidance per `clean-code.rules.md`).

This Story authors a fixture suite asserting that the extended rubric and Wisdom-Frage protocol behave correctly:

- For each review-gated principle (SRP, OCP, KISS-conceptual, YAGNI-feature, TDA), a synthetic story / code-change scenario is constructed that should trigger a FAIL under the rubric.
- Each fixture asserts the rubric's Step 10 evaluation produces the expected verdict (FAIL or MEDIUM-with-downgrade) per the Wisdom-Frage logic.
- For each principle, ONE fixture exercises the FAIL-maintained path (Wisdom-Frage = YES) and ONE exercises the FAIL-downgraded path (Wisdom-Frage = NO/UNCERTAIN).

The fixture suite is the operationalization of `clean-code.rules.md` §Application Discipline Clause 7 — Wisdom-Frage discipline is not just prose; the qa-review rubric's behavior is observable + testable.

**Authoring-classification note (DEC-22 vs DEC-67 vs rubric-behaviour test category):** These fixtures are NOT DEC-22 RED-first artefacts. DEC-22's RED-first applies to first-party application code authored under the Iron Law (production code preceded by a failing test against unmodified code). The `qa-review` Step 10 prose ships in the same atomic Discovery commit as this Story per Brief D-12 — a literal RED-first ordering against unmodified code is impossible, and a simulated RED against a stripped-copy harness would be a fabricated RED, not a real one (which would itself violate DEC-22's spirit). Per `feedback_governance_pure.md`, the Step 10 prose IS the governance change; these fixtures validate the rubric's *behaviour* — they are **rubric-behaviour regression tests**, structurally similar to DEC-72/E57S04's ArchUnit-guard fixtures (which assert the guard fires on injected violations, but are not themselves DEC-22 RED-first against the guard prose). The classification follows DEC-67's spirit (non-first-party-code-authoring — the fixtures author no application code; they exercise a skill-rubric definition). The fixtures are GREEN-from-first-run against the as-shipped Step 10 rubric, and remain GREEN as the rubric is preserved; a future regression that silently weakens Step 10 trips the fixtures.

This is the operationalization story for the cycle-2 reviewer finding NEW-MEDIUM-1 (Clause 7 scope clarity): the fixtures explicitly assert Clause 7 does NOT apply to guidance-classified principles (no LSP fixture; LSP has no FAIL gate).

## Acceptance Criteria

- [ ] **AC1 (governance / rubric-behaviour regression fixture suite — NOT DEC-22 RED-first)**: A test directory `.gaai/core/scripts/tests/clean-code/qa-review/` (or equivalent vvwt-prj fixture location) contains one fixture per review-gated principle. Each fixture is a **rubric-behaviour regression test** per the Context §Authoring-classification note (NOT a DEC-22 RED-first artefact; analogous to DEC-72/E57S04's ArchUnit-guard fixtures). The fixtures are GREEN-from-first-run against the as-shipped Step 10 rubric and trip on any future regression that silently weakens Step 10.
  - **AC1a — SRP**: synthetic story body OR diff that introduces a class violating SRP per `clean-code.rules.md` §Application Discipline Clause 1 (reason-to-change — NOT logging-cross-cutting). The fixture invokes qa-review Step 10 and asserts the verdict is FAIL with finding "SRP violation" + Wisdom-Frage = YES.
  - **AC1b — OCP**: synthetic diff introducing a speculative extension point without ≥2 concrete extensions; asserts Step 10 verdict FAIL with finding "OCP — speculative extension point" + Wisdom-Frage = YES.
  - **AC1c — KISS-conceptual**: synthetic diff that lowers cyclomatic complexity by introducing five tiny methods replacing one clear medium-sized method, with NO clarity gain; asserts Step 10 verdict FAIL with "KISS-conceptual — primitivity-not-clarity" + Wisdom-Frage = YES.
  - **AC1d — YAGNI-feature**: synthetic diff adding a configuration parameter / abstraction / extension point NOT covered by the story's ACs; asserts Step 10 verdict FAIL with "YAGNI-feature — speculation" + Wisdom-Frage = YES.
  - **AC1e — TDA**: synthetic diff where caller queries getter-state then acts externally on the queried object; asserts Step 10 verdict FAIL with "TDA — state-then-act" + Wisdom-Frage = YES.

- [ ] **AC2 (governance / Wisdom-Frage downgrade fixtures, one per principle)**: For each review-gated principle, ONE additional fixture exercises the Wisdom-Frage downgrade path:
  - The fixture constructs a synthetic case where the rubric would trip on FAIL literally, but the proposed fix (also synthetic) would NOT improve maintainability — Wisdom-Frage = NO.
  - Asserts the Step 10 verdict is MEDIUM-with-guidance (downgrade per Clause 7), NOT FAIL.
  - The fixture verifies the downgrade is recorded in the verdict trace (not silently dismissed).

- [ ] **AC3 (testing / Wisdom-Frage scope assertions)**: A NEGATIVE-CONTRACT fixture asserts the Wisdom-Frage does NOT apply to:
  - **AC3a**: hard-gated principle FAILs (e.g., a PMD CPD finding from E70S01) — the fixture verifies Step 10 does NOT attempt to downgrade a Step 8 (`mvn verify`) FAIL. The hard-gated FAIL stands per DEC-71.
  - **AC3b**: guidance-classified principles (LSP) — the fixture asserts Step 10 contains NO rubric row for LSP and produces no LSP-related verdict (because guidance-classified principles have no FAIL gate to downgrade).

- [ ] **AC4 (governance / anti-dogma rejection fixtures, one per anti-pattern)**: For each anti-dogma misreading listed in `clean-code.rules.md` §Anti-Patterns Reference, a fixture asserts qa-review REJECTS the misreading as a basis for FAIL:
  - **AC4a — "Logging violates SRP"**: synthetic code where a method logs an operation. Fixture asserts Step 10 verdict is PASS (no SRP FAIL — Clause 1).
  - **AC4b — "Two similar lines violate DRY"**: synthetic code with two similar 3-line blocks. Fixture asserts Step 10 verdict is PASS (Rule of Three — Clause 2; note: lexical DRY is hard-gated via E70S01, but two similar lines should NOT trip the threshold either — verified via PMD CPD threshold > 100 tokens).
  - **AC4c — "Every class needs an interface"**: synthetic concrete class without interface, NOT a Spring-bean. Fixture asserts Step 10 verdict is PASS (DIP is review-gated for general-instantiation, NOT mandate-everywhere).
  - **AC4d — "Speculative extension points satisfy OCP"**: synthetic diff introducing an abstract class with no concrete subclass. Fixture asserts Step 10 verdict is FAIL (per Clause 5: speculative extension point IS a YAGNI violation, NOT OCP-positive).
  - **AC4e — "Getters violate TDA"**: synthetic class with getters used for rendering / serialization / logging. Fixture asserts Step 10 verdict is PASS (Anti-Patterns Reference: getters for non-behavior purposes are appropriate).

- [ ] **AC5 (testing / mvn verify GREEN)**: After all fixtures land, `mvn verify` from vvwt-prj root is BUILD SUCCESS, exit code zero per DEC-54. The fixtures execute under `mvn verify` either (i) as shell-test invocations bound to a Maven phase via `exec-maven-plugin`, OR (ii) as Java-based driver tests in `src/test/java`. The `impl-report.md` documents the chosen execution path per AC6 — both are acceptable. The fixtures produce verdict PASS (exit zero) when Step 10 + Wisdom-Frage behave per the rubric.

- [ ] **AC6 (governance / impl-report)**: `impl-report.md` documents the fixture-suite layout, the synthetic violation scenarios per principle, the Wisdom-Frage downgrade scenarios, and the anti-dogma rejection scenarios. Citations: DEC-78, DEC-54, DEC-71, DEC-67 (non-first-party-authoring spirit per §Context Authoring-classification note), DEC-72 (rubric-behaviour regression-test precedent).

## Notes

**Fixture architecture**: The fixtures may be implemented as either (i) script-based shell tests (under `.gaai/core/scripts/tests/clean-code/qa-review/`) that simulate a qa-review invocation with synthetic inputs and assert the verdict, or (ii) Java-based tests using a mock or a real qa-review process driver. The implementation choice is documented in `impl-report.md` per AC6 — both are acceptable provided RED-first authoring is preserved.

**Anti-dogma — load-bearing**: AC4 fixtures are explicitly load-bearing. They guard against future Tier-2 reviewer drift toward dogmatic literal-rule application. Without them, the §Application Discipline anti-cargo-cult clauses risk becoming prose that no one enforces. The fixtures ARE the enforcement — they assert that the rubric correctly identifies the misreadings as non-FAILs.

**Wisdom-Frage observability**: AC2's downgrade fixtures ARE the audit-trail for Clause 7. Without them, the Wisdom-Frage protocol could be silently bypassed (e.g., reviewer issuing FAIL on review-gated principle WITHOUT answering the Wisdom-Frage). The fixtures assert the protocol is observable in qa_report output.

**Asymmetric-error preference**: Per DEC-47-F / DEC-71 — fixtures err on the strict side. If a fixture is uncertain whether to assert FAIL or PASS, it asserts FAIL by default (Story author then documents the ambiguity for review).
