# Story E63S07: Dispatcher offline/online status in the admin UI with manual re-check

## User Story

**As a** Tournament Manager operator,
**I want** to see whether the slot-optimization dispatcher is reachable and to re-check on
demand,
**so that** I know whether large-phase optimizations will run on the dispatcher (Leg 2) or
fall back to in-process compute (Leg 3) — before I commit to planning.

---

## Context

`DispatcherReachabilityService` already determines whether the dispatcher is reachable —
`RoutingSlotOptimizationClient` consults it to choose between Leg 2 and Leg 3, and it returns
`false` when `tm.slotopt.dispatcher.url` is null (DEC-49 D-12: no URL = no dispatcher). But
the operator has no visibility of this: no admin-UI element shows the dispatcher's
reachability, and there is no way to re-check it on demand.

This story surfaces that state. The TM admin UI shows whether the dispatcher is reachable,
distinguishes "no dispatcher configured" from "configured but currently unreachable", and
gives the operator a control to re-probe reachability on demand.

Today `DispatcherReachabilityService` exposes only a binary `isReachable()` that returns
`false` for *both* a null/unset URL and a configured-but-unreachable dispatcher — it cannot,
as-is, yield the not-configured-vs-unreachable distinction the UI needs. So this story
**extends `DispatcherReachabilityService`'s contract** to expose that distinction (e.g. a
tri-state result `REACHABLE` / `UNREACHABLE` / `NOT_CONFIGURED`, or an added `isConfigured()`
query — the exact shape is a Delivery design choice). The reachability **probe mechanism**
itself (the HEAD probe, the timeout) is unchanged — no new probing mechanism is introduced.

This story is independent of Epic E60.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-STATUS-DISPLAYED** — RED-first (DEC-22): the TM admin UI displays the
  dispatcher's reachability status (reachable / unreachable / not-configured).
- [ ] **AC-TEST-MANUAL-RECHECK** — an operator action (a click) re-probes dispatcher
  reachability and updates the displayed status to the fresh result.
- [ ] **AC-TEST-STATUS-DISTINGUISHES-NOT-CONFIGURED** — when `tm.slotopt.dispatcher.url` is
  null / unset, the status shows a distinct "no dispatcher configured" state — not the same
  state as a configured-but-unreachable dispatcher (DEC-49 D-12).

### Error Handling

- [ ] **AC-ERR-RECHECK-TIMEOUT-SHOWS-OFFLINE** — a re-check against an unreachable dispatcher
  has its **probe** bounded by the configured reachability timeout
  (`tm.slotopt.dispatcher.reachability-timeout-ms`); the re-check endpoint then returns the
  "unreachable" status — it surfaces a defined status, not a raw error or a 5xx, and the UI
  does not hang. (The configured timeout bounds the HEAD probe; the AC does not assert the
  full controller→service→UI round trip completes within that exact bound.)
- [ ] **AC-ERR-NOT-CONFIGURED-IS-NOT-AN-ERROR** — a null / unset dispatcher URL yields the
  defined "not configured" status in a successful response — it is not an error state.
- [ ] **AC-ERR-RECHECK-CONCURRENT-CLICKS** — repeated rapid re-check clicks are handled
  gracefully (no error, no probe pile-up that destabilizes the UI) — a defined, debounced or
  serialized behaviour.

### Security

- [ ] **AC-SEC-RECHECK-ENDPOINT-AUTHENTICATED** — the status / re-check endpoint requires the
  same admin authentication as the rest of the TM admin console; there is no unauthenticated
  surface that lets an anonymous caller trigger dispatcher probes.
- [ ] **AC-SEC-STATUS-NO-INTERNAL-LEAK** — the status response exposes only the reachability
  state (reachable / unreachable / not-configured) and, at most, the configured dispatcher
  URL already known to the operator — no credentials, no internal error/stack detail.

## Notes

The "not configured" vs "configured but unreachable" distinction matters operationally: the
former is a deliberate offline-first deployment (DEC-49 D-12 — Leg 3 always), the latter is
a likely misconfiguration or a transient outage the operator may want to act on. Related
Session Brief items: D-7, O-8, S-5, Q-4.
