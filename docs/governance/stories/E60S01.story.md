# Story: Wire packet decomposition into `submit-job` (`RECEIVED → DECOMPOSED`) + pipeline confirm-audit

## User Story

**As an** operator of the slot-optimization service,
**I want** a submitted job to be decomposed into solvable packets,
**so that** workers actually receive work and the job progresses beyond intake instead of
sitting inert in `RECEIVED` forever.

---

## Context

`vvwt-slotopt-dispatcher`'s `DefaultJobService.submitJob` persists a `JobRecord` with status
`RECEIVED` and stops. `PacketDecomposerService.decompose()` — built and unit-tested by E37S08
— has **zero production callers**: nothing invokes it. Consequently no `PacketRecord` is ever
created, `DefaultPullPacketService` (which claims the lowest-id `UNCLAIMED` packet) always
finds nothing, and every worker that registers and pulls receives "no packet" indefinitely.
The job-processing pipeline is dead at its first seam.

This story wires that seam: a submitted, non-cache-hit job is decomposed via the existing
`PacketDecomposerService` (algorithm unchanged), its packets are persisted, and the
`JobRecord` advances `RECEIVED → DECOMPOSED`. After this story `pull-packet` serves real work.

This is the first story of Epic E60, so it also carries the pipeline **confirm-audit**: the
two pipeline gaps found during Discovery (unwired decomposition; missing
finalization/aggregation/result-retention) are the *illustrative* basis for the Epic scope,
not a guaranteed-complete list. Delivery re-verifies the whole
`submit-job → decompose → pull → submit-result → finalize` chain at HEAD against
`E37.slotopt-contract.md` and surfaces any further broken seam rather than silently absorbing
or ignoring it.

The existing cache-hit short-circuit in `submitJob` (E37S10 — a structurally-identical prior
job returns immediately, persisting no `JobRecord`) is preserved unchanged: a cache-hit job
is not decomposed.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-DECOMPOSE-INVOKED-ON-SUBMIT** — RED-first (DEC-22): a non-cache-hit job
  submitted via `submit-job` results in its packets persisted and queryable by `jobId`.
  The test fails on current `HEAD` (zero packets created) and passes after the wiring.
- [ ] **AC-TEST-JOB-DECOMPOSED-TRANSITION** — once decomposition completes, the job's
  `JobRecord.status` is `DECOMPOSED` (the delivered enum value — see AC-GOV-DELIVERED-ENUM);
  a job not yet decomposed reads `RECEIVED`.
- [ ] **AC-TEST-PULL-PACKET-SERVES-DECOMPOSED-JOB** — after a job is submitted and
  decomposed, a `pull-packet` call by a registered worker returns one of that job's packets
  (the decomposition→pull seam works end-to-end at the dispatcher boundary).
- [ ] **AC-TEST-CACHE-HIT-NOT-DECOMPOSED** — a `submit-job` that hits the E37S10 cache
  short-circuit creates no `PacketRecord` and persists no `JobRecord` — the existing
  short-circuit behaviour is unchanged.
- [ ] **AC-TEST-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for `vvwt-slotopt-dispatcher`
  (DEC-54); the existing E37/E40 test suite remains GREEN.

### Governance

- [ ] **AC-GOV-CONFIRM-AUDIT** — Delivery re-verifies, at the delivery `HEAD`, the full
  `submit-job → decompose → pull → submit-result → finalize` chain against
  `E37.slotopt-contract.md`. If a broken seam beyond the Epic E60 scope (S-1..S-5 of the
  Session Brief) is found, Delivery **STOPs and escalates to Discovery** — it neither
  silently fixes nor ignores it. The qa-report records the audit outcome (chain confirmed
  complete-as-scoped, or the escalation). No pre-computed file/violator inventory is relied
  upon — the audit is performed fresh.
- [ ] **AC-GOV-DECOMPOSER-REUSED** — decomposition uses the existing
  `PacketDecomposerService` unchanged; the packet-decomposition algorithm is not
  re-implemented or modified. The change is the invocation/wiring and packet persistence.
- [ ] **AC-GOV-DELIVERED-ENUM** — the job lifecycle uses the delivered `JobRecord` status
  enum (`RECEIVED` / `DECOMPOSED` / `COMPLETED`), not the stale `E37.slotopt-contract.md`
  enum (`queued` / `decomposing` / `ready` / `done`). `submit-job → decompose` writes
  `DECOMPOSED`.
- [ ] **AC-GOV-INTERFACE-MANDATE** — any new behaviour-bearing first-party Spring component
  introduced by the wiring is addressable through an interface in its module-root package
  with a `Default*` implementation in `.internal` (DEC-58 / DEC-72 / DEC-35 / DEC-36); the
  build-time interface-mandate guard stays green. Wiring decomposition into the existing
  `DefaultJobService` introduces no new bean.
- [ ] **AC-GOV-RED-FIRST** — new first-party code is authored RED-first per DEC-22; the
  impl-report records the RED-state evidence (failing test + commit) for each new behaviour.
  The wiring modifies the existing E37-delivered `DefaultJobService.submitJob`: the inserted
  decompose → persist-packets → `DECOMPOSED` behaviour is genuinely new and is authored
  Q-1a RED-first; the edit to the existing method is an in-place reconstruction per DEC-22
  §refactor-clause. The impl-report records this per-change classification.
- [ ] **AC-GOV-DAO-IT-THREE-RULE** — the integration tests that assert packets are
  persisted/queryable by `jobId` and that `JobRecord.status` reads `DECOMPOSED` follow the
  DEC-26 / DEC-46 three-rule generator/evaluator-separation pattern (schema-from-migration;
  an independent persistence verifier; read/write decoupling), using the dispatcher's
  per-module DAO test support utility — persistence is not verified solely through the
  DAO's own read methods. Any new Repository read method introduced has a production
  callsite (DEC-69) — a read method exercised only by tests is forbidden.
- [ ] **AC-GOV-NO-MODULE-BOUNDARY-BREACH** — no compile dependency on the Tournament Manager
  or any non-dispatcher module is introduced; the dispatcher stays an independent deployable
  (DEC-11).
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); Java touches compile
  warning-free (DEC-29) and pass Spotless / google-java-format (DEC-30); no production
  method, constructor, or field exists solely for tests (DEC-70).
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use `chore(E60S01):` (RED tests, refactor,
  housekeeping) and `feat(E60S01):` (GREEN production change) prefixes per the
  close-story.sh contract.

### Error Handling

- [ ] **AC-ERR-DECOMPOSE-FAILURE-DETERMINISTIC** — if decomposition fails (e.g. a malformed
  `jobDefJson` that the decomposer cannot process), the job is not left in an ambiguous
  half-decomposed state: either no packets and no advanced status are persisted, or the job
  is marked with a defined failure state — Delivery picks the mechanism, but the outcome is
  deterministic and observable, and orphaned partial packets are not left behind.
- [ ] **AC-ERR-DECOMPOSE-ONCE-PER-JOB** — a job is decomposed exactly once; a re-processed or
  re-submitted job does not produce a duplicate packet set for the same `jobId`.
- [ ] **AC-ERR-PULL-EMPTY-WHEN-NO-PACKETS** — `pull-packet` against a dispatcher with no
  `UNCLAIMED` packet still returns the existing defined "no packet" response (not an error) —
  verified to be unchanged by this story.
