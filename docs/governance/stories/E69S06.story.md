# Story: Pin RaspiOS base-image URL in `build-image.sh:294` to the last Bookworm-armhf-lite release so FullPageOS 0.14.0 chroot keeps working

## User Story

**As a** tournament operator,
**I want** `./build-image.sh` to download the specific RaspiOS-Bookworm
armhf-lite release that FullPageOS 0.14.0 was tested against (2025-05-13),
**so that** the FullPageOS chroot script's hardcoded `chromium-browser`
package name resolves successfully — instead of failing on RaspiOS-Trixie
images that ship the renamed `chromium` package.

---

## Context

Discovery's Bug-Triage chain under Epic E69 continued past E69S05's Python-
deps gap. With the operator's locally apt-installed `python3-git` +
`python3-yaml`, the 2026-05-27 live-attest got significantly further —
through CustomPiOS clone, `update-custompios-paths`, Raspbian-image
download, overlay-apply, and into the FullPageOS chroot phase — before
failing at:

```
+ apt-get install -y --force-yes chromium-browser
Package chromium-browser is not available, but is referred to by another
package. This may mean that the package is missing, has been obsoleted,
or is only available from another source
E: Package 'chromium-browser' has no installation candidate
build failed, unmounting image...
```

Root cause is empirically established against upstream sources at review
time. The defect is **not** in our wrapper's logic but in the wrapper's
**URL-pinning posture**: `build-image.sh:294` uses the unpinned
`raspios_lite_armhf_latest` redirect, which currently lands on the
2026-04-21 Trixie-base image. FullPageOS 0.14.0's chroot scripts hardcode
`chromium-browser` — the Bookworm-era Debian package name. In Debian
Trixie the package was renamed to plain `chromium`. The two versions
therefore are incompatible.

E69S03 AC5 Escalation-Clause is the governing pattern: gap → new story
(`track: bug-triage`, single-class) → fix → re-attest → next defect (or
green light). E69S06 is the fourth such retrofit under Epic E69.

The fix conforms `build-image.sh` to FullPageOS 0.14.0's actual
tested-against base by pinning the wget URL to the LAST Bookworm
armhf-lite release before the Bookworm→Trixie transition
(`2025-05-13-raspios-bookworm-armhf-lite.img.xz`). FullPageOS 0.14.0 was
tagged 2025-07-14 — two months after the 2025-05-13 image, and before any
later release existed — so 2025-05-13 is necessarily the image generation
0.14.0 was developed and tested against.

This story is `track: bug-triage` per the Discovery Bug-Triage Flow in
`.gaai/core/agents/discovery.agent.md`. Like E69S04/E69S05, it is a
script-level retrofit (one URL value change + one wget flag removal + one
inline-comment update + one README note + bats assertion + attestation
row), not a feature expansion.

## Root Cause Analysis

Single defect in `vvwt-prj/pi-display/build-image.sh:293-295`:

```bash
wget -c --trust-server-names \
    'https://downloads.raspberrypi.org/raspios_lite_armhf_latest' \
    -P "${WORK_DIR}/FullPageOS/src/image/"
```

**Upstream contract** — FullPageOS 0.14.0 (released 2025-07-14) was
developed against the RaspiOS-Bookworm base. Its
`src/modules/fullpageos/start_chroot_script:41` reads (verbatim at tag
0.14.0):

```bash
apt-get install -y --force-yes chromium-browser
```

The `chromium-browser` package name is Bookworm-era. In Debian Trixie
(Debian 13, released mid-2025) the package was renamed to plain
`chromium` (no `-browser` suffix).

**The wrapper's failure mode** — `build-image.sh:294` uses the
server-side-redirect URL `raspios_lite_armhf_latest`. Live verification
2026-05-27: redirects to `2026-04-21-raspios-trixie-armhf-lite.img.xz`.
This Trixie image lacks the `chromium-browser` package; FullPageOS
0.14.0's chroot then fails the apt-install step with
`E: Package 'chromium-browser' has no installation candidate`. Per
`build-image.sh:87` (`set -euo pipefail`), the script aborts. The
operator-attest log at line 905 confirms the image in use was
`2026-04-21-raspios-trixie-armhf-lite.img`.

**Upstream Raspberry Pi Foundation archive** —
`https://downloads.raspberrypi.com/raspios_lite_armhf/images/`
directory listing (verified at review time): the last Bookworm
armhf-lite release is in subdirectory `raspios_lite_armhf-2025-05-13/`.
HTTP probes of subdirectory dates between 2025-05-14 and 2025-09-30
returned 404 — no intervening release; the Bookworm→Trixie transition
was atomic between 2025-05-13 and the first Trixie release that the live
build downloaded (2026-04-21). Since FullPageOS 0.14.0 was tagged
2025-07-14 — after 2025-05-13 and before any later Bookworm or any
Trixie — the 2025-05-13 image is necessarily the base 0.14.0 was
developed and tested against.

**Pin target URL** —
`https://downloads.raspberrypi.com/raspios_lite_armhf/images/raspios_lite_armhf-2025-05-13/2025-05-13-raspios-bookworm-armhf-lite.img.xz`.
Verified at review time: HTTP 200, Content-Type `application/x-xz`,
Content-Length 517084228, Last-Modified 2025-05-13. The URL is stable
and the file is a genuine `.xz` archive (not a redirect, not HTML).
The domain migration from `.org` (legacy CDN) to `.com` (current
canonical Raspberry Pi Foundation archive) is part of this fix —
both currently serve identical content, but `.com` is the canonical
archive going forward.

**Fix** — replace the `_latest` URL on `build-image.sh:294` with the
explicit dated `.com` URL; remove `--trust-server-names` from the
wget invocation (the flag was added to follow the `_latest` redirect's
`Content-Disposition` header; with a direct URL there is no redirect
chain, so the flag is semantically moot and removing it eliminates a
future-reader-confusion gap); update the inline comment at
`build-image.sh:289-290` to record the date-pin rationale.

**Why it slipped past E69S05** — E69S05's scope (Python-deps pre-flight)
is statically independent of the RaspiOS-image-pin defect; the two
defects surface at distinct pipeline stages (E69S05 at
`execution_order.py` module-load, E69S06 at chroot's apt-install). The
sequential discovery is exactly what the E69S03 AC5 Escalation-Clause
predicts.

**Alternative paths rejected at Brief time:**
- **Fork FullPageOS chroot to use `chromium`** — violates E69S01 Brief
  T-3 Wrapper-identity (no upstream fork).
- **CustomPiOS devel HEAD** — violates E69S01 AC3 (no unpinned upstream
  refs).
- **FullPageOS tag-bump beyond 0.14.0** — no newer release exists
  (0.13.0 → 0.14.0 was 2023-10-22 → 2025-07-14; cadence ~21 months per
  E69S02 Known Limitations §2). Future FullPageOS releases land as
  separate stories per E69S01 Brief D-9.
- **CLI flag `--raspios-image-url`** — operator footgun (arbitrary URL
  bypassing the tested Bookworm contract); inconsistent with E69S01
  AC3's hardcoded-pin-with-override-confirmation pattern. Operator
  overrides remain available via local edit-and-rebuild, not as a
  first-class CLI surface.
