# Story E52S03: Remove redundant Timer-Link button from Tournaments row (entry preserved via TimerAudio sub-page; parentRouteMap unchanged per Path-γ)

## User Story

**As a** Tournament Organizer,
**I want** the redundant "Timer-Link" button removed from the tournament row in the admin overview, given the same navigation target is already discoverable from the TimerAudio sub-page header,
**so that** the tournament row carries only non-redundant entry-points and the new "Zeitpläne" + renamed "Urkunden" buttons (E52S01 + E52S02) do not push the row into visual overload.

---

## Context

The admin tournament list at `vvwt-prj/vvwt-tm-web/src/main/ui/src/routes/Tournaments.svelte` exposes 8 tournament-row buttons. Among them, `Timer-Link` (i18n key `tournaments.timerLinkButton` = "Timer-Link") is rendered inside `{#if t.status === 'PLANNED' || t.status === 'ACTIVE'}` at lines 228-234. Empirically verified 2026-05-08: the same `/tournaments/:tournamentId/timer-link` route is also reachable via a header-right push handler in `TimerAudio.svelte:78`:

```typescript
handler: () => push(`/tournaments/${tournamentId}/timer-link`)
```

The Tournament-row button is therefore a redundant secondary entry-point. Removing it does not lose reachability — the operator opens TimerAudio (via the `tournaments.timerAudioButton` row button) and reaches Timer-Link from there. This is exactly the user-stated rationale during Discovery: *"Dieser Button befindet sich auf der Seite 'Timer-Audio' das ist ausreichend"*.

This story is **track:hygiene**, NOT bug-triage. There is no broken workflow — the row is just visually heavier than it needs to be, and E52S01 (adding "Zeitpläne") + E52S02 (renaming "Urkunden-Vorlage" to "Urkunden") share the same surface, making this removal a natural co-shipped cleanup.

### Path-γ — parentRouteMap.ts NOT touched

During Discovery the user originally proposed retargeting `TimerLink.svelte`'s back-arrow from `/tournaments` to `/tournaments/:tournamentId/audio` (TimerAudio). The Tier-2 Reviewer surfaced that the documented `parentRouteMap.ts` convention is URL-nesting-based ("Tournament-sub-routes target /tournaments; sub-sub-routes target their immediate parent") — and the proposed retargeting would be the first exception to that rule for tournament-sub-routes. The user chose **Path-γ** in response: TimerLink-back stays on `/tournaments`. The convention is not extended; no exception class is introduced; the parent-routing semantics remain unchanged. The trade-off accepted: the operator clicking "Zurück" on TimerLink lands on the tournament list, not on TimerAudio.
