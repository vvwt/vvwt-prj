# Story: Complete the siegerehrung → awardCeremony anglicization (English UI text, comments, test names)

## User Story

**As an** operator using the Tournament Manager in English, and as a developer maintaining `vvwt-prj`,
**I want** the English UI text, source comments and test names to use the English term for the award-ceremony game mode,
**so that** the English UI contains no German domain term and the codebase consistently speaks of `awardCeremony`, as DEC-73 D-7 intends.

---

## Context

E58S04 (PR #298, done) renamed the German domain term `siegerehrung` to `awardCeremony` in registry keys,
code identifiers and i18n message keys. DEC-73 D-7 reads: "renamed … everywhere it appears in `vvwt-prj`
code as a registry-key / wire-format string, constant, class-name fragment, i18n message **key**, or test
name. i18n translation **values** (the human-readable label strings, including the German display label)
are NOT renamed — only keys and code identifiers anglicize."

Two gaps remain at HEAD:

1. **English translation value.** D-7's "values are NOT renamed" clause bounded the E58S04 *key/identifier
   rename sweep* — it kept display labels out of a mechanical rename. It does not mandate that an English
   translation value keep a German word. The English lap-time disabled-tooltip still reads "… Siegerehrung
   phases" — a translation defect (German word in English UI text), corrected here as a translation fix, not
   as a key rename. German values (the German display label "Siegerehrung") stay untouched, consistent with D-7.
   This reading of D-7 (the clause bounds the rename sweep; it does not protect a German word inside an English
   value) was explicitly validated by the operator in the Discovery Session Brief of 2026-10-03 (item D-2).
2. **Comments, test names, log text.** D-7 lists test names as in scope, but the E58S04 audit covered keys
   and identifiers only. Many source comments, test-method names, test display names (`describe`/`it`,
   `@DisplayName`), and assertion/description messages still use `siegerehrung` as the domain term (production log text is excluded, AC3(i)).

Scope is `vvwt-tm-web` only, matching Epic E58's module boundary.

This story completes D-7's test-name coverage and extends the anglicization to comments and assertion text (operator decision 2026-10-03). It changes text only: no keys, no identifiers, no behaviour.

---

## Acceptance Criteria

- [ ] AC1 (governance): The English locale's translation value for `draftConfig.rundenzeit.disabledTooltip` no longer contains "Siegerehrung"; it uses the English term "award ceremony" (e.g. "Lap time has no effect for award ceremony phases"). A fresh audit at delivery HEAD of all translation values in the TM frontend's English locale finds zero occurrences of "siegerehrung" (case-insensitive).
- [ ] AC2 (governance): **Deciding rule** — every occurrence of `siegerehrung` (case-insensitive) in the `vvwt-tm-web` source and test trees (`src/main`, `src/test`, including the frontend under `src/main/ui`) that is (a) comment text, (b) a test-method name or a test display name (`describe`/`it`/`test` titles, `@DisplayName`), or (c) an assertion / `.as(...)` / failure-message string literal, is replaced by the English term — `awardCeremony` when referring to the gameMode key/value; "award ceremony" / "award-ceremony" when used as a prose noun; the current identifier when it is a stale reference to an old `Siegerehrung…` class or method name (e.g. `AwardCeremonyMatchGenerator`, `AwardCeremonyMatchGeneratorTest`, `isAwardCeremonyPhase()`) — **unless** it falls under an AC3 exclusion. The occurrence set is determined by a fresh audit at delivery HEAD over **git-tracked files only** (e.g. `git grep -i siegerehrung -- vvwt-tm-web/src`; build output such as `dist/`, `node_modules/`, `target/` is not audited); this story carries no authoritative occurrence list.
- [ ] AC3 (governance): The following occurrences remain unchanged, and the impl-report lists which exclusion each remaining occurrence falls under: (a) translation values in the German locale (e.g. the German display label "Siegerehrung"); (b) historical rename notes — in comments, test display names, or test-method names — including the old key or class names quoted in them (e.g. "renamed from siegerehrung by E58S04", "renamed from lastPhaseMustBeSiegerehrung by E58S04", "originally SiegerehrungMatchGeneratorTest"); (c) historical acceptance-criterion IDs embedded in comments or test names (e.g. `AC-TEST-…-SIEGEREHRUNG-…-RED`), which are traceability references to past stories; (d) test assertions that deliberately check the old literal is absent or rejected (e.g. a `not.toMatch(/…siegerehrung…/)` guard) — their literal must stay so the guard keeps working; (e) anything under `.gaai/` and the governance snapshots under `vvwt-prj/docs/governance/` (byte-identical copies per DEC-31); (f) German i18n key names such as `rundenzeit`; (g) test assertions and test titles that deliberately check a German translation value (e.g. a test asserting the German label is 'Siegerehrung'); (h) test-fixture data values that model operator-entered data, such as phase or tournament names (e.g. a phase named "Siegerehrung") — these represent realistic German user data, not the domain key. This applies to any tournament/phase-name fixture string regardless of wording (e.g. a tournament named "IT preview siegerehrung E48S09"); (i) production log and exception message text (not part of the operator's chosen sweep — e.g. an `LOG.info` text mentioning "siegerehrung").
- [ ] AC4 (governance): After the story, a fresh case-insensitive audit of `siegerehrung` over the git-tracked files of the `vvwt-tm-web` source and test trees finds only occurrences covered by an AC3 exclusion.
- [ ] AC5 (governance): No i18n key, production code identifier (class, method, field, constant), registry key, or runtime behaviour is changed — the diff touches only English-locale translation values, comment text, test-method names, test display names, assertion/description message strings, expected-value literals in tests that assert a changed English text (per AC6), and the new English-locale test required by AC6.
- [ ] AC6 (testing): DEC-22 — AC1 is a user-visible text fix and is driven RED-first: a frontend test asserts that the English locale's `draftConfig.rundenzeit.disabledTooltip` value uses "award ceremony" and that no English-locale translation value contains "siegerehrung" (case-insensitive); it fails before the AC1 change and passes after (precedent: E58S06 asserts an i18n translation value in `PhaseList.test.ts`). The comment / test-name / assertion-message changes (AC2) carry no behaviour change; for them the existing test suite is the regression gate and passes. If an existing test asserts a changed English text, it is updated to the new text.
- [ ] AC7 (testing): `mvn verify` run from the vvwt-prj root is BUILD SUCCESS, including the `vvwt-tm-web` frontend build and frontend tests (DEC-54 / DEC-71).

> All acceptance criteria must be verifiable.
