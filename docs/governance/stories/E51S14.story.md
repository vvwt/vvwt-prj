# Story E51S14: Wire MatchGenJobExecutor → PhaseLifecycleService.transition(PREPARED, "match-gen-done")

## User Story

**As a** Tournament Operator,
**I want** the phase status to auto-flip from PENDING to PREPARED after the background match-gen job completes successfully,
**so that** the Phasenübersicht shows the correct lifecycle status (PREPARED, not "Ausstehend") and the correct action button ("Phase starten" / "Übernehmen", not "Vorbereiten") right after the apply-pipeline finishes — without operator having to refresh, retrigger, or guess whether the job ran.

---

## Context

DEC-55 D-3 step 2 (operationalized by E51S03) introduced the events-only Match-Gen background pipeline. `MatchGenJobExecutor.execute(tournamentId, phaseId)` (`vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/internal/MatchGenJobExecutor.java`) currently:
- acquires per-tournament row-lock (line 84)
- loads phase + invokes `phasePreparationService.generateMatches(phaseId, generatorKey)` (line 104)
- sets `phase.lastJobState='idle'` + saves (line 107-108)
- publishes `SlotOptJobScheduledEvent` if `tournament.optimize=true` (line 117-126)

It does **NOT** invoke `phaseLifecycleService.transition(phaseId, PREPARED, "match-gen-done")`. Per DEC-55 D-4 transition-table (E51S05 implementation), `PENDING → PREPARED` via verb `"match-gen-done"` is the canonical edge after match-gen success — but the wire is missing.

**Symptom (operator report 2026-05-08 23:30+):** Phasenübersicht shows Phase 1 status = "Ausstehend" (PENDING) although matches have been generated (count visible in row). PhaseList.svelte:349-357 button-visibility logic shows "Vorbereiten" for PENDING; clicking it lands the operator on the drag&drop page instead of the post-prep "Phase starten" path.

**Bug 4 root cause:** wire-gap between E51S03 (listener+executor) and E51S05 (lifecycle authority + transition table). Both stories merged independently; the connecting call was missed.

This story closes the gap. Single-line wire-add inside `MatchGenJobExecutor.execute` after line 108 (after `last_job_state='idle'` is set, before `SlotOptJobScheduledEvent` is published if `tournament.optimize=true`). Test surface: integration test asserting `phase.status=PREPARED` after successful match-gen completion.
