# Story: Display SPA Multi-Round Display + Vertical-Fill + Active-Round Highlight

## User Story

**As a** tournament operator and audience member viewing the public Display screen at venue,
**I want** all rounds of the active phase visible simultaneously per court (not just the current round), with round rows distributed evenly across the available vertical space, and the currently-active round visually emphasized via a darker background,
**so that** the audience sees the upcoming match plan at a glance and can identify the round currently being played without ambiguity.

---

## Context

Three coupled symptoms surfaced in the live observation 2026-05-10 (`Bildschirmfoto_2026-05-10_19-50-08.png`):

1. **Round-completeness gap**: The `/display/overview` SPA shows matches for only the current lap (e.g., 2 rows per field for a 3-field setup → 6 visible matches), while the active phase has more configured rounds (user reported "Phase 1 hat 4 Runden, Display zeigt nur 2"). Empirical root cause (Brief O-8): `DefaultDisplayOverviewService.getMatchesByLap` lines 198-201 hard-filters `Integer.valueOf(effectiveLap).equals(m.getLapNumber())` and returns only matches of the single currentLap.
2. **Vertical-space inefficiency**: Within each field column, match rows do not fill the available vertical space — there is unused area below the rendered rows. The screen is wide-format and intended for far viewing; sparse vertical layout reduces readability.
3. **Active-round ambiguity**: Once multiple rounds are visible, the operator and audience cannot identify which round is currently being played at a glance — there is no visual emphasis on the active row.

These three symptoms share the same code surface (`CourtGrid.svelte` rendering pipeline + match-data fetch path) and the same underlying data shape (multi-lap match rows). Bundling them into one story per Brief D-1 (revised after cycle-1 reviewer F3 finding) avoids the F3 coupling problem (T4/T5 are no-op until T3 ships).

The active-round source is empirically clarified (Brief O-7): `DisplayPhaseOverview.currentLap` is already in the API contract, exposed via `DefaultDisplayOverviewService.java:175` (`phase.getCurrentLapNumber()`) and read by `App.svelte:49` + passed to `CourtGrid.svelte:27,30` as a prop. T5 is a pure FE visualization addition — no backend change required for the active-round detection.
