# Story E38S08: `vvwt-info-client` Svelte 5 + TS SPA — per-team timeline view, WebSocket reader with reconnect-on-gap (single state machine), HTTP poll fallback (5s default), supersede frozen view (24h grace) + 410-Gone UX, server-side CSP-header emission for static-resource path, Referrer-Policy `no-referrer` for token-leakage defense, externalised DE-only strings, packaged into `vvwt-info-server` static resources

## User Story

**As a** tournament participant scanning my QR code on a phone,
**I want** a fast-loading SPA that shows my team's full timeline (schedule, finished games, Sondertermine) in German, auto-updates as the tournament progresses, gracefully handles brief network drops, and displays a clear final-state view if my organizer has started a new tournament (within 24 h) or a clear expiry message thereafter,
**so that** my tournament-day experience is smooth and self-explanatory without needing to refresh, log in, or wonder why something disappeared.

## Context

DEC-42 D1 specifies `vvwt-info-client` as a separate Maven module with **Svelte 5 + TypeScript** per DEC-2 (no SvelteKit, version pinned per cycle-1 F-6). Brief T-10 + Epic Out-of-Scope: Phase 1 builds the SPA into `vvwt-info-server/src/main/resources/static/` (single deployable; CDN deferred Phase 2+). Brief D-10 + D-11 + D-G6 + D-G6a specify reader behavior: snapshot-on-connect, deltas-after, sequence-gap-detection → **reconnect-on-gap (single state machine, NOT buffer-then-reapply** — cycle-1 F-3 fix).

Brief D-6 + Epic E38S06 specifies supersede UX: during 24h grace, server returns `tournament_ended: true` flag with frozen final-state snapshot; client renders read-only "Dieses Turnier ist beendet" message; after 24h, 410 Gone → "Dieser Link ist nicht mehr gültig — bitte fragen Sie Ihren Veranstalter nach dem aktuellen Link."

**This story owns server-side CSP-header emission** (cycle-1 F-1 fix — the static-resource serve path is configured here since this story owns the SPA packaging into `vvwt-info-server/static/`). **Plus Referrer-Policy `no-referrer`** to defend URL-token leakage via Referer header on outbound link clicks (cycle-1 F-4).

The story is single-story-justified per Epic E38S08 cycle-1 fix: rendering, WS reader, sequence-gap recovery, supersede UX, and 410-detection are tightly coupled in a single Svelte component graph; splitting would force premature interface design between rendering and connection-management layers.

## Acceptance Criteria

- [ ] **AC1 (testing)**: Every Svelte component, store, and TypeScript module has a RED-first unit test per DEC-22 Iron Law. Test framework: **Vitest** (Apache 2.0, OSS per DEC-3) + `@testing-library/svelte`. RED-state commit hashes cited in `impl-report.md`.
- [ ] **AC2 (testing)**: **E2E test against real `vvwt-info-server`** (cycle-1 F-2 fix — eliminates the implementation-choice between non-equivalent oracles): the test launches `vvwt-info-server` via `spring-boot:run` against H2 in-memory DB seeded with a fixture tournament (using `InfoDaoTestSupport` from E38S03). **Playwright** (Apache 2.0, OSS per DEC-3) drives the SPA. Flow: page loads → WS connects → snapshot rendered → server publishes a delta (test backend emits via direct DB-write fixture) → DOM updates with new state → simulated network drop → WS reconnects → re-snapshot received → DOM remains consistent. NO Node.js stub; NO contract-divergence risk.
- [ ] **AC3 (testing)**: **Sequence-gap recovery state machine — single state machine, reconnect-on-gap** (cycle-1 F-3 fix — eliminates AC3-vs-Notes contradiction): given an in-memory store of applied deltas with `last_known_seq=5`, a new delta arrives with `seq=8` → store DOES NOT buffer; instead it triggers WS reconnect. New WS connection requests `?since=5` (or equivalent) in the handshake; server returns either deltas `[6,7,8]` (if retained) OR fresh snapshot (if retention exceeded — per E38S06 AC4). Client applies the response. **No buffering, no re-apply, no idempotency assumption — single clean state machine.**
- [ ] **AC4 (testing)**: **Sondertermine + ScheduleEntry rendering positive AC** (cycle-1 F-9): given a snapshot containing all three sealed `ScheduleEntry` subtypes (Match, SpecialAppointment, Pause), the rendered timeline displays each with its DE label ("Spiel" / "Mannschaftsfoto" or specific Sondertermin name / "Pause"). Test asserts each subtype renders with the correct visual treatment + DE label.
- [ ] **AC5 (testing)**: **Supersede UX rendering test**: given a `tournament_ended: true` snapshot from server, rendering shows final-state schedule + results + Sondertermine plus DE message "Dieses Turnier ist beendet"; auto-update spinner is hidden; live-update indicator removed.
- [ ] **AC6 (testing)**: **410 Gone UX test**: when WS handshake or first poll returns 410 (post-grace), SPA shows DE message "Dieser Link ist nicht mehr gültig — bitte fragen Sie Ihren Veranstalter nach dem aktuellen Link." with no schedule data leaked from any prior state.
- [ ] **AC7 (governance)**: **Build configuration**: Vite 5+ + **Svelte 5** (NOT Svelte 4 — pinned per cycle-1 F-6) + TypeScript 5+; `package.json` includes `svelte`, `typescript`, `vite`, `@sveltejs/vite-plugin-svelte`. NO `@sveltejs/kit` (DEC-2 ban verified by `npm ls @sveltejs/kit` returning empty).
- [ ] **AC8 (governance)**: Build output goes to `vvwt-info-server/src/main/resources/static/` per Brief T-10. `mvn package -pl vvwt-info-server` includes the SPA bundle in the resulting JAR via `frontend-maven-plugin` (Apache 2.0, OSS per DEC-3) — wires `npm install` + `npm run build` into Maven `generate-resources` phase. Plugin version pinned in `vvwt-info-client/pom.xml`.
- [ ] **AC9 (governance)**: Skill attestation per Epic Success Metrics; DEC-23 / DEC-31 governance propagation. Vitest unit-test results + Playwright E2E results captured in `impl-report.md`. **DEC-13 in `related_decs`** (cycle-1 F-11 fix — staging branch model + squash-merge for closure commit).
- [ ] **AC10 (security)**: **URL-as-bearer client-side enforcement**: the SPA reads `tournament_token` and `team_token` from the URL **path** (not query string, not cookies); never persists them to localStorage / sessionStorage / IndexedDB; never logs them to the browser console. Test verifies via DOM/storage inspection.
- [ ] **AC11 (security)**: **Server-side CSP-header emission for the static-resource serve path** (cycle-1 F-1 fix — this story owns the static-resource serving config since it owns SPA packaging): `vvwt-info-server`'s `WebMvcConfigurer` (or equivalent Spring Boot 4 config bean) sets `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self' wss://<same-host>; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` on responses to the SPA static-resource path. Test in build: bundled SPA passes a strict CSP smoke test (Vite plugin verifies no inline `<script>` / inline `<style>` in build output).
- [ ] **AC12 (security)**: **Referrer-Policy `no-referrer` header** on the SPA static-resource path (cycle-1 F-4 fix — defends URL-token leakage via Referer header on outbound link clicks): server adds `Referrer-Policy: no-referrer` alongside CSP. Test verifies header presence on `GET /` and `GET /<sub-path>` SPA responses. Plus: SPA template uses `rel="noreferrer noopener"` on any external link (defensive belt-and-suspenders; minimal links in Phase 1).
- [ ] **AC13 (security)**: NO third-party telemetry / analytics / tracking — Phase 1 is participant-privacy-respecting by default. NO external CDN dependencies (Vite bundles all dependencies into the build output, served same-origin per Brief T-10). Verified by `package.json` audit and Vite build output review.
- [ ] **AC14 (error-handling)**: **Network-error UX with pinned exponential-backoff numerics** (cycle-1 F-7 fix): when WS connection fails AND HTTP poll fallback fails (total network outage), SPA shows "Verbindung verloren — Wiederverbindung..." indicator. Retry policy: **initial 1s, exponential factor ×2, full-jitter (random `[0, current-delay]`), max 60s, retry indefinitely**. Reset to initial 1s after a successful connection. Test verifies indicator appears and retry happens with measurable backoff progression.
- [ ] **AC15 (error-handling)**: **Stale-data indicator differentiated from connection indicator** (cycle-1 F-8 fix): when SPA HAS an established connection (no WS drop, no poll failure) but hasn't received a delta or successful poll-response in > **60 seconds** (configurable, distinct from AC14's "Verbindung verloren" trigger), show "Daten möglicherweise veraltet" warning. Cleared automatically on next successful update. AC14 and AC15 indicators have distinct DE copy AND distinct DOM testid — confirmable in tests.
- [ ] **AC16 (governance)**: **DE-only Phase 1 with externalised strings** — single string-table at `src/lib/i18n/de.ts` (typed object `Record<string, string>`); components import the table and reference keys; **NO inline string literals in component templates** beyond placeholder data binding. Enforcement: **`eslint-plugin-svelte` with a custom rule** OR a custom Vite plugin that scans for non-data string literals in `.svelte` template blocks and FAILS the build (cycle-1 F-5 fix — pin a concrete tooling path). If the custom rule proves infeasible, fallback is a build-time `grep` invocation against `.svelte` files via npm script that fails the build on any match against an inline-literal pattern. Tooling decision documented in `impl-report.md`.

## Notes

- **Svelte 5 pinned** (cycle-1 F-6): runes (`$state`, `$derived`, `$effect`) are the natural reactive primitives for delta application. Svelte 5 release stable in 2024; aligned with current best practice. Architectural decision pinned at story-level, not Delivery-level.
- Vite + Maven integration via `frontend-maven-plugin` (com.github.eirslett, Apache 2.0). Output to `vvwt-info-server/src/main/resources/static/`. Skippable via Maven property for fast Java-only iteration.
- AC3 single-state-machine reconnect-on-gap (cycle-1 F-3): simpler state machine; avoids deltas-idempotency assumption (which was unspecified in v1 and would have required server cooperation). Server's seq guarantee + reconnect-with-`since=N` + server's "if too old, return snapshot" already provides the recovery semantic.
- AC11 CSP same-origin policy: SPA bundles all deps locally (per AC13); no inline scripts/styles in Svelte 5 output by default. CSP `frame-ancestors 'none'` defends clickjacking; `wss://<same-host>` allows the WS connection.
- AC12 Referrer-Policy `no-referrer`: `tournament_token` + `team_token` in URL path would leak via Referer header on outbound link clicks — `no-referrer` zeroes the leak. Belt-and-suspenders: any explicit `<a target="_blank">` also gets `rel="noreferrer noopener"`.
- AC14 backoff numerics pin (cycle-1 F-7): standard "exponential backoff with full jitter, capped at 60s, retry indefinitely" from AWS Architecture Blog "Exponential Backoff and Jitter" (2015) recommended pattern. No max-retries for indefinite outages; admin UX surfaces the indicator.
- AC15 stale-data threshold (cycle-1 F-8): 60s threshold with established connection covers the case "WS still open but server stopped sending" (rare; possible during server-side stall). Distinct DOM testid + DE copy ensures testable distinction from AC14.
- AC16 inline-literal enforcement: cycle-1 F-5 fix pins a concrete tooling fallback (grep via npm script) if `eslint-plugin-svelte`'s rule capability is insufficient. Either path gates the build.
