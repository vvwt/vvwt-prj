# Story E15S07: Atomic cutover commit — delete legacy auth package + delete db/migration/V1..V6 + wire new beans

## User Story

**As a** reviewer of the Pilot's final step,
**I want** the legacy `auth` classes AND all six legacy Flyway migrations deleted in one atomic commit on `staging`,
**so that** the Wave-1 `auth` context is fully reconstructed, the DEC-21 atomic-cutover protocol has been exercised end-to-end including Flyway clearance, and nothing in the codebase references the pre-reconstruction auth stack.

---

## Context

This is the climactic story of the E15 Pilot. All preceding stories (E15S01–S06) built the new stack in parallel with the live legacy `AdminCredentialsBootstrap`, `AdminCredentialsProvider` (legacy interface), `SecurityConfig` (legacy), and their `V6` migration. E14S07 deleted the legacy `tenant` code but left `V1..V6` alone per DEC-22 O-9.

E15S07 is the single commit that deletes: legacy `auth` classes at `vvwt-prj/vvwt-tm-web/src/main/java/de/vvwt/tm/auth/{AdminCredentialsBootstrap,AdminCredentialsProvider,SecurityConfig}.java` (exact file list enumerated at plan time), AND `vvwt-prj/vvwt-tm-web/src/main/resources/db/migration/V1__*.sql` through `V6__*.sql`. After the commit, `mvn verify` must be green and `ApplicationModulesTest` must pass with only new code present.

Per DEC-21, no feature flags, no `@ConditionalOnProperty`. Per DEC-13, the cutover lands on `staging`.

---

## Acceptance Criteria

- [ ] AC1 (governance — single atomic commit): The cutover lands as ONE commit on `staging` that simultaneously: (a) deletes the legacy `auth` files enumerated in the Delivery plan, (b) deletes `V1__*.sql` through `V6__*.sql` under `vvwt-tm-web/src/main/resources/db/migration/`, (c) removes any Spring wiring referencing the legacy classes, (d) promotes the new beans as the sole implementations (no `@Primary` required — collision sources are gone). Git log shows one commit; no intermediate "delete legacy classes only" or "delete migrations only" commits. Per DEC-21.

- [ ] AC2 (governance — zero feature-flag annotations in the cutover commit): `git diff` of the cutover commit, filtered to `*.java`, shows ZERO additions of the following annotations: `@Profile`, `@ConditionalOnProperty`, `@ConditionalOnBean`, `@ConditionalOnMissingBean`, `@ConditionalOnClass`, `@ConditionalOnExpression`, `@ConditionalOnJava`, `@ConditionalOnResource`, `@ConditionalOnWebApplication`. Per DEC-21 "no feature flags" — explicit enumeration of the `@Conditional*` family removes ambiguity.

- [ ] AC3 (governance — legacy V1..V6 fully removed): `git diff` for the cutover commit shows deletion of exactly six files: `V1__*.sql`, `V2__*.sql`, `V3__*.sql`, `V4__*.sql`, `V5__*.sql`, `V6__*.sql` (exact filenames enumerated in the Delivery plan — V6 was the auth-related one). No `V7+` files are deleted; no new root-level migration files are added.

- [ ] AC4 (testing — full verify green): Post-cutover, `mvn verify` from `vvwt-prj/` is green: `ApplicationModulesTest`, the cross-tenant isolation test (E14S06), all E15 auth tests, and every pre-existing module test. No test is skipped or `@Disabled`.

- [ ] AC5 (security — cross-module smoke test): A fresh-machine integration test (via `@TempDir`) simulates a complete clean start: tenant context initialises (E14), `db/migration/auth/V1__admin_credentials.sql` applies to the default tenant's DB (E15S05 via E14S04), `AdminCredentialsBootstrap` generates a fresh password and logs plaintext at INFO, persists the bcrypt hash, a second start reads the existing hash without regeneration. Basic auth with `admin` + logged password grants access; invalid credentials are rejected. Exercises E14 + E15 together.

- [ ] AC6 (error-handling — no legacy-symbol drift): After cutover, a source-level search (`git grep` with the enumerated legacy class names and legacy migration filenames) returns zero hits across the entire `vvwt-prj` project. No straggler imports, no documentation still pointing at legacy classes.

- [ ] AC7 (security — Modulith verify post-cutover): `ApplicationModulesTest` is green with only the new `de.vvwt.tm.auth` (annotated `allowedDependencies = {"tenant"}`) and the new `de.vvwt.tm.tenant` (annotated `allowedDependencies = {}`) present. No legacy package is required to pass verify.

- [ ] AC8 (governance — rollback readiness): Per DEC-21, the Delivery plan documents the rollback procedure: `git revert` the cutover commit returns the repo to the last-good parallel-phase state. The procedure is documented but not expected to be exercised.

- [ ] AC9 (governance — retrospective file is cutover deliverable): The cutover commit INCLUDES the file `.gaai/project/contexts/artefacts/reports/E15-pilot-retrospective.md`. Commit without this file (regardless of content) fails AC. This codifies E15S08 AC5's inter-lock from S07's side — the inter-lock is now explicit in both directions. Content of the retrospective is E15S08's concern; existence of the file at the cutover commit is E15S07's concern.

## Notes

The Delivery plan's enumeration of legacy auth files is the single most error-prone pre-work step. Any legacy file missed here becomes AC6 drift and blocks merge. Delivery should run `find vvwt-tm-web/src/main/java/de/vvwt/tm/auth/ -type f` and inspect every result: is it legacy-to-delete or new-to-keep? Enumerate explicitly, do not glob-delete.

AC5 (cross-module smoke test) is the single E2E confirmation that the whole Wave-1 stack — tenant + auth, both reconstructed — works on a clean machine. It is the Pilot's hardest-earned deliverable and the evidence the human will weigh at the Wave-1 gate.
