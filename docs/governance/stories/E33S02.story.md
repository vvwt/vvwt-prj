# Story E33S02: Extract `TeamService` public interface + `DefaultTeamService` impl; migrate nested `BulkCreateRequest`/`BulkCreateResult` records

## User Story

**As a** maintainer of the `de.vvwt.tm.tournament` Modulith module post-E21,
**I want** `TeamService` exposed as a public interface in
`de.vvwt.tm.tournament.*` root (with `DefaultTeamService` in `.internal`,
`@Service("tmTeamService")` preserved) AND the existing public nested
records `TeamService.BulkCreateRequest` + `TeamService.BulkCreateResult`
relocated in-place via the enclosing-type change (FQN shifts from
`tournament.internal.TeamService.X` → `tournament.TeamService.X`;
record structures unchanged),
**so that** E22's `de.vvwt.tm.web.TeamController` migration per DEC-40
Clause D can consume the interface + nested records without reaching
into `tournament.internal.*`.

---

## Context

Per E33 epic + session brief, `TeamService` is one of 4 tournament
services requiring DEC-35 interface extraction. Distinct from E33S01:
`TeamService` has 2 public nested records (`BulkCreateRequest`,
`BulkCreateResult` at `TeamService.java:282,294`) which are consumed
by production code (`TeamController.java:5,143,147`,
`TeamBulkCreateResponse.java:3`) and tests (`TeamDtoTest.java:211-224`,
`TeamServiceTest.java:65`, `TeamControllerSliceTest.java:200`). The
enclosing-type change (concrete class → interface) requires FQN updates
across all these consumer sites.

Classification: Q-1b pure refactor. No RED-first test required. All
existing tests green pre- and post-refactor.
