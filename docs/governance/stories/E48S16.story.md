# Story E48S16: First-Phase sortType=team_number Invariant (Backend Validation + Frontend Auto-Lock)

## User Story

**As a** Tournament Organizer,
**I want** the Phasenplan UI and backend to enforce that the first phase always has sortType=team_number,
**so that** the uniform sortType-driven Vorbereiten-Algorithm (E48S17/S18) has a sensible source for Phase 1 (placement_group / group_placement require a previous phase's placements which Phase 1 does not have).

---

## Context

Per Brief D-3 + D-4 + O-7 + O-8: der Vorbereiten-Algorithmus wird uniform sortType-driven. Phase 1 hat keinen Vorgänger; nur sortType=team_number macht Sinn (Round-Robin-Verteilung der Teams nach teamNumber). placement_group und group_placement setzen TeamAvatarRating der vorherigen Phase voraus, die für Phase 1 nicht existiert.

Diese Story enforcet die Invariante symmetrisch zu E48S01's last-phase=siegerehrung-Invariante: die Section mit dem niedrigsten sectionNumber (= erste Phase) MUSS sortType=team_number haben. Backend rejected andere Werte beim Submit, Frontend setzt das Dropdown der ersten Section auto auf "Teamnummer" und sperrt es visuell.
