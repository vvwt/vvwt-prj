# Story E22S02: Remove `DefaultTournamentService` eager registry validation (Approach A boundary fix)

## User Story

**As a** scoring bounded-context maintainer / architecture steward,
**I want** `DefaultTournamentService` to no longer constructor-inject
`ScoringRuleRegistry` + `SetValidationRuleRegistry` and no longer
validate tournament rule IDs at creation time,
**so that** the `tournament → scoring-registries` coupling edge is
severed — which is the structural prerequisite for E22S11's atomic
cutover (once `scoring.*` reconstructs the registries, the opposite-
direction edge would close a Modulith dependency cycle) — with rule-ID
validation correctly preserved downstream via the existing
`TournamentRuleResolver` cascade-entry path (E31S03 impl-report
§ Step 1).

---

## Context

Per Brief v3 D-2(b): Approach A boundary fix removes eager registry
validation from `DefaultTournamentService`. Current state (on-disk,
verified at Brief v3 time):

- `DefaultTournamentService.java` constructor injects
  `ScoringRuleRegistry` + `SetValidationRuleRegistry` (constructor
  params at approx. lines 59-60) and stores them as fields (approx.
  lines 75-76).
- On tournament creation, the service iterates the tournament's
  configured rule IDs and looks them up in the registries, throwing
  `ValidationException` if an ID is unknown.

Problem: Once E22S03-E22S05 reconstructs `scoring.*` public API (with
registries living in `scoring.*` per D-9), the tournament→scoring-registry
edge would need to go through a public scoring surface — but even if
publicly available, tournament-depending-on-scoring combined with
scoring-depending-on-tournament (via the
`@ApplicationModule(allowedDependencies = {"tenant", "tournament"})`
declared at scoring) would form a Modulith dependency cycle.
`ApplicationModules.verify()` rejects cycles. Hence C-16 invariant:
the edge MUST be removed BEFORE cutover.

Per E31S03 impl-report § Step 1, rule-ID validation is already
performed at cascade entry by `TournamentRuleResolver` — the resolver
throws `ValidationException` (same exception type) on unknown IDs at
the first score submission. Removing eager validation preserves the
validation semantic but shifts the failure timing from creation-time
to first-submit-time.

Classification: Q-1b pure refactor under DEC-22 § refactor-clause.
Behavior-preserving at the domain-invariant level — unknown rule IDs
still fail with `ValidationException`, only the timing moves. Existing
coverage anchor is `TournamentRuleResolverIT.java` which already
asserts the downstream throw.

## Acceptance Criteria

### Governance

- [ ] **AC-CONSTRUCTOR-SIGNATURE-TRIMMED**: `DefaultTournamentService`
  constructor signature loses the 2 registry parameters
  (`ScoringRuleRegistry scoringRuleRegistry`,
  `SetValidationRuleRegistry setValidationRuleRegistry` — current
  approximate lines 59-60 of the ctor). The 2 corresponding `private
  final` fields (approximate lines 75-76) are DELETED. Any
  `this.scoringRuleRegistry = ...` / `this.setValidationRuleRegistry =
  ...` assignments inside the ctor body are DELETED.
- [ ] **AC-EAGER-VALIDATION-REMOVED**: Every code path in
  `DefaultTournamentService` that calls
  `scoringRuleRegistry.find(...)` / `.get(...)` /
  `.contains(...)` (or equivalent) OR
  `setValidationRuleRegistry.find(...)` / `.get(...)` /
  `.contains(...)` — for the purpose of validating a tournament's
  configured rule IDs at creation or update time — is DELETED. The
  tournament entity's `scoringRuleId` + `setValidationRuleId` fields
  are persisted verbatim without registry lookup.
- [ ] **AC-NO-OTHER-LOGIC-CHANGE**: No other change to
  `DefaultTournamentService` business logic. All other methods, field
  declarations, annotations, and bean metadata remain byte-identical
  pre/post. The `@Service("tmTournamentService")` qualifier (C-12)
  is untouched.
- [ ] **AC-IMPORT-CLEANUP**: `import
  de.vvwt.tm.domain.rules.ScoringRuleRegistry;` and `import
  de.vvwt.tm.domain.rules.SetValidationRuleRegistry;` are removed from
  `DefaultTournamentService.java`. Grep-sweep gate:
  `grep -rln "de\.vvwt\.tm\.domain\.rules\..*Registry" src/main/java/de/vvwt/tm/tournament/`
  returns ZERO hits post-commit. Impl-report cites pre-edit + post-edit
  grep counts.
- [ ] **AC-NO-CONSUMER-CALLSITE-BREAK**: All production callsites that
  `new DefaultTournamentService(...)` or that Spring-wire via
  `@Qualifier("tmTournamentService")` still compile + inject cleanly
  — the 2 registry bean dependencies at the wiring layer become
  unused (their bean definitions remain untouched; they are still
  injected into `TournamentRuleResolver` and the concrete rules per
  E31S03). Post-commit: `mvn spring-boot:run` (or equivalent context
  boot smoke) starts cleanly. Impl-report attests.
- [ ] **AC-MODULITH-VERIFY-GREEN**: `mvn -Dtest=ApplicationModulesTest
  verify` GREEN post-commit. The removed edge does NOT yet resolve
  to zero cross-module access because the scoring registries still
  live in `de.vvwt.tm.domain.rules.*` (legacy) — but the
  tournament-module source graph now has no direct reference to
  them from `DefaultTournamentService`. Verify-output cited verbatim.

## Notes

- **Why now and not at cutover**: Removing the edge at the atomic
  cutover commit (E22S11) would conflate two distinct edits
  (boundary-fix + legacy-deletion) in one commit, violating
  single-responsibility of commits. Doing it now as a stand-alone
  Q-1b lets QA regression-gate the boundary fix independently.
- **Coverage-anchor justification for test deletion**: Deleting the
  creation-time validation unit tests is normally a red flag, but
  in this case the semantic (throws on unknown rule ID) is already
  asserted downstream at cascade entry by `TournamentRuleResolverIT`.
  The deletion removes duplication, not coverage. Impl-report MUST
  make this explicit with the test-name mapping.
- **E31S03 coupling**: This story depends conceptually on E31S03's
  `TournamentRuleResolver` already being in place and already
  asserting the downstream throw — which it is, per E31 closure.
- **Commit message template**: `refactor(E22S02): remove
  DefaultTournamentService eager registry validation (DEC-40 Approach
  A boundary fix)`.
