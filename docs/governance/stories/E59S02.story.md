# Story: Per-file AGPL-3.0 SPDX license headers, build-enforced via Spotless

## User Story

**As a** contributor or downstream user of vvwt-prj,
**I want** every source file to carry an SPDX license header naming AGPL-3.0-or-later,
**so that** the license of any file is unambiguous even when the file is read, copied, or
extracted on its own — and so the coverage cannot silently drift as the codebase grows.

---

## Context

DEC-75 licensed vvwt-prj under AGPL-3.0-or-later; story E59S01 added the repo-root `LICENSE`
file. But individual source files carry no license marker — if a file is viewed or copied in
isolation, its license is invisible. DEC-76 (amending DEC-30) authorizes expanding the
Spotless configuration with a `licenseHeader` step so that a per-file SPDX header is added to
every first-party source file and build-enforced.

This is the second story of Epic E59. It depends on no other story.

---

## Acceptance Criteria

- [ ] AC1 (governance): every in-scope first-party source file in `vvwt-prj` carries, at its
  top, the two-line SPDX header in that file type's native comment syntax —
  `SPDX-FileCopyrightText: Copyright (C) 2026 Thomas Steinke` and
  `SPDX-License-Identifier: AGPL-3.0-or-later`. In-scope file types: Java, Svelte,
  TypeScript, JavaScript, CSS, Mustache, HTML. The in-scope file set is determined by a fresh
  inspection of the repository at delivery time — not from any pre-computed list.
- [ ] AC2 (governance): config/build/data files are NOT given a header — `pom.xml`,
  `application.yaml`/`.yml`, `.properties`, SQL migration files, JSON files. Generated,
  vendored, and build-output trees (`target/`, `node_modules/`, `dist/`) are never modified
  (DEC-76 D3).
- [ ] AC3 (governance): the Spotless configuration in the parent POM gains a `licenseHeader`
  step covering all in-scope file types (the `<java>` block plus generic `<format>` blocks
  for the non-Java types), bound to the existing `verify`-phase `spotless-check` execution
  (DEC-76 D1).
- [ ] AC4 (governance): header enforcement is real, not merely configured — verified by a
  deliberate negative check: a first-party source file with its header removed or altered
  makes `spotless:check` / `mvn verify` fail, and `spotless:apply` restores it. The check
  basis and result are recorded in the impl-report.
- [ ] AC5 (governance): if Spotless cannot enforce a `licenseHeader` on one of the in-scope
  file types, Delivery STOPS and escalates — naming the file type and the limitation —
  rather than silently dropping that type from enforcement (DEC-76 D5).
- [ ] AC6 (governance): the header rollout lands as a single atomic commit; the impl-report
  records the count of files given a header and notes any WIP-branch conflict encountered
  (DEC-30 §Impact branch-coordination risk; DEC-76 §Impact).
- [ ] AC7 (governance): `mvn verify` from the `vvwt-prj` root is BUILD SUCCESS (DEC-54) — the
  header rollout and the Spotless configuration change leave the build green.

> All acceptance criteria must be verifiable.

## Out of Scope

- The repo-root `LICENSE` file — delivered by E59S01.
- The AGPL §13 in-application source-code offer — E59S03.
- Headers on config/build/data files (DEC-76 D3).
- Activating any other Spotless rule (trailing-whitespace, custom import-order) — DEC-76 D4
  expands scope by `licenseHeader` only.
- Changing the license or the copyright holder — settled by DEC-75.

## Notes

Non-semantic, non-authoring change: adding a comment header to existing files and a
`licenseHeader` step to a build plugin authors no first-party logic — DEC-22's RED-first Iron
Law does not apply (same non-authoring category as the DEC-29/DEC-30 mechanical-hygiene
changes and the DEC-67 dependency-coordinate carve-out). AC7's `mvn verify` green and AC4's
negative check are the regression guards. The header is applied uniformly to every in-scope
file including AI-generated ones; the legal uncertainty about copyright in machine-generated
code is documented in DEC-75 §Impact and is not in scope here. Per memory
`feedback_no_precomputed_inventory_in_stories.md`, AC1 carries a fresh-audit obligation, not
a file list. Per DEC-13 the work is delivered on a `story/E59S02` branch off `staging`; AI
never pushes or merges to `vvwt-prj/main`.
