# Story E54S01: L2 voting-driven phase-global slot-filling (port of legacy MatchDistributor)

## User Story

**As a** tournament operator running a phase with multiple groups,
**I want** the match schedule to distribute matches phase-globally with voting-driven fairness (avatar + group voting), not per-group sequentially,
**so that** each team's idle stretches between matches are minimized and no two teams from different groups sit idle for half the phase.

---

## Context

DEC-61 (this story's operationalization target, authored 2026-05-11) amends DEC-56 D-1 L2 row: the L2 `RoundAssignmentService` algorithm is replaced from per-group greedy edge-coloring + cumulative-lap-offset concatenation to phase-global voting-driven greedy slot-filling. The new algorithm ports legacy `vvw-tournaments-services` `de.vvwerratal.vvw.tournaments.services.match.MatchDistributor.createMatchListForTournament` (lines 332-425) including its Voting-Triple (`avatar1Voting + avatar2Voting + groupVoting`, lines 295-330).

Empirical defect being fixed (verbatim operator report 2026-05-10): the user's 12-team / 2-group / 3-field test tournament showed the Laufzettel with only 5 rounds and two matches scheduled on the same field at the same time. Root-cause analysis (Brief v6 O-3 + Defect 1 in DEC-61 Context): `DefaultRoundAssignmentService.assignRoundsAndFields` (`vvwt-tm-web/.../tournament/internal/DefaultRoundAssignmentService.java:171-217`) partitions matches by `groupNumber`, runs greedy edge-coloring within each group, then concatenates via `cumulativeLapOffset` — producing disjoint lap ranges (Group 1 laps 1..5, Group 2 laps 6..10) that maximize idle-time per team. After E51S18 (per-group partition fix) and E53S06 (1-based lap offset), this concatenation is the remaining structural defect.

Legacy reference is the user-mandated canonical (verbatim, 2026-05-10): *"Der Match-Distributor sollte eigentlich die Funktionalität von der Legacy-Anwendung übernehmen. Dort war das schon so implementiert. siehe Modul vvw-tournament-services de.vvwerratal.vvw.tournaments.services.match.MatchDistributor"*. Voting-Triple choice confirmed: `avatar1+avatar2+groupVote`.

DEC-60 (operationalized by E53S09, merged inner PR #255) established 1-based `lapNumber` AND `fieldNumber` write-convention. E54S01 preserves this: the new voting algorithm emits `setLapNumber(lap)` with `lap ∈ [1..lapCount]` and `setFieldNumber(field)` with `field ∈ [1..fieldCount]` at every persisted Match-Row.

L1 (`RoundRobinMatchGenerator`) returns a flat `List<Match>` phase-wide (verified `RoundRobinMatchGenerator.java:102, 143-176`); the new voting algorithm consumes this flat list directly without per-group re-partitioning.

Bye-Slots: when no conflict-free match exists for the current `(lap, field)` slot, no Match-Row is created (no `setLapNumber` / `setFieldNumber` call for the would-be Bye-Slot). Display surfaces (E50S04-delivered Display SPA; E53S08-pattern Print Laufzettel) render missing slots as Spielfrei without further intervention.

DEC-22 §refactor-clause does NOT apply: the algorithm contract itself is being replaced (not refactored). Q-1a fresh-RED-first applies per memory `feedback_dec22_refactor_phase_first.md` Pattern B.

## Acceptance Criteria

### Testing (DEC-22 RED-first; DEC-54 mvn verify gate)

- [ ] **AC-TEST-VOTING-TRIPLE-LOWEST-VOTE-WINS-RED**: New JUnit unit test asserts that, given a list of `VotedMatch` instances with explicit per-match `avatar1Voting + avatar2Voting + groupVoting` totals, the slot-filling loop selects the match with the strictly lowest combined vote at each slot (when conflict-free). RED before implementation; commit log shows RED before GREEN per DEC-22 Iron Law.

- [ ] **AC-TEST-VOTING-INCREMENT-ON-ASSIGNMENT-RED**: New unit test asserts that after a `VotedMatch` is assigned to a slot, each of its three associated voting counters (`avatar1Voting`, `avatar2Voting`, `groupVoting`) is incremented by exactly 1; remaining (still-unassigned) matches that share the same avatar or group see their vote totals reflect the increment on the next selection iteration. RED before GREEN.

- [ ] **AC-TEST-CONFLICT-SKIP-NO-AVATAR-TWICE-PER-LAP-RED**: New unit test asserts that within any single lap, no avatar appears in two matches (per Brief D-1: "max 1 Spiel pro Team"). Construct a scenario where the lowest-vote next match would re-use an avatar already playing in the current lap; assert the slot-filling loop skips it in favor of the next-lowest-vote conflict-free candidate. RED before GREEN.

- [ ] **AC-TEST-SYMMETRIC-12T-2G-3F-PRODUCES-10-LAPS-3-MATCHES-RED**: New `DefaultRoundAssignmentServiceTest` or sibling IT asserts: for a phase with 12 avatars in 2 groups of 6 + `tournament.fieldCount = 3`, after `assignRoundsAndFields` (or its replacement method) the persisted matches have exactly 10 distinct `lapNumber` values in `[1..10]`, each lap contains exactly 3 matches (one per field), and zero `(lapNumber, fieldNumber)` duplicates across phase matches. RED before GREEN.

- [ ] **AC-TEST-ASYMMETRIC-11T-2G-3F-BYE-SLOTS-RED**: New unit/IT asserts: for a phase with 11 avatars in 2 groups (e.g., 5+6 or 6+5), after L2 the persisted matches sum to the expected total (10 + 15 = 25 matches per `n*(n-1)/2` formula per group); the distribution across laps satisfies "no avatar twice per lap" AND "no field twice per lap"; lap-slots without a conflict-free match assignment produce no Match-Row (Bye-Slot). Exact lap count is voting-deterministic but bounded by `ceil(25 / 3) = 9` laps minimum. RED before GREEN.

- [ ] **AC-TEST-IDLE-TIME-MINIMIZATION-VS-BASELINE-RED**: New unit/IT computes the maximum-consecutive-idle-laps per avatar in the post-E54S01 12T/2G/3F output and asserts this value is strictly less than the baseline-5 (= 5 consecutive idle laps per avatar under per-group + cumulative-offset L2). Baseline is captured by either a fixture-record of the pre-E54S01 output or by an explicit comment-comparison against the documented edge-coloring behavior. RED before GREEN.

- [ ] **AC-TEST-1-BASED-LAP-AND-FIELD-DEC-60-PRESERVED-RED**: New unit/IT asserts that after L2 runs, `MIN(match.lap_number) = 1` AND `MIN(match.field_number) = 1` for any non-empty phase (DEC-60 D-1 1-based write-convention preserved). RED before GREEN.

- [ ] **AC-TEST-EMPTY-PHASE-NO-OP-GREEN**: Existing or new unit test asserts that when L1 returns an empty match list for a phase, L2's voting-driven slot-filling completes without exception and produces zero Match-Row updates. GREEN expected (graceful no-op).
