# Story E51S08: Fix — Symmetric `waitForPipelineQuiescent` quiescence barrier in `DefaultDraftServiceApplyNoTeamAvatarsIT.tearDown` to deflake the DEC-54 `mvn verify` gate

## User Story

**As a** GAAI Delivery operator dependent on the DEC-54 `mvn verify` gate to gate-check every story's close-commit,
**I want** `DefaultDraftServiceApplyNoTeamAvatarsIT.tearDown` to deterministically clean up `match` and `phase` rows without racing the async `MatchGenJobListener`,
**so that** the gate stops firing false-FAILs on intermittent FK_MATCH_PHASE errors and stories like E50S02 close cleanly without escalation cycles unrelated to their own diff.

---

## Context

**Verified failure:** `mvn verify -pl vvwt-tm-web` exits non-zero with `DefaultDraftServiceApplyNoTeamAvatarsIT.tearDown:131 » DataIntegrityViolation` — `FK_MATCH_PHASE: PUBLIC.MATCH FOREIGN KEY(PHASE_ID) REFERENCES PUBLIC.PHASE(ID)` — when `DELETE FROM phase WHERE tournament_id = ?` runs while async-inserted `match` rows still reference the phase. Empirically observed in two independent runs on 2026-05-08: (a) Discovery's repro on E50S02 worktree HEAD `f84fecd` (base 5 commits behind staging) at 17:29; (b) Delivery daemon's 2nd attempt on the same worktree after rebase onto current staging HEAD `345954c` (worktree HEAD `efa7be2`) at 22:56. Verified via `git merge-base --is-ancestor 345954c HEAD = true`. **The race fails even on the rebased-to-current-staging worktree** — it is a real intermittent defect, not a stale-base artefact.

**Root cause (verified via git provenance):**

1. Commit `f782a53` (`feat(E51S03): Background-Job-Pipeline foundation`) introduced the async `MatchGenJobListener` (`@Async` + `@TransactionalEventListener(AFTER_COMMIT)` + `REQUIRES_NEW`). The listener inserts `match` rows on a background thread after `apply()` returns.
2. The same commit added an identical `DELETE FROM match WHERE phase_id IN (SELECT id FROM phase WHERE tournament_id = ?)` to BOTH sister tearDowns (`DefaultDraftServiceApplyAvatarsIT` + `DefaultDraftServiceApplyNoTeamAvatarsIT`). Both tearDowns received the delete-order-fix.
3. Commit `e25b917` (`feat(E51S04): implement Slot-Opt FIFO-Queue serial per tournament`) **subsequently** added the `waitForPipelineQuiescent()` helper (polls `phase.last_job_state IN ('match_gen_running','slot_opt_running')` until empty, max 5 s) plus `SET REFERENTIAL_INTEGRITY FALSE/TRUE` belt-and-suspenders to **`DefaultDraftServiceApplyAvatarsIT` only**. **`DefaultDraftServiceApplyNoTeamAvatarsIT` was left without the helper**. Verified via `git log --all --oneline -S "waitForPipelineQuiescent" -- DefaultDraftServiceApplyAvatarsIT.java` returning only `e25b917` + `e13e4dc` (the squashed PR-merge variant), and zero matches for the NoTeam file.

This is the asymmetric-helper-port that this Story repairs.

**Empirical FAIL-rate context:** Five successive stories (E51S03..E51S07) closed on `mvn verify BUILD SUCCESS` claims (qa-report counts 555/570/586/-/-) with the same NoTeamAvatars-IT class present and unprotected from `f782a53` onward. With ≥2 verified failures (Discovery 17:29 + daemon 22:56) across 7 known runs, lower-bound FAIL-rate ≈25% if uniformly distributed — substantial enough to keep tripping the gate.

**Sister IT TournamentCrossContextSmokeIT** was mentioned as "intermittently affected" in E50S02's cycle-1 qa-report (text in git ref `eb98572` on local worktree branch `story/E50S02`, not on origin/staging). Whether it requires the same patch is UNVERIFIED; Delivery investigates as part of "`mvn verify` must be green" obligation per AC-GOVERNANCE-DEC-54-MVN-VERIFY-DETERMINISTIC.

**Scope posture:** Test-only fix. Zero `.java` files under `src/main/`. The asymmetric-helper-port from `DefaultDraftServiceApplyAvatarsIT` to `DefaultDraftServiceApplyNoTeamAvatarsIT` (and any other IT class affected) is the WHAT; HOW (extract-helper-to-shared-utility vs duplicate-inline vs alternative-deterministic-approach) is at Delivery's discretion per Q-1/Q-4. The 5-state public API of `phase.last_job_state` is preserved.
