# Story E52S02: Restore admin-UI access to CertificateRenderController + rename Urkunden-Vorlage button to Urkunden + add Urkunden-erstellen sub-page button + new /tournaments/:id/certificates route

## User Story

**As a** Tournament Organizer,
**I want** a single tournament-row button labelled "Urkunden" that opens the certificate-template management sub-page where, for completed tournaments, a header-right "Urkunden erstellen" button takes me to a new generation/download UI,
**so that** I can reach both certificate-template configuration AND post-tournament certificate generation from the admin UI without overloading the tournament row with a separate Generate button.

---

## Context

The Wave-2 certificate context reconstruction (E23S06–S10, all done) and E24S05 (CertificateRenderController, done) rebuilt the BE certificate module:

- **Template management** (E23S07–S09): `CertificateTemplateController` at `/api/certificate/tournaments/{tournamentId}/template/*` — reachable today via the existing tournament-row button "Urkunden-Vorlage" (i18n key `tournaments.certificateTemplateButton`) → `/tournaments/:tournamentId/certificate-template` SPA route → `CertificateTemplate.svelte`.
- **Certificate generation** (E24S05): NEW `CertificateRenderController` at `de.vvwt.tm.web.certificate.CertificateRenderController` with `@RequestMapping("/certificate/tournaments/{tid}")` exposing two server-rendered Mustache/SVG/HTML/ZIP endpoints:
  - `GET /print/{teamId}` — single team certificate
  - `GET /print` — all team certificates (ZIP)

The certificate-generation BE endpoints exist on staging (verified empirically 2026-05-08) but **no admin-UI surface invokes them**. There is no "Urkunden erstellen" / "Urkunden generieren" button in `Tournaments.svelte` and no `/tournaments/:id/certificates` route in `App.svelte`. The original Wave-1 E12S07 "Certificate generation + download UI" delivery (PR #28 merged) introduced a `tournaments.certificatesButton` and a `/tournaments/:id/certificates` route on dangling branch `story/E12S07` (commit `4219930`), but git pickaxe confirms neither key nor route reached `staging` in that exact form post Wave-2 cutover.

User-observable symptom (Brief): after a tournament transitions to `COMPLETED`, the operator cannot generate certificates from the admin UI. The operator must construct `/certificate/tournaments/{tid}/print` BE URLs manually or skip certificate output entirely.

User-decision during Discovery (2026-05-08): rather than adding a SECOND tournament-row button next to "Urkunden-Vorlage" (which would overload the row), rename the existing template-management button label to "Urkunden" and add the generate-button as a header-right action on the existing `CertificateTemplate.svelte` sub-page. This makes "Urkunden" the workflow hub and "Urkunden erstellen" the post-event action.

**Alternative considered (rejected)**: keep `tournaments.certificateTemplateButton` key + label `Urkunden-Vorlage` + add header-button on sub-page only. Rejected per User correction: the rename surfaces the workflow-name (Urkunden) at the tournament row, not the configuration-name (Urkunden-Vorlage); the configuration-name belongs only inside the sub-page.

This is a **producer-side fix at the admin-UI layer** (per memory `feedback_discovery_cycle_resolution_scope_creep.md`): `Tournaments.svelte` for the rename + `CertificateTemplate.svelte` for the sub-page header button + `App.svelte` for the new route. Discovery does NOT prescribe access shape for the generation UI (Svelte-component-with-fetch / iframe-wrapper / new-tab-open) — Brief T-3 lists three viable shapes; Delivery selects.

### Empirically-verified rename touch-surface (Brief D-5, 5 lines)

- `de.json:27` — KEY rename `certificateTemplateButton` → `certificatesButton`, value rename "Urkunden-Vorlage" → "Urkunden"

- `certificateTemplateStore.test.ts:7,80,82` — three test assertions updated to new key

The FE route URL `/tournaments/:tournamentId/certificate-template` STAYS unchanged (URL stability + bookmark safety per Brief D-5). The BE URLs (`/api/certificate/tournaments/{id}/template/*`) STAY unchanged (BE not modified).
