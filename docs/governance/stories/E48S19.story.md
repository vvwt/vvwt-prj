# Story E48S19: Fix — PhaseList.handlePrepare Navigation + i18n phases.columns Merge

## User Story

**As a** Tournament Organizer,
**I want** the PENDING-state "Vorbereiten" button to navigate me to the Drag&Drop preparation UI (where I can review and adjust the team-to-group assignment), AND the Phase-Übersicht column headings to display translated labels (not raw i18n keys),
**so that** I can perform the deliberate Vorbereiten step (per E48S17/E48S18 design) AND read the Phase-Übersicht table without seeing developer-facing key strings.

---

## Context

After E48S17 (PR #210 merged 2026-05-07) and E48S18 (PR #211 merged 2026-05-07T20:17Z post-rescue-reconcile), two consumer-side bugs remain that prevent the Vorbereiten-Step + Phase-Übersicht UI from working as designed.

### Bug 1 — PhaseList.handlePrepare bypasses Vorbereiten-Route

`vvwt-tm-web/src/main/ui/src/routes/PhaseList.svelte:248-256` wires the PENDING-state button to `handlePrepare(phaseId)` (lines 119-131), which directly calls `preparePhase(phaseId)` via the API. The phase status switches PENDING → PREPARED instantly, **bypassing** the Drag&Drop UI at `/tournaments/:tournamentId/phases/:phaseId/prepare` (delivered by E48S18 in `PhasePreparation.svelte`).

This violates E48S17's own acceptance criterion `AC-FRONTEND-PHASE-OVERVIEW-BUTTONS-EXTENDED` ("PENDING: 'Phase vorbereiten' navigiert zu `/tournaments/:id/phases/:phaseId/prepare`"). User-observable symptom (2026-05-07): "Klick auf 'Vorbereiten' — das einzige Ergebnis ist, dass sich der Status auf 'Vorbereitet' geändert hat."

### Bug 2 — Duplicate `phases.columns` block in `de.json`

`vvwt-tm-web/src/main/ui/src/locales/de.json` defines the `phases.columns` object **twice**:
- Lines 65-72 — `sequenceNumber`, `description`, `status`, `gameMode`, `currentLap`, `matches`
- Lines 86-88 — `actions`

JSON parsers retain only the **last** occurrence of a duplicate key, silently dropping the first block. `PhaseList.svelte:225-231` renders `{$_('phases.columns.sequenceNumber')}` etc.; six of seven keys are now unresolved and svelte-i18n falls back to the literal key string. User-observable symptom (Screenshot 2026-05-07-21-47-12): all column headings display `phases.columns.<key>` instead of translated text.

### Scope posture

This story is a **producer-fix at the PhaseList component scope** (per memory `feedback_discovery_cycle_resolution_scope_creep.md` — fix at the source, not via consumer tolerance). Pure FE consumer refactor: backend `prepare()` service + endpoint unchanged. Only DE locale is active in V1 (per user 2026-05-07); en.json is out of scope.
