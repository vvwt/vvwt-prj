# Story E51S10: L2 Round-Assignment Service — generic edge-coloring + initial field assignment + tournament.fieldCount wiring

## User Story

**As a** Tournament Operator,
**I want** every match to receive a valid `lapNumber` and `fieldNumber` immediately after Match-Gen — without depending on Slot-Opt running — using my tournament's configured number of fields,
**so that** Schiri-Zuordnung in the drag&drop flow works regardless of `tournament.optimize` setting, and the schedule is physically valid (no field number exceeds the actual court count).

---

## Context

**Architecture (Brief D-1 + Approach-Evaluation Approach D-V3):** Layered Decomposition introduces L2 — a Spielart-agnostic Round-Assignment service between L1 (Match-Generation) and L3 (Slot-Optimization). L2 takes matches from L1 (no lap/field) and produces matches with `lapNumber` + `fieldNumber` assigned, respecting:
- Round-conflict-freedom (no team plays >1 match per lap)
- Field-count constraint (≤ `fieldCount` matches per lap)
- Minimal lap count (`max(N-1, ⌈totalMatches / fieldCount⌉)`)
- Spielart-agnostic algorithm (NOT circle-method; works on any match-graph)

**Initial field assignment (Brief D-1 row 2 + D-7):** L2 lays out matches in a flat row-ordering such that index `i` maps to `(lap = i / fieldCount, field = i % fieldCount)`. This ordering is consumed by L3 (Story 11) for lap-permutation optimization without further field-reassignment.

**`tournament.fieldCount` threading (Brief O-16 + D-13):** today `tournament.fieldCount` (operator-set on Tournament aggregate, visible at `DefaultDisplayOverviewService.java:176`, `TournamentController.java:109,150`) is NEVER passed to slot-opt; the application-level config `tm.slotopt.fallback.field-count:3` is used regardless. Story 10 fixes this: `tournament.fieldCount` flows from Tournament aggregate through `MatchGenJobExecutor` to L2-Service. **Fallback (D-13):** when `tournament.fieldCount` is null/zero, L2 falls back to `tm.slotopt.fallback.field-count` config default.

**`PhaseToRawPhaseDefMapper.fieldCount` activation (Brief O-15 + D-11):** the dead-code field at `PhaseToRawPhaseDefMapper.java:64` is wired to L2-Service in this story (becomes the read-source for downstream Slot-Opt invocations consuming Mapper output, post-Story-11).

This story is the L2 layer of the Layered Decomposition. L3 refactor is OUT OF SCOPE (Story 11). L2 must work even if L3 is disabled (`tournament.optimize=false`).

- [ ] **AC-IMPL-L2-SPIELART-AGNOSTIC** (governance): the L2-Service implementation does NOT reference `gameMode`, `Spielart`, or `roundRobin` strings. - [ ] **AC-IMPL-L2-EDGE-COLORING-ALGORITHM** (governance): L2's default implementation uses a generic edge-coloring algorithm (greedy with capacity-check, OR Misra-Gries-Variante with field-count constraint, OR equivalent) — NOT the circle-method. Algorithm choice is Delivery's discretion provided round-conflict-freedom + field-count-constraint + minimal-lap-count are achieved.
- [ ] **AC-IMPL-INITIAL-FIELD-VIA-ROW-POSITION** (governance): L2 lays matches in **flat row-ordering, lap-major** (lap 0 fills first with up-to-fieldCount matches, then lap 1, …, last lap holds the remainder). Position-index `i` derives `lapNumber = i / fieldCount` and `fieldNumber = i % fieldCount`. Partial trailing laps occupy ONLY `fieldNumber 0..k-1` where `k = matchesInThisLap` — no virtual field assignments beyond `k-1`. This ordering is the L3 input contract (Story 11 consumes it). Documented in the L2 service's javadoc with at least one numeric worked example.
