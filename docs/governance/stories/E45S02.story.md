# Story E45S02: Pre-Reset — `infoportal` Modulith formalization (`package-info.java` + `@ApplicationModule(allowedDependencies={})` + `ApplicationModules.verify()` green)

## User Story

**As a** Tournament Manager developer maintaining the Spring Modulith bounded-context layout,
**I want** the `de.vvwt.tm.infoportal` package formally declared as a Modulith module via `package-info.java` + `@ApplicationModule`,
**so that** the infoportal code (Ed25519KeypairManager, InfoPortalPublisherService, InfoPortalStateDao, InfoPortalStateRecord, InfoPortalStatusController, TmJcsCanonicalizer, etc.) is governed by Modulith boundary verification and ready for the Wave-2 Big-Bang-Reset (E45S05) where its V17 schema lands in `infoportal/V1`.

---

## Context

Brief O-4 surfaced this gap: the `de.vvwt.tm.infoportal` package was created during
E38S09 (TM publisher integration for Public Participant Info Service) but never received
a `package-info.java` declaration. It is a half-state Modulith module — Java code is
present and functional, but boundary verification doesn't apply because the module
isn't formally declared. Brief audit confirmed:

- All other bounded contexts have `package-info.java`: `auth`, `tenant`, `tournament`,
  `scoring`, `certificate`, `timer`, `display`, `print`, `slotopt`, `photo`, `web`.
- `infoportal` is the lone exception.
- Empirical import scan: `grep -rn 'import de\.vvwt\.tm\.' vvwt-tm-web/src/main/java/de/vvwt/tm/infoportal/` returned zero cross-module imports of `de.vvwt.tm.*` types in infoportal production code (only Spring + Java + own-package imports).

Story authors `package-info.java` with `@ApplicationModule(allowedDependencies = {})`
initially. If the import re-verification at story-authoring identifies cross-module
imports introduced after Brief audit (2026-05-03), `allowedDependencies` expands at
that point. The DEC-25 §Production-data-escape-hatch clause is unaffected by this
story (no schema change; no production-data risk).

E45S05's atomic SQL Reset places V17 (`info_portal_state`) into `infoportal/V1`.
For Modulith Flyway-folder ordering to work, the `infoportal` package must be a
declared Modulith module before S05 lands. S02 closes this gap.

## Acceptance Criteria

### Modulith module declaration

- [ ] **AC-PACKAGE-INFO-AUTHORED [governance]:** New file `vvwt-tm-web/src/main/java/de/vvwt/tm/infoportal/package-info.java` is authored. File content: standard Java package declaration + `@ApplicationModule` annotation with `allowedDependencies = {}` (empty initial list). Javadoc summary describing the bounded context responsibility (TM-side publisher integration for Public Participant Info Service per DEC-42 + E38).
- [ ] **AC-EMPIRICAL-IMPORT-VERIFICATION [governance]:** At story-authoring time, story-author re-runs `grep -rn 'import de\.vvwt\.tm\.\(auth\|tenant\|tournament\|scoring\|certificate\|timer\|display\|print\|slotopt\|photo\|web\)\.' vvwt-tm-web/src/main/java/de/vvwt/tm/infoportal/` to confirm cross-module import set. If empty (per Brief audit) → `allowedDependencies = {}`. If non-empty → `allowedDependencies` lists the imported modules' names (e.g., `{tenant, tournament}`); rationale documented in `impl-report.md`. Empirical evidence (the grep output) is recorded in `impl-report.md`.
- [ ] **AC-MODULITH-VERIFY-GREEN-POST-DECLARATION [governance]:** `ApplicationModules.of(TournamentManagerApplication.class).verify()` is GREEN after `package-info.java` is in place. The existing `ApplicationModulesTest` continues to pass.
- [ ] **AC-NO-INFOPORTAL-INTERNAL-LEAK [governance]:** Other Modulith modules MUST NOT import from `de.vvwt.tm.infoportal.internal.*` (if any `.internal` sub-package exists or is created in the future). Verified by `grep -rn 'import de\.vvwt\.tm\.infoportal\.internal' vvwt-tm-web/src/main/java/de/vvwt/tm/{auth,tenant,tournament,scoring,certificate,timer,display,print,slotopt,photo,web}/` returning empty.

### DEC-35 internal vs public split (informational, not mandatory in S02)

- [ ] **AC-DEC35-INTERNAL-CLASSIFICATION-DEFERRED [governance]:** S02 does NOT split existing infoportal classes into `internal` sub-package per DEC-35 §pragmatic-hexagonal. Today every infoportal class sits at the package root (`de.vvwt.tm.infoportal.*`). Story-author records in `impl-report.md` whether any class would benefit from `.internal` relocation per DEC-35 (e.g., `Ed25519KeypairManager` is implementation detail), but the actual relocation is a follow-up Story (or a Wave-3 cleanup) — NOT in S02 scope. S02 ships package-info only.

### DEC-22 + test invariants

- [ ] **AC-NO-NEW-PRODUCTION-CODE [governance]:** S02 commit must NOT add or modify any `*.java` file outside `package-info.java`. Specifically, no Ed25519KeypairManager / InfoPortalPublisherService / InfoPortalStateDao / etc. modifications. Verified by `git diff --stat ${baseSha}..HEAD vvwt-tm-web/src/main/java/de/vvwt/tm/infoportal/` showing exactly one added file (`package-info.java`) and zero modifications.
- [ ] **AC-NO-FLYWAY-CHANGES [governance]:** S02 commit must NOT modify any file under `vvwt-tm-web/src/main/resources/db/migration/`. Same guard as S01.
- [ ] **AC-EXISTING-TESTS-GREEN [testing]:** All existing infoportal-package tests (`InfoPortalStateDaoIT`, any `InfoPortalPublisherServiceTest`, etc.) continue to pass post-commit. New tests are NOT authored by S02 — `package-info.java` is metadata, not behavior; DEC-22 Iron Law's "no production code without RED-first" does not apply (a `package-info.java` declaration is not production code in the behavioral sense).

### Build + verify gate

- [ ] **AC-MAVEN-VERIFY-GREEN [testing]:** `mvn -pl vvwt-tm-web verify` is GREEN post-commit.
- [ ] **AC-SPOTLESS-CLEAN [governance]:** Spotless format check passes on the new `package-info.java` (DEC-30).

### Failure-mode handling

- [ ] **AC-VERIFY-FAILURE-ROLLBACK [error-handling]:** If `ApplicationModules.verify()` FAILs post-`package-info.java` authoring (e.g., a previously-undetected cross-module import surfaces under stricter Modulith analysis once `infoportal` is formally declared), Delivery does NOT silently expand `allowedDependencies` to absorb the violation. Instead: (a) document the unexpected import in `impl-report.md` with file:line; (b) escalate to Discovery for explicit `allowedDependencies` decision (per Brief D-8 "story-authoring re-verifies pre-commit"); (c) DO NOT proceed with commit until Discovery rules. Rationale: speculative dependency expansion creates false governance signal — the Modulith verify failure is a useful early-warning signal that S02 must surface, not suppress. Rollback path if S02 commit is reverted: `git revert ${S02-sha}` removes only the `package-info.java` file; no other files modified.

### Single-commit cutover

- [ ] **AC-SINGLE-COMMIT-CUTOVER [governance]:** S02 lands as a single commit on `staging` per DEC-13.

  (e.g., infoportal subscribing to tournament-context events for snapshot
  publication), `allowedDependencies` expands at THAT story's commit. S02 ships
  the minimal viable declaration.

  not a memory artefact; standard close-story propagation applies.
