# Story E18S04 (Bug-Triage): Remove the 9 test-only / orphan Repository/DAO read methods (DEC-69 operationalization)

## User Story

**As a** developer maintaining `vvwt-prj`,
**I want** every public Repository/DAO read method to have at least one production consumer,
**so that** the codebase contains no production methods that exist only for tests (a TDD anti-pattern per DEC-69) and the read-API surface reflects actual production need.

---

## Context

A 2026-05-15 code audit enumerated every public method on all 45 Repository/DAO interfaces across the 3 persistence-bearing `vvwt-prj` modules and found **9 public read methods with zero production callsites** — exercised only by tests, or by nothing at all. DEC-69 (amendment to DEC-22) codifies the rule: a public Repository/DAO read method MUST have a production consumer; a test-only read method is removed together with the test(s) that exercised only it.

The 9 methods (re-verified 2026-05-15 against `staging` HEAD `b4dcbb5`):

| # | Module | Type | Method | prod / test |
|---|---|---|---|---|
| 1 | vvwt-tm-web | `tournament.AuditLogRepository` (+`DefaultAuditLogRepository` impl) | `findByTournamentIdAndId(UUID,UUID)` | 0 / 0 — orphan |
| 2 | vvwt-tm-web | `tournament.AuditLogRepository` (+`DefaultAuditLogRepository` impl) | `findByTournamentIdAndMatchIdAndSetIndexOrderByChangedAt(UUID,UUID,int)` | 0 / 1 |
| 3 | vvwt-slotopt-dispatcher | `audit.AuditRepository` (Spring Data derived query) | `findByWorkerIdOrderByOccurredAtDesc(UUID)` | 0 / 2 |
| 4 | vvwt-slotopt-dispatcher | `audit.AuditRepository` (Spring Data derived query) | `findByEventTypeOrderByOccurredAtDesc(String)` | 0 / 2 |
| 5 | vvwt-slotopt-dispatcher | `packet.PacketRepository` (Spring Data derived query) | `findByStatus(String)` | 0 / 2 |
| 6 | vvwt-slotopt-dispatcher | `result.LateResultRepository` (Spring Data derived query) | `findByPacketId(UUID)` | 0 / 2 |
| 7 | vvwt-slotopt-dispatcher | `result.ResultAuditRepository` (Spring Data derived query) | `findByPacketId(UUID)` | 0 / 2 |
| 8 | vvwt-info-server | `persistence.audit.AuditLogDao` (Spring Data) | `findById(Long)` | 0 / 0 — orphan |
| 9 | vvwt-info-server | `persistence.audit.AuditLogDao` (`@Query`) | `findByRequestId(String)` | 0 / 3 |

Provenance: the audit originated from a finding on `AuditLogRepository`; finding #1 was a QA-gate escape — E55S13 renamed `findById` → `findByTournamentIdAndId`, kept it in the interface, but carried no test, so it passed QA both untested and unconsumed. Removal authors no new production code — DEC-69 clause 3: orphans (#1, #8) are dead-code removal; test-only methods (#2–#7, #9) are removed together with their tests as the legitimate DEC-22 RED-GREEN-**REFACTOR** phase. No RED-first test is required for any deletion; the regression guard is the existing suite staying GREEN (`mvn verify`, DEC-54).

## Acceptance Criteria

### Implementation

- [ ] **AC-IMPL-DELETE-TM-WEB**: Remove method #1 `findByTournamentIdAndId(UUID, UUID)` and method #2 `findByTournamentIdAndMatchIdAndSetIndexOrderByChangedAt(UUID, UUID, int)` from the `de.vvwt.tm.tournament.AuditLogRepository` interface AND their hand-authored implementations in `de.vvwt.tm.tournament.internal.DefaultAuditLogRepository`. After the removal, `save(AuditLogEntry)` is the only public method remaining on `AuditLogRepository`. Any private helper in `DefaultAuditLogRepository` left unreferenced by the removal is also removed — the observable condition is AC-BUILD-DEC-29-CLEAN (Delivery derives the unused-helper set from the compiler; it is not enumerated in this story).
- [ ] **AC-IMPL-DELETE-DISPATCHER**: Remove these 5 read-method declarations from their interfaces — `findByWorkerIdOrderByOccurredAtDesc(UUID)` and `findByEventTypeOrderByOccurredAtDesc(String)` from `de.vvwt.slotopt.dispatcher.audit.AuditRepository`; `findByStatus(String)` from `de.vvwt.slotopt.dispatcher.packet.PacketRepository`; `findByPacketId(UUID)` from `de.vvwt.slotopt.dispatcher.result.LateResultRepository`; `findByPacketId(UUID)` from `de.vvwt.slotopt.dispatcher.result.ResultAuditRepository`. These are Spring Data name-derived queries — removing the declaration removes the generated query; there is no implementation body to remove. The production-used `PacketRepository.findByPacketId` and every other production-used finder on `PacketRepository` are NOT removed.
- [ ] **AC-IMPL-DELETE-INFO**: Remove `findById(Long)` and `findByRequestId(String)` (the latter including its `@Query` annotation) from the `de.vvwt.info.persistence.audit.AuditLogDao` interface. The `save(...)` method and the `append(...)` default method are NOT removed.
- [ ] **AC-IMPL-DELETE-ORPHANED-TESTS**: Remove the test methods that exercised only a deleted method, together with any `@DisplayName` and now-unused fixture/import: `FileAuditLogRepositoryIT.readApi_returnsEntriesInChronologicalOrder` (callsite line 258); the `AuditRepositoryIT` test methods exercising `findByWorkerIdOrderByOccurredAtDesc` (callsites 121, 130) and `findByEventTypeOrderByOccurredAtDesc` (callsites 150, 158); the `PacketRepositoryIT` test method exercising `findByStatus` (callsites 203, 204); `LateResultRepositoryIT.findByPacketIdReturnsRecordWhenPresent` and `findByPacketIdReturnsEmptyWhenAbsent` (callsites 112, 119); `ResultAuditRepositoryIT.findByPacketIdReturnsEntryWhenPresent` and `findByPacketIdReturnsEmptyWhenAbsent` (callsites 111, 118). Methods #1 and #8 have no test to remove.
- [ ] **AC-IMPL-CONTROLLER-IT-ASSERTION-PRESERVED**: `PublishControllerIT` (`findByRequestId` callsite line 298) and `RegistrationControllerIT` (callsites 267, 292) currently use `auditLogDao.findByRequestId(...)` as the assertion oracle for a production audit-write path. The integration tests themselves stay; their audit-write verification intent MUST be preserved via an alternative independent verifier (e.g. a direct read of the persisted `audit_log` row) — per DEC-69 clause 2(d). The mechanism of the alternative verifier is a Delivery decision; the verification MUST remain genuine (it must still fail if the production write path does not fire).

### Testing

- [ ] **AC-TEST-NO-RED-FIRST**: Per DEC-69 clause 3, every deletion in this story authors no new production code — no RED-first test is required or permitted for the removals. The regression guard is the existing suite staying GREEN plus, for orphans #1/#8, the empirical zero-reference audit. The impl-report documents, per finding, which removal class applies (orphan vs test-only).
- [ ] **AC-TEST-SUITE-GREEN**: After the deletions, every remaining test across `vvwt-tm-web`, `vvwt-slotopt-dispatcher`, and `vvwt-info-server` passes — no test is disabled, skipped, or `@Disabled` to achieve green.
- [ ] **AC-TEST-NO-DANGLING-REFERENCE**: No test file retains a reference to any of the 9 removed methods after the story (verifiable: a grep for each removed method name across `*/src/test/` returns zero hits, except the controller-IT files whose references are replaced per AC-IMPL-CONTROLLER-IT-ASSERTION-PRESERVED).

### Build

- [ ] **AC-BUILD-MVN-VERIFY**: `mvn verify` invoked from the `vvwt-prj` root exits zero (BUILD SUCCESS) — per DEC-54. This covers all 3 affected modules and is the closure gate.
- [ ] **AC-BUILD-DEC-29-CLEAN**: `mvn verify` produces no new javac hygiene warning — `failOnWarning=true` (DEC-29) stays satisfied; in particular no unused-import or unused-private-method warning is introduced by the deletions.
- [ ] **AC-BUILD-DEC-30-CLEAN**: `mvn spotless:check` stays green (DEC-30) — the deletions leave no formatting drift.

### Governance

- [ ] **AC-GOV-DEC-69-CITED**: The implementation commit references DEC-69 as the governing decision.
- [ ] **AC-GOV-ATOMIC-COMMIT**: All deletions (9 methods + impls + orphaned tests + controller-IT assertion rewrites) land in a single atomic commit.
- [ ] **AC-GOV-DEC-26-SKELETON-INTACT**: Only supplementary `@Test` methods are removed from the affected DAO integration tests; the DEC-26 three-rule skeleton (schema-from-migration, independent assertj-db verifier, read/write decoupling via direct JDBC) of each affected DAO-IT remains intact.
