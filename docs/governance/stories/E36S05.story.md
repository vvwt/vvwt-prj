# Story E36S05: DefaultCertificateAssembler impl Q-1a TDD rebuild — interface preserved (CertificateAssembler stays); 6-arg constructor injection preserved (PhaseRepository + TeamAvatarRepository + TeamAvatarRatingRepository + TeamRepository + PhotoStorageService + PhotoUrlBuilder); D-7 Option γ at canonical FQN de.vvwt.tm.certificate.internal.DefaultCertificateAssembler

## User Story

**As a** maintainer of `vvwt-tm-web` continuing Track 2 (Certificate) of Epic E36,
**I want** the legacy `DefaultCertificateAssembler` Q-1b implementation deleted
and rebuilt under DEC-22 Iron Law Q-1a TDD RED-first authorship at the same
canonical FQN (D-7 Coexistence Option γ), with the preserved
`CertificateAssembler` interface contract (6 methods + nested `AvatarPlacement`
record) and the existing 6-argument constructor injection signature
(`PhaseRepository`, `TeamAvatarRepository`, `TeamAvatarRatingRepository`,
`TeamRepository`, `PhotoStorageService`, `PhotoUrlBuilder`) preserved verbatim,
**so that** the certificate assembler implementation carries a trustworthy
correctness oracle and Track 2 advances toward controller rebuild + Cutover-2,
while `CertificateRenderController` (interface consumer) and the preserved
interface-level test `CertificateAssemblerTest` (DEC-22 Q-1a TDD-authored,
contains a DEC-41 §1(d) Spec-Anchored method) continue to compile and execute
unchanged.

## Context

Per Session Brief `discovery-2026-04-26-e36-retro-correction` D-7 Option γ +
audit `E36-discovery-legacy-inventory.md` Certificate Assembler Impl
(E23S08-impl-half) group: 1 in-scope production artefact —
`de.vvwt.tm.certificate.internal.DefaultCertificateAssembler` (258 LOC).

Per audit (i) DUAL classification: **interface Q-1a, impl Q-1b**. The
`CertificateAssembler` interface was Q-1a TDD-extracted in E23S08. The impl was
Q-1b legacy logic relocated from `de.vvwt.tm.infrastructure.print.*` and
renamed per DEC-35 Default* canon. The interface is the trustworthy oracle and
remains preserved; this story rebuilds the impl under Q-1a TDD with the
interface as the contract.

**Verified facts read from source files (NOT cached):**

`de.vvwt.tm.certificate.CertificateAssembler` interface declares **6 methods +
1 nested record**:
- `Optional<Phase> getFinalPhase(UUID tournamentId)`
- `List<AvatarPlacement> computePlacementOrder(UUID tournamentId, Phase finalPhase)`
- `List<CertificatePlacementRow> buildSvgRows(Tournament tournament, List<AvatarPlacement> placements, String locationDisplayName)`
- `List<CertificatePlacementRow> buildHtmlRows(Tournament tournament, List<AvatarPlacement> placements, String locationDisplayName)`
- `String renderSvgTemplate(String templateContent, CertificatePlacementRow row)`
- `Map<String, Object> toMustacheMap(CertificatePlacementRow row)`
- `record AvatarPlacement(int placement, UUID teamId, UUID avatarId)` (nested on interface per DEC-35 Item 4 VO)

`de.vvwt.tm.certificate.internal.DefaultCertificateAssembler` impl constructor
(verified at lines 87-100 of source) injects **6 dependencies** in this order:
1. `PhaseRepository`
2. `TeamAvatarRepository`
3. `TeamAvatarRatingRepository`
4. `TeamRepository`
5. `PhotoStorageService`
6. `PhotoUrlBuilder`

Per audit `E36-discovery-dec41-test-classification.md`:
`DefaultCertificateAssemblerTest` (15 methods at `de.vvwt.tm.certificate.internal.*`)
classified 100% Snapshot-Driven; replaced — not reused.

**Audit (ii) gap (acknowledged in this story for delivery transparency):** A
SECOND test file `de.vvwt.tm.certificate.CertificateAssemblerTest` (interface-
level test in the public package per DEC-36) was NOT enumerated in audit (ii).
This test was authored RED-first per DEC-22 Q-1a in E23S08 (per its own
javadoc), references the `CertificateAssembler` PUBLIC INTERFACE only (DEC-36
compliant), and contains at least one DEC-41 §1(d) **Spec-Anchored** method
(`computePlacementOrder_resultMatchesTeamAvatarRatingNaturalOrder` — named
algebraic invariant quantified over a representative 3-team input set). It
instantiates the concrete impl in `@BeforeEach` via the 6-arg constructor — so
its compilation depends on constructor-signature preservation. This test is
PRESERVED in this story; the rebuild MUST preserve the 6-arg constructor.

Consumer chain (per audit (i)): `CertificateRenderController` (out-of-scope;
uses the interface, not the impl). The rebuild MUST satisfy the unchanged
interface contract so the controller continues to work.

This story depends on E36S04 because the rebuilt assembler will exercise (via
its preserved constructor) the rebuilt cert-domain types from E36S04. Note:
the 6 INJECTED dependencies are tournament-domain repositories +
photo-domain types — NOT cert-domain types. The dependency on E36S04 is for
Track-2 sequencing discipline (Brief D-3) and to ensure the cert-domain
rebuild is GREEN before assembler reconstruction. Tournament-domain types are
out of E36 scope and treated as stable.
