# Story: Display overview — center the set scores and unify the active-round highlight to a single color

## User Story

**As a** member of the venue audience watching the public Display screen,
**I want** the set scores centered in their cells and the active round highlighted in a single uniform color,
**so that** the overview is easy to read and the round currently being played is visually unambiguous.

---

## Context

The Display overview (`/display/overview`) has two presentation defects, operator-reported 2026-05-16. Both are pure-frontend CSS in the Display SPA (`vvwt-prj/vvwt-tm-web/src/main/ui-display/`).

**(1) Set scores are not centered.** In `MatchRow.svelte`, the set-scores element (`.match-row__scores`) carries no `text-align` rule, so it defaults to left-aligned — while the team-name pair directly above it reads as visually centered (it is a flex pair). The result is a score string ("23:8", "19:20", "0:30") jammed to the left edge of its cell, misaligned with the centered team names above it. The scores must be centered.

**(2) The active round is highlighted in two different colors.** The round currently being played is highlighted by two CSS rules at two levels: the active round-row (`.round-row--active` in `CourtGrid.svelte`) and the match rows inside it (`.match-row--current` in `MatchRow.svelte`). The two rules use **two different background colors** — two distinct blue tints stacked, producing a visible two-tone seam within the highlighted round. The active-round highlight must read as a **single uniform color**.

Both defects originate in the active-round-highlight + match-row styling introduced by E50S04. They are **orthogonal to the `Phase.currentLapNumber` semantic** (E56S01 / E56S02): this story changes *which color* the highlight uses and *the score alignment* — not *when* the highlight moves between rounds.

## Acceptance Criteria

### Testing (DEC-22 RED-first; DEC-54 `mvn verify` gate)

- [ ] **AC-TEST-SCORES-CENTERED-RED**: A RED-first test asserts that the set-scores element (`.match-row__scores` in `MatchRow.svelte`) carries a `text-align: center` rule — the property whose absence is the defect (O-6: the element has no `text-align` and therefore defaults to left). The test MUST fail on current HEAD and pass after the fix; the RED commit precedes the GREEN commit in `git log`. This is a CSS-property assertion, not a layout-geometry assertion — a CSSOM-level test is acceptable (the real-browser-layout-engine requirement of E50S06 applies specifically to viewport-fill geometry and does not apply here); the test mechanism is a Delivery HOW decision.
- [ ] **AC-TEST-ACTIVE-HIGHLIGHT-UNIFORM-RED**: A RED-first test asserts that the active round renders a **single uniform background color**. The assertion MUST cover **both** rules that style the active round — the active-round-row rule (`.round-row--active` in `CourtGrid.svelte`) **and** the current-match-row rule (`.match-row--current` in `MatchRow.svelte`) — and confirm the two resolve to the **same** background color (no two distinct values). The test MUST fail on current HEAD (the two rules resolve to two different colors) and pass after the fix; the RED commit precedes the GREEN commit. Checking only one of the two rules does NOT satisfy this AC — the defect is the mismatch between them.
- [ ] **AC-TEST-INACTIVE-ROWS-UNCHANGED-GREEN**: Regression — inactive round-rows and non-current match rows keep their existing (non-highlighted) appearance. The pre-existing Display-SPA component test suites from E50S04 / E50S05 / E50S06 (the `CourtGrid` tests and the `OverviewLayout` layout test) remain GREEN. Note: no `MatchRow`-specific test file exists at HEAD — Delivery creates the `MatchRow` test file as the home for AC-TEST-SCORES-CENTERED-RED and AC-TEST-ACTIVE-HIGHLIGHT-UNIFORM-RED; this regression guard applies to the pre-existing suites, not to a phantom `MatchRow` corpus.

### Error Handling

- [ ] **AC-ERROR-NO-SCORES-ROW**: A match row with no recorded sets (the set-scores element absent — e.g. a not-yet-played match) renders without error; the centering rule has no adverse effect when the element is absent.
- [ ] **AC-ERROR-MULTI-ROUND-HIGHLIGHT-SCOPED**: Given the `currentLap` value passed to `CourtGrid`, with multiple rounds displayed simultaneously exactly the round matching `currentLap` carries the uniform highlight and the non-active rounds are visually unaffected by the change. This AC governs the CSS highlight applied for a given `currentLap` prop value; whether `currentLap` itself is fresh is the separate, out-of-scope S-7 Display-refresh concern.

### Security

- [ ] **AC-SECURITY-NO-NEW-SURFACE**: CSS-only presentational change — no new fetch call, no new endpoint, no authentication change, no new device-token handling.

## Out of Scope

- **When the active-round highlight moves between rounds** — that is driven by the `Phase.currentLapNumber` semantic (operationalized by E56S01 and, for the correction path, E56S02). This story changes the highlight *color* and the score *alignment* only.
- **The Display SPA live refresh of the active-round highlight after a correction** — `App.svelte` does not refresh its `phaseData.currentLap` on result events; that pre-existing Display refresh gap is a separate, deferred concern and is not addressed here.
- **Display vertical-fill / layout** — shipped by E50S04 / E50S05 / E50S06; the vertical-fill mechanism is preserved, not modified.
- **Other SPAs** (admin, Timer, Score-Tablet) and backend code.
