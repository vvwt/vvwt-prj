# Story E27S01: Foundation — `slotopt` Modulith Registration + `RoutingSlotOptimizationClient` Skeleton + DEC-49 Amendment Authoring

## User Story

**As a** Tournament Manager developer maintaining slot-optimization integration,
**I want** the `slotopt` package registered as a Spring Modulith bounded context with a single canonical `@Primary SlotOptimizationClient` entry point and a memory-recorded routing-policy decision (DEC-49),
**so that** future stories (E27S02 Leg 3, E27S03 Leg 2) can incrementally compose new compute paths without modifying existing classes, and the routing policy is governance-traceable.

---

## Context

E27 is the last Wave-2 epic per DEC-45 D2 trajectory. Per Brief D-1 + Q-5, E27 follows Pattern C STRICT-ADDITIVE: zero modification of existing `de.vvwt.tm.slotopt.*` classes (E04-delivered, pre-DEC-22; preserved untouched). This foundation story establishes the architectural substrate before behavior changes land:

1. `slotopt` becomes a Spring Modulith bounded context (per DEC-21).
2. A NEW `RoutingSlotOptimizationClient` `@Primary @Service` bean wraps the existing `DirectSlotOptimizationClient` — for now it delegates ALL N values to Direct (Leg 1 only; Leg 2/3 not yet implemented). Net behavior change: **zero**. N≤10 works as before; N>10 still throws `UnsupportedOperationException` via Direct's existing branch.
3. DEC-49 is authored, codifying the routing rule + admin-cancel scope + Best-So-Far semantics + dispatcher URL config + DEC-43 D3 admin-warning obligation + documentation requirement. DEC-49 amends DEC-4 V1 amendment via delta-pattern per DEC-46 precedent.

This story is foundational: small surface, zero risk of regression, ratifies the architecture before E27S02/S03 implement the new legs.

## Notes

**Routing skeleton with NO behavior change is intentional:** S01 lands the architectural substrate (Modulith registration + @Primary wrapper + DEC-49 ratification) without changing any user-observable behavior. This minimizes regression risk on the pre-existing N≤10 happy path and provides a clean integration point for S02 (Leg 3) and S03 (Leg 2) to extend `RoutingSlotOptimizationClient.optimize(...)` by case-on-N + reachability.

**Spring `@Primary` mechanic (per Brief O-14):** Two `SlotOptimizationClient` beans coexist post-S01 (Direct without `@Primary`, Routing with `@Primary`); `@Autowired SlotOptimizationClient` consumers get Routing; Fallback's `@ConditionalOnMissingBean` evaluates to false → stays disabled. No source change to Direct or Fallback. (Wiring contract enforced by `AC-ROUTING-CLIENT-PRIMARY-WIRING-VERIFIED`.)

**DEC-49 authored at S01 vs S04 (rationale):** DEC-49 lands at S01 (foundation) so it can be cited by S02 + S03 ACs and `related_decs` frontmatters. DEC-31 propagate-governance to `vvwt-prj/docs/governance/` defers to S04 (per E25S03/E26S04 batch-snapshot pattern) for re-snapshot efficiency (DEC-49 + any subsequent DEC-49 amendments at S02/S03 batched). S04's AC-DEC31-PROPAGATE-SECOND-COMMIT explicitly covers DEC-49 + updated `patterns/conventions.md` snapshot.

**Naming flexibility on `RoutingSlotOptimizationClient`:** DEC-35 prescribes `Default*` for the canonical impl of a public interface. `Routing*` is a same-canon variant when the impl name expresses a behavioral category beyond "the default impl" (analogous to Spring's `RoutingDataSource`). Story-author may rename to `DefaultRoutingSlotOptimizationClient` at delivery if §refactor-clause review prefers strict `Default*` — non-blocking judgment call. Either name preserves DEC-35 semantics (`I`-prefix prohibited; impl in `.internal`).

**DEC-26 N/A:** No DAO classes added at S01 (no new entity, no new repository — DEC-49 authoring is governance only; RoutingSlotOptimizationClient is a service bean with no persistence).
