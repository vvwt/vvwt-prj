# Story E21S16: Refactor — migrate tournament-context consumers from legacy `TenantContext` bridge to `de.vvwt.tm.tenant::api`

## User Story

**As a** reviewer of the Wave-2 Track-3 pre-cutover consolidation,
**I want** every consumer inside the tournament context (`de.vvwt.tm.tournament.*`) that currently depends on the legacy `de.vvwt.tm.domain.repo.TenantContext` bridge migrated to inject `de.vvwt.tm.tenant.TenantContext` and call `.current()` in place of `.getTenantId()` (plus the test-fixture lifecycle analogue `.bind(UUID)` in place of `.set(UUID)`/`.clear()`),
**so that** E21S13's atomic cutover can delete the legacy bridge without leaving uncompilable consumers inside the reconstructed tournament context.

---

## Context

E21S02–S11 bound the new tournament repos (`tournament/PhaseRepository`, `tournament/MatchRepository`, etc.) to the legacy `de.vvwt.tm.domain.repo.TenantContext` bridge for parallel-phase coexistence — a defensible choice at reconstruction time because the bridge's dual-read fallback supported test fixtures using `.set(UUID)`. Post-E14S11 (RoutingTenantDataSource activated as `@Primary`), the new `de.vvwt.tm.tenant::api` became the canonical tenant-binding mechanism. The legacy bridge is slated for deletion in E21S13's atomic cutover (Brief §D-7 authorization).

This story is the first of a two-step pre-flight (α → β) that removes every live consumer of the legacy bridge BEFORE E21S13 cutover, split by blast-radius: α covers the tournament-context scope, β covers cross-context consumers.

**Behavioral equivalence (Session Brief v7 §O-1):** the legacy bridge's `.getTenantId()` already delegates to `de.vvwt.tm.tenant.TenantContext.current()` (bridge class lines 91–93). The migration is behavior-preserving. This story is therefore **refactoring under DEC-22's Red-Green-Refactor "refactor as needed" clause (DEC-22 §Decision, line 89)** — existing tests are the regression oracle; no new failing tests are introduced per migrated file; DEC-22's characterization-test prohibition is not implicated because the assertions in existing tests remain unchanged (only fixture call sites swap APIs).

The DEC-32 FQN-rewrite carve-out applies to E21S13's cutover commit, not to α. α is NOT a DEC-32 invocation.

## Notes

**Why refactor-phase, not new DEC.** Earlier in the same Discovery session, DEC-35 was drafted as a carve-out parallel to DEC-32 for "mechanical type-migration." The human correctly pointed out that DEC-22's own Decision section (line 92–93) explicitly includes the refactor phase as part of the TDD cycle — refactor is behavior-preserving, existing tests are the regression oracle, no new red-first is required. DEC-35 was withdrawn; α/β execute under DEC-22's refactor phase directly. The Session Brief's Trade-off T-3 documents this withdrawal.

**Grep-command-of-record.** AC-GREP-BASELINE + AC-GREP-COMPLETION embed the exact grep command. Delivery runs it at story start (to discover scope) and at story end (to prove completeness). This replaces a Discovery-time enumeration that proved difficult to keep comprehensive across iterative Brief revisions (v4, v5 were under-counted) — Delivery-time grep against the actual tree is more reliable.

**DEC-26 preservation is per-IT, not blanket.** AC-DEC26-PRESERVED requires Delivery to walk each migrated IT against the three rules individually and state preservation in impl-report. Any rule that would have to soften for the fixture migration triggers AC-STOP-ON-AMBIGUITY — the migration does NOT unilaterally relax DEC-26 discipline.

**Binder adoption (AC-TENANT-BINDER-ADOPTION).** `TenantContextTestSupport.Binder` already uses the new tenant::api (O-9 of Brief v7). Adopting it via `@Import` gives the ITs a consistent binding shape with other Wave-1/Wave-2 ITs. Hand-rolled `try (Scope s = ...)` is allowed only when the test's lifecycle genuinely differs — Delivery documents the reason per exception.

**β (E21S17) depends on this story.** Per Session Brief §T-2, the α-before-β ordering is a review-simplicity choice, not a technical dependency. α + β could technically run in parallel; the sequential ordering bounds the reviewer's mental model and isolates any regression per story.

**E21S13 amendment.** After α + β complete, E21S13's scope amendment adds `WebSocketSecurityConfig.java` and `DeviceTokenHandshakeInterceptor.java` to the DEC-32 mechanical consumer set for Device + DeviceRepository FQN substitution at cutover. That amendment is additive and orthogonal to α.
