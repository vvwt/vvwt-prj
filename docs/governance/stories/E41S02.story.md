# Story E41S02: Config + CLI layer (WorkerConfig + WorkerConfigLoader + OptimizerWorkerMain skeleton with Picocli `@Command` + `--signing-algorithm` flag default Ed25519)

## User Story

**As a** dispatcher operator deploying the greenfield slot-opt-standalone-worker,
**I want** a Picocli-driven CLI entry point (`OptimizerWorkerMain`) that accepts standard worker config (dispatcher URL, key storage path, polling interval, etc.) PLUS the new DEC-43 D2 `--signing-algorithm <id>` flag with default `Ed25519`,
**so that** I can launch the worker with `java -jar vvwt-slotopt-standalone-worker.jar --dispatcher-url <url> --key-dir <path>` (default Ed25519 signing) OR explicitly pin a signing algorithm via `--signing-algorithm Ed25519` for forward-compat audit clarity.

---

## Context

Per Brief D-6: CLI flag `--signing-algorithm <id>` with default `Ed25519` (option β from session intake). Per Brief Q-4: operator-controlled tempo — operator must explicitly set the flag to switch algorithms post-V1; auto-pick (option α) was rejected to prevent silent migration.

Per Brief D-4: source basis = E37S02 spec § (c) "CLI Argument Schema (picocli)" + E01S05 (original standalone-worker story) ACs + delivered worker-lib API. Legacy `vvwt-standalone-worker/src/` MUST NOT be read (per C-19 + C-23).

Per Brief C-20: V1 single algorithm = `Ed25519`. CLI flag at V1 accepts only `Ed25519`; other values → fail-fast with explicit error before any dispatcher contact (defensive validation per Q-5).

This story authors the CLI surface but does NOT yet wire HTTP client (E41S04) or runtime loop (E41S05) — those stories consume the WorkerConfig produced here.

- [ ] **AC-OPTIMIZER-WORKER-MAIN**: `de.vvwt.slotopt.standalone.OptimizerWorkerMain` class with `public static void main(String[] args)` entry point. - [ ] **AC-FAIL-FAST-MISSING-REQUIRED** (error-handling category): Missing required CLI options (e.g., `--dispatcher-url`, `--key-dir`) → Picocli emits usage message to stderr + worker exits with non-zero code (per E37S02 spec § (c) "Exit Codes" and Picocli convention). Test asserts non-zero exit + usage-message content.
- [ ] **AC-DEC36-CROSS-PACKAGE-WORKER-CONFIG-LOADER-TEST**: Test class for `WorkerConfigLoader` lives in cross-package location (e.g., `de.vvwt.slotopt.standalone.config` test package); mocks the public `WorkerConfigLoader` interface, not the `Default*` impl.
