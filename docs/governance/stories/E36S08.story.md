# Story E36S08: GlobalExceptionHandler four-phase migration + Photo/Certificate advice consolidation + advice deletion atomic — Phase 1 FQN-relocation tournament.internal.web → de.vvwt.tm.web; Phase 2 bulk-delete PhotoExceptionAdvice + CertificateExceptionAdvice; Phase 3 RED-first NEW handler methods absorbing photo/cert exception types; Phase 4 governance propagation

## User Story

**As a** maintainer of `vvwt-tm-web` closing Track 3 (web cross-cutting) of
Epic E36,
**I want** the `GlobalExceptionHandler` migrated through a four-phase
choreography (Phase 1 FQN-relocation, Phase 2 advice bulk-delete, Phase 3
RED-first NEW handler methods absorbing photo/cert exception types, Phase 4
governance propagation), preserving bean name and basePackages verbatim,
**so that** the web-tier error-handling surface is consolidated into a single
relocated `de.vvwt.tm.web.GlobalExceptionHandler` with no per-module advice
classes lingering, the Photo/Certificate exception-handling behavior is
preserved verbatim per C-11, and Track 3 closes Epic E36 under DEC-22 Iron Law
+ DEC-21 atomic-cutover discipline.

---

## Context

Per Session Brief `discovery-2026-04-26-e36-retro-correction` D-4 + C-10 + Q-9
+ Q-10 + C-11 + S-7: this story is the canonical four-phase migration that
consolidates the per-module exception advice classes (`PhotoExceptionAdvice`,
`CertificateExceptionAdvice` — Q-1b CREATED per audit (i)) into a single
relocated `GlobalExceptionHandler` at `de.vvwt.tm.web.*`.

**Phase choreography rationale**:
- **Phase 1 (FQN-relocation)** moves `GlobalExceptionHandler` from
  `de.vvwt.tm.tournament.internal.web` to `de.vvwt.tm.web` via `git mv` + a
  single-line package declaration edit. The bean name
  (`@Component("tmGlobalExceptionHandler")`) and basePackages
  (`@ControllerAdvice(basePackages={"de.vvwt.tm.tournament","de.vvwt.tm.infrastructure","de.vvwt.tm.web"})`)
  are preserved verbatim per Brief Q-9 + Q-10. ApplicationModulesTest stays
  GREEN because Modulith ignores unmanaged packages.
- **Phase 2 (advice bulk-delete)** deletes `PhotoExceptionAdvice` +
  `CertificateExceptionAdvice` in a single commit. After this point, endpoints
  that throw photo/cert exceptions return Spring's default 500, which is the
  required clean RED state for Phase 3 (per Brief D-7 / O-9: without Phase 2,
  the legacy advice's `@Order(HIGHEST_PRECEDENCE)` would intercept and prevent
  observable RED on absent NEW handler methods).
- **Phase 3 (RED-first NEW handler methods)** adds one `@ExceptionHandler`
  method per absorbed photo/cert exception type to the relocated handler. Each
  type follows a RED+GREEN commit pair: RED test asserts target HTTP code +
  JSON shape against current Spring-default-500 baseline; GREEN adds the
  handler method. Impl-report cites N RED-state commit hashes (one per
  Phase-3 handler-method cycle).
- **Phase 4 (governance propagation)** is the standard DEC-31 §(c) propagation
  commit.

Per Brief C-11: NEW handler methods preserve legacy advice behavior verbatim
(HTTP code, JSON shape, logging behavior, ordering semantics). Any divergence
triggers stop-and-escalate to Discovery — this is **C-11 behavioral-divergence**,
distinct from C-3 which governs signature evolution.

Per Brief S-7: legacy exception types `domain.audio.*`, `domain.timer.*`,
`infrastructure.display.NoActivePhaseException` MUST have their handler methods
relocated WITHIN the moved class in Phase 1 (no method-level edits in Phase 1).
Their own context-reconstruction is future-epic work.

Per audit (ii): pre-existing 8-method `GlobalExceptionHandlerTest`
(Snapshot-Driven) tests for the relocated handler stay in place; new
Photo/Cert handler tests are fresh per DEC-41 §3 clause (1).

## Notes

- **Per Brief D-4 four-phase choreography rationale**: Phase 1 isolates the
  pure relocation (FQN move only) to keep diff readable + Modulith green.
  Phase 2 establishes the RED state for Phase 3 by removing the legacy
  intercepting advice. Phase 3 is the substantive RED-first DEC-22 work.
  Phase 4 finalizes via governance propagation per DEC-31.
- **Per Brief C-10 multi-commit shape** (one of the few stories in the
  framework with more than 2 commits): the four-phase shape is mandatory; the
  total commit count is 3 + 2N + 1 (= 4 + 2N) where N is the absorbed
  exception-type count.
- **Per Brief Q-9 bean name preservation rationale**: `tmGlobalExceptionHandler`
  may be qualifier-injected by tests or other beans; renaming would break
  consumers and is forbidden across all 4 phases.
- **Per Brief Q-10 basePackages preservation rationale**: the legacy handler
  declares `basePackages` covering tournament + infrastructure + web trees.
  Removing or narrowing this scope would orphan exception throw-sites in the
  unscoped trees. Preservation guarantees full coverage across all 4 phases.
- **Constraint** (Brief C-11 — primary risk for this story): behavioral
  equivalence on HTTP code, JSON shape, logging, ordering. Any divergence
  is a stop-and-escalate trigger.
- **Constraint** (Brief C-3): bean name + basePackages signatures preserved.
- **Risk**: If the relocated handler's existing `@Order` (or absence of
  `@Order`) creates an ordering ambiguity with the absorbed handlers (e.g.,
  generic `RuntimeException` handler intercepting before specific photo/cert
  handlers), explicit `@ExceptionHandler` precedence may be needed.
  Spring's `@ExceptionHandler` ordering is by exception-type specificity
  (most-specific wins), not by `@Order` — typically the absorbed handlers
  with specific photo/cert exception types will resolve first naturally.
  Verify at delivery via Phase 3 RED+GREEN test cycles.
- **Per Brief S-7**: This story explicitly does NOT touch legacy
  domain.audio/timer/infrastructure.display handler methods beyond relocating
  them within the moved file. Their reconstruction is future-epic work.
- **Per Brief C-2**: DEC-32 invocation count remains 1 (E21S13 only).
- **DEC-35 placement**: Relocated handler at `de.vvwt.tm.web.*` is the public
  module surface for the `web` module — appropriate per DEC-35 (cross-cutting
  web infrastructure stays at module root, not in `.internal`).
