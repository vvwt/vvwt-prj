# Story E13S05: Propagate Wave-1 governance artefacts into `vvwt-prj/docs/governance/` + document code-reference convention

## User Story

**As an** external reader of `vvwt-prj` (GitHub visitor, contributor without outer-GAAI-repo access, security reviewer),
**I want** the DECs and Stories referenced by the code to live inside `vvwt-prj` itself,
**so that** I can resolve every `@see DEC-N` or `@see E{N}S{N}` reference without needing access to a separate private governance repo.

---

## Context

Per DEC-23 (governance artefact propagation), governance artefacts that code references must be propagated as **point-in-time snapshots** into `vvwt-prj/docs/governance/`. This story is the one-time Wave-1 bootstrap of that mechanism: it copies the Wave-1 DECs and Stories into the sub-repo, sets up the snapshot directory structure, and records the code-reference convention for all subsequent Wave-1 (and future) code.

Without this story, E15's reconstructed `auth` code has nowhere valid to reference DEC-20/DEC-21/DEC-22 or its own story's AC rationale from within vvwt-prj. Legacy outer-repo paths (like the one in `AdminCredentialsBootstrap.java:62`) are forbidden for new code per DEC-23, so the target path (`vvwt-prj/docs/governance/`) must exist and be populated before E14S01 starts.

The Wave-1 artefacts are fixed: DEC-20, DEC-21, DEC-22 (three DECs) + stories E13S01 through E15S08 inclusive (18 stories — E13S04 is `deferred` but still gets snapshotted for completeness). Epic files are NOT propagated in this story (per DEC-23: code references DEC + Story IDs, not Epics).

Wave-2 will design the automation (Delivery skill extension triggering snapshots at story-closure). This story is deliberately manual-one-time — its purpose is to unblock Wave 1, not to build infrastructure.

## Acceptance Criteria

- [ ] AC1 (testing — test-first for diff script): A verification script (shell or simple test) exists under `vvwt-prj/docs/governance/verify-snapshot-integrity.sh` (or equivalent) that, given a list of snapshot files and outer-repo source paths, asserts byte-identity at a named outer-repo commit SHA. The script is authored BEFORE the copies land — at first run against empty snapshots, it fails. After copies land against the recorded SHA, it passes. Git history shows the failing→passing ordering per DEC-22.

- [ ] AC2 (governance — directory + index files exist): `vvwt-prj/docs/governance/` contains `decisions/`, `stories/`, a `README.md` explaining the snapshot model + linking to DEC-23, and a `DEC-INDEX.md` under `decisions/` listing each snapshotted DEC with a one-line description.

- [ ] AC3 (governance — DEC snapshots byte-identical): `vvwt-prj/docs/governance/decisions/DEC-20.md`, `DEC-21.md`, `DEC-22.md`, `DEC-23.md` exist. Each contains: (a) a single `<!-- Snapshot of ... at {commit-sha} {date} -->` comment on line 1, (b) the exact byte-for-byte content of the outer-repo original from that SHA. The diff script verifies byte-identity (modulo the attribution comment).

- [ ] AC4 (governance — Story snapshots byte-identical): `vvwt-prj/docs/governance/stories/E13S01.story.md` through `E15S08.story.md` (19 files, including E13S05 itself and deferred E13S04) exist with the same attribution-comment-plus-byte-identical-body convention.

- [ ] AC5 (error-handling — diff script fails on mismatch): If any snapshot differs from its source (byte-for-byte, ignoring only the attribution comment line), the verify script exits non-zero with a clear message naming the drifting file. A deliberate-drift spike (change one snapshot by one character, run script, confirm fail) is exercised once during Delivery and reverted before commit.

- [ ] AC6 (governance — convention added to patterns/conventions.md): The outer-repo file `.gaai/project/contexts/memory/patterns/conventions.md` gains a "Governance References in Code" subsection stating: (a) code uses stable IDs (`DEC-N`, `E{N}S{N}`); (b) when paths are used, they point to `docs/governance/` within `vvwt-prj` (relative paths OK); (c) no outer-repo (`.gaai/project/...`) paths in new code; (d) legacy occurrences are cleaned up during reconstruction.

- [ ] AC7 (error-handling — missing snapshot surfaces): If a future Delivery Agent writes code referencing a DEC or Story ID whose snapshot does NOT exist in `vvwt-prj/docs/governance/`, the reference is a bug (caught by human review or later automation per Wave-2). This story does NOT install the automation; AC7 declares the failure mode and makes it visible in Delivery's mental model.

- [ ] AC8 (testing — reference commit attribution recorded): The attribution comment in every snapshot records the outer-repo commit SHA that the snapshot was taken from. Selection: the most recent outer-repo commit on `staging` that touched the respective source file (derived via `git log -1 --format=%H -- {path}` on the outer repo). This makes backtracking trivially possible.

- [ ] AC9 (governance — vvwt-prj commit landing): The snapshot-copy commit lands on `vvwt-prj`'s `staging` branch per DEC-13. Commit message: `docs(governance): propagate Wave-1 DECs + stories per DEC-23`. The outer-repo commit (patterns/conventions.md update) lands separately on the outer-repo `staging` as its own commit.

## Notes

This story is deliberately two-repo: the snapshot files land in `vvwt-prj` (code sub-repo), the convention update lands in the outer GAAI repo. Delivery must be clear about which file-write goes where; the AC9 phrasing makes this explicit.

E13S05 itself will be in the snapshot (per AC4, the stories folder includes "E13S01 through E15S08, 19 files including E13S05 and deferred E13S04"). That is intentional: a reader who wonders "why are these snapshots here?" can read E13S05.story.md right in vvwt-prj to understand.

The attribution comment choice (`<!-- Snapshot of ... at {sha} -->`) keeps each snapshot as valid Markdown — the comment is invisible in rendered output but visible in source. GitHub renders governance files correctly as a result.

Insertion in the dependency chain: `E13S03 → E13S05 → E14S01`. E14S01's depends_on is updated to `[E13S05]` to enforce this ordering (snapshots must exist before E14 starts writing code that will reference them).
