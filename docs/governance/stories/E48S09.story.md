# Story E48S09: Siegerehrung Preview Match-Skip + Rundenzeit-Input-Disable

## User Story

**As a** Tournament Organizer,
**I want** the Phasenplan-Vorschau to show 0 matches and 0 rounds for a Siegerehrung phase, with the Rundenzeit input field disabled when Siegerehrung is selected,
**so that** the preview reflects the actual runtime behavior (E48S02 SiegerehrungMatchGenerator no-op) and I am not misled by inflated match/round counts that will never occur.

---

## Context

Per Brief D-2 / D-3 / O-7 (`discovery-2026-05-06-phasenplan-preview-fixes`): `DefaultDraftService.computePreview` (`vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/internal/DefaultDraftService.java:334-359`) computes match counts via the round-robin formula regardless of `section.gameMode`. For a Siegerehrung phase with 12 teams in 1 group, it produces matchesPerGroup=66, totalLaps=11 (or whatever S10's field-aware formula yields) — but `SiegerehrungMatchGenerator.generate()` returns `Collections.emptyList()` at runtime per E48S02 (`vvwt-tm-web/.../tournament/internal/SiegerehrungMatchGenerator.java`). Preview misinforms the user.

Variant (b) per Brief T-2: when `gameMode == "siegerehrung"`, preview returns matchesPerGroup=0, totalLaps=0, totalMatches=0; `estimatedTimeMinutes` still includes intra-phase breaks + sectionBreakTimeMinutes (preserves user-specified ceremony pause). Variant (a) "all 0" rejected because user might still want a 15-min Pause-nach-Phase before/after the ceremony; variant (c) ceremony-duration schema extension rejected (Brief out-of-scope).

Frontend pairs by disabling the "Rundenzeit (Minuten)" input for siegerehrung phases — UX consistency with the existing disabled-Spielmodus-for-last-phase pattern from E48S01 (`DraftConfig.svelte:357`). Per Brief D-3: the previously-entered Rundenzeit value is **preserved in the DraftConfig** (not cleared, not zeroed) so that switching back to roundRobin restores the user's value editable.

**Reviewer-cycle-1 correction:** Brief F-3 hypothesised a negative-arithmetic boundary at `totalLaps=0` (`(totalLaps-1) * lapBreakTimeMinutes` becomes `-1 * lapBreakTimeMinutes`). Empirical verification of `DefaultDraftService.java:341` confirms `interLapBreaks = Math.max(0, totalLaps - 1) * section.getLapBreakTimeMinutes()` is **already present** — the clamp exists. No fix is needed. Brief F-3 is therefore informational only; this story does NOT modify line 341.
