# Story E41S05: Runtime loop (WorkerLoop + CpuThrottle + StructuredLogger; polling + processing + result submission with algorithm field + supportedAlgorithms on PullPacketRequest; HTTP 410 handling)

## User Story

**As a** running standalone-worker process after successful registration with the dispatcher,
**I want** a polling-loop runtime that continuously pulls packets from the dispatcher (sending `supportedAlgorithms: ["<chosen>"]` on the PullPacketRequest body per delivered DTO), processes them via the worker-lib `PacketSolver`, and submits results via `ResultSigner` + `DispatcherClient.submitResult()` with the `algorithm` field per delivered SubmitResultRequest DTO,
**so that** the greenfield worker actively contributes compute to the slot-opt service end-to-end against the delivered E37/E40 dispatcher.

---

## Context

Per Brief O-6 (i): PullPacketRequest delivered request body carries `supportedAlgorithms: List<String>` field per E37S08 (NOT response side as spec § (d) heading suggests — Brief D-10 follows delivered reality). Per Brief O-6 (ii): SubmitResultRequest delivered request body carries `algorithm` field per E37S09. Implementer reads both DTO sources for exact field shapes.

Per Brief C-21 + D-9: this story depends on E40S03 (deprecation enforcement at registration — done; PR 141 merged 2026-04-27). Although deprecation enforcement happens at register-key (E41S04 territory), the runtime loop must handle the rare race-condition where deprecation crosses the deadline between worker startup and a packet-result-submission attempt: in that case, the dispatcher would return HTTP 410 Gone on submit-result; runtime must surface this clearly and exit (per Brief Q-5 fail-fast philosophy).

This story consumes E41S03's `ResultSigner` and E41S04's `DispatcherClient` to drive the polling + processing + submission loop.

CpuThrottle implements the polling-interval pacing (per E37S02 spec § (c) "CPU Throttle" + E01S05 ACs). StructuredLogger emits structured event-logs for observability (per spec § (c) "Observability").

### Story-specific ACs

- [ ] **AC-WORKER-LOOP-INTERFACE**: `de.vvwt.slotopt.standalone.runtime.WorkerLoop` interface declared with method:
  ```java
  void run() throws WorkerLoopException;
  ```
  Loops indefinitely until shutdown signal (e.g., SIGINT/SIGTERM via JVM shutdown hook). Authored RED-first.
- [ ] **AC-DEFAULT-WORKER-LOOP**: `de.vvwt.slotopt.standalone.runtime.internal.DefaultWorkerLoop` impl per DEC-35-by-analogy. Constructor receives: `DispatcherClient` (E41S04), `ResultSigner` (E41S03), `WorkerKeyManager` (worker-lib), `WorkerConfig` (E41S02), `CpuThrottle`, `StructuredLogger`. Single-threaded polling loop. RED-first authored.
- [ ] **AC-PULL-PACKET-WITH-CAPABILITY-ADVERTISEMENT**: Each loop iteration calls `DispatcherClient.pullPacket(PullPacketRequest)` with `workerId` (from registered KeyRegistration; cached after E41S04 register-key call) AND `supportedAlgorithms: ["<chosen>"]` per delivered PullPacketRequest DTO (per Brief O-6 (i)). The chosen algorithm comes from `WorkerConfig.signingAlgorithm` — at V1 always `["Ed25519"]`. RED test asserts request body shape.
- [ ] **AC-PACKET-PROCESSING**: When pull-packet returns a non-empty packet (HTTP 200 with body), worker delegates packet computation to `vvwt-slotopt-worker-lib`'s `PacketSolver` (instantiated via worker-lib API). Output is a `PacketResult` (worker-lib type). RED test mocks PacketSolver + asserts invocation.
- [ ] **AC-SUBMIT-RESULT-WITH-ALGORITHM**: After computation, worker calls `DispatcherClient.submitResult(SubmitResultRequest)` with the `algorithm` field per delivered SubmitResultRequest DTO (per Brief O-6 (ii)). Signature is produced by `ResultSigner.signResult(payload)` (E41S03). The `algorithm` field value is `WorkerConfig.signingAlgorithm` (V1 always `"Ed25519"`). RED test asserts request body shape.
- [ ] **AC-EMPTY-PULL-RESPONSE-BACKOFF**: When pull-packet returns HTTP 204 No Content (no packets available), worker invokes `CpuThrottle.sleep(WorkerConfig.pollInterval)` before next iteration. Verifiable via test that mocks 204 response + asserts `CpuThrottle.sleep(...)` invocation.
- [ ] **AC-HTTP-410-DEPRECATED-AT-SUBMIT** (error-handling category): If submit-result returns HTTP 410 Gone (deprecated algorithm rejected at submit-time — rare race-condition where deprecation crossed the deadline between this worker's registration and this packet's submission), worker:
  - Logs ERROR with explicit message naming the deprecation
  - Exits with non-zero exit code (per E37S02 spec § (c) "Exit Codes" — implementer maps to spec-prescribed value)
  RED test mocks 410 response + asserts log output + exit code.
- [ ] **AC-HTTP-410-DEPRECATED-AT-REGISTER**: If E41S04's register-key returns HTTP 410 Gone at startup (worker's chosen algorithm was just deprecated past deadline between announcement query and register-key call — extremely rare race), the same handler path applies: log ERROR + non-zero exit. Note: this AC is about the runtime loop's handling of the upstream-bubbled error from E41S04 — E41S04 throws DispatcherException(410, ...); the runtime loop surfaces it to operator. RED test asserts the bubble-up.
- [ ] **AC-CPU-THROTTLE**: `de.vvwt.slotopt.standalone.runtime.CpuThrottle` interface + Default impl per DEC-35-by-analogy. Method `void sleep(Duration)` calls `Thread.sleep` with cooperative interruption handling (re-throws `InterruptedException` as `WorkerLoopException` to break the polling loop). RED test asserts sleep invocation + interrupt handling.
- [ ] **AC-STRUCTURED-LOGGER**: `de.vvwt.slotopt.standalone.log.StructuredLogger` interface + Default impl per DEC-35-by-analogy. Emits slf4j WARN/INFO/ERROR events with structured key-value fields per E37S02 spec § (c) "Observability" (e.g., `event=packet_pulled, jobId=..., packetId=...`). RED test asserts event payload shape.
- [ ] **AC-GRACEFUL-SHUTDOWN**: JVM shutdown hook (`Runtime.getRuntime().addShutdownHook`) breaks the polling loop cleanly when SIGINT/SIGTERM received. In-flight packet (if any) is allowed to complete + submit before exit; if no packet in-flight, immediate exit. Exit code 0 on graceful shutdown. RED test asserts shutdown-hook behavior with mock signal.
- [ ] **AC-OBSERVABILITY-EVENTS-RUNTIME** (per E37S02 spec § (c) "Observability"): Runtime path emits structured slf4j events at INFO level for each milestone:
  - `event=packet_pulled` (after successful pull-packet returning HTTP 200 with body; included keys: packetId, jobId)
  - `event=packet_processed` (after PacketSolver completes; included keys: packetId, jobId, durationMs)
  - `event=result_submitted` (after successful submit-result; included keys: packetId, jobId, accepted=true)
  - `event=result_superseded` (after submit-result returns accepted=false per DEC-6 first-valid-wins; included keys: packetId, jobId, reason)
  - `event=worker_stopped` (in shutdown hook, just before final exit; included keys: exitCode)
  RED test asserts log shape via slf4j test-binding for each event type.
- [ ] **AC-EXIT-CODE-RUNTIME** (per E37S02 spec § (c) "Exit Codes"): Runtime-stage error exit codes follow E37S02 spec § (c) matrix; specifically:
  - HTTP 410 at submit-result → exit code per spec § (c) "submit_rejected_deprecated"
  - graceful shutdown → exit code 0
  - thread interrupted unexpectedly → exit code per "interrupted"
  - dispatcher unreachable mid-runtime → exit code per "dispatcher_unreachable"
  Implementer reads E37S02 spec § (c) "Exit Codes" verbatim. RED tests assert each.

## Notes

- The polling loop is single-threaded per E37S02 spec § (c). One packet processed at a time. Multi-threading is a Phase-2+ scaling concern outside V1.
- HTTP 410 handling at submit-time is a rare race-condition path (deprecation crossing the deadline mid-runtime). Deterministic behavior: log + exit. Operator restarts the worker with a non-deprecated algorithm via CLI flag.
- The cached `workerId` from register-key (in E41S04) is held in-memory by the runtime loop for the lifetime of the JVM; no persistence needed (per E37S02 spec § (c) "Key Storage" — keypair persisted by worker-lib WorkerKeyManager; workerId derivable from public key fingerprint or returned by register-key response and held in-memory).
