# Story E53S01: Fix Mustache `{{!...}}` comment leak in all print templates + remove dead-code stub-model attributes at PrintController:375-384

## User Story

**As a** Tournament Operator (or a participating team viewing a printed Laufzettel),
**I want** every print page in the application to render without literal Mustache template-documentation text leaking into the visible HTML body,
**so that** I can read the actual print content (tournament name, schedule, team data) without internal-developer-comments obscuring it and without losing trust in the printout's correctness.

---

## Context

User-observable symptom (Discovery 2026-05-08, screenshots in session brief):

- The print-index page (`/print/tournaments/{tid}`) shows a long block of literal Mustache-comment text at the top of the visible body, including phrases like "Required model attributes (populated by PrintController):", template-attribute lists, URL-shape documentation, and a stray `}}` at the bottom.
- The Laufzettel-all page (`/print/tournaments/{tid}/team-schedules`) shows a raw `List<Map>.toString()`-style dump (`[isPhaseHeader, ..., isMatch, matchTimeWindow, isReferee, refereeOpponentName=Mannschaft 02, fieldNumber=2 ...]`) before the actual table.

### Root cause (verified empirically 2026-05-09)

jmustache (used per Spring Boot's auto-configured MustacheViewResolver — see `print-layout.mustache:9-13` documentation) closes a `{{! ... }}` multi-line comment at the FIRST `}}` it sees inside the comment body. When the comment body documents model attributes like `{{locale}} — HTML lang attribute`, the `}}` at the end of `{{locale}}` is interpreted as the comment's closing `}}` — and the rest of the comment block (lines following the first interior `}}`) renders as visible HTML text.

This bug is already documented in code: `PrintController.allTeamSchedules():375-384` says:

> "laufzettel-all.mustache comment block references {{teamNumber}}, {{teamName}}, {{heading}}, {{hasTime}}, {{showPageBreak}}, {{rows}} at the top-level template context (lines 16–17). jmustache in strict mode evaluates {{...}} tags even inside {{! }} comments — expose stub top-level values so strict-mode doesn't throw."

The stub model attributes (`hasTime`, `teamNumber`, `teamName`, `showPageBreak`, `rows = List.of()`) prevent jmustache strict-mode from THROWING on the unresolved tags, but they do NOT prevent the visible text leak — jmustache still renders the post-first-`}}` comment body as HTML.

### Empirically-identified leak surface (verified 2026-05-09)

The following templates were directly verified to have multi-line `{{!...}}` headers containing `{{tag}}` references:

- `vvwt-prj/vvwt-tm-web/src/main/resources/templates/print/index.mustache:1-22`
- `vvwt-prj/vvwt-tm-web/src/main/resources/templates/print/print-layout.mustache:1-21`
- `vvwt-prj/vvwt-tm-web/src/main/resources/templates/print/laufzettel.mustache:1-21`
- `vvwt-prj/vvwt-tm-web/src/main/resources/templates/print/activity-schedule.mustache:1-30`

Reasonable inference (H-2 in Brief): the same `{{!...}}`-with-embedded-tags pattern exists in:

- `print-header.mustache` (partial — referenced from index/print-layout/laufzettel/activity-schedule via `{{> print-header}}`)
- `laufzettel-all.mustache`
- `laufzettel-no-matches.mustache`
- `error.mustache`

Delivery's grep on `{{!` in `templates/print/` confirms full surface.

### Scope posture

This is a **producer-side fix at the Mustache template layer** (per memory `feedback_discovery_cycle_resolution_scope_creep.md` — fix the root cause, not consumer-side). Discovery does NOT prescribe the leak-free shape; four alternatives are documented in Brief T-3-E53S01:

- (α) HTML comments (`<!-- ... -->`) — stay in HTML source but not visually rendered.
- (β) Single-line `{{!...}}` per attribute — verbose but jmustache-safe.
- (γ) README-extraction — cleanest separation but loses inline doc proximity.
- (γ-1) jmustache library configuration — disable strict comment-tag-evaluation OR change comment delimiters; if jmustache exposes such a config flag, Delivery may achieve a zero-template-edit fix that ALSO obviates the dead-code stub-model attributes at PrintController:375-384. Trade-off: library-config changes have global effect on all Mustache templates; Delivery must verify no regression on non-print Mustache surfaces. If jmustache does not expose such a config, fallback to (α)/(β)/(γ).
