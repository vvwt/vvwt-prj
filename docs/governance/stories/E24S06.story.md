# Story E24S06: Q-1a TDD RED-first NEW `PrintController` at `de.vvwt.tm.web.*` (4 print-native endpoints, fresh reconstruction) + `web.allowedDependencies += print` atomic + SecurityConfig `/print/**` regression verify

## User Story

**As a** maintainer of `vvwt-tm-web` completing the fresh reconstruction
of the print HTTP surface under strict DEC-22 Iron Law,
**I want** a NEW `PrintController` at `de.vvwt.tm.web.*` serving 4
print-native endpoints (index, laufzettel-single, laufzettel-all,
activity-schedule) at new URLs `/print/tournaments/{tid}/…` — authored
Q-1a TDD RED-first, injecting fresh `LaufzettelAssembler` (S02) +
`ActivityScheduleAssembler` (S03) public interfaces + `LocationDisplayResolver`
(S04) + `TenantContext` — with `web.allowedDependencies += print` atomic
in the same commit,
**so that** fresh HTTP surface for print bounded context is DEC-22-
compliant, legacy PrintController at `infrastructure.print.*` continues
to serve legacy URLs (`/print/{tid}/…`) untouched until S07 atomic cutover.

---

## Context

Per Brief v6 Seq-C + Q-1a full. This is the major new-code story in E24.

Legacy `infrastructure.print.PrintController` (1191 LoC; 6 endpoints —
4 print-native + 2 certificate) stays UNTOUCHED. S06 writes a NEW
`de.vvwt.tm.web.PrintController` RED-first with ONLY the 4 print-native
endpoints (the 2 certificate endpoints are owned by S05's
CertificateRenderController — separate controller, separate module
subtree).

**New URLs introduced at S06 (domain-aligned per Brief E-1):**
- `GET /print/tournaments/{tid}` — index (was `/print/{tournamentId}`)
- `GET /print/tournaments/{tid}/team-schedules/{teamId}` — Laufzettel single
- `GET /print/tournaments/{tid}/team-schedules` — Laufzettel batch
- `GET /print/tournaments/{tid}/activity-schedule/{activityTypeId}` —
  Mannschaftsfoto-Übersicht (photo schedule)

**URL parallel phase (S06 → S07 window):**
- Legacy `/print/{tid}/…` URLs (4 print-native + 2 cert) served by legacy
  PrintController at `infrastructure.print.*` (unchanged).
- Legacy `/print/tournaments/{tid}/certificates/*` URLs (2 cert) served
  by legacy PrintController until S07 (S05's CertificateRenderController
  already serves NEW `/certificate/tournaments/{tid}/print*` URLs).
- NEW `/print/tournaments/{tid}/…` URLs (4 print-native) served by NEW
  web.PrintController.
- **URL disjointness**: legacy URLs use `/print/{UUID}/` segment; new
  URLs use `/print/tournaments/{UUID}/` segment. Spring's URL matcher
  distinguishes (UUID-typed `{tournamentId}` path-variable cannot match
  literal "tournaments"). No `AmbiguousMappingException`.
- **Bean-name collision prevention**: Both legacy + new controllers
  are `@Controller`-annotated classes; Spring default bean name is
  simple-class-name-lowercased = `printController` for BOTH. **Must
  assign explicit bean names** via `@Controller("tmPrintController")`
  on new + (leave legacy at default `printController`), OR
  `@Controller("legacyPrintController")` on legacy via a non-invasive
  Spring configuration. **Empirical check at authoring**: verify
  `@Component("tmGlobalExceptionHandler")` pattern from existing code
  suggests explicit-name convention available.
  
  **Resolution AC below (AC-BEAN-NAME-NEW-EXPLICIT)**.

**Mustache templates unchanged**: Legacy `templates/print/*.mustache` (7
templates + 2 shared partials) used by BOTH legacy PrintController and
new PrintController. Classpath-resources, not Spring beans — no collision.
NEW PrintController returns view names `print/index`, `print/laufzettel`,
`print/laufzettel-all`, `print/activity-schedule`, `print/error`,
`print/laufzettel-no-matches` (6 view names, empirically verified via
`grep 'return "print/' on legacy PrintController.java`).
`print-layout.mustache` is a layout/partial resource — NOT a controller-
returned view.

**`web.allowedDependencies += print` atomic**: Required because NEW
web.PrintController imports `de.vvwt.tm.print.LaufzettelAssembler` +
`ActivityScheduleAssembler` public interfaces (S02/S03). Without this
addition, `ApplicationModules.verify()` fails. Per Brief E-7.
