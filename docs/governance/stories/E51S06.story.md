# Story E51S06: Drag&drop-Refactor + E48S21 prepare-flow rollback + Dead-Code Removal + sync RefereeAssigner-wiring

## User Story

**As a** Tournament Operator,
**I want** the drag&drop "Vorbereiten" step to ONLY confirm the team-to-slot assignment proposal — and not (re-)create avatars, not (re-)generate matches, and not invoke slot-optimization at click time —
**so that** clicking Vorbereiten is fast, the matches that already exist (from background match-gen) are preserved with their slot coordinates, and the operator gets immediate feedback that the phase is ready to start.

---

## Context

E51S01–S05 establish the upfront-pipeline (avatars at apply-time + match-gen as background-job + serial slot-opt FIFO + ASSIGNED lifecycle status + activation-guard). This story refactors the drag&drop commit path to fit the new architecture and removes the now-obsolete code paths.

Three concurrent edits in `DefaultPhaseTransitionService.commitTransition()`:

1. **REMOVE line 160** (`new TeamAvatar()` + `setTeamId` + `save`) — avatars exist already (E51S02). Replace with `teamAvatarRepository.findByPhaseIdAndGroupNumberAndGroupPosition(...)` + `setTeamId(proposal.teamId())` + `save` (UPDATE not INSERT).
2. **REMOVE line 177** (`phasePreparationService.generateMatches(toPhaseId, gameMode)`) — matches exist already (E51S03 background match-gen). The drag&drop must NOT regenerate matches because that would overwrite slot coordinates set by slot-opt.
3. **ADD synchronous `RefereeAssigner.assignReferees(phaseId)` invocation** at the end of the transaction — referee-assignment requires teamId-populated avatars (per `RefereeAssigner.java:140` reads `avatar.getTeamId()`), which is exactly the post-state of step (1).

After step (3), call `phaseLifecycleService.transition(phaseId, ASSIGNED, "assign")` (E51S05's API) to flip the phase status PREPARED → ASSIGNED.

Two dead-code removals in tournament context:

4. **REMOVE `PhasePreparationService.preparePhase()` method** — verified zero production callers (the method calls `assignReferees` internally; both are dead in production after E51 wires referee-assignment into commitTransition).
5. **REMOVE the `assignReferees` invocation site inside `preparePhase()`** — naturally removed when (4) removes the entire method.

One E48S21 rollback in `DefaultPhaseLifecycleService.prepare()`:

6. **ROLLBACK E48S21 prepare-flow shape**: revert `DefaultPhaseLifecycleService.prepare()` to the E48S17-original-contract — pure status-flip PENDING → PREPARED (via E51S05's `transition(phaseId, PREPARED, "match-gen-done")` API). Remove any slot-payload consumption + match-gen invocation introduced by E48S21 (PR #215).
7. **`POST /api/phases/{id}/prepare`**: Delivery's choice — either reduce to a no-op safety-guard returning HTTP 200 with the current status, OR remove the endpoint entirely if `PhaseLifecycleService.prepare()` is now only called by the match-gen-listener (E51S03). The chosen approach is documented in the impl-report. Frontend (`PhasePreparation.svelte` E48S18 wrapper) is updated correspondingly to NOT invoke `/prepare` at user-click time — Phase 1 click on "Vorbereiten" navigates to drag&drop UI, and the drag&drop commit flips PREPARED → ASSIGNED via `transition-commit`.

The drag&drop UI itself (`PhaseTransition.svelte`) is unchanged in shape — operator still sees the proposal grid, drags teams, clicks "Übernehmen". The backend behavior on commit changes (steps 1–3 above).
