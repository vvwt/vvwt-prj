# Story E45S05: Atomic SQL Big-Bang-Reset — single commit per DEC-25 §Decision (delete 15 root V*.sql + create 3 per-module V1 with DEC-39+DEC-50 deltas + replace migration ITs + rewrite TenantDaoTestSupport + delete FlywayRootMigrationsCustomizer)

## User Story

**As a** Tournament Manager developer realizing the post-Reset end-state per DEC-20 + DEC-25 + DEC-39 + DEC-50,
**I want** all remaining root-level Flyway migrations deleted, the per-module Flyway layout completed for `tenant`/`tournament`/`infoportal`, the DEC-39+DEC-50 schema rationalization applied, the migration-IT inventory rewritten, the DAO test-support utility re-pointed, and the `FlywayRootMigrationsCustomizer` removed — all in **one atomic commit** per DEC-25 §Decision,
**so that** post-Reset the `db/migration/` root contains zero `V*.sql`, the `PerTenantFlywayRunner` (DEC-20) is the sole schema-application path, and the system is ready for S06's Java INSERT cleanup in the DEC-21 §Deploy-pause window.

## Context

S05 is the canonical Big-Bang-Reset commit — the single commit that DEC-25
§Decision authorizes as a one-time SQL-schema carve-out from DEC-21 §atomic-cutover-
protocol. Prerequisites are met:

- DEC-39 D5 sequencing (E21..E27 done) — Brief D-1.
- DEC-25 §Production-data-escape-hatch NOT triggered — Brief H-3 (human attestation
  2026-05-03 "no production data exists anywhere").
- DEC-50 amendment authoring complete — extends DEC-39 D1 to the 17th table
  (`info_portal_state`).
- Java predicate-cleanup landed via S03+S04 — production code is ready for the
  schema column drop (no WHERE-tenant_id predicates remain that the column drop
  would falsify; INSERT/UPDATE-side `tenant_id`-passing remains, which S06 cleans
  up post-S05).

S05 ships a large but bounded commit: 15 file deletions + 3 file creations + ~5
test-class rewrites + 1 utility rewrite + 1 customizer + companion test deletion.
The atomicity is essential because the per-module Flyway layout cannot coexist
with root migrations under Spring Modulith's `SpringModulithFlywayMigrationStrategy`
(out of scope per S-6, but the underlying invariant — root and per-module cannot
both apply the same table — applies). DEC-21 §Deploy-pause line 148-151 explicitly
authorizes the inter-commit transient state between S05 and S06; H-3 attestation
makes the no-production-data rationale concretely current.

The `db/migration/` reconstruction follows D-3's table-to-context map. Each new
`{context}/V1__*.sql` file is **DEC-39+DEC-50-target schema reconstructed-from-
scratch** (Brief D-4 consolidation-vs-mutation invariant) — NOT a literal concat
of the legacy V*.sql files.
