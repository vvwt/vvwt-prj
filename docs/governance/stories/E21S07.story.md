# Story E21S07: Draft — phase-planning VOs + DraftService + DraftController + 10 DTOs (reconstruction-in-place with TDD)

## User Story

**As a** tournament organiser planning the phase layout of an event,
**I want** the Draft sub-aggregate (config VOs, preview-result VOs, service, REST controller, DTOs) reconstructed under `de.vvwt.tm.tournament.*` with DEC-22 TDD,
**so that** pre-tournament phase planning (sections, breaks, preview, apply-to-Phases) is a clean tournament-owned feature, its JSON configuration contract is preserved, and the draft→Phase mutation is explicit and tested.

---

## Context

Per the E21S01 legacy inventory, the Draft feature spans 17 legacy classes: 5 value objects (`domain.draft.DraftConfig` — line 238, `DraftSection` — line 241, `DraftBreak` — line 237, `DraftPreviewResult` — line 239, `DraftPreviewSection` — line 240), the `domain.DraftService` (line 171 — draft→Phase mutation is a tournament-aggregate-mutating service), the `infrastructure.web.DraftController` (line 424), and 10 request/response DTOs at `infrastructure.web.dto.*` (lines 431–440: `DraftApplyResponse`, `DraftBreakRequest`, `DraftBreakResponse`, `DraftPreviewResponse`, `DraftPreviewSectionResponse`, `DraftRequest`, `DraftResponse`, `DraftSectionRequest`, `DraftSectionResponse`, `DraftTimelineEntryResponse`).

Per D-8, the `DraftController` lands at `de.vvwt.tm.tournament.DraftController`; per D-5 the `@ApplicationModule({"tenant"})` annotation was added in E21S12. All VOs, the service, and the 10 DTOs live under `de.vvwt.tm.tournament.internal.*` — specifically `internal.draft.*` for the 5 VOs and `internal.dto.draft.*` for the 10 DTOs.

Per DEC-22, each class is written test-first. Per C-13, `DraftController` is tested with Hybrid-Split-Minimalist-IT: `@WebMvcTest(DraftController.class)`+`TenantContextSliceTestSupport` slice + `@SpringBootTest(RANDOM_PORT)` IT, with `@WithMockUser` + `.with(csrf())`. The `DraftService` unit tests mock the Phase-aggregate dependency from E21S03 (service-level orchestration is the SUT; the collaborator's behaviour is already verified in S03's own tests — the E15S03 precedent applies).

Legacy `de.vvwt.tm.domain.draft.*`, `de.vvwt.tm.domain.DraftService`, `de.vvwt.tm.infrastructure.web.DraftController`, and `de.vvwt.tm.infrastructure.web.dto.Draft*` remain live until E21S13 (atomic cutover per D-6 / DEC-32). Do not touch in this story.

## Notes

**DraftTimelineEntryResponse does NOT block on S11 timeline classes.** The DTO (inventory row 440) is a plain data-carrier (fields like `startTime`, `activity`, `durationMinutes`) — it can be authored and tested in S07 without depending on the timeline domain classes arriving in S11. S11's `Timeline*` classes will *consume* this DTO shape (or be mapped onto it), but S07 authors the shape independently. The DTO's Javadoc must cross-reference S11 as the future producer.

**17 classes is the largest count in E21.** Delivery MUST produce the Q-7 safety-valve assessment BEFORE the first commit. If session-tauglichkeit is not met, the natural seam is after the 15 data classes (5 VOs + 10 DTOs — pure data, testable with no DB) and before the 2 behavioural classes (service + controller — require REST IT infrastructure). Split would be `E21S07a` (15 data classes) + `E21S07b` (DraftService + DraftController + REST IT).

The `DraftService.apply()` mutation creates Phase entities — this is the one place Draft touches the Phase aggregate. In unit tests mocks are appropriate (the collaborator's persistence is already tested in S03's DAO tests — E15S03 precedent). In the REST IT the real Phase-aggregate collaborator exercises the full wiring.

Idempotency (AC-DRAFT-APPLY-IDEMPOTENCY): the legacy `DraftService` behaviour on re-apply is not documented in the inventory — confirm empirically during RED-first commit (read legacy `domain.DraftService.apply()` per row 171). Do not guess.
