# Story E71S02: Per-certificate-template photo aspect-ratio override

## User Story

**As an** operator who uploads custom certificate templates,
**I want** to set the photo aspect ratio that a given template expects,
**so that** team photos are cropped to match whatever template I use, not only the default layout.

---

## Context

The default certificate template displays the team photo as an ~11:5 landscape band, so E71S01
crops to a global default of 11:5. But operators can upload their own certificate templates
(`de.vvwt.tm.certificate`) whose photo area may have a different ratio. This story lets the
operator declare a per-template ratio that overrides the global default; the crop (E71S01) then
uses the **effective ratio** = per-template override if set, else the global default.

Per reuse-search this is a HIT: the certificate-template subsystem already has config
persistence (`certificate_template` table + `CertificateTemplateMetadata` record +
`CertificateTemplateRepository` upsert), an upload page (`CertificateTemplate.svelte` +
`certificateTemplateStore.ts`), an upload endpoint/DTO, a service following the interface +
`Default*` convention, and a `@ConfigurationProperties` default+override pattern — all extended,
none duplicated. The certificate render is NOT changed (`object-fit: cover` stays; DEC-78 / Brief
D-7).

---

## Acceptance Criteria

- [ ] **AC1 (set + persist override):** Given the certificate-template upload page, when the
  operator enters an aspect-ratio value (optional field) and uploads/saves a template, then the
  value is persisted per template and shown when the template is viewed again.
- [ ] **AC2 (effective-ratio resolution):** Given a tournament whose certificate template has a
  ratio override set, when the operator crops a team photo (E71S01), then the crop uses the
  override ratio; given no override is set, the crop uses the global default ratio (11:5 unless
  ENV-overridden). Until/unless an override exists, behaviour is identical to E71S01 (graceful
  fallback to the global default).
- [ ] **AC3 (validation + error-handling):** Given an invalid ratio input (e.g. non-numeric,
  zero, or malformed like `0:0`), when the operator saves, then the input is rejected with a
  localized validation message and the previously effective ratio (override or default) is
  retained — no crash, no corrupt value persisted.
- [ ] **AC4 (interface mandate + backend hygiene):** Any new Spring bean introduced carries a
  public interface in the bounded-context root with a `Default*` implementation (DEC-58/DEC-72);
  the persisted column(s) are added via a new versioned Flyway migration in the certificate module.
- [ ] **AC5 (testing — RED-first):** Effective-ratio resolution (override-else-default), ratio
  validation, and persistence round-trip (write→read) are covered by RED-first automated tests
  (DEC-22). `mvn verify` is BUILD SUCCESS (DEC-54).
- [ ] **AC6 (i18n):** The new ratio field label, help/placeholder text, and validation message
  are provided through the frontend i18n layer, German-first per the TM convention — no
  hardcoded user-facing strings.

## Out of Scope

- Changing the certificate render / pinning the photo slot to the ratio (stays `object-fit: cover`).
- The crop UI/downscale itself (E71S01) and best-shot selection (E71S03).
- Any per-team (as opposed to per-template) ratio; the override is per certificate template.

---

## Dependencies

- **E71S01** — provides the crop step and the global default ratio that this story's effective-
  ratio resolution falls back to (edge: certificate-template-config → preprocessing-consumer).

## Notes

- Reuse-search HIT (see frontmatter): extend `certificate_template` persistence + upload page +
  service; do NOT create a parallel config/persistence path.
- Schema note: `certificate_template` is keyed per `tournament_id` (one template per tournament).
  The override therefore persists on that existing single-row-per-tournament record — Delivery
  must NOT introduce a new template-identity dimension; "per certificate template" == "the
  tournament's template" at storage.
- Global-default ownership: the global default ratio is owned by E71S01 (the `tm.photos` default);
  E71S02 READS it for the fallback and does NOT define a competing default property.
- Ratio storage format (e.g. `"11:5"` vs decimal) is a Delivery implementation choice; the AC
  is behavioural (override else default, validated).
- Delivery mode: source (PR to vvwt-prj inner repo).
