# Story E44S03: Info branding rollout — `<link rel="icon">` (yellow hex-icon) + lockup `<img>` + `"ToM · Live Information"` title in `vvwt-info-client` Vite SPA, served via `vvwt-info-server` Spring static handler

## User Story

**As a** participant of a tournament who opens the public participant info portal (`/info/`) on a smartphone or laptop to check the timeline, results, or schedule of their team,
**I want** the page to show the VVW lockup in its header, the yellow VVW hex-icon as its favicon (visually distinguishing this surface from the admin-facing TM-family blue surfaces), and `"ToM · Live Information"` in the browser tab,
**so that** I immediately recognise the portal as a VVW-family service and as the public information portal specifically (not an admin app), in a single screen frame, without needing to read any text.

---

## Context

E44S01 establishes the asset-distribution mechanism. E44S03 is the Info-side consumer.

`vvwt-info-client` is a single Vite-built Svelte SPA at `vvwt-info-client/src/main/ui/`. Its `vite.config.ts` writes `outDir` directly into `vvwt-info-server/src/main/resources/static/info/` with `emptyOutDir: true` — so every build wipes and replaces the `static/info/` contents in `vvwt-info-server`. (E44S01 makes this directory gitignored to align git state with this empty-on-build behaviour.) `vvwt-info-server` then serves the bundle via Spring Boot's static resource handler at base `/info/`.

The Discovery decision (Brief D-6) is that the **UI palette stays uniformly blue across the family** — Info does NOT adopt yellow as its UI primary colour. The differentiation between the Info portal and the admin-facing TM surfaces happens **only at the favicon and lockup level**: the favicon uses the yellow hex-icon variant (`vvw-icon-yellow.svg`, `vvw-favicon-yellow-{16,32,64,128,256}.png`), and the in-page lockup uses the yellow-inverted lockup (`vvw-info-logo.svg`). This is a deliberate, human-validated deviation from the HANDOFF visual-intent phrasing ("Info auf einen Blick als 'die andere App' erkennbar"); the honest trade-off is documented in Brief T-3 — the visual distinction is reduced to favicon and header lockup but is preserved in those two locations.

DEC-42 makes `vvwt-info-server` **internet-facing** — distinct from the LAN-mode self-host posture of the rest of the TM family. This raises the bar on the `compliance` AC category: WCAG AA contrast for any text rendered on top of brand colours, sprechende `alt` text per Brief Q-4, Apple-touch-icon for iOS home-screen pinning by participants on mobile devices.

Like E44S02, this Story includes a conditional CSS-token migration with the same threshold guard: the audit phase counts component-local color values; if >20, token migration defers to a follow-up Story while the favicon/lockup/title rollout ships standalone.

## Notes

**Asset variant choice (yellow, not blue)**: All Info-portal favicon and lockup assets use the **yellow** variant filenames per Brief D-6:
- favicon: `vvw-icon-yellow.svg` + `vvw-favicon-yellow-{16,32,64,128,256}.png`
- lockup: `vvw-info-logo.svg` (the inverted-palette lockup specifically designed for the Info app per HANDOFF)

The blue variants are reserved for TM-family surfaces (E44S02). Mixing variants between Stories is a defect — verify by grep at PR-review time.

**WCAG AA contrast (AC5)**: HANDOFF specifies brand colours `--vvw-blue: #1956a8` (luminance ~0.10) and `--vvw-yellow: #ffcb1f` (luminance ~0.74). Common safe text-on-background combinations:
- `--vvw-ink` (#0a1f3a) text on `--vvw-yellow` background: ~10:1 contrast ratio (AAA-compliant).
- White text on `--vvw-blue` background: ~7:1 contrast ratio (AAA-compliant).
- `--vvw-yellow` text on `--vvw-blue` background: ~5:1 (AA-compliant for normal text).
Risky combinations to avoid: light grays on `--vvw-yellow` (low contrast), `--vvw-blue` text on `--vvw-ink` background (similar luminance). Delivery should document the actual rendered combinations and verify each against the WCAG threshold.

**Brief H-3 likely outcome**: The existing palette has Tailwind-style grays + `#1e40af` blue, which is close to but not equal to `--vvw-blue` `#1956a8`. A naive token-replace `s/#1e40af/var(--vvw-blue)/g` would shift the visual identity slightly; a careful migration would map each existing colour to the closest token semantically. If the count is high (likely), defer is the safer choice — ship the favicon/lockup/title rollout, track the migration as a follow-up.

**Internet-facing posture (DEC-42) reminder**: The Info portal serves participants over the open internet (not LAN-mode like the rest of the TM family per DEC-15/DEC-16). Compliance defects (broken favicon, missing alt text, low contrast) are user-visible at scale — the testing and compliance ACs in this Story carry higher real-world consequence than the same ACs in E44S02.
