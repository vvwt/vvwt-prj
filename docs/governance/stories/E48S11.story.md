# Story E48S11: Phasenplan-Vorschau-Tabelle — Sum-Row + H:MM Format + Phase Start Times

## User Story

**As a** Tournament Organizer,
**I want** the Phasenplan-Vorschau-Tabelle to show a summary row with totals (matches, time), durations in H:MM format instead of raw minutes, and the projected start time of each phase when the tournament has a planned start time,
**so that** I can quickly assess the entire tournament's scope and timing without manually adding values, converting minutes to hours, or computing per-phase start times in my head.

---

## Context

Per Brief D-7 / Q-4 / Q-5 / S-12 (`discovery-2026-05-06-phasenplan-preview-fixes`): The current Vorschau-Tabelle in `DraftConfig.svelte:481-509` shows per-phase columns only (Phase, Gruppen, Teams/Gruppe, Spiele/Gruppe, Runden, Spiele gesamt, Geschätzte Zeit). Geschätzte Zeit shows raw minutes ("99 Min."). For multi-phase tournaments, summing values mentally is tedious; converting minutes to hours requires mental math; and there's no indication of when each phase actually starts.

This enhancement (1) adds a footer Sum-Row across phases for `totalMatches` and `estimatedTimeMinutes`; (2) formats durations as H:MM per Brief Q-4 final (0=`0:00`, 45=`0:45`, 60=`1:00`, 90=`1:30`, 125=`2:05`, 600=`10:00`); (3) adds a "Voraussichtl. Beginn" column computed cumulatively from `tournament.plannedStartTime` when set.

**Reviewer-cycle-1 correction (S-CREEP-1, B-COVER-1, SUB-1, SUB-2):** A timeline-table render exists at `DraftConfig.svelte:512-536` (E08S05 AC6) — conditional on `preview.timeline.length > 0` — but `DefaultDraftService.preview():137-138` hardcodes `timeline = List.of()`, so the table never renders. The Backend-Wiring of `TimelineCalculationService` into `DraftService.preview()` is the scope of **sibling story E48S12** (path δ per Brief D-9). This story (E48S11) is the COMPACT (α) per-phase summary in the structural table; S12 activates the per-lap DETAIL in the timeline table. Both coexist after both ship — user gets overview AND detail. This story does NOT remove or modify the timeline-table render block; it does NOT touch the dead-code surface.

**Time arithmetic representation (Reviewer A-1 clarification):** `tournament.plannedStartTime` is a `LocalDateTime` (e.g., `"2026-06-01T09:00:00"`). The cumulative computation parses it once via JS `Date` constructor (or `dayjs(...)` if Delivery prefers — equivalent results), accumulates per-phase offsets in **minutes-of-day** (or millisecond timestamps), and renders the result via a NEW helper `formatStartTime(date: Date | string, offsetMinutes: number): string` returning `"HH:mm"` (zero-padded both sides). The existing `formatTime(t: string)` helper at `DraftConfig.svelte:309` operates on `HH:mm:ss` LocalTime strings only — it is NOT reusable for LocalDateTime + minute-offset arithmetic. Story therefore introduces a NEW helper distinct from `formatTime`.

**Sum-Row "Voraussichtl. Beginn" cell semantics (Reviewer A-2 user-authorization):** The user has authorized (2026-05-06 Discovery exchange) the Sum-Row's start-time cell to display the **projected tournament END time** = `plannedStartTime + Σ estimatedTimeMinutes`. Rationale: tells the user "wann ist alles vorbei". Brief D-7 is updated to reflect this user authorization.

Per Brief S-12: story is **FE-only** — uses existing `DraftPreviewResponse` per-phase `estimatedTimeMinutes` and existing `getTournament(...).plannedStartTime` (already loaded in `DraftConfig.svelte:78-86`). No backend changes; if Delivery discovers backend additions are needed, escalate.
