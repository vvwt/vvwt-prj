# Story E22S03: TDD-reconstruct scoring strategy interfaces + VOs in `de.vvwt.tm.scoring.*` public (Part 1 of 12-class reconstruction)

## User Story

**As a** scoring bounded-context developer,
**I want** the 4 scoring strategy contract types (`ScoringRule`,
`SetValidationRule`, `ScoringResult`, `ValidationResult`) authored
fresh under DEC-22 Iron Law RED-first in the public root package
`de.vvwt.tm.scoring.*` — with legacy
`de.vvwt.tm.domain.rules.{ScoringRule,SetValidationRule,ScoringResult,ValidationResult}`
left untouched at this commit per DEC-22 Reconstruction-in-Place,
**so that** E22S04 (5 concrete rules) and E22S05 (registries +
`TournamentRuleResolver`) can build against a reconstructed
strategy-pattern contract that matches the D-9 final public surface
without requiring a later `.internal` → root promotion refactor.

---

## Context

Per Brief v3 D-5 (Q-1a TDD classification) and D-9 (scoring public
surface of 6 types), this story is the first of the 12-class scoring
reconstruction and delivers 4 of the 6 planned public types:
- `de.vvwt.tm.scoring.ScoringRule` (interface)
- `de.vvwt.tm.scoring.SetValidationRule` (interface)
- `de.vvwt.tm.scoring.ScoringResult` (VO)
- `de.vvwt.tm.scoring.ValidationResult` (VO)

The remaining 2 public types (`ScoringRuleRegistry`,
`SetValidationRuleRegistry`) ship at E22S05.

**Target package = `scoring.*` public root from the start.** Per D-9
these 4 types ARE the public strategy-pattern contract — registries'
public methods return `ScoringRule` / `SetValidationRule` — so placing
them in `scoring.internal` at this story and promoting them at E22S05
would be a wasted move. Placing them at `scoring.*` root now matches
D-9's final decided surface and avoids the intermediate move.

Legacy `de.vvwt.tm.domain.rules.{ScoringRule, SetValidationRule,
ScoringResult, ValidationResult}` remain UNCHANGED at this commit —
DEC-22 Reconstruction-in-Place invariant. Legacy deletion happens
atomically at E22S11 cutover per DEC-21. During the coexistence
window (E22S03 → E22S11), the legacy types still satisfy their
current consumers; the new types satisfy NEW test-driven behavior
only.

Classification: Q-1a TDD RED-first per DEC-22 Iron Law (D-5). Each of
the 4 types gets a RED-first test class authored + failing before the
production type exists. Impl-report MUST include evidence (commit
hash or grep output) that the test class existed + was RED before
the implementation landed.

## Notes

- **Why `scoring.*` root and not `scoring.internal` first**: Brief v3
  D-9 decided the final public surface. `ScoringRuleRegistry` public
  API will return `ScoringRule` — transitive-exposure makes
  `ScoringRule` public by consequence. Authoring directly at root
  matches the final decision and avoids a mid-epic Q-1b relocation
  (Q-11 transitive-exposure rule permits mid-delivery promotion but
  is wasted work here since the target is already known).
- **Legacy coexistence**: During E22S03 → E22S11, both legacy
  `de.vvwt.tm.domain.rules.*` AND new `de.vvwt.tm.scoring.*` types
  exist. Legacy consumers continue using legacy; E22S04/S05 build
  new consumers against new types. No consumer swap happens until
  cutover.
- **RED-first discipline**: Per DEC-22 Iron Law + DEC-34, this story
  is a canonical TDD reconstruction. The impl-report is REJECTED at
  QA if it does not cite per-type RED-first evidence.
- **Record vs. class for VOs**: Java records are the default per
  project conventions (consistent with D-7 REST-DTO records). If any
  VO has behavior beyond equality + getters (e.g., derived methods),
  a record with methods is still preferred over a class.
- **E31S02 module boundary**: The `de.vvwt.tm.scoring` module declared
  by E31S02 already has `allowedDependencies = {"tenant",
  "tournament"}`. The new types import only tournament-public
  (`MatchOutcome`, `MatchFormat`) — fits the existing allowance. No
  module descriptor change at this story.
- **Commit message template**: `feat(E22S03): TDD-reconstruct scoring
  strategy contracts (ScoringRule, SetValidationRule, ScoringResult,
  ValidationResult) in scoring.* public (DEC-22 Iron Law)`.
