# Story E51S13: Bug 2a — Source-pane label sortType-driven (replaces hasSourceSlot heuristic)

## User Story

**As a** Tournament Operator,
**I want** the "Bisherige Zuordnung" column on the Phase-Vorbereiten/Drag&drop page to show meaningful labels for every team — for Phase 1 the team's number (e.g., "Nr. 1", "Nr. 2", ...), for Phase 2+ the team's previous-phase position (e.g., "Gruppe 1, Platz 3") — instead of the buggy literal text "Gruppe undefined, Platz undefined" that appears today,
**so that** the source pane is informative regardless of phase number and JSON serialization edge-cases.

---

## Context

**Empirically verified mechanism (Brief O-5 + H-5 + H-3):** `PhaseTransition.svelte:156-163` uses `hasSourceSlot(slot)` (`phaseTransitionStore.ts:54-58`) which checks `sourceGroupNumber !== null && sourceGroupPosition !== null`. For Phase 1 proposals, `DefaultPhaseTransitionService.computePhase1Proposals:314-316` sets these to `null`. JSON serialization with Jackson `NON_NULL` inclusion config can omit null fields → the JS-side value becomes `undefined` → `undefined !== null` evaluates to `true` → `hasSourceSlot` returns `true` → the label-resolver renders "Gruppe undefined, Platz undefined" (literal `String(undefined)`).

**Brief D-9 (root-cause-fix decision):** the source-pane label switch is sortType-driven, NOT data-presence-driven. `phase.sortType` is the canonical domain trigger:
- `team_number` → label = "Nr. {teamNumber}" (Phase 1 case)
- `placement_group` / `group_placement` → label = "Gruppe {g}, Platz {p}" (Phase 2+ case)

**Backend scope (Brief S-5):** `TeamAvatarProposal` record (`vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/TeamAvatarProposal.java:65`) extended with nullable `sortType: String` field. `DefaultPhaseTransitionService.computePhase1Proposals:308-316` populates `sortType` from `toSection.getSortType()`. `DefaultPhaseTransitionService.computeProposals:333+` populates `sortType` per-branch (team_number / placement_group / group_placement).

**Frontend scope (Brief S-5):** `phaseTransitionStore.ts` `TeamAvatarSlot` type extended with `sortType: string | null` field. New label-resolver function `sourceLabelBySortType(slot)` switches on `sortType`. `PhaseTransition.svelte:156-163` updated to call new resolver. `hasSourceSlot` type-guard at `phaseTransitionStore.ts:54-58` **DELETED** (Brief D-8 — dead code post-Story-13).

**i18n keys:** existing `phaseTransition.sourceLabelPhase1` ("Nr. {n}") and `phaseTransition.sourceLabelPhase2plus` ("Gruppe {g}, Platz {p}") preserved unchanged (DEC-52 V1-DE-only). NO new keys.
