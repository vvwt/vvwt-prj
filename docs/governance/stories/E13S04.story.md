# Story E13S04: Conditional — minimal ArchUnit complement skeleton (IF adopted in E13S03)

## User Story

**As a** TM maintainer seeking build-time module-boundary feedback complementing Modulith's test-time `verify()`,
**I want** a minimal ArchUnit rule-set integrated in `vvwt-tm-web`,
**so that** IDE-time and Maven-compile-time diagnostics catch violations earlier than running the full verify() test.

---

## Context

This story is **conditional**. Its status starts at `deferred` in the backlog, gated on E13S03's ArchUnit decision (AC-ARCHUNIT-DECISION). If E13S03 records "YES adopted" → this story flips to `refined`. If "NO deferred" → this story flips to `cancelled`.

Per DEC-21, ArchUnit (if adopted) is a complement to Modulith `verify()`, NOT a replacement. Its value is IDE/dev-feedback speed; the Modulith verify() remains the authoritative gate per DEC-21 C-8.

Per DEC-22, the ArchUnit rule test is itself production test code and MUST be written test-first (rule expressed → assertion fails on the current codebase due to absent annotations → annotations arrive → rule goes green). No bulk-import of "standard ArchUnit rules" without individual red-green cycles.

---

## Acceptance Criteria

- [ ] AC1 (testing — test-first for the rule test): The first ArchUnit rule test is authored in a failing state (expressing a rule the codebase does not yet satisfy — e.g., "all classes under `de.vvwt.tm.{context}.internal` must not be imported from outside the same context"); `mvn -pl vvwt-tm-web test` fails at this commit. A subsequent commit (or the E14/E15 work) brings annotations that make the test green.

- [ ] AC2 (governance — dependency managed centrally per DEC-10 C-1): `com.tngtech.archunit:archunit-junit5` dependency is added to `vvwt-tm-web/pom.xml` with the version declared in `vvwt-prj/pom.xml`'s `<dependencyManagement>`. No version pin in the child module.

- [ ] AC3 (governance — rule scope minimal): The rule set initially contains ONE rule that is genuinely enforceable AND complementary to Modulith's own checks. Candidates: "no class in `de.vvwt.tm.{any}.internal` is imported from any package outside its own `de.vvwt.tm.{same}`" (enforceable and meaningful once contexts are annotated). Discovery / Delivery chooses and documents.

- [ ] AC4 (error-handling — ArchUnit failure containment): If the ArchUnit rule incorrectly flags a pre-existing legacy package (e.g., `de.vvwt.tm.config` or `de.vvwt.tm.slotopt` has cross-cutting imports that pre-date annotations), the rule is either: (a) scoped to avoid legacy, (b) paired with a deliberate exclusion comment documenting the exception, or (c) held back until E14+ contexts exist. A Delivery run validates the rule against the current codebase BEFORE claiming it green.

- [ ] AC5 (testing — rule test runs in Maven verify phase): The ArchUnit test runs in `mvn verify` alongside the Modulith `ApplicationModulesTest`. Both tests green = module boundaries consistent between ArchUnit's static check and Modulith's reflective scan.

- [ ] AC6 (governance — E13S03 decision linkage): The rule test file header (Javadoc or top-of-file comment) references E13S03's recorded decision: "Adopted per E13S03 AC-ARCHUNIT-DECISION (YES, <two-sentence rationale copied from E13S03's conventions doc>)". Traceability explicit.

## Out of Scope

- Replacing Modulith `verify()` (DEC-21 C-8: verify() remains mandatory gate)
- ArchUnit as enforcement for business-layer rules (e.g., naming conventions, DDD tactical patterns) — Wave-2 or later
