# Story E51S15: Feature — DraftConfig.distribution_mode (sequential default + round-robin toggle)

## User Story

**As a** Tournament Operator,
**I want** to choose how teams are distributed across the groups of a phase — sequentially (Group 1 fully filled before Group 2) as the new default, or round-robin (1 to G1, 1 to G2, 1 to G3, 1 to G1, ...) as today's behavior — via a per-section toggle on the Phasenplan,
**so that** the team distribution matches the natural workflow expectation (sequential), while preserving the round-robin option for tournaments where it's valid.

---

## Context

**Empirically verified mechanism (Brief O-8):** `DefaultDraftService.persistStructuralAvatars` (`vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/internal/DefaultDraftService.java:627-633`) for Phase 1 uses round-robin distribution: `groupNumber = (i % groupCount) + 1`, `groupPosition = (i / groupCount) + 1`. Same algorithm in `DefaultPhaseTransitionService.computePhase1Proposals:298-301`. This means: for 12 teams + 2 groups of 6, team-1 → G1P1, team-2 → G2P1, team-3 → G1P2, etc. (snake/round-robin order).

**Operator request (Brief D-10 + 2b):** the natural workflow expectation is sequential — fill Group 1 first (team-1 → G1P1, team-2 → G1P2, ..., team-6 → G1P6, team-7 → G2P1, etc.). Sequential becomes the new default; round-robin remains available as a per-section toggle.

**Schema scope (Brief S-7 + O-9):** `DraftSection` (`vvwt-tm-web/src/main/java/de/vvwt/tm/tournament/draft/DraftSection.java`) gets a new field `distribution_mode: String` with values `"sequential"` (default) or `"round_robin"`. Persistence: stored in `tournament.draft_json` (existing JSON column, DEC-14 H2 schema), so NO Flyway migration needed — additive JSON field, defaults to "sequential" via Jackson `@JsonProperty(defaultValue = "sequential")` or via service-side fallback.

**Code branching (Brief S-7):** `DefaultDraftService.persistStructuralAvatars:627-633` Phase-1 branch + Phase-2+ branch (line 634-645) switch on `section.getDistributionMode()`:
- `sequential`: `groupNumber = (i / positionsPerGroup) + 1`, `groupPosition = (i % positionsPerGroup) + 1`
- `round_robin` (legacy): `groupNumber = (i % groupCount) + 1`, `groupPosition = (i / groupCount) + 1`

`DefaultPhaseTransitionService.computePhase1Proposals:298-301` follows the same switch.

**UI scope (Brief S-7):** `DraftConfig.svelte` (Phasenplan) per-section dropdown for `distribution_mode`. DE labels per DEC-52: "Mannschaftsverteilung" with options "Gruppen nacheinander füllen" (sequential) / "Gruppen gleichmäßig füllen" (round-robin).

**Migration (Brief S-7):** existing tournaments default to `"sequential"` (DEC-25 Wave-2 Big-Bang-Reset means no production data; new tournaments default to sequential).

This story is the Feature track (NOT bug-triage). Discovery-track per Brief T-3 (concern-locality: feature decisions live in Discovery flow).
