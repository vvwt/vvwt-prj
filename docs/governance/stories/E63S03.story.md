# Story E63S03: TM embedded worker — core: opt-in runtime wrapper, own keypair, worker-thread lifecycle with dispatcher-outage survival

## User Story

**As a** Tournament Manager operator,
**I want** to optionally let my TM server contribute slot-optimization compute to the
dispatcher pool,
**so that** the shared compute pool grows with the deployment — without my server's primary
duties being affected and without me having to run a separate worker process.

---

## Context

The original (blocked) Story E01S11 envisaged the slot-optimization worker embedded in TM
as a background thread. Epic E63S01 makes the worker compute path available as a shared
library. This story builds the **core** of the TM embedded worker: a Spring component that
wraps the extracted runtime and runs it on a background thread.

The embedded worker is **opt-in — OFF by default** (a config flag). With the flag absent or
false the worker thread MUST NOT start, MUST NOT generate a keypair, MUST NOT contact the
dispatcher. When enabled it registers with the dispatcher and pulls / solves / submits
packets for the general job pool.

The embedded-form **lifecycle is designed here**, not reused from the standalone worker. The
standalone `DefaultWorkerLoop` registers a JVM shutdown hook and terminates the loop on a
dispatcher outage — correct for a CLI process, wrong for an embedded worker inside a
long-lived host. The embedded worker registers no JVM shutdown hook, and on a dispatcher
outage it **survives and resumes** (backoff, then resume when the dispatcher returns) rather
than terminating.

The embedded worker is a separate background thread; it does not access the TM database and
does not couple to the DEC-64 Saga-Orchestrator. Host-protection (auto-pause during
live-scoring, CPU throttle) is E63S04; operator controls and metrics are E63S05.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-OFF-BY-DEFAULT** — RED-first (DEC-22): with the enable flag absent or false,
  no embedded-worker thread starts, no keypair is generated, and no dispatcher request is
  made. Verified by config-absent and config-false cases.
- [ ] **AC-TEST-ENABLED-PULLS-AND-SOLVES** — with the flag enabled and the dispatcher
  reachable, the embedded worker registers, then pulls, solves, and submits packets via the
  E63S01 shared compute-path library.
- [ ] **AC-TEST-OUTAGE-SURVIVE-AND-RESUME** — RED-first: when the dispatcher becomes
  unreachable while the worker is running, the embedded worker does NOT terminate; it backs
  off and resumes pulling once the dispatcher is reachable again. (The standalone worker
  terminates on outage — the embedded worker must not.)
- [ ] **AC-TEST-THREAD-LIFECYCLE-START-STOP** — starting the worker spawns exactly one
  background thread; stopping it interrupts the worker cleanly between packets (not
  mid-packet) and leaves no live worker thread.
- [ ] **AC-TEST-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for `vvwt-tm-web` (DEC-54).

### Governance

- [ ] **AC-GOV-OPT-IN-CONFIG** — the embedded worker is governed by a single config property
  (e.g. `tm.slotopt.embedded-worker.enabled`), OFF by default; the property is documented in
  the operator-facing config reference. Absent ⇒ disabled (no implicit-on).
- [ ] **AC-GOV-REUSES-RUNTIME-LIBRARY** — the worker uses the E63S01 shared compute-path
  library for pull-solve-submit; the loop's compute step is not re-implemented (Q-3 — one
  compute path, two deployment forms).
- [ ] **AC-GOV-EMBEDDED-LIFECYCLE-NOT-CLI-LIFECYCLE** — the embedded worker registers no JVM
  shutdown hook and does not adopt the standalone loop's terminate-on-outage behaviour; its
  start/stop/outage-resume lifecycle is the embedded-form lifecycle designed in this story.
- [ ] **AC-GOV-NO-HOST-DB-OR-ORCHESTRATOR-COUPLING** — the embedded worker does not read or
  write the TM database and does not couple to the DEC-64 `phaselifecycle` Saga-Orchestrator;
  it runs on its own background thread, independent of the per-tournament orchestrator
  threads (DEC-64; Session Brief C-5).
- [ ] **AC-GOV-NO-DISPATCHER-COMPILE-DEP** — the embedded worker talks to the dispatcher over
  HTTP only (via the E63S01 runtime library's hand-rolled client); no compile dependency on
  `vvwt-slotopt-dispatcher` (DEC-11).
- [ ] **AC-GOV-INTERFACE-MANDATE** — the embedded worker's behaviour-bearing Spring
  components get an interface in the module root + a `Default*` implementation in `.internal`
  (DEC-58 / DEC-72 / DEC-35 / DEC-36); the interface-mandate build guard stays green.
- [ ] **AC-GOV-RED-FIRST** — new first-party code is authored RED-first per DEC-22; the
  impl-report records RED-state evidence.
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); warning-free (DEC-29);
  Spotless / google-java-format (DEC-30); no production member exists solely for tests
  (DEC-70).
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use `chore(E63S03):` / `feat(E63S03):`
  prefixes per the close-story.sh contract.

### Error Handling

- [ ] **AC-ERR-OUTAGE-BACKOFF-NO-BUSY-LOOP** — during a sustained dispatcher outage the
  worker backs off (e.g. capped exponential backoff), does not busy-loop, does not consume
  CPU spinning, and does not crash; it resumes on reachability.
- [ ] **AC-ERR-PERSISTENT-FAILURE-SELF-STOPS-NOT-CRASH** — a persistent, non-recoverable
  failure (e.g. the dispatcher rejects the worker's registration definitively) stops the
  embedded worker and logs at ERROR — it MUST NOT crash or destabilize the TM host process.
- [ ] **AC-ERR-NO-PACKET-IDLES-GRACEFULLY** — when the dispatcher has no packet available,
  the worker idles gracefully (no error, no busy-loop) and pulls again later.

### Security

- [ ] **AC-SEC-OWN-DISTINCT-KEYPAIR** — the embedded worker generates and uses its OWN
  Ed25519 keypair, distinct from every other TM DEC-6 identity (in particular any TM
  slot-opt submitter keypair); a test verifies the key files coexist without collision. On
  first enabled start the keypair is generated; on subsequent starts the existing key is
  loaded.
- [ ] **AC-SEC-KEYPAIR-PATH-FROM-TM-DATA-DIR** — the embedded worker's key file derives its
  default path from `${tm.data.dir}` (DEC-68), with `TM_SLOTOPT_WORKER_KEY_DIR` as the
  per-purpose override; no new independent path root is introduced.
- [ ] **AC-SEC-REGISTRATION-DEC6-HANDSHAKE** — the worker registers its public key with the
  dispatcher via the DEC-6 / DEC-43 registration handshake (Ed25519, V1); the registration
  request carries no team UUIDs or PII (DEC-9).
- [ ] **AC-SEC-KEY-MATERIAL-NOT-LOGGED** — private key material never appears in logs or in
  any dispatcher request beyond the public key the handshake requires.
