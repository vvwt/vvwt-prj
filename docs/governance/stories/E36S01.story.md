# Story E36S01: Photo domain Q-1a TDD rebuild — PhotoStorageService + DefaultPhotoStorageService + 3 exceptions + PhotoFileMetadata + PhotoStorageConfig (D-7 Option γ at canonical FQN de.vvwt.tm.photo.*)

## User Story

**As a** maintainer of `vvwt-tm-web` correcting the post-E23 Q-1b mis-application
of DEC-40 Clause D on the photo domain surface,
**I want** the legacy photo-domain Q-1b artefacts at `de.vvwt.tm.photo.*` deleted
and rebuilt under DEC-22 Iron Law Q-1a TDD RED-first authorship at the same
canonical FQNs (D-7 Coexistence Option γ),
**so that** the photo domain carries a trustworthy correctness oracle, satisfies
DEC-41 §3 hierarchy clause (1) MANDATORY, and Track 1 of Epic E36 begins with
production code paired to fresh RED-first tests.

---

## Context

Per Session Brief `discovery-2026-04-26-e36-retro-correction` O-1: DEC-40 Clause D's
Q-1b authorization is scoped to *already-Q-1a-reconstructed code being moved*. E23's
Q-1b on legacy `infrastructure.web.{photo,certificate}.*` was a Brief-level
mis-application — the legacy code was never Q-1a TDD-authored, so Q-1b
refactor-clause invocation lacked a trustworthy oracle.

Audit `E36-discovery-legacy-inventory.md` (artefact group "Photo Domain (E23S01)")
enumerates 7 in-scope artefacts under `de.vvwt.tm.photo.*` totaling ~267 LOC. Audit
`E36-discovery-dec41-test-classification.md` classifies the entire pre-existing
photo test corpus (`DefaultPhotoStorageServiceTest`, 21 methods) as 100%
Snapshot-Driven (criterion (a)/(b)/(c)/(d) all ✗); zero Contract Test reuse
candidates exist.

Per Brief D-7 Option γ this story executes delete-then-rebuild within the
feature-branch lifecycle at the same canonical FQN. Consumer imports
(`TeamPhotoController`, `DefaultCertificateAssembler`, `WebModuleTestConfig`) MUST
remain unchanged because the FQN is preserved. Per Brief C-3, signature-preservation
is the default; deviations on records (`PhotoFileMetadata`), exception constructors,
or config getters/setters trigger stop-and-escalate.

This is the first story in Track 1 (Photo). The closing housekeeping for Track 1
(Javadoc-historical-provenance sweep, governance propagation, Photo-track Success
Metrics verification) happens in E36S03 (Cutover-1).

- **Constraint** (Brief C-3): `PhotoFileMetadata` record + 3 exception constructors
  + `PhotoStorageConfig` getters/setters are signature-preservation candidates.
  Any unavoidable signature evolution during rebuild triggers stop-and-escalate
  to Discovery before GREEN code lands.
- **Risk** (Brief C-11): If during RED-first authoring a pre-existing behavioral
  characteristic (e.g., specific exception-cause chaining, specific HTTP-tier
  expectations from `PhotoExceptionAdvice`) cannot be reproduced verbatim, this
  is a **behavioral-divergence** trigger and MUST stop-and-escalate. Note: C-11
  applies broadly across E36; in this story it is most likely to surface around
  exception messages consumed by the still-resident `PhotoExceptionAdvice`.
- **Escalation triggers**: C-3 (signature evolution), C-11 (behavioral divergence
  of exception messages or storage semantics), C-2 (any consumer-import change
  required — would invalidate Option γ).

  only). This story uses canonical FQN preservation, not DEC-32 carve-out.

  `de.vvwt.tm.photo`; `DefaultPhotoStorageService` impl stays under
