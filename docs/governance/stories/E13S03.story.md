# Story E13S03: Document Modulith package + cutover conventions + decide ArchUnit complement

## User Story

**As a** Delivery Agent about to start E14S01 (the first bounded-context story),
**I want** the Modulith package layout, the atomic cutover protocol, and the ArchUnit yes/no decision written down in one discoverable place,
**so that** I do not re-derive naming conventions or cutover mechanics from DEC-21 on every story, and I know whether ArchUnit rules belong in the Delivery execution plan.

---

## Context

DEC-21 specifies: top-level packages under `de.vvwt.tm.*` are bounded contexts; `{context}.internal` is hidden implementation; `package-info.java` declares `@ApplicationModule(allowedDependencies = {...})`; cutover is a single commit without feature flags. These rules exist in DEC-21 but need a shorter, implementation-facing document that Delivery can load quickly.

Additionally, DEC-21 leaves the ArchUnit decision open: Modulith's verify() is test-time only; ArchUnit could complement it with IDE-time / compile-time rule checking. This story forces the decision — yes with minimal scaffolding, or no with a recorded rationale — so E14 does not re-open it.

This story is documentation + one optional-minimal code decision; no bounded-context work happens here.

---

## Acceptance Criteria

- [ ] AC1 (governance — conventions document): A markdown file (candidate location: `docs/modulith-conventions.md` in `vvwt-tm-web/`, or an equivalent path agreed in the Delivery plan) exists and documents: (a) top-level packages under `de.vvwt.tm.*` = bounded contexts; (b) `{context}.internal` sub-package for hidden implementation; (c) `package-info.java` declaration pattern for `@ApplicationModule(allowedDependencies = {...})`; (d) per-module Flyway path `db/migration/{context}/V1__*.sql`; (e) link to DEC-21.

- [ ] AC2 (governance — atomic cutover protocol section): The same conventions document describes the five-step atomic cutover protocol (delete legacy, promote new, remove old Flyway migrations per DEC-22 O-9, update Spring wiring, `verify()` stays green) as a checklist Delivery can follow during E14S07 and E15S07.

- [ ] AC-ARCHUNIT-DECISION (governance — ArchUnit complement decision is recorded): The conventions document contains a section "ArchUnit as Modulith Complement" that records a binary decision (YES adopted / NO deferred) with at least two sentences of rationale. If YES, E13S04 is unblocked and moves from `deferred` to `refined` in the backlog. If NO, E13S04 is marked `cancelled` in the backlog. The decision itself is authored by the human at story delivery time OR by Discovery with explicit escalation. Either way, a draft decision entry with the rationale is committed in this story; the human may amend before E13S04's status-change commit.

- [ ] AC6 (error-handling — convention doc discoverability): The conventions document is linked from `patterns/conventions.md` and from the `patterns/conventions.md` Testing section so that the rule-loading path surfaces it. A broken or missing link fails AC.

- [ ] AC7 (governance — no premature annotation): This story does NOT add `@ApplicationModule` annotations to any existing package. Annotations appear starting in E14S01 (on `de.vvwt.tm.tenant`). `git diff` at merge confirms no `package-info.java` was modified under `de.vvwt.tm.{auth,tenant,domain,infrastructure,config,slotopt}`.

## Out of Scope

- Implementing cutover steps (E14S07 and E15S07 exercise the protocol on real contexts)
- Full ArchUnit rule coverage (even if ADOPTED, only a skeleton rule set is in scope here)
- Runtime verification configuration

## Notes

Per E13 Epic scope, E13S03's purpose is package + cutover convention documentation + the ArchUnit-adopt-or-defer decision. The IMPLEMENTATION of ArchUnit (if adopted) is carved out to E13S04, which lives in the backlog with status `deferred` until this story's decision lands. This avoids bundling two incompatible futures into one story per Tier-2 finding F-6.

The ArchUnit decision is consequential — it affects how E14 and E15 structure their test suites. A genuinely neutral weighing is expected: Modulith's `verify()` is sufficient for boundary enforcement at merge time, but ArchUnit gives earlier feedback in the IDE. Delivery documents the weighing in the execution plan so the choice is traceable.

The conventions document intentionally avoids restating DEC-21 verbatim — it translates the decision into an implementation-facing checklist. If the two ever drift, DEC-21 is the authoritative source.
