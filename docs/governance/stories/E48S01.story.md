# Story E48S01: gameMode-Whitelist + Per-Phase gameMode-UI in DraftConfig + Last-Phase-Siegerehrung-Invariante

## User Story

**As a** Tournament Organizer,
**I want** to select the game mode per phase in the Phasenplan UI (RoundRobin or Siegerehrung) and have the system enforce that the last phase is Siegerehrung,
**so that** I can configure a complete tournament from regular play phases through to the final placement ceremony with a backend-validated structure.

---

## Context

Per Brief D-5 / D-7 / D-10 + O-7 / O-8: `DraftSection.gameMode` existiert per-Phase im Draft-JSON (`DraftSection.java:40`), aber `DraftSection.validate()` (lines 118-120) akzeptiert JEDEN non-blank String (keine Whitelist). DraftConfig.svelte hardcodet aktuell `gameMode: 'roundrobin'` in `addSection()` (Memory note `project_phase2plus_verification_gap_e21s21.md` zitierte fälschlich line 90; tatsächlicher Standort ~line 104; Delivery verifiziert via grep `gameMode.*roundrobin` über `DraftConfig.svelte`). Um Siegerehrung als Phase-Mode (D-5) zu ermöglichen und die strikte D-10 Invariante (last phase MUST be siegerehrung) durchzusetzen, fügt diese Story hinzu: Whitelist-Validation (`{roundrobin, siegerehrung}`), Last-Phase-Invariante (höchster `sectionNumber` MUSS gameMode=siegerehrung haben), per-Phase gameMode-Dropdown in DraftConfig.svelte mit i18n-Keys, sowie Pre-Submit Frontend-Validation, die das Backend-Verhalten spiegelt (sofortiges Feedback).

---

## Acceptance Criteria

- [ ] **AC-TEST-DRAFT-SECTION-WHITELIST-RED** (testing): RED-first JUnit Test in `DraftSectionTest` (oder neues Test-File falls nicht existent) asserted, dass `DraftSection.validate()` `IllegalArgumentException` wirft für jeden gameMode ∉ {roundrobin, siegerehrung}. Test ist RED vor jeder Production-Änderung. (DEC-22 Iron Law, Q-1a)
- [ ] **AC-IMPL-DRAFT-SECTION-WHITELIST**: `DraftSection.validate()` akzeptiert nur gameMode ∈ {roundrobin, siegerehrung}; Fehlermeldung enthält die erlaubten Werte explizit ("must be one of: roundrobin, siegerehrung").
- [ ] **AC-TEST-LAST-PHASE-INVARIANT-RED** (testing): RED-first Test: `DraftConfig` mit N Sections, wo der höchste sectionNumber gameMode=roundrobin hat, wirft `IllegalArgumentException` mit Message identifying the offending sectionNumber.
- [ ] **AC-IMPL-LAST-PHASE-INVARIANT**: Phasenplan-Submit-Validation in `DefaultDraftService.apply()` (oder einem von dort aufgerufenen Validator vor Phase-Erzeugung) enforcet last-phase=siegerehrung; Fehlermeldung nennt den offending sectionNumber + actual gameMode. (Submit-Pfad ist kanonisch — D-10 verlangt Validation bei Submit, nicht beim DraftConfig in-memory edit.)
- [ ] **AC-FRONTEND-GAMEMODE-DROPDOWN** (i18n): DraftConfig.svelte rendert ein `<select>` pro Phase mit Optionen "RoundRobin" / "Siegerehrung" via i18n-Keys (`draftConfig.gameMode.roundrobin`, `draftConfig.gameMode.siegerehrung`); Default-Selektion = roundrobin für neue Sections; Last-Section auto-set auf siegerehrung mit visueller Sperrung (disabled oder warning).
- [ ] **AC-TEST-FRONTEND-PRE-SUBMIT-VALIDATION-RED** (testing): RED-first Vitest Test asserted, dass die Pre-Submit-Validation-Funktion (noch nicht existent) für eine 3-Phase-Konfiguration mit last phase = roundrobin einen pre-submit Error zurückgibt UND keinen Backend-Call auslöst.
