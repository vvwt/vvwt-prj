# Story E51S20: Replace String literals with Enum constants for `gameMode` ("siegerehrung", "roundRobin") and `distributionMode` ("sequential", "round_robin") across vvwt-tm-web — codebase-wide hygiene sweep

## User Story

**As a** vvwt-tm-web developer (production code author or test author),
**I want** all comparisons + dispatch logic on `DraftSection.gameMode` and `DraftSection.distributionMode` to use type-safe enum constants instead of String literals (e.g., `"siegerehrung".equals(...)`, `"round_robin".equals(...)`),
**so that** typos at call-sites become compile-time errors instead of silent runtime mismatches, refactor / rename operations are mechanically safe, and the project benefits from IDE-driven autocomplete + usage-search on the canonical set of allowed values.

---

## Context

User-stated 2026-05-09 during multi-track Discovery audit: *"Bei der Durchsicht des Codes ist mir noch ein weiteres Problem aufgefallen. Es werden hier Strings statt Konstanten oder besser noch Enums für Vergleiche verwendet z.B.: `"siegerehrung".equals(section.getGameMode())` oder `String distributionMode = section.getDistributionMode(); if ("round_robin".equals(distributionMode))`."*

K-5 (per the multi-track session deferred-items registry) covers two distinct enumerations:
1. **`gameMode`** values — current call-sites use String literals like `"siegerehrung"`, `"roundRobin"` (and presumably `"swiss"`, `"singleElimination"`, etc. per Tournament-Manager domain). Comparisons via `.equals(...)`, dispatch via `MatchGeneratorRegistry.getGenerator(gameMode)`.
2. **`distributionMode`** values — current call-sites use String literals like `"sequential"`, `"round_robin"`. Comparisons via `.equals(...)` in `DefaultDraftService.apply()` (per K-4 fixed by Story A) and in `DefaultPhaseTransitionService` proposal-computation paths.

Empirical 2026-05-10 audit (greppable via `grep -rln "\"siegerehrung\"\|\"round_robin\"" vvwt-tm-web/src`):
- **Production-side files:** `ScoringRulesController.java`, `DraftController.java`, `RoundRobinMatchGenerator.java`, `DraftSectionResponse.java` (DTO), `SiegerehrungMatchGenerator.java` (newly authored under Story A or DEC-59 ops), `DefaultPhaseTransitionService.java`, `DraftConfig.java`, `DraftSectionRequest.java` (DTO), `DraftSection.java`, `DefaultDraftService.java`.
- **Test-side files:** `DraftControllerIT.java`, `SiegerehrungGeneratorRegistryIT.java`, `DefaultDraftServiceDistributionModeIT.java`, `SlotOptFifoQueueIT.java`, `DefaultDraftServiceApplyNoTeamAvatarsIT.java`, `MatchGenJobListenerIT.java`, `TournamentLifecycleSupportTest.java`, `PhaseTransitionDistributionModeIT.java`, `SiegerehrungMatchGeneratorTest.java`, `DefaultDraftServiceApplyAvatarsIT.java`.

Approximate count: ~20 files + ~30-50 call-sites + 2-3 DTO surfaces (`DraftSection`, `DraftSectionRequest`, `DraftSectionResponse`). Bounded scope; mechanical Q-1b refactor.

### Concrete enum-extraction plan

**Enum 1: `GameMode`** in `de.vvwt.tm.tournament.gamemode` (or `de.vvwt.tm.tournament.draft` per package locality with `DraftSection`):
```java
public enum GameMode {
    SIEGEREHRUNG,    // wire-format: "siegerehrung"
    ROUND_ROBIN,     // wire-format: "roundRobin" (verify camelCase or snake_case at call-site)
    // additional values discovered during audit (likely SWISS, SINGLE_ELIMINATION, etc.)
}
```

**Enum 2: `DistributionMode`** in same package or sibling:
```java
public enum DistributionMode {
    SEQUENTIAL,      // wire-format: "sequential"
    ROUND_ROBIN,     // wire-format: "round_robin"
}
```

**JSON serialization preservation:** `DraftSectionRequest` (incoming) and `DraftSectionResponse` (outgoing) DTOs MUST preserve the existing wire-format (string values). Either:
- (a) Use `@JsonValue` + custom `@JsonCreator` to map enum ↔ wire-format strings.
- (b) Use Spring/Jackson's default enum-name conversion (which would NOT preserve `"siegerehrung"` lowercase / `"round_robin"` snake_case wire formats).

Option (a) is required to preserve API stability. Delivery picks specifics; qa-report documents.

**Reflection / dispatch preservation:** `MatchGeneratorRegistry.getGenerator(gameMode)` (or equivalent) currently accepts `String` keys. Either:
- (a) Migrate registry to `Map<GameMode, MatchGenerator>`.
- (b) Preserve string-keyed registry but adapt at call-sites: `registry.getGenerator(gameMode.getWireFormat())`.

Option (a) is preferred for type-safety. Delivery picks; qa-report documents.

### Why ONE Story (not 2 split: gameMode + distributionMode)

- Both enums are in the same domain (`DraftSection` configuration values).
- Both are currently surfaced via the same DTO classes (`DraftSectionRequest`, `DraftSectionResponse`).
- Both refactors share the JSON-serialization preservation concern (option (a) `@JsonValue` pattern).
- Atomic mvn verify gate.

### Why a new Story (not amend Story A or Story B)

- **Story A (E51S18) scope:** K-1+K-3+K-4+K-6 production+test fix. Story A consumes/produces String literals as part of its delivery; switching to enums during Story A would entangle two distinct refactor types (behavior change + hygiene).
- **Story B (E51S19) scope:** Universal interface mandate per DEC-58. Story B refactors class-shape (interface + Default* impl), NOT value-type representation. Different concern.
- K-5 is hygiene; bundling with A/B would inflate scope without dependency.

### Error Handling

- [ ] **AC-ERROR-UNKNOWN-WIRE-FORMAT-VALUE**: When `DraftSectionRequest` is deserialized with a wire-format value not present in the enum (e.g., `"gameMode": "unknown_mode"`), the Jackson deserialization fails fast with `HttpMessageNotReadableException` (HTTP 400) with a message naming the unrecognized value. Verified via IT — `DraftControllerIT` (existing or new test) exercises the bad-input path. Pre-fix behavior: silent acceptance of any string value (untyped); post-fix: typed rejection. **NOTE:** This is a Q-1a behavior-change-on-error-path improvement, not a Q-1b mechanical refactor. qa-report documents the deliberate error-shape upgrade.
- [ ] **AC-ERROR-LATENT-TYPO-SURFACED**: If the migration surfaces ANY pre-existing typo at a call-site (e.g., a typo `"sigerehrung"` in production or test code that previously evaluated as "not-siegerehrung" silently), qa-report explicitly enumerates the typo + the latent-bug classification. The typo-fix counts as a Q-1a fresh-RED-first per DEC-22 — Delivery authors a RED test demonstrating the wrong behavior pre-fix, then GREEN with the typo corrected.
