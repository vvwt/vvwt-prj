# Story E51S19: Operationalize DEC-58 — universal interface extraction for self-created Spring components in `de.vvwt.tm.tournament.internal` (6 known violators) + codebase-wide audit closure-criterion across all bounded-context `.internal` packages

## User Story

**As a** vvwt-tm-web developer (cross-package consumer or test author),
**I want** every self-created Spring component (`@Service`, `@Component` incl. listeners/executors/writers, hand-authored `@Repository`) to be addressable via a public interface in the bounded-context root package — with `Default{Foo}` implementation classes living in `.internal` and respecting the established naming canon — and a codebase-wide audit confirming compliance,
**so that** the operator's universal interface intent codified in DEC-58 (commit `c73f60f`) is in force across the codebase, JDK-proxy + Mockito mockability is uniform, listener-pattern beans are no longer second-class citizens, and future delivery work has a fully-conforming Spring-component layout to extend.

---

## Context

DEC-58 (commit `c73f60f` on staging) amends DEC-35 §1's interface mandate from cross-boundary-consumed-services-only to a UNIVERSAL mandate for self-created Spring components. DEC-58's audit identified six current violators in `de.vvwt.tm.tournament.internal` and notes a sister-context sample in `de.vvwt.tm.slotopt.internal` (`SlotOptInvocationListener`, `SlotOptJobScheduler`, `SlotOptFifoDispatcher`) — without on-disk verification.

This Story operationalizes DEC-58 in two parts:
1. **Interface-extraction for the 6 known tournament-context violators** (in-scope code change).
2. **Codebase-wide audit (HARD AC closure-criterion per DEC-58 § Implementation)** — qa-report enumerates ALL `@Service` / `@Component` / hand-authored `@Repository` classes in EVERY bounded-context `.internal` package and classifies each per DEC-58 Clauses A/C/D. Other-context violators surface in qa-report Notes — fix is FOLLOW-UP STORY scope, not this Story (per DEC-58 Implementation § bounded-scope clause).

For each violator, the interface-extraction is classified:

- [ ] **AC-ERROR-DEAD-CODE-DELETION-FALLBACK**: If `PhasePreparationService` is determined dead per DEC-55 D-10 (option (b) of AC-TEST-INTERFACE-EXTRACTED-PHASEPREPARATIONSERVICE), the deletion path's error-handling: any caller in production code is verified-absent before deletion. - [ ] **AC-ERROR-AOP-PROXY-SHIFT-DETECTION**: AOP-proxy semantic shift from CGLIB (subclass-based) to JDK Proxy (interface-based) on the impl classes is the expected outcome of interface extraction. If any existing test breaks due to this shift (e.g., `equals` / `hashCode` semantics, final-method overrides), the breakage is the empirical signal of a Q-1b → Q-1a reclassification. Delivery responds by: (a) reclassifying that specific refactor as Q-1a, (b) authoring fresh-RED-first per DEC-22, (c) GREEN commit fixing the proxy-related test break. Silent test-skip is NOT acceptable.
