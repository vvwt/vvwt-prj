# Story E23S08: Q-1a TDD-extract `CertificateAssembler` public interface + Q-1b relocate impl to `certificate.internal.DefaultCertificateAssembler` (with `CertificatePlacementRow` + `AvatarPlacement` records on public type-surface)

## User Story

**As a** maintainer of the newly-relocated `de.vvwt.tm.certificate` module,
**I want** the concrete `CertificateAssembler` (currently at legacy
`de.vvwt.tm.infrastructure.print.*` and refactored at E23S03 to inject
PhotoUrlBuilder) extracted into a PUBLIC interface at
`de.vvwt.tm.certificate.CertificateAssembler` via TDD RED-first, with the
impl relocated and renamed to `certificate.internal.DefaultCertificateAssembler`
per DEC-35 naming canon,
**so that** certificate exposes its renderer port cleanly (consumed
cross-module by PrintController in E24 / the Cutover-2 FQN-rewrite), value
objects `CertificatePlacementRow` + `AvatarPlacement` sit on the interface
type-surface (DEC-35 VOs crossing module boundaries), and certificate
architecture is DEC-35-compliant post-cutover.

---

## Context

Per Brief v4 D-15, CertificateAssembler-refactoring splits into TWO distinct
changes:
(1) Q-1a interface-extraction: NEW interface `de.vvwt.tm.certificate.CertificateAssembler`
    authored TDD RED-first per DEC-22 Iron Law. Existing concrete class is
    `@Service`-annotated at legacy `infrastructure.print.*` (methods `getFinalPhase`,
    `computePlacementOrder`, `buildSvgRows`, `buildHtmlRows`, `renderSvgTemplate`,
    `toMustacheMap`, `resolveLocationDisplayName`, `fetchPhotoAsBase64DataUri`,
    `buildPhotoUrl`, + nested `AvatarPlacement` record).
(2) Q-1b impl-relocation: `infrastructure.print.CertificateAssembler` moves
    to `certificate.internal.DefaultCertificateAssembler`.

Per Brief v4 D-13 (C2=β): `resolveLocationDisplayName(UUID tenantId)` method
is being MOVED out of CertificateAssembler entirely — the migration to
PrintController is an E23S10 concern. IN THIS STORY: the method remains on
CertificateAssembler's surface (present on both the extracted interface and
impl). The removal happens at Cutover-2 (E23S10) when PrintController gains
the SQL + JdbcTemplate Q-1a.

Story-ordering per Brief v4 D-15: "Interface-Extraction + RED-Test MÜSSEN vor
Impl-Relocation-Commit landen (innerhalb der Story)." Two sequential commits
within this story (or two stages of a single PR).
