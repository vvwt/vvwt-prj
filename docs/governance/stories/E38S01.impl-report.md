# Implementation Report — E38S01

## Summary

Bootstrapped three new Maven submodules under `vvwt-prj`:
- `vvwt-info-dto` — pure Java 21 contract (Jackson + Bean Validation API, no Spring/JPA)
- `vvwt-info-server` — Spring Boot application with dual `self-host`/`primary` profiles, Maven Enforcer bannedDependencies, startup assertion for DEC-42 D3, durable Enforcer negative-test IT
- `vvwt-info-client` — Svelte 5 + TypeScript 5 + Vite SPA scaffold, frontend-maven-plugin wired

Plus:
- `vvwt-tm-web` gains `vvwt-info-dto` dependency (AC4, DEC-42 D2 allowed edge)
- Enforcer rule on `vvwt-tm-web` banning `vvwt-info-server` and `vvwt-info-client` (AC7)
- `.gitignore` updated for `vvwt-info-client` node_modules and dist

## TDD Cycle Log (DEC-22 Iron Law)

### AC1 — RED-first existence tests

| Module | Test class | RED state | GREEN state |
|--------|-----------|-----------|-------------|
| vvwt-info-dto | `InfoDtoModuleExistsTest` | Module dir + pom absent → compile failure | After pom.xml + package-info.java created |

Running `mvn test -pl vvwt-info-dto` with only the test file present (no pom) produced: `Child module ... pom.xml does not exist` — this is the RED state evidence.

Spring log output confirms GREEN state: `No active profile set, falling back to 1 default profile: "self-host"`

### AC9 — BannedDependencies Enforcer IT (DEC-22 iteration 3)

| Test | RED state | GREEN state |
|------|-----------|-------------|
| `BannedDependenciesEnforcerIT.enforcerRejectsFixturePomWithForbiddenDependency` | Initial attempt used `enforcer:enforce` CLI goal which bypasses lifecycle bindings (exit 1 but wrong error: "No rules configured") | After switching to `validate` phase goal; Enforcer fires via lifecycle binding |
