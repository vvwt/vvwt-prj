# Story: Fix — single-certificate print produces a two-page PDF (Chromium content overflow + Firefox trailing empty page) instead of one A4-landscape page; force fixed A4 dimensions inside `@media print`

## User Story

**As a** tournament organizer who clicks Print in the browser on
`/certificate/tournaments/{tid}/print/{teamId}`,
**I want** the browser to produce exactly one A4-landscape page per
certificate (and N pages for a batch print of N teams),
**so that** I can hand out Urkunden without the footer landing on a
phantom second page (Chromium) or a blank trailing page being appended
(Firefox).

---

## Root Cause Analysis

Empirically isolated in Discovery via headless Chromium
(`chromium --headless --print-to-pdf …`) + `pdfinfo` page-count assertions
on a stripped-down render of the same Mustache template with mock values.

**Test matrix (Discovery session, 2026-05-31):**

| Variant | Pages | Conclusion |
|---|---|---|
| baseline (unmodified `_certificate_styles.mustache`) | **2** | Bug reproduced |
| H-2 only (`page-break-after: always` + `break-after: page` removed from `.page`) | **2** | H-2 refuted as the Chromium-primary cause |
| H-4 only (body `display: block !important; min-height: 0 !important` injected for print) | **2** | H-4 insufficient alone |
| Forced-dim only (`.page { width: 297mm !important; height: 210mm !important; aspect-ratio: auto !important; padding: 12mm 18mm 10mm !important }` in `@media print`) | **1** | **Minimal sufficient fix for Chromium** |
| Full (forced-dim + body override + page-break-after auto) | **1** | Works |

**Verified Chromium root cause (H-3, CONFIRMED empirically):**

The `.page` block on `_certificate_styles.mustache:44` declares
`container-type: inline-size`, and the page itself and downstream
descendants (`.hero`, `.placement`, `.photo-wrap`) declare layout sizes in
`cqh` units (`_certificate_styles.mustache:46, 83, 97, 115`). Per CSS
Containment, `cqh` (block-direction container query unit) only resolves
against the container when the container's `container-type` includes
`size`; under `inline-size`, `cqh` falls back to the *small-viewport*
height. In the screen-rendering context the viewport is the operator's
browser window; in the print-rendering context the viewport is the
print's A4-landscape page. The viewport heights differ, the `cqh`-based
padding evaluates to a different absolute value, and the cert content's
flex-stacked vertical sum exceeds the `.page`'s aspect-ratio-derived
height. `aspect-ratio: 1684/1191` (line 40) is then ignored — per CSS spec,
`aspect-ratio` is a *preferred* ratio and yields when intrinsic content
forces the element taller. The cert overflows the page; the footer lands
on a second page.

**Verified Firefox-specific surface (H-2, observation-anchored — Firefox
headless not driven by Discovery, so the user's screenshot is the
empirical anchor):**

`_certificate_styles.mustache:47–48` declares
`.page { page-break-after: always; break-after: page; }`. On a
single-certificate print, this applies to the only/last `.page`. Chromium
absorbs the trailing forced break; Firefox emits it as an additional
blank page. Confirmable post-fix by the operator on Firefox: if Firefox
still produces `1 von 2` after the Chromium-primary forced-dim fix is
deployed, the additional `:not(:last-child)` guard on the
`page-break-after` rule is the secondary fix surface.

**Combined fix shape** (Delivery decides exact CSS but the AC2 surface
locks the structural contract):

In the existing `@media print { … }` block at
`_certificate_styles.mustache:146–151`, add:

```css
@media print {
  body { display: block; min-height: 0; align-items: initial; justify-content: initial; }
  .stage { width: 297mm; }
  .page { width: 297mm; height: 210mm; aspect-ratio: auto; padding: 12mm 18mm 10mm; }
  .page:last-child { page-break-after: auto; break-after: auto; }
  /* existing rules: body { background: white; padding: 0 }; .stage { width: 100% }; .page { box-shadow: none; border-radius: 0 }; @page { size: A4 landscape; margin: 0 } — preserved */
}
```

The fix replaces `cqh`-based padding with literal millimetre values for
print only; preserves screen rendering unchanged (the existing
`container-type: inline-size` and `cqh` units are only active outside
`@media print`); guards the page-break-after rule from emitting trailing
forced-breaks; and prevents the screen-mode flex centering + `min-height:
100vh` from contaminating the print layout. The literal `12mm 18mm 10mm`
padding mirrors the screen rendering's `5cqh 7cqw 4cqh` proportions
against an A4-landscape page (210 mm × 297 mm: `5% × 210 = 10.5 mm`,
`7% × 297 = 20.8 mm`, `4% × 210 = 8.4 mm`); Delivery may fine-tune the
exact millimetre values per AC1's visual attestation while keeping the
fixed-mm structural contract.

**Why this slipped past E46S04** (certificate Mustache + CSS author):
E46S04's qa-attestation was screen-render visual review on the developer
machine — the print divergence only surfaces when the browser switches
to print layout, which the qa flow did not exercise. No automated
print-output test surface exists in the project (per memory
`project_scoring_tablet_test_surface` — score/field.mustache has the
same limitation).

## Out of Scope

- **`jdk.localedata` jlink module fix** — separate bug-triage story
  E12S10; independent root cause (production-only locale-data
  absence), independent change surface (jlink module list in
  `vvwt-tm-web/pom.xml`).
- **Other Mustache templates** — `templates/print/laufzettel.mustache`,
  `templates/score/field.mustache`, `templates/print-header.mustache`,
  `templates/print-page-break.mustache` and the static
  `static/print/assets/print.css` are not modified. The `.page-break`
  CSS gap in the certificate render path (the certificate templates
  include `print-page-break.mustache` but do not load
  `static/print/assets/print.css` where `.page-break` is defined —
  documented in Brief O-7) is **not** repaired in this story; the
  combined fix above (forced-dim per-page + `:last-child` guard)
  makes that gap behaviourally irrelevant for the certificate render
  path because the `.page { page-break-after: always }` rule already
  drives the page breaks on its own. A separate hygiene story may
  remove the dead `print-page-break.mustache` include later.
- **`DefaultCertificateAssembler` Java code** — including the HTML-row
  hardcode of `Locale.GERMAN` at
  `DefaultCertificateAssembler.java:277` (separate bug, deferred per
  E12S10 § Out of Scope), the unused `resolveLocaleForRow` private
  method (same), and any other Java-side change.
- **`CertificateRenderController` Java code** — endpoints, model
  population, override parameters, security pattern unchanged.
- **`messages.properties` label values** — the German tom.label.*
  values stay unchanged; the print layout fix is locale-text-neutral.
- **`LocaleResolver` chain** — unchanged.
- **SVG certificate path** — the SVG branch in
  `CertificateRenderController.singleCertificate` /
  `allCertificates` (the per-template SVG byte-response /
  per-template ZIP archive) is unaffected by this story; SVG
  certificates do not pass through the HTML `@media print` CSS.
- **Browser-side print preferences** — DPI, paper colour, scaling
  override, header/footer toggle — operator-driven, not in the
  rendered HTML's scope.
- **Headless-Chromium CI integration test** — operator decision in
  Discovery session 2026-05-31: build-portability cost of adding
  chromium + its system deps to `mvn verify` outweighs the
  regression-guard benefit. The Mustache-render guard in AC2 plus the
  impl-report attestation in AC1/AC4 are the canon for this story
  (per memory `project_scoring_tablet_test_surface`).
- **`@page { size: A4 landscape; margin: 0 }`** — existing rule
  retained; the fix is additive to the existing `@media print` block,
  not a replacement of the `@page` declaration.
- **Container query refactor** — Discovery considered replacing
  `container-type: inline-size` with `container-type: size` for the
  whole template; rejected as scope-creep (would also change screen
  rendering layout in ways the operator did not request). The
  print-only `aspect-ratio: auto` override is sufficient.
