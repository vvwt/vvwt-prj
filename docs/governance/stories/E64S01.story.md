# Story: Phase overview shows the game mode as a German label

## User Story

**As a** tournament organizer,
**I want** the phase-overview "Spielmodus" column to show each game mode in plain German,
**so that** I can read the phase plan without decoding technical identifiers.

---

## Context

In the phase overview (Phasenübersicht), the "Spielmodus" column shows raw registry keys —
`roundRobin`, `awardCeremony` — instead of German text. In `PhaseList.svelte` the column
cell renders `formatGameMode(phase.gameMode)`, and `formatGameMode` returns the
`phase.gameMode` string unchanged (it only maps a null/absent value to "—"). The adjacent
"Status" column in the same table already renders correctly through i18n with a
default-fallback lookup — so the defect is an inconsistency inside the one component.

`phase.gameMode` carries a match-generator **registry string-key** (per DEC-73 — the
`GameMode` enum was removed in favour of registry string-keys). The German display labels
for those keys **already exist** in the `de.json` catalogue under `matchOption.generator.*`
(`roundRobin` → "Jeder gegen Jeden", `awardCeremony` → "Siegerehrung") — added when DEC-73
D-7 anglicized the i18n message keys. This story only needs to route the game-mode value
through that existing catalogue; it adds no key and changes no translation value.

---

## Acceptance Criteria

- [ ] AC1 (testing): TDD per DEC-22 — a failing test for the game-mode→German-label
  mapping is authored before the production change. The mapping is tested directly at the
  logic level; mounting the Svelte component is **not** required (Svelte 5 component
  mounting is infeasible in the project's current Vitest+jsdom environment — a pre-existing
  gap documented by E58S05, out of this story's scope).
- [ ] AC2: In the phase-overview "Spielmodus" column, each game mode is displayed as its
  German label sourced from the existing `de.json` `matchOption.generator.*` entries — a
  `roundRobin` phase shows "Jeder gegen Jeden", an `awardCeremony` phase shows
  "Siegerehrung". No raw registry key is shown for a game mode that has a catalogue entry.
- [ ] AC3 (governance): the label lookup uses the project's canonical
  fallback-aware i18n pattern — `$_(`matchOption.generator.${value}`, { default: value })`
  or an equivalent that supplies a default. A game-mode key that has no catalogue entry
  degrades to showing the key string itself — never a blank cell and never a runtime
  error. A null or absent game mode still renders "—" (the current defensive behaviour of
  `formatGameMode` is preserved).
- [ ] AC4: at delivery, the phase-overview rendering is audited so that no raw game-mode
  registry key is visible anywhere in it. This AC is satisfied by the rule (no raw key
  surfaces), not by matching a fixed key list — the registered game-mode set is whatever
  the match-generator registry currently exposes.
- [ ] AC5 (governance): no game-mode registry key is renamed and no `de.json` translation
  **value** is added or changed — the story only consumes existing `matchOption.generator.*`
  keys (DEC-73 D-7 — translation values are not renamed; §Scope — no `draft_json` migration).
  The frontend stays Vite + Svelte + TypeScript, no SvelteKit
  (DEC-2). `mvn verify` is BUILD SUCCESS for `vvwt-tm-web`, including the frontend build
  via `frontend-maven-plugin` (DEC-54).

> All acceptance criteria must be verifiable.

---

## Out of Scope

- Adding, renaming, or removing any game-mode registry key, or changing any German
  translation value — the `matchOption.generator.*` entries already exist and are used
  as-is (DEC-73 D-7 + §Scope).
- Any other phase-overview column or any other page — only the "Spielmodus" cell rendering
  changes.
- Fixing the project's infeasible Svelte-5 / Vitest+jsdom component-mount test environment
  (pre-existing gap, E58S05).

---

## Dependencies

- None — the `matchOption.generator.*` catalogue entries already exist (delivered with
  Epic E58, `done`). Independently deliverable.
- DEC-73 — the governing decision: game modes are registry string-keys; the
  `matchOption.generator.*` i18n keys are the canonical German labels.

---

## Notes

The fix mirrors a pattern already present one line away in the same component — the
"Status" column resolves its value through i18n with a default fallback, while the
"Spielmodus" cell does not. Delivery decides the exact testable seam (e.g. the game-mode→
label mapping as a directly-callable unit); the AC states the behaviour, not the test
mechanism, because component mounting is infeasible in the project's test environment
(E58S05).
