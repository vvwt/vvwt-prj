# Story E35S02: Reconstruct identity package — TDD + WorkerKeyManager interface extraction + consumer fan-out

## User Story

**As a** Delivery Agent (and the human reviewing the reconstruction),
**I want** the `de.vvwt.worker.identity.WorkerKeyManager` class fully TDD-reconstructed under DEC-22 Iron Law, with interface extraction (`WorkerKeyManager` interface in package root + `DefaultWorkerKeyManager` impl in `.internal` per the new G3 inline conventions sub-section, by-analogy from DEC-35), and all 4 sibling-module consumers updated under DEC-22 RED-first for any new wiring,
**so that** the only stateful service in `vvwt-worker-lib` (per Brief O-13 β-trigger classification) carries proper DEC-22 RED-first provenance, supports clean cross-package test mocking per DEC-36, and the conventions canon for non-Spring interface extraction has its first concrete instantiation in the codebase.

---

## Context

`WorkerKeyManager` (`vvwt-prj/vvwt-worker-lib/src/main/java/de/vvwt/worker/identity/WorkerKeyManager.java`, 425 LOC) is the ONLY β-trigger class in `vvwt-worker-lib` per Brief O-13 — `public class` with instance fields (`Path dataDir`, `Path privateKeyPath`, `Path publicKeyPath`, `Logger logger`) and constructor-injected collaborators (`WorkerKeyManager(Path dataDir, Logger logger)`). It is the only class in the module that benefits structurally from interface extraction (test mockability for file-system collaborators, DEC-36 cross-package mocking from 4 sibling modules).

This story executes DEC-22 § item 1 (Iron Law) for new identity-package code (interface + Default impl + tests + any consumer-side updates) per Brief C-1 / C-11. Utility-package production code is OUT OF SCOPE per Brief T-7 X-scoping (DEC-22 § item 5 grandfather).

The new G3 inline conventions sub-section "Module Package Layout — Non-Spring Modules (analogy from DEC-35)" is added to `patterns/conventions.md` in this story as a SKELETON (rule statement + DEC-35 by-analogy citation). E35S04 finalizes it with the concrete `WorkerKeyManager` / `DefaultWorkerKeyManager` example once this story is merged.

## Acceptance Criteria

- [ ] **AC1 — RED-first TDD reconstruction of `WorkerKeyManager` per DEC-22 Iron Law (RED-first per § Decision item 4, activated project-wide per § item 1).** All new tests for the reconstructed `WorkerKeyManager` (now in form of `WorkerKeyManager` interface + `DefaultWorkerKeyManager` impl) demonstrably go RED before GREEN. The impl-report MUST cite per-test RED state (test name + the ABSENT or MINIMAL implementation state under which it was red) for every new test method. No method on `DefaultWorkerKeyManager` may be implemented before its corresponding test is RED. (Testing, governance.)

- [ ] **AC2 — Interface extraction per G3 inline conventions (DEC-35 by-analogy).** `WorkerKeyManager` becomes a public interface in `de.vvwt.worker.identity` (package root) declaring all methods previously public on the legacy class. `DefaultWorkerKeyManager` is a class in `de.vvwt.worker.identity.internal` (NEW sub-package) implementing the interface. Constructor injection of `Path` + `Logger` collaborators preserved. Naming canon: no `I`-prefix per DEC-35 / G3 sub-section (DEC-35 § naming canon does not mandate `final` on the impl class; the implementer may add `final` if no subclass extension is anticipated, but it is not required by the canon). The `de.vvwt.worker.identity.internal` sub-package is created in this story. **FQN preservation:** the new interface KEEPS the legacy FQN `de.vvwt.worker.identity.WorkerKeyManager` — consumer-side TYPE references (e.g., `import de.vvwt.worker.identity.WorkerKeyManager;` declarations, field/parameter type declarations) compile UNCHANGED across the 4 sibling modules; only constructor-call sites (`new WorkerKeyManager(...)`) require updates per AC4. (Governance.)

- [ ] **AC3 — `patterns/conventions.md` SKELETON sub-section authored.** A new sub-section titled `### Module Package Layout — Non-Spring Modules (analogy from DEC-35)` is added to `patterns/conventions.md` BELOW the existing `### Web-Tier-as-Module (DEC-40)` sub-section. The skeleton states the rule by-analogy: "When interface extraction is performed in a non-Spring `vvwt-prj` module, follow the DEC-35 naming canon by analogy: `{Foo}` interface in package root, `Default{Foo}` impl in `.internal` sub-package; same `I`-prefix prohibition applies." The skeleton cross-references DEC-35 and notes "Concrete example to be added in E35S04 once `DefaultWorkerKeyManager` is merged." Length target: 8–15 lines. E35S04 enriches with the concrete example. (Governance.)

- [ ] **AC4 — Consumer fan-out across 4 sibling modules under DEC-22 Iron Law (per § Decision item 4 RED-first).** Per AC2 FQN preservation, type-reference imports continue to compile unchanged. The implementer enumerates and updates per consumer module ONLY the call sites that genuinely change: (i) constructor-call sites (`new WorkerKeyManager(...)` → `new DefaultWorkerKeyManager(...)` with import of `.internal.DefaultWorkerKeyManager`, OR migration to factory/DI injection of the interface), (ii) any other call sites whose signature changed under D2 (Brief D-6 allow-signature-changes). For ANY new consumer-side test or production-code addition required by the wiring update, the implementer follows DEC-22 § item 4 RED-first. The impl-report enumerates per consumer module: (i) constructor-call sites updated (file:line), (ii) signature-driven updates (file:line + reason), (iii) any new tests added (file:line + RED state evidence). If a consumer requires no code change (no constructor calls, no signature-driven changes), the impl-report explicitly states "no production code added → DEC-22 § item 4 not triggered" with the reasoning. **Blast-radius note:** because the interface keeps the legacy FQN, the consumer-side change is bounded to constructor-call sites — typically a small fraction of total references; the impl-report enumeration makes this concrete. (Testing, governance.)

- [ ] **AC5 — DEC-36 cross-package mocking in consumer-side tests.** Any new or updated consumer-side test in vvwt-dispatcher / vvwt-benchmark / vvwt-standalone-worker / vvwt-tm-web that mocks `WorkerKeyManager` MUST mock the `WorkerKeyManager` interface, NEVER `DefaultWorkerKeyManager` (the cross-package mocking rule per DEC-36 § Decision). Same-package tests in `de.vvwt.worker.identity.internal` MAY white-box `DefaultWorkerKeyManager`. The impl-report enumerates each new test class with its mock target. (Testing, governance.)

- [ ] **AC6 — Atomic cutover commit deletes legacy `WorkerKeyManager` production code at the same commit as the new interface + Default impl + consumer updates land.** The legacy concrete `WorkerKeyManager` class in `de.vvwt.worker.identity` (the original 425-LOC `public class`) is deleted in the same commit as the new interface (in package root) + `DefaultWorkerKeyManager` (in `.internal`) + consumer updates. No coexistence; no `@Deprecated` wrapper; no parallel-code window. (DEC-21 atomic-cutover principle applied here even though DEC-21 itself is Spring-Modulith-anchored — the principle preserves consumer-graph atomicity.) (Governance.)

- [ ] **AC7 — DEC-41 audit-classification check on any reused tests.** If E35S01 audit (`AC2 / AC3`) classifies any pre-existing `WorkerKeyManagerTest` (or any other identity-package test) method as Spec-Anchored AND the implementer reuses it as a Contract Test against `DefaultWorkerKeyManager`, the impl-report MUST include the DEC-41 audit-classification table per `patterns/conventions.md` § "Spec-Anchored Test Reuse (DEC-41)" — naming the test (file path + method name) + qualifying observable criterion (a/b/c/d) + criterion evidence. Per DEC-41 § hierarchy clause 3, NO Snapshot-Driven test from `WorkerKeyManagerTest` may be reused — those are replaced with fresh TDD tests under AC1. (Testing, governance.)

- [ ] **AC8 — `mvn verify` green across vvwt-worker-lib + 4 consumer modules at the cutover commit.** `mvn -pl vvwt-worker-lib,vvwt-dispatcher,vvwt-benchmark,vvwt-standalone-worker,vvwt-tm-web -am verify` (or equivalent) produces BUILD SUCCESS at the cutover commit. The `ban-spring-boot-in-worker-lib` enforcer rule remains green (no Spring imports added). DEC-29 `failOnWarning=true` and DEC-30 `spotless:check` both pass. (Testing.)

- [ ] **AC9 — Concurrency contract documentation in scope per Brief Deferred limitation.** The implementer EXPLICITLY states in the impl-report whether `WorkerKeyManager` reconstruction surfaces a need for explicit concurrency contract documentation (e.g., key-rotation race conditions, file-lock semantics for the key-pair files). If no, state "no concurrency contract change identified during reconstruction" with the reasoning. No follow-up-DEC blanket pre-authorization (per Brief Deferred limitation). (Governance, testing.)

- [ ] **AC10 — Commit & push to vvwt-prj `staging`.** All edits committed in atomic commits per the cutover protocol; the cutover commit titled `feat(E35S02): reconstruct WorkerKeyManager via TDD — interface extraction + DefaultWorkerKeyManager + consumer fan-out`.
