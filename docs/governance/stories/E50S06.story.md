# Story: Display SPA Overview — vertical-fill regression: `OverviewLayout` grid-row placement defect (E50S05 follow-up)

## User Story

**As a** tournament operator and a member of the venue audience watching the public Display screen,
**I want** the court grid and the group-standings sidebar to fill the full height of the screen,
**so that** the overview uses the whole display and the round rows are large enough to be read from across the venue.

---

## Context

`/display/overview` does not fill the screen vertically. On an operator screenshot from 2026-05-15, the court grid (`Feld 1 / Feld 2 / Feld 3` columns with round rows) **and** the group-standings sidebar both stop at roughly half the viewport height, leaving the lower half empty grey space.

The vertical-fill defect persists despite two prior fixes:

- **E50S04** (PR #254, 2026-05-10) introduced multi-round display + vertical-fill + active-round highlight.
- **E50S05** (PR #269, 2026-05-12) fixed a vertical-fill regression by adding a row-distribution mechanism to `.court-grid__body` inside `CourtGrid.svelte`.

E50S05's fix is real but addresses **one CSS level too low**. The controlling defect is one level up, in `OverviewLayout.svelte`.

**Empirical root cause** (verified at HEAD — the Display SPA has had no commit since E50S05 merged, so this is not a new regression; E50S05's fix never reached the observed scenario): `OverviewLayout.svelte`'s root element `.overview-layout` is a CSS grid with `grid-template-rows: auto 1fr`. The `auto` row is intended for the optional `{#if phaseData.preparationPreview}` preview banner; the `1fr` row is intended for the two content children `.overview-layout__main` (court grid) and `.overview-layout__sidebar` (standings). But **neither child carries an explicit `grid-row` placement.** When the preview banner is absent — which is the case for every ACTIVE phase, the normal running-tournament state — CSS grid auto-placement puts both children into **row 1 (`auto`, content-sized)**, and the `1fr` row stays empty. Both columns therefore collapse to content height, leaving the lower half of the screen blank — exactly matching the screenshot, where the court grid and the sidebar both stop at the same mid-screen height.

The definite height chain is intact down to `.overview-layout` (`body 100vh → #app 100vh flex-column → .display-app flex:1 → .overview-layout height:100%`); the break is the auto-placement of `__main` / `__sidebar` into the `auto` track.

**Why this keeps recurring — the test gap.** E50S04's vertical-fill test was a source-inspection regex over `.svelte` text; E50S05's was a jsdom CSSOM-property assertion. **Neither exercises a layout engine** — jsdom computes no layout — so neither can detect that the rendered page fails to fill the viewport. The defect has now passed `mvn verify` twice. This is the recurring DEC-54 / E48S11 false-PASS class. Per the human decision for this story, the regression test must verify the **rendered** layout in a **real browser layout engine** — a structurally layout-blind test does not satisfy the DEC-54 gate for this defect.

This story is pure frontend. The orthogonal active-round-highlight defect (the current round is not highlighted) is a separate backend story, **E56S01**, and is not touched here.

## Acceptance Criteria

### Testing (DEC-22 RED-first; DEC-54 `mvn verify` gate; real browser layout engine)

- [ ] **AC-TEST-VERTICAL-FILL-REAL-ENGINE-RED**: A RED-first regression test renders `/display/overview` (or the `OverviewLayout` component) in a test environment that **computes layout geometry** (a real browser layout engine), with a fixture representing a banner-absent (ACTIVE) phase, and asserts that the court grid and standings sidebar **fill the viewport height** — i.e. the content area is not collapsed to content-height with empty space below it. The measurement technique and assertion API are a Delivery HOW decision. The test MUST fail on current HEAD and pass after the fix; the RED commit precedes the GREEN commit in `git log`. A source-inspection or jsdom-CSSOM-only test does NOT satisfy this AC — jsdom computes no layout, which is precisely why the defect twice escaped.
- [ ] **AC-TEST-VERTICAL-FILL-BANNER-PRESENT-GREEN**: A test asserts that with the preview banner present (a `preparationPreview` phase fixture) the layout **also** fills the viewport — the fix must make `__main` / `__sidebar` fill regardless of whether the banner row is rendered. This is a non-recurring guard case; its test mechanism is a Delivery HOW decision and need not use the real-layout-engine harness (a structural assertion is acceptable here — the real-layout-engine requirement of AC-TEST-VERTICAL-FILL-REAL-ENGINE-RED applies specifically to the banner-absent defect).
- [ ] **AC-TEST-EXISTING-DISPLAY-TESTS-GREEN**: The existing `CourtGrid` / `OverviewLayout` / `App` test cases from E50S03 / E50S04 / E50S05 (including the `.court-grid__body` row-distribution assertion and the `noPhase` / loading-state tests) remain GREEN. Regression guard — the `OverviewLayout` fix must not regress the `CourtGrid`-level fix E50S05 already shipped.
