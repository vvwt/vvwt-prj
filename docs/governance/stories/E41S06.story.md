# Story E41S06: Integration tests + observability + final assembly (end-to-end smoke against running dispatcher; structured-log assertions; exit-code matrix; reactor mvn verify GREEN)

## User Story

**As a** maintainer of E41 ensuring the greenfield slot-opt-standalone-worker actually interoperates end-to-end with the delivered E37/E40 dispatcher,
**I want** an integration test suite that launches the worker against a running dispatcher (or a high-fidelity test-double), exercises the full path (algorithm announcement query → register-key → poll-packet → process → submit-result), asserts structured-log events on each happy-path stage and on each error-handler path, AND verifies the exit-code matrix matches E37S02 spec § (c),
**so that** the Epic closure is independently demonstrable: a single end-to-end test exercises everything E41S01–S05 produced, AND all spec § (c) Observability + Exit Codes contracts are explicitly verified.

---

## Context

Per Brief D-1 + D-9: E41S06 is the closure / integration story. All E41S01–S05 must be `done` before this story starts (per `depends_on` chain).

Per E37S02 spec § (c): "Observability" sub-section enumerates event types (e.g., `worker_started`, `algorithm_picked`, `key_registered`, `packet_pulled`, `result_submitted`, `algorithm_deprecation_warning`, `worker_stopped`). "Exit Codes" sub-section defines the worker's exit-code matrix (e.g., 0 = graceful, non-zero values for various error categories).

Per Brief Q-3: greenfield TDD discipline — integration test asserts spec-conformance, NOT legacy-parity.

This story does NOT add new production logic to the worker; it adds integration test infrastructure that exercises E41S01–S05 production code in concert.

### Story-specific ACs

- [ ] **AC-INTEGRATION-TEST-HAPPY-PATH**: An integration test (`de.vvwt.slotopt.standalone.integration.HappyPathIT`) that:
  - Starts a high-fidelity dispatcher test-double (e.g., MockServer or WireMock) configured with the delivered E37/E40 endpoints (`GET /api/algorithms`, `POST /api/register-key`, `POST /api/pull-packet`, `POST /api/submit-result`)
  - Launches `OptimizerWorkerMain` in-process or as a sub-process with valid CLI args
  - Asserts: algorithm announcement queried (HTTP request observed); register-key invoked with `algorithm: "Ed25519"`; pull-packet invoked with `supportedAlgorithms: ["Ed25519"]`; submit-result invoked with `algorithm: "Ed25519"` + valid signature
  - Asserts: worker exits with code 0 after configurable shutdown signal
- [ ] **AC-INTEGRATION-TEST-DEPRECATION-WARNING**: An integration test (`DeprecationWarningIT`) that:
  - Starts dispatcher test-double with `Ed25519` having `deprecation_date` in the future
  - Launches worker
  - Asserts: stderr contains `"WARNING: Signature algorithm 'Ed25519' will be deprecated on <date>"` line
  - Asserts: WARN-level log event with structured field `event=algorithm_deprecation_warning`
  - Asserts: worker continues running (no exit)
- [ ] **AC-INTEGRATION-TEST-DEPRECATION-FAIL**: An integration test (`DeprecationFailIT`) that:
  - Starts dispatcher test-double with `Ed25519` having `deprecation_date` in the PAST (already deprecated)
  - Launches worker
  - Asserts: worker fails-fast at startup with explicit error log + non-zero exit code
- [ ] **AC-INTEGRATION-TEST-HTTP-410-AT-REGISTER**: An integration test (`Http410AtRegisterIT`) that:
  - Starts dispatcher test-double; configures algorithm announcement to show Ed25519 with future deprecation_date BUT returns HTTP 410 Gone on register-key (simulating a rare race-condition where deprecation deadline crosses between announcement query and register-key call — per DEC-43 D3 server-side enforcement at registration)
  - Launches worker
  - Asserts: worker logs ERROR + exits non-zero per E41S04 AC-EXIT-CODE-BOOTSTRAP "registration_rejected_deprecated" code
  Note: HTTP 410 at submit-result is NOT a DEC-43-specified path — DEC-43 D3 explicitly states "Signature verifications for pre-existing registrations using a now-deprecated algorithm continue to succeed." The 410 deprecation enforcement is at register-key only.
- [ ] **AC-INTEGRATION-TEST-DISPATCHER-UNREACHABLE**: An integration test (`DispatcherUnreachableIT`) that:
  - Configures dispatcher URL to an unreachable port (e.g., localhost:1)
  - Launches worker
  - Asserts: worker fails-fast at announcement-query step with explicit error log + non-zero exit
- [ ] **AC-OBSERVABILITY-EVENT-MATRIX**: An integration test (or assertion library) that verifies the union of events emitted by E41S04's AC-OBSERVABILITY-EVENTS-BOOTSTRAP (`worker_started`, `algorithms_announced`, `algorithm_picked`, `algorithm_deprecation_warning`, `key_registered`) AND E41S05's AC-OBSERVABILITY-EVENTS-RUNTIME (`packet_pulled`, `packet_processed`, `result_submitted`, `result_superseded`, `worker_stopped`) — total 10 distinct event types, each emitted at the appropriate moment in the worker lifecycle. The canonical authority for event-name conformance is E37S02 spec § (c) "Observability" — implementer reads spec § (c) verbatim and reconciles any discrepancy between sibling-story enumerations and the spec list (D-10 delivered-authoritative does NOT apply here since this is a brand-new spec section being implemented for the first time; the spec § (c) list is the canonical contract).
- [ ] **AC-EXIT-CODE-MATRIX**: An integration test (or table-driven matrix) that verifies the worker's exit-code matrix per E37S02 spec § (c) "Exit Codes". Each error category from the spec maps to a specific exit code. Implementer reads spec § (c) "Exit Codes" verbatim for the canonical matrix.
- [ ] **AC-FINAL-ASSEMBLY-SMOKE**: A final smoke test that runs the assembled worker JAR against a real dispatcher instance (if available in CI) — or against a high-fidelity test-double. Asserts: complete happy-path round-trip (announcement query → register → poll → process → submit → graceful shutdown) completes within a configurable time budget (e.g., 30 seconds for one packet).
