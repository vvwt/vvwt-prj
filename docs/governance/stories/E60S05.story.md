# Story: End-to-end live-worker verification + Epic closure

## User Story

**As an** operator of the slot-optimization service,
**I want** proof that a submitted job, solved by a real worker, yields the correct global
optimum end-to-end,
**so that** "the dispatcher works" is a demonstrated fact, not an assumption — and Epic E60
closes on evidence.

---

## Context

E60S01–S04 assemble the dispatcher's job-processing pipeline: decomposition wiring,
per-packet result retention, job finalization + cross-packet aggregation, and the queryable
result surfaces. Each of those stories verifies its own slice. This closing story verifies
the **whole chain** with a real worker, end to end, and closes the Epic.

The human-chosen verification bar for this work is "end-to-end with a live worker": a
submitted job, solved by the existing `vvwt-slotopt-standalone-worker` (a real worker
process / instance, not a stub), must produce the correct global optimum on query. E41S06
established the cross-process integration-test pattern against a running dispatcher; this
story applies it to the now-complete job pipeline.

The dispatcher itself does not submit jobs — `vvwt-slotopt-standalone-worker` only registers,
pulls, and submits packet results. The harness therefore needs a test job-submitter (a test
client) to play the submitting role.

This story also performs Epic closure: a final confirm-audit that the pipeline chain is
closed, verification of the Epic's Success Metrics, and DEC-31 propagation of the Epic and
story snapshots to the in-repo governance copy.

---

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-E2E-LIVE-WORKER** — a cross-process integration test demonstrates the full
  round trip: a test job-submitter submits a slot-optimization job to a running
  `vvwt-slotopt-dispatcher`; a live `vvwt-slotopt-standalone-worker` registers, pulls,
  solves, and submits packet results; the dispatcher decomposes, retains, finalizes, and
  aggregates; a job-status query then returns status `COMPLETED` with a `finalResult`. The
  harness mechanism is Delivery's choice (per the E41S06 cross-process IT precedent); the AC
  is the behavioural round trip.
- [ ] **AC-TEST-E2E-MULTI-PACKET-CORRECTNESS** — the end-to-end test exercises a job large
  enough to decompose into multiple packets, and asserts the finalized `finalResult` is the
  **global** optimum across all packets (lowest `bestScore`, tie lowest `bestRank`) — not
  any single packet's sub-range result. This is the multi-packet correctness the Epic
  exists to guarantee.
- [ ] **AC-TEST-REACTOR-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for the
  `vvwt-slotopt-dispatcher` module and the reactor build is GREEN (DEC-54); no
  pre-existing test regressed.

### Governance

- [ ] **AC-GOV-PIPELINE-CHAIN-CONFIRMED** — Delivery confirms at the delivery `HEAD` that the
  full `submit-job → decompose → pull → submit-result → finalize → query` chain is closed
  end-to-end; the qa-report records the confirmation.
- [ ] **AC-GOV-EPIC-SUCCESS-METRICS** — the qa-report verifies each Epic E60 Success Metric
  one-for-one against the delivered behaviour.
- [ ] **AC-GOV-GOVERNANCE-PROPAGATION** — per DEC-31, the Epic E60 artefact and the
  E60S01–S05 story snapshots are propagated to the in-repo governance copy under
  `vvwt-prj/docs/governance/` (additive snapshot; idempotent — byte-identical files are
  skipped). No new DEC is authored by Epic E60, so no decision file is propagated.
- [ ] **AC-GOV-NO-MODULE-BOUNDARY-BREACH** — the end-to-end test introduces no compile
  dependency from `vvwt-slotopt-dispatcher` on the Tournament Manager or any non-dispatcher
  production module; the dispatcher stays an independent deployable (DEC-11). The test
  job-submitter is test-scope code.
- [ ] **AC-GOV-BUILD-HYGIENE** — `mvn verify` exits zero (DEC-54); Java touches compile
  warning-free (DEC-29) and pass Spotless / google-java-format (DEC-30); no production
  member exists solely for tests (DEC-70); the end-to-end test is classified per DEC-41.
- [ ] **AC-GOV-COMMIT-FORMAT** — commit subjects use `chore(E60S05):` / `feat(E60S05):`
  prefixes per the close-story.sh contract.

### Error Handling

- [ ] **AC-ERR-NO-WORKER-NO-MISFINALIZE** — with no worker connected, a submitted job is
  decomposed and sits at `DECOMPOSED` indefinitely without error; the dispatcher does not
  crash and does not finalize a job whose packets are unsolved (no premature / empty
  finalization).
- [ ] **AC-ERR-SINGLE-PACKET-BOUNDARY** — a job that decomposes into exactly one packet
  finalizes correctly: the job optimum equals that single packet's result, the job reaches
  `COMPLETED`, and `finalResult` is exposed — the degenerate boundary of cross-packet
  aggregation.
- [ ] **AC-ERR-E2E-DETERMINISTIC** — the end-to-end integration test is deterministic: it
  contains no timing race that intermittently fails (it polls / waits on a condition rather
  than a fixed sleep), so a GREEN run is reproducible.
