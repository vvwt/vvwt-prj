# Story E24S04: Q-1a TDD RED-first NEW `tenant.LocationDisplayResolver` interface + `DefaultLocationDisplayResolver` impl + DEC-26-compliant DAO test (Rule 2 N/A read-path). Legacy PrintController UNTOUCHED.

## User Story

**As a** maintainer of `vvwt-tm-web` providing a tenant-scoped location-
display-name service for fresh web-module controllers (S05 + S06),
**I want** a new public `LocationDisplayResolver` interface at
`de.vvwt.tm.tenant.*` + `DefaultLocationDisplayResolver` impl at
`tenant.internal.*` (DEC-35 canon, DEC-26-compliant DAO test) authored
Q-1a TDD RED-first,
**so that** fresh S05 `CertificateRenderController` + fresh S06
`PrintController` can inject the service; legacy PrintController's
`resolveLocationDisplayName` in-class method + `JdbcTemplate` field remain
UNTOUCHED until S07 cutover (strict DEC-22 — legacy is frozen).

---

## Context

Per Brief v6 D-4 + D-7 (S04) + E-3a (LocationDisplayResolver in tenant —
placement decision validated by empirical `LocationContext` already existing
at `de.vvwt.tm.tenant.*` public interface).

Brief v6 diverges from Brief v5 on one critical point: **S04 does NOT
refactor legacy PrintController** to use the new resolver. Under strict
DEC-22 Seq-C, legacy at `infrastructure.print.*` stays UNTOUCHED. This
means:
- Legacy PrintController.resolveLocationDisplayName + JdbcTemplate field
  remain in-class through S01→S07.
- Legacy PrintControllerResolveLocationTest (E23S10-delivered) remains
  on disk through S01→S07.
- New LocationDisplayResolver is used ONLY by fresh S05 + S06 controllers.
- No "drift window" risk — legacy and fresh serve DIFFERENT controllers;
  each has its own single source-of-truth for display-name lookup.

At S07 atomic cutover, legacy PrintController + legacy
PrintControllerResolveLocationTest + legacy in-class method all DELETED
with the package.

DEC-26 Rule 2 N/A for read-path: resolver returns `String` value; assertion
is on returned value via assertj standard matchers, NOT assertj-db on
DB-state-post-write. Per DEC-26 § Rule 2 intent (post-write verification)
and matches legacy `PrintControllerResolveLocationTest` precedent.

## Acceptance Criteria

### Q-1a TDD RED-first resolver

- [ ] **AC-RESOLVER-REDFIRST-TEST**: New DAO test
  `de.vvwt.tm.tenant.internal.DefaultLocationDisplayResolverTest`
  (same-package white-box per DEC-36) authored BEFORE impl. Initial
  execution RED (class absent). Commit history RED → GREEN per DEC-22
  Iron Law.
- [ ] **AC-RED-SEMANTICS-ALPHA**: Brief v6 selects **interpretation α
  (compile-error-as-RED)** for Q-1a interface + impl reconstruction
  (matches E22 scoring precedent). Required commit sequence:
  (1) RED commit: test file exists; interface + impl both ABSENT →
      compile error (this IS the RED state);
  (2) GREEN commit: interface + impl both authored in same commit; test
      compiles AND passes.
  **NOT** interpretation β (interface-first then test RED then impl).
  Impl-report cites this α pattern + commit-SHA pair.
- [ ] **AC-RESOLVER-INTERFACE-CREATE**: New file at
  `vvwt-tm-web/src/main/java/de/vvwt/tm/tenant/LocationDisplayResolver.java`.
  **Behavioral contract** (NOT an implementation specification —
  implementer drives shape RED-first from AC-RESOLVER-REDFIRST-TEST):
  - **Visibility**: `public interface`.
  - **Package**: `de.vvwt.tm.tenant` (root, public surface).
  - **Method contract**: a single method that takes a tenant identifier
    of type `java.util.UUID` and returns a `java.lang.String` location
    display name. Method name `resolveLocationDisplayName` (matches
    legacy semantic; permits S05/S06 grep-locatable callsites).
  - **Return-value semantic**: empty string `""` when no location row
    exists for the tenant — NEVER throws an exception for absence.
  - **Javadoc requirements**: documents (i) purpose (tenant-scoped
    location display-name lookup for rendering); (ii) single-result
    semantics with empty-string-on-absence; (iii) NO DEC-39 interim-
    state note on the interface (that's implementation concern; lives
    on impl Javadoc per AC-DEC-39-TENANT-ID-PRESERVED).
  - Implementer chooses I-prefix-free naming, no defaults, etc.
- [ ] **AC-RESOLVER-IMPL-CREATE**: New file at
  `vvwt-tm-web/src/main/java/de/vvwt/tm/tenant/internal/DefaultLocationDisplayResolver.java`.
  **Behavioral contract** (NOT an implementation snippet):
  - **Visibility**: `public class` (impl visible to Spring DI, callable
    cross-package only via the interface per DEC-36).
  - **Package**: `de.vvwt.tm.tenant.internal` (DEC-35 `Default*` impl
    convention).
  - **Implements**: the public `LocationDisplayResolver` interface.
  - **Spring-managed**: registered as a Spring bean (e.g., via
    `@Service` stereotype or equivalent `@Component`-derivative).
  - **Persistence dependency**: consumes `org.springframework.jdbc.core.JdbcTemplate`
    via constructor injection (no field injection per project convention).
  - **SQL contract** (data specification — the single code-fragment
    permitted in this story per user direction):
    ```sql
    SELECT display_name FROM locations WHERE tenant_id = ? LIMIT 1
    ```
    Byte-equivalent to legacy SQL at
    `infrastructure.print.PrintController.java:1186`. DEC-39 interim-
    state — `tenant_id` predicate preserved until DEC-25 Big-Bang-Reset.
  - **Parameterization**: `tenantId` argument bound to the `?` placeholder
    via JdbcTemplate's parameterized API (no string concatenation).
  - **Return-value mapping**: returns the `display_name` column of the
    first (and only, due to `LIMIT 1`) returned row; returns empty
    string `""` when query returns no rows.
  - **Javadoc**: impl Javadoc carries the DEC-39 interim-state note +
    the SQL rationale; the interface stays clean of impl-detail.
  All shape decisions beyond the above (RowMapper style, lambda vs
  method-reference, exception propagation specifics) are implementer's
  call, driven RED-first by AC-RESOLVER-REDFIRST-TEST + AC-DAO-TEST-CASES.
