# Story E63S06: Leg-2 operator-cancel with Best-So-Far + DEC-49 delta-amendment

## User Story

**As a** tournament organizer waiting on a slow large-phase optimization,
**I want** to cancel a running dispatcher-path optimization and keep the best schedule found
so far,
**so that** I am never stuck waiting on the dispatcher and always end up with a usable phase.

---

## Context

DEC-49 gives the operator a per-tournament admin-cancel that applies the Best-So-Far result
— but only for the **in-process** path (Leg 3). For a **Leg-2** (dispatcher-path)
optimization there is no operator cancel at all. Worse: `RoutingSlotOptimizationClient.tryLeg2()`
registers no handle in `SlotOptimizationJobRegistry`, so today an operator cancel issued
while a Leg-2 optimization is running hits `SlotOptimizationCancelController`, finds no
active handle, and returns HTTP 409 `NO_ACTIVE_OPTIMIZATION` — the cancel never reaches the
Leg-2 job.

This story makes a Leg-2 optimization cancelable:

1. **Register the Leg-2 job as cancellable** — so the existing per-tournament cancel surface
   (`POST /api/slotopt/tournaments/{tid}/cancel` + the admin-UI cancel button + the DEC-64
   `phase_lifecycle_job.cancelled` flag + `CancelFlagRegistry`) resolves for a Leg-2 job.
2. **On cancel, interrupt the dispatcher poll** — `DefaultSlotOptimizationDispatcherClient`'s
   blocking `pollResult` poll stops waiting.
3. **Resolve the phase by the three-case Best-So-Far rule** — (1) cancel raced with
   completion (the dispatcher already finalized) → the normal Leg-2 final-result apply runs
   and the cancel is effectively a no-op; (2) the dispatcher exposes a partial `bestSoFar`
   (≥1 packet completed) → TM applies it; (3) the dispatcher has produced nothing → the
   phase keeps its existing valid L1+L2 assignment (the orchestrator's L1+L2 step always
   runs before slot-opt per DEC-56 — the phase is never unassigned).

On cancel TM **detaches** — the dispatcher job itself keeps running for the shared
structural-fingerprint cache; TM sends no abort.

This story authors a **DEC-49 delta-amendment** extending the D-11 / D-11a admin-cancel +
Best-So-Far semantics to the Leg-2 path.

## Acceptance Criteria

### Testing

- [ ] **AC-TEST-LEG2-JOB-REGISTERED-CANCELLABLE** — RED-first (DEC-22): while a Leg-2
  optimization is running, the job is registered such that an operator cancel for that
  tournament reaches it. The test fails on current `HEAD` (`tryLeg2` registers nothing → the
  cancel returns 409 `NO_ACTIVE_OPTIMIZATION`) and passes after the fix.
- [ ] **AC-TEST-CANCEL-INTERRUPTS-POLL** — an operator cancel during Leg 2 stops TM waiting
  on the dispatcher poll — the blocking `pollResult` loop is interrupted promptly.
- [ ] **AC-TEST-CANCEL-CASE-PARTIAL-BEST-SO-FAR** — case (2): when the dispatcher exposes a
  partial best-so-far at cancel time, TM applies it via `SlotResultApplicator`; the phase's
  matches reflect that best-so-far optimum.
- [ ] **AC-TEST-CANCEL-CASE-NO-RESULT** — case (3): when the dispatcher has produced no
  result at cancel time, the phase retains its existing valid L1+L2 assignment — it is never
  left unassigned.
- [ ] **AC-TEST-CANCEL-RACE-WITH-COMPLETION** — case (1): a cancel that arrives after the
  dispatcher has already finalized the job results in the normal Leg-2 final-result apply;
  the cancel is a no-op (not an error, not a regression of the applied result).
- [ ] **AC-TEST-DISPATCHER-JOB-NOT-ABORTED** — on cancel TM detaches and sends no abort /
  cancel request to the dispatcher; the dispatcher job is left to run for the shared cache.
- [ ] **AC-TEST-SUITE-GREEN** — `mvn verify` is BUILD SUCCESS for `vvwt-tm-web` (DEC-54).

### Error Handling

- [ ] **AC-ERR-CANCEL-NO-ACTIVE-OPTIMIZATION** — an operator cancel for a tournament with no
  active optimization (Leg 2 or Leg 3) still returns the existing defined response (the
  current 409-class `NO_ACTIVE_OPTIMIZATION` semantics) — this story does not regress the
  no-active-job path.
- [ ] **AC-ERR-BEST-SO-FAR-FETCH-FAILURE** — if fetching the dispatcher's best-so-far fails
  at cancel time, the phase is resolved by case (3) (retain the existing valid L1+L2
  assignment) — it is never left unassigned and the cancel never throws to the operator.
- [ ] **AC-ERR-PER-TOURNAMENT-CANCEL-SCOPE** — cancelling tournament A's Leg-2 optimization
  affects only tournament A; a concurrent optimization for tournament B is untouched
  (DEC-49 D-11 per-tournament scope).

### Security

- [ ] **AC-SEC-CANCEL-ENDPOINT-AUTHENTICATED** — the cancel endpoint remains admin-
  authenticated as today; this story introduces no new unauthenticated surface.
- [ ] **AC-SEC-NO-PII-IN-BEST-SO-FAR** — the best-so-far fetch carries only structural
  optimization data (a permutation rank); no team UUID / name / PII crosses the dispatcher
  boundary (DEC-9).

## Notes

The genuinely new part is that `tryLeg2()` must *register* the Leg-2 job as cancellable —
today it does not, so an operator cancel during Leg 2 returns 409. The operator surface and
the DEC-64 `phase_lifecycle_job.cancelled` / `CancelFlagRegistry` substrate already exist;
the Leg-2 cancel *mechanism* (register + interrupt the poll + three-case resolve) is new.
