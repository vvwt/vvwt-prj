# Story E50S02: Fix — Display SPA header layout — single-row band with logo + connection indicator at field-header band height

## User Story

**As a** Tournament Operator viewing a display device,
**I want** the brand logo and the WebSocket connection indicator to share a single horizontal band — sized to the height of the `Feld 1` / `Feld 2` / `Feld 3` field-headers — instead of occupying two separate vertical bands above the headers,
**so that** the upper portion of the display screen does not waste vertical space and more of the viewport is available for the match grid and group-standings panel.

---

## Context

The display SPA's header currently consumes ~3 vertical bands above the match grid:
1. A `<header class="brand-header">` strip with the brand logo at `height: 2em` and `padding: 0.5rem 1rem` (`vvwt-tm-web/src/main/ui-display/src/App.svelte:322-324, 411-420`).
2. A fixed-position `ConnectionStatus.svelte` component at `position: fixed; top: 0.5rem; right: 0.75rem; z-index: 100` (`vvwt-tm-web/src/main/ui-display/src/components/ConnectionStatus.svelte:53-64`) that visually overlays the brand-header strip — but renders independently of it.
3. The field-header band (`Feld 1` / `Feld 2` / `Feld 3`) inside `OverviewLayout` → `CourtGrid`.

The screenshot supplied by the user (Bildschirmfoto 2026-05-08_00-58-36.png) shows the result: a tall white strip with a small logo, then a wide whitespace below the indicator, then the field-header band. This wastes vertical space on a fixed-resolution display screen where every pixel below the field-header band hosts match data.

The user's stated layout target: logo on the left at the height of the field-header band, indicator at the right at the same band height (vertically centred), no separate strip.

### Scope posture

Frontend-only. CSS + Svelte component composition change. No backend impact. No i18n change. The connection-status states (connecting / connected / reconnecting / polling / disconnected) and their visual semantics (spinner / green / amber / red) are preserved.

The exact selectors are at Delivery's discretion; the test asserts the structural relationship via parent / sibling / `closest()` queries. - [ ] **AC-TEST-LAYOUT-LOGO-HEIGHT-CSS-RED** (testing): RED-first Vitest + jsdom — the logo element's effective `height` (read via `getComputedStyle(logo).height` OR an explicit `height` style attribute OR a CSS class whose stylesheet rule resolves to a height ≤ ~3em / ≤ ~2.5× the field-header text size) MUST be measurably smaller than the current pre-fix `2em + padding 0.5rem` envelope of the `<header class="brand-header">` strip. The assertion uses the computed-style string returned by jsdom, NOT bounding-box geometry (which jsdom does not implement reliably). Test fails before fix because the current logo + header padding total exceeds the ≤ ~3em envelope.
- [ ] **AC-TEST-LAYOUT-INDICATOR-IN-FLOW-RED** (testing): RED-first Vitest + jsdom — the connection-status indicator element MUST NOT have `position: fixed` in its computed style (or any style attribute resolving to fixed positioning) AND MUST share its parent or grandparent with the brand logo element such that a `closest()` query for the common header container resolves successfully from both.
