# Story E70S02: Activate jscpd for frontend (TypeScript / Svelte / Mustache) token-duplication detection in `mvn verify`

## User Story

**As an** operator + every Delivery agent,
**I want** frontend code duplication (TypeScript + Svelte + Mustache) to fail the build mechanically alongside Java duplication detection,
**so that** the print-schedule-class drift pattern is detected at build time on the frontend layer too — not only Java.

---

## Context

DEC-78 classifies DRY-lexical as hard-gated across the codebase. E70S01 covers Java; this Story covers the **frontend** (`vvwt-tm-web` web frontend Svelte + TypeScript, `vvwt-info-server` frontend, `vvwt-tm-web` scoring-tablet Mustache pages). The chosen tool is **jscpd** wired via `frontend-maven-plugin`'s npm execution — consistent with the existing Vite build binding in `vvwt-tm-web/pom.xml:341–349` per DEC-2 + DEC-54.

Two hypotheses are Delivery-verified during this Story (recorded in `impl-report.md`):

- **H-2 (DEC-78)**: jscpd supports `.svelte` parsing such that template + script blocks tokenize meaningfully (not as opaque HTML). UNVERIFIED at decision time.
- **H-3 (DEC-78)**: jscpd Mustache file parsing yields useful tokenization for scoring-tablet `.mustache` templates. Mustache template detection by any OSS tool is plain-text-token-based — semantic structural parsing is not expected. UNVERIFIED.

**Fallback path if H-2 or H-3 is rejected empirically**: PMD-CPD multi-language mode (supports JS/TS/Apex/Python/Lua/...) treats `.svelte`/`.mustache` as plain-text tokens with reduced precision; if jscpd's Svelte/Mustache support proves insufficient, Delivery STOPS and escalates — Discovery follow-up may decide between PMD-CPD multi-language fallback OR Layer-A-only handling (mechanical detection skipped for the affected file types). Silent reduction of scope is forbidden per DEC-78 §Hypotheses.

## Notes

**Tool choice rationale**: jscpd is the JS/TS/Svelte/Mustache duplication detector with widest language plugin support, MIT-licensed (AGPL-compatible per DEC-75), wired naturally through `frontend-maven-plugin` (existing precedent in `vvwt-tm-web/pom.xml:341–349`). Steel-manned alternatives (PMD-CPD multi-language mode, SonarQube) per DEC-78 §T-4: PMD-CPD as primary tool was rejected because PMD's Svelte/Mustache language support is less mature than jscpd's; however PMD-CPD multi-language remains the documented fallback if H-2/H-3 fail. SonarQube rejected per DEC-3.

**Threshold tuning**: jscpd defaults are aggressive (~50 tokens). Empirical tuning may justify a stricter floor (e.g., 100 tokens) to reduce noise on intentional symmetries (Svelte component prop-passing patterns, mustache partial-templates). Threshold is documented in `impl-report.md` per AC7.

**Anti-dogma**: Per `clean-code.rules.md` §Application Discipline Clause 2 (Rule of Three), small repeated patterns in template code (e.g., 5-line `{#each}` blocks following a CRUD list convention) are NOT violations — the suppression baseline absorbs them.

**Honest H-3 stance**: If jscpd Mustache support empirically yields false-positive-heavy output (because Mustache templates are token-similar by design — same partials, same conventions), AC4's decision may be SCOPE-REDUCED-with-honest-doc: jscpd skips `.mustache`, and the framework rule's Layer-A clause is the sole DRY mechanism for Mustache. Documented honestly, no silent scope reduction.
