# Story: Operationalize DEC-65 — `Phase.currentLapNumber` as a 1-based running-lap index across all consumers

## User Story

**As a** tournament operator and a member of the venue audience watching the Display,
**I want** the Display, the Timer, and the Score-Tablet to consistently reflect the round that is currently being played,
**so that** the active round is highlighted on the Display overview, the Score-Tablet finds the match in progress, and the Timer shows the correct lap — without per-screen arithmetic guesswork.

---

## Context

`Phase.currentLapNumber` is the phase-aggregate field that tracks lap progression. At the delivery HEAD it still carries the **legacy 0-based "laps completed" semantic**:

- `Phase.java` javadoc (verified): *"Active lap index within this phase. Starts at 0 (no lap completed). Incremented automatically during cascade recompute at round finalization."*
- Sole write site `DefaultScoringService` (scoring cascade Step 10): `phase.setCurrentLapNumber(previousLapNumber + 1)` inside the `allTerminalInLap` branch — incremented only after every match of a lap is terminal. Initial value `0` (DB default). There is **no initialization at the ASSIGNED→ACTIVE transition** and **no last-lap sentinel**.

This 0-based counter diverges from the **1-based `Match.lapNumber`** that L2 emits per DEC-60 (operationalized by E53S06 / E53S09). During ACTIVE play of lap 1 — before any lap is finalized — `currentLapNumber == 0` while matches carry `lapNumber ∈ [1, lapCount]`. Three latent consumer defects follow (DEC-65 Context):

1. **Display active-round highlight** — the FE compares `lap === currentLap` (`CourtGrid.svelte`); with `currentLap == 0` no round row is ever marked active. The FE code is already correct — it begins working the moment the backend emits the 1-based value.
2. **Score-Tablet active-match lookup** — `DefaultScoreEntryService` calls `findByFieldNumberAndLapNumber(fieldNumber, currentLapNumber)`; with `currentLapNumber == 0` and 1-based match laps the query returns an empty list.
3. **Timer off-by-one** — `DefaultTimerDataService` passes `currentLapNumber` to the Timer FE one lap behind during initial ACTIVE play.

**DEC-65** (2026-05-12) codified the corrected semantic and the full operationalization spec (D-1…D-8) but **deferred operationalization** until the DEC-64 Saga-Orchestrator (Epic E55) landed. **E55 is now `done`** — the deferral is resolved and this story is the post-E55 follow-up that DEC-65 D-8 forecasted ("E50S06 or equivalent").

This story implements DEC-65 D-1…D-7. It does **not** redefine the semantic — DEC-65 is the locked WHAT. Discovery defines the corrected observable behavior; Delivery picks the HOW (the init-hook call-site, the `lapCount` derivation, the siegerehrung treatment per DEC-65 D-10).

**Consumer audit must be re-derived fresh at the delivery HEAD.** DEC-65 D-5 enumerated 6 production sites as of 2026-05-12 — that list is now a stale snapshot. A 2026-05-15 verification against HEAD found the surface is broader: `DefaultScoringService` and `DefaultScoreEntryService` have moved into a new `de.vvwt.tm.scoring` module; `DefaultMatchCorrectionService` (new, E55-era) reads `currentLapNumber` into a `MatchResultChangedEvent`; `DefaultPhaseQueryService` reads it into `PhaseOverviewResponse` for the admin Phase-Overview UI; and at least four DTO/entity javadocs (`Phase.java`, `PhaseOverviewResponse`, `DisplayPhaseOverviewResponse`, `TimerDataResponse`, plus `LapAdvancedEvent`) encode "starts at 0". DEC-65 itself authorized this broader scope: D-8 point (c) states that *any new consumer of `Phase.currentLapNumber` introduced during E55 is to be authored against this DEC's semantic* — so auditing the post-E55 consumers is within DEC-65's own intent, not beyond it. No DEC-65 amendment is required.

## Acceptance Criteria

### Testing (DEC-22 Iron Law — fresh Q-1a RED-first; DEC-44 web-module IT framework; DEC-54 `mvn verify` gate)

- [ ] **AC-TEST-INIT-ON-ACTIVE-RED**: A RED-first test asserts that when a phase transitions ASSIGNED→ACTIVE, `phase.currentLapNumber == 1` post-transition, written in the **same transaction** as `status = ACTIVE` (DEC-65 D-2 — partial state `status=ACTIVE, currentLapNumber=0 mid-phase` is forbidden). The test MUST fail on current HEAD (no init-hook exists) and pass after the fix. RED commit precedes GREEN in `git log`.
- [ ] **AC-TEST-MIDPHASE-INCREMENT-RED**: A RED-first test exercises an ACTIVE phase (`lapCount ≥ 2`) set up **via the ASSIGNED→ACTIVE transition** — not by directly seeding `currentLapNumber` — then finalizes a non-last lap K (`1 ≤ K < lapCount`) and asserts `phase.currentLapNumber == K + 1` post-scoring-cascade (DEC-65 D-3 — the running lap advances to K+1). The `+1` increment operation itself is preserved verbatim per DEC-65 D-3; the test is RED on current HEAD because HEAD lacks the init-hook, so its running-lap sequence is the 0-based `0 → 1 → …` (after lap 1 the value is 1, not 2). This AC's RED commit therefore follows AC-TEST-INIT-ON-ACTIVE-RED's.
- [ ] **AC-TEST-LASTLAP-SENTINEL-RED**: A RED-first test uses a phase with `lapCount ≥ 2` and asserts **both**: (i) after every match of the **last** lap (`lapNumber == lapCount`) is terminal, `phase.currentLapNumber == 0` (sentinel) post-cascade and `phase.status` remains `ACTIVE`; (ii) after every match of a **non-last** lap (`lapNumber == lapCount - 1`) is terminal, `phase.currentLapNumber == lapCount` — the sentinel branch fires **only** on the last lap, not unconditionally. MUST fail on current HEAD (which increments the last lap to `lapCount + 1`). (DEC-65 D-3 + D-4.)
- [ ] **AC-TEST-NO-AUTO-COMPLETED-GREEN**: A test asserts that last-lap finalization does **not** auto-transition the phase to `COMPLETED` — the phase stays `ACTIVE` until an explicit operator action (DEC-65 D-4). Preserves the operator score-correction window (DEC-65 D-7).
- [ ] **AC-TEST-NON-ACTIVE-AND-COMPLETED-ZERO**: Tests assert `currentLapNumber == 0` for `PENDING`, `PREPARED`, `ASSIGNED` phases, and `== 0` post-commit after an operator `complete` / `forceComplete` transition to `COMPLETED` — idempotent when already 0, explicit reset when non-zero (DEC-65 D-1 case table + D-4).
- [ ] **AC-TEST-DISPLAY-ACTIVE-ROUND-IT**: A web-module integration test (DEC-44 framework) asserts that for a phase in ACTIVE play of lap K, the Display overview response surfaces a current-lap value equal to K, so that the FE `lap === currentLap` highlight matches the round row of lap K. Closes the latent Display defect.
- [ ] **AC-TEST-SCORE-TABLET-ACTIVE-MATCH-IT**: A web-module integration test asserts that the Score-Tablet active-match lookup (`findByFieldNumberAndLapNumber`) returns the in-progress match during lap 1 of an ACTIVE phase — i.e. the lookup is no longer queried with `0`. Closes the latent Score-Tablet defect.
- [ ] **AC-TEST-TIMER-CURRENTLAP-IT**: A web-module integration test asserts that the Timer response reports the lap currently being played (K), not K−1, during initial ACTIVE play. Closes the latent Timer off-by-one.
- [ ] **AC-TEST-PHASETEST-MIGRATION**: `PhaseTest` is migrated to assert the full DEC-65 D-1 lifecycle picture (init → increment → last-lap sentinel → COMPLETED sentinel). The pre-existing `currentLapNumber == 0` assertion is **re-scoped, not deleted** — it remains a passing assertion bounded to PENDING/PREPARED/ASSIGNED phases (still valid per DEC-65 D-1).

### Governance (DEC-65 fidelity; DEC-22/29/30/44/54; consumer audit; commit format; attestation)

No clause of DEC-65 D-1…D-7 is reinterpreted, narrowed, or extended.
- [ ] **AC-GOVERNANCE-CONSUMER-AUDIT-FRESH-AT-HEAD**: The consumer audit is re-derived by a fresh search of `Phase.currentLapNumber` / `current_lap_number` usages at the delivery HEAD — **not** copied from DEC-65 D-5's 2026-05-12 enumeration. Every site is classified and handled per the four categories: **(a) mutation** — only the scoring-cascade write site in `DefaultScoringService` (its existing increment is preserved verbatim per DEC-65 D-3 and gains the last-lap sentinel branch; the increment-base read of the prior `currentLapNumber` at that same site is unchanged) plus the new ASSIGNED→ACTIVE init-hook; **(b) read / pass-through** — Display, Timer, Score-Tablet, MatchCorrection and PhaseQuery consumers see the corrected value via passthrough with no behavior redesign; **(c) DTO / javadoc** — `Phase.java`, `PhaseOverviewResponse`, `DisplayPhaseOverviewResponse`, `TimerDataResponse`, `LapAdvancedEvent` documentation text updated to the new semantic; **(d) test fixtures** — every fixture encoding the old semantic is migrated. ### Error Handling

- [ ] **AC-ERROR-OPERATOR-CORRECTION-WINDOW**: A regression test asserts that after the last lap is finalized — `currentLapNumber == 0`, `status` still `ACTIVE` — a subsequent score correction on a last-lap match still succeeds and does **not** advance `currentLapNumber` or auto-complete the phase (DEC-65 D-7).
- [ ] **AC-ERROR-SIEGEREHRUNG-PHASE**: A siegerehrung phase (vacuous L1+L2, no match rows, `lapCount == 0` per DEC-59 Clause F) transitions ASSIGNED→ACTIVE without error. DEC-65 D-10 requires the operationalizing story to make this an explicit decision: Delivery MUST choose either `currentLapNumber == 0` (siegerehrung special-case) or the inert `currentLapNumber == 1` (the D-2 default), **record the chosen value and its rationale in the impl-report**, and cover the chosen value with a dedicated test assertion.
- [ ] **AC-ERROR-COMPLETED-IDEMPOTENT**: The COMPLETED transition's `currentLapNumber = 0` write is idempotent — a no-op when already 0, an explicit reset when non-zero (covers the operator `forceComplete` mid-phase case per DEC-65 D-4).
