# Story E36S02: Photo controller Q-1a TDD rebuild — TeamPhotoController + PhotoMetadataResponse (D-7 Option γ at canonical FQN de.vvwt.tm.web.photo.*)

## User Story

**As a** maintainer of `vvwt-tm-web` continuing the post-E23 Q-1b retro-correction
on the photo primary-adapter surface,
**I want** the legacy photo-controller Q-1b artefacts at `de.vvwt.tm.web.photo.*`
deleted and rebuilt under DEC-22 Iron Law Q-1a TDD RED-first authorship at the
same canonical FQNs (D-7 Coexistence Option γ), with HTTP wire contract preserved
verbatim,
**so that** the photo controller carries a trustworthy correctness oracle and
Track 1 of Epic E36 advances toward Cutover-1 with zero observable client impact.

---

## Context

Per Session Brief `discovery-2026-04-26-e36-retro-correction` D-7 Option γ:
delete-then-rebuild within feature-branch lifecycle at the same canonical FQN.
This story is the second step of Track 1 (Photo); E36S01 completed the photo
domain rebuild at `de.vvwt.tm.photo.*`.

Audit `E36-discovery-legacy-inventory.md` enumerates 2 in-scope artefacts under
`de.vvwt.tm.web.photo.*` (TeamPhotoController, 220 LOC; PhotoMetadataResponse,
38 LOC). Audit `E36-discovery-dec41-test-classification.md` classifies the
pre-existing `TeamPhotoControllerIT` (15 methods, count flagged 15→17 for
delivery-time re-verification per Brief Q-7) as 100% Snapshot-Driven; zero
Contract Test reuse candidates.

Per Brief D-7 controller RED model + DEC-40 boundary preservation: HTTP URL paths
and JSON wire-format shapes MUST be preserved verbatim across rebuild. The
controller is consumed by the Svelte UI; consumer URL/JSON expectations are the
boundary contract that the rebuild MUST satisfy.

DEC-38 governs the IT pattern: `@ApplicationModuleTest` is the web-module IT canon.
DEC-41 §3 clause (1) governs the test corpus: NEW IT methods authored RED-first
regardless of pre-existing inventory.

## Notes

- **Constraint** (Brief C-3): `PhotoMetadataResponse` JSON shape is the wire
  contract; field names/types/nullability MUST match the legacy DTO.
- **Risk** (Brief C-11): HTTP code mappings (e.g., 400 on validation errors, 404
  on unknown entity, 413 on size limit) are behavioral characteristics that MUST
  match legacy behavior verbatim. Any divergence triggers C-11 stop-and-escalate.
  This is delicate because some HTTP code mappings come from
  `PhotoExceptionAdvice` (still resident in this story) — the rebuilt controller
  must throw the same exception types so the still-resident advice maps them
  identically.
- **Escalation triggers**: C-3 (DTO shape), C-11 (HTTP/JSON behavioral
  divergence), C-2 (consumer Svelte modifications would invalidate Option γ).
- **Method-count caveat** (Brief Q-7): Audit (ii) flagged 15→17 method count
  uncertainty on `TeamPhotoControllerIT`. AC-METHOD-COUNT-RECONFIRMATION
  mandates delivery-time empirical verification.
- **DEC-38 application**: `@ApplicationModuleTest` boots the `web` module +
  collaborating modules; this is the canonical IT pattern for web-tier rebuilds
  per DEC-38.
- **PhotoExceptionAdvice still resident**: This story does NOT delete
  `PhotoExceptionAdvice`. That deletion happens in E36S08 Phase 2. The rebuilt
  `TeamPhotoController` continues to throw the same exception types from E36S01
  so PhotoExceptionAdvice continues to map them.
