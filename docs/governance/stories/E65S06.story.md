# Story: Scoring-tablet field-page layout refinements — header, swap-control placement, footer, score inputs, symmetric header

## User Story

**As a** referee using the scoring tablet courtside,
**I want** the field page laid out for glanceable, large-touch use with a symmetric header,
**so that** I can read and operate it quickly regardless of how long the team names are.

---

## Context

Epic E61 redesigned the scoring-tablet field page. Reviewing it in use, the operator asked
for a set of layout refinements (Discovery session 2026-05-17): bigger header team names; the
side-swap control moved to the top; bigger footer text; the version in parentheses; the
AGPL §13 source-code link restored to the footer; bigger score inputs with aligned buttons;
and a symmetric header that does not distort when a team name is long.

The §13 source-code link is effectively a regression fix: E59S03 added the §13 source-code
offer to the Mustache scoring pages as a plain static link, and it is present on
`register.mustache` and `hello.mustache`, but the field page's footer (redesigned by E61S01)
does not carry it (Brief O-6).

---

## Acceptance Criteria

- [ ] AC1 (L1 — header team names): The team names in the field-page header are rendered
  larger than at present.
- [ ] AC2 (L2 — swap-control placement): The side-swap control ("Seiten wechseln") is
  positioned at the top of the page, directly below the header bar, horizontally centred,
  and only as wide as its label text — not full width.
- [ ] AC3 (L3 — footer text size): The "Feld N" field label and the "Scoring Tablet"
  wordmark in the footer are rendered somewhat larger than at present.
- [ ] AC4 (L4 — version): The application version in the footer is shown in parentheses
  (e.g. "(Version: dev)"). Unlike the footer text enlarged in AC3, the version text is NOT
  enlarged — it keeps the size at which it currently renders.
- [ ] AC5 (L5 — §13 source-code link): The field-page footer shows, at the bottom-right,
  the AGPL §13 source-code offer as a plain static link — the same link text and target
  E59S03 established for the Mustache scoring pages on `register.mustache` /
  `hello.mustache`: the text "Source code (AGPL-3.0-or-later):" followed by the link to
  `https://github.com/vvwt/vvwt-prj`. No new JavaScript is introduced for it (DEC-19).
- [ ] AC6 (L6 — score inputs and aligned buttons): The score input fields are rendered
  larger and without the browser-native number-spinner control (the + / - buttons serve
  that purpose). Per Brief D-7 the operator may veto this spinner removal at delivery — if
  vetoed, retaining the native spinner is not an AC failure. The + / - buttons and the
  result-submit button are sized so the button group stays flush with the left and right
  edges of the score input fields.
- [ ] AC7 (L7 — symmetric header bar): The top header bar lays out the two team names and
  the "vs." separator as three zones — team 1, a centred "vs.", team 2 — so that "vs."
  stays horizontally centred regardless of the two team names' lengths. This entails
  rendering the header's team names and "vs." as separate elements — a change to the header
  markup and to the inline ES5 that populates it — kept within the DEC-19 Mustache + ES5
  constraint.
- [ ] AC8 (L7 — aligned score boxes): In the score-entry area each score box carries a
  team-name label above it; when one team-name label is longer than the other (including
  wrapping onto more than one line), the two score boxes stay vertically aligned with each
  other — both at the same height — rather than one box sitting lower than the other.
- [ ] AC9 (error-handling — long names): With team names of very different lengths
  (including a name long enough to wrap onto more than one line), the header bar stays
  symmetric, the two score boxes stay aligned, and the score-entry area stays usable — no
  overlap, no clipped controls, no horizontal scroll.
- [ ] AC10 (governance — DEC-19): The field page remains Mustache + inline vanilla ES5
  JavaScript + inline CSS only — no Svelte or other framework, no ES2015+ syntax, no
  bundler.
- [ ] AC11 (testing): The structural changes are covered by tests on the project's existing
  automated test surface for this Mustache page — rendered-HTML / attribute inspection in
  the existing `ScoreFieldLayoutIT` pattern (e.g. the §13 link's presence and target, the
  swap control's relocation in the DOM, the header's three-element structure, the
  number-input spinner suppression). The visual properties — relative text sizes, "vs."
  centring, score-box alignment, absence of overlap or horizontal scroll — are, where not
  reachable by that automated surface, verified by the implementer and explicitly recorded
  in the impl-report, which states exactly what is automated and what is attested.
  First-party ES5 logic is authored test-first per DEC-22 where the surface supports it.
- [ ] AC12 (governance — build gate): `mvn verify` from the `vvwt-prj` root is BUILD
  SUCCESS (DEC-54, DEC-71).

> All acceptance criteria must be verifiable.

## Notes

Per Brief D-6 / O-6, AC5 restores the §13 offer to the field page in the form E59S03
already uses on the sibling Mustache pages — the operator's quoted link text is that form,
not a new design. Per Brief D-7 the native number-spinner is removed when the input is
enlarged (AC6); the operator may veto this at delivery if desired. AC7 requires the header
bar's markup and the inline ES5 that populates it to be restructured into discrete
team / "vs." elements; because E65S03 also modifies the field page's swap rendering (which
writes the header), this story is sequenced after it (via E65S05) so the layout change
builds on the corrected swap logic. AC7 (header-bar symmetry) and AC8 (score-box alignment)
govern two structurally distinct page regions — the top header bar and the score-entry
area — and are stated separately for that reason. Per memory
`feedback_ac_behavioural_what_not_test_how`, AC11 is honest about the project's test
surface for this Mustache page: structural assertions are automatable in the
`ScoreFieldLayoutIT` pattern, while the visual sizing/symmetry properties are
impl-report-attested. `mvn verify` is the build gate per DEC-54 / DEC-71. This is the
layout-polish story and is sequenced last per the bugs-before-polish ordering (Brief D-3).
