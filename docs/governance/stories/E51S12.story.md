# Story E51S12: DEC-56 Authoring + Bug 3 Resolution + RefereeAssigner Precondition Tests

## User Story

**As a** Tournament Operator,
**I want** the system to formally codify the new Layered Decomposition architecture (L1/L2/L3/L4) and the lifecycle changes (matches have lap+field after Match-Gen-Pipeline), AND verify that `assignReferees` succeeds in `commitTransition` for both `tournament.optimize=true` and `optimize=false` paths,
**so that** the architectural invariants are governance-recorded in DEC memory (preventing silent drift in future stories) and the originally-reported HTTP 500 bug is structurally resolved.

---

## Context

**DEC-56 authoring (Brief D-4 + D-7 + D-13):** new architectural-level DEC amendiert DEC-55 + DEC-49 per delta-amendment pattern (DEC-46/48/50/51/53/55 precedent). Scope:

- **DEC-56 D-1 (NEW):** Layered Decomposition architecture pflicht. L1=MatchGenerator (per-Spielart, existing), L2=RoundAssignmentService (Spielart-agnostic, NEW Story 10), L3=SlotOptimizationClient (existing, refactored Story 11), L4=FieldAssignmentService (V2+, interface-stub only in V1). Layer-Pflicht: L1+L2 always run; L3 optional via `tournament.optimize`; L4 optional V2+. Schnittstellen-Vorlage für future-pluggable Implementierungen.
- **DEC-55 D-3 step 2 amendiert:** matches persisted with lap+field set after L1+L2 (NOT lap=null/field=null). DEC-55 D-3 step text: "MatchGenJobListener consumes the event, invokes phasePreparationService.generateMatches → matches with lap+field assigned via L2-RoundAssignmentService" (text replaces the old "lapNumber=null, fieldNumber=null, refereeTeamId=null" wording; refereeTeamId stays null).
- **DEC-55 D-4 PREPARED-Defn amendiert:** "Match-Gen + Round-Assignment completed; matches persisted with lap+field set" (replaces old "matches persisted with lap=null, field=null").
- **DEC-55 D-5 amendiert:** `optimize=false` skippt nur L3 (Slot-Opt-Permutation-Suche); L1+L2 laufen IMMER; matches haben lap+field auch ohne L3.
- **DEC-49 D-3 amendiert:** N-Definition für Routing-Rule = `lapCount` (NOT `rowCount`/`matchCount`). Threshold `tm.slotopt.exhaustive-max-n=10` wird gegen lapCount gehalten.
- **DEC-55 D-10 textuell unverändert:** assignReferees synchron in commitTransition; matches haben dank DEC-56 D-1 + amended D-3 immer lap+field zur commitTransition-Zeit.
- **`tournament.fieldCount` fallback (D-13):** L2 fällt bei null/zero auf `tm.slotopt.fallback.field-count` Config-Default zurück.

**Bug 3 resolution (Brief O-10 + O-21):** the originally-reported HTTP 500 stacktrace 2026-05-08T23:45:40 (`RefereeAssigner.assignReferees:131 → DefaultPhaseTransitionService.commitTransition:227`) is **structurally resolved by Stories 9+10**: after L1+L2, matches always have lap+field non-null → `RefereeAssigner.assignReferees` precondition (line 124-134) passes. This story adds the regression-guard tests to confirm.

**Refereeassigner-Korrektheits-Invariante (NF-MED-2 from Tier-2 cycle-2):** L3 lap-permutation preserves per-lap team-membership; refereeTeamId is match-attached (`Match.refereeTeamId` column persisted at `RefereeAssigner.java:216-217`); therefore L3 running AFTER assignReferees does NOT invalidate referee assignments. Story 12 adds a regression-guard test for this structural invariant.
