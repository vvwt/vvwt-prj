# Story E51S01: Foundation — DEC-55 authoring + Flyway schema migration

## User Story

**As a** Tournament Manager developer (Delivery Agent),
**I want** the foundational schema columns + enum values + DEC-55 governance file in place before any later E51 story implements job-pipeline / lifecycle / drag&drop refactor work,
**so that** every subsequent E51 story can rely on `team_avatar.team_id` being nullable, `tournament.optimize` and `phase.optimized` and `phase.last_job_state` columns existing, the `ASSIGNED` enum value being valid for `phase.status`, and FK-CASCADE being in place for invalidation-cascade simplicity (D-2 + D-7).

---

## Context

E51 (Phase-Preparation Background-Job Pipeline) operationalizes DEC-55 across 7 stories. Five of those stories require schema state that does not exist in today's `vvwt-tm-web`:

- `team_avatar.team_id` is currently NOT NULL (verified via `TeamAvatar.java:43`) — incompatible with structural-avatar persistence at DraftConfig-Apply (E51S02 + DEC-55 D-1).
- `tournament.optimize` (operator switch per DEC-55 D-5) and `phase.optimized` (slot-opt-completion flag per DEC-55 D-6) and `phase.last_job_state` (job-status field per DEC-55 D-2) do not exist.
- `phase.status` enum has values `PENDING / PREPARED / ACTIVE / COMPLETED` (E48S17); `ASSIGNED` does not exist (DEC-55 D-4).
- FKs `match.member_avatar_X_id` + `team_avatar_rating.avatar_id` use `ON DELETE RESTRICT` — incompatible with phase-precise auto-invalidation cascade (DEC-55 D-7).

DEC-55 itself does not exist in `contexts/memory/decisions/` — it must be authored. Per memory `feedback_governance_pure.md`, the authorization act is the Brief-validation that occurred during this Discovery; the file is committed in this story.

This story is foundation-only: it produces the governance artefact + the schema delta. No business logic, no controller change, no event publication, no UI change. The new columns get default values that preserve today's behavior pre-E51S02 (`tournament.optimize` default TRUE; `phase.optimized` default FALSE; `phase.last_job_state` default NULL).

DEC-25 §Wave-2-Big-Bang-Reset applies — no production data exists, no data migration needed.
