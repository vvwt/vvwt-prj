# Story E23S02: TDD RED-first `PhotoUrlBuilder` public interface + `DefaultPhotoUrlBuilder` impl — single source of truth for photo URL construction (D-17 decoupling)

## User Story

**As a** maintainer of the `de.vvwt.tm.photo` Modulith module,
**I want** a new public `PhotoUrlBuilder` interface owning team-photo URL
construction, with `DefaultPhotoUrlBuilder` impl in `photo.internal`,
**so that** CertificateAssembler (and any future consumer needing photo URLs)
depends on photo's stable port instead of hardcoding photo's URL schema,
enabling the photo atomic cutover (E23S05) to flip the URL in a single
commit without coupling certificate's cutover to photo's URL changes.

---

## Context

Per Brief v4 D-17 (C1=b resolution): CertificateAssembler.java:377 currently
hardcodes `"/api/tournaments/" + tournamentId + "/teams/" + teamId + "/photo"`.
This hardcoded URL is the only coupling between certificate and photo URL
schemas. Removing it (via dependency injection on PhotoUrlBuilder) enables
two separate atomic cutovers per DEC-21 Line 152-154 ("No global cutover of
multiple contexts in one commit").

Q-1a TDD RED-first new code per DEC-22 Iron Law. During parallel phase, the
interface + impl emit the OLD URL pattern (byte-identical to the current
hardcoded string). At E23S05 Cutover-1, the URL template is updated in an
atomic RED-GREEN pair within a single commit.

## Acceptance Criteria

- [ ] **AC-INTERFACE-CREATED**: `de.vvwt.tm.photo.PhotoUrlBuilder` public
  interface with method `String buildTeamPhotoUrl(UUID tournamentId, UUID teamId)`.
  Javadoc documents the URL-construction contract + cites Brief D-17.
- [ ] **AC-IMPL-CREATED**: `de.vvwt.tm.photo.internal.DefaultPhotoUrlBuilder`
  `@Component` implementing the interface. Emits URL pattern
  `/api/tournaments/{tid}/teams/{teamId}/photo` during parallel phase
  (byte-identical to current CertificateAssembler.java:377 hardcoded string).
- [ ] **AC-TESTING-RED-FIRST**: RED-first TDD cycle per DEC-22 Iron Law.
  `DefaultPhotoUrlBuilderTest` authored BEFORE impl; first test run FAILS
  compilation / assertion (no impl yet); impl written; test GREEN. Commit
  history shows RED → GREEN.
- [ ] **AC-TESTING-OBSERVABLE-FORM-QUANTIFIED**: Test assertions satisfy
  DEC-41 Clause 1 criterion (d) observable-form via QUANTIFICATION over
  a representative input set. Implementation MUST use either:
  (i) jqwik `@Property` over `@ForAll UUID x, @ForAll UUID y` asserting
      `buildTeamPhotoUrl(x, y) == "/api/tournaments/" + x + "/teams/" + y + "/photo"`
      for all generated pairs, OR
  (ii) JUnit 5 `@ParameterizedTest` with `@MethodSource` yielding ≥5
       representative `(UUID tournamentId, UUID teamId)` rows, asserting
       the same invariant.
  The algebraic invariant is NAMED in the test method name and Javadoc
  (e.g., `buildTeamPhotoUrl_conformsToUrlTemplate(UUID, UUID)` / Javadoc
  "Invariant: buildTeamPhotoUrl(x, y) produces the canonical photo URL
  template"). A single hardcoded-example `@Test` method behind the named
  invariant is EXPLICITLY INSUFFICIENT per DEC-41 criterion (d) parenthetical.
- [ ] **AC-TESTING-DEC36**: Test class placed at public-facing package
  `de.vvwt.tm.photo.PhotoUrlBuilderTest` (cross-package relative to
  `de.vvwt.tm.photo.internal.DefaultPhotoUrlBuilder` impl). Per DEC-36
  cross-package rule, test type-references `PhotoUrlBuilder` interface
  (type + mock), NOT `DefaultPhotoUrlBuilder` concrete class. Acts as the
  port-contract test consumed by downstream cross-module consumers
  (CertificateAssembler E23S03, and the atomic RED-GREEN pair at E23S05
  Cutover-1).
- [ ] **AC-TESTING-EDGE-CASES**: Explicit test cases cover: (a) normal
  UUID pair; (b) UUIDs with distinguished formats (all-zeros UUID pair
  included in the parameterized / jqwik generator set); (c) null-argument
  handling per AC-ERROR-HANDLING below. Edge cases are cases-in-addition-to
  the AC-TESTING-OBSERVABLE-FORM-QUANTIFIED invariant check, not a
  substitute.
- [ ] **AC-ERROR-HANDLING**: Null-argument handling contract is EXPLICIT-NPE.
  `buildTeamPhotoUrl(null, UUID)` and `buildTeamPhotoUrl(UUID, null)`
  and `buildTeamPhotoUrl(null, null)` all throw `NullPointerException`.
  Javadoc documents `@throws NullPointerException` on both parameters.
  Test asserts this via `assertThrows(NullPointerException.class, ...)`
  for each of the 3 null-combinations. Rationale: canonical Java port
  contract (fail-fast on invalid input; defensive empty-string returns
  would hide programmer errors at call sites).
- [ ] **AC-NO-CONSUMER-REWIRE**: CertificateAssembler NOT yet modified in
  this story. CertificateAssembler.java:377 still has the hardcoded string.
  DI refactor of CertificateAssembler deferred to E23S03.
- [ ] **AC-MODULITH-VERIFY-GREEN**: `ApplicationModulesTest` GREEN. No
  new cross-module dependency introduced (PhotoUrlBuilder lives entirely
  within photo module).
- [ ] **AC-MVN-VERIFY-GREEN**: `mvn verify` GREEN on staging PR.
- [ ] **AC-GOVERNANCE-DEC35**: PhotoUrlBuilder at public package + Default*
  impl at internal per DEC-35 pattern. Naming canon respected.
- [ ] **AC-SECURITY-NA**: No security surface in this story (URL-string
  builder only; no HTTP endpoint, no authorization logic).
