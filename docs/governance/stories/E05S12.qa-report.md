## Notable Findings

1. **`deleteByTournamentId` addition**: Adding `deleteByTournamentId()` to `TeamRepository` and
   `DefaultTeamRepository` is an unplanned but necessary addition — the `ON DELETE RESTRICT` FK
   constraint on `team.tournament_id` means `deleteTournament()` would fail at the DB level if
   seeded teams are not cleaned up first. This is a direct consequence of seeding, not scope
   creep.

2. **Pre-existing IT latent bug fixed**: `DraftControllerIT.sampleSection()` was using gameMode
   `"roundrobin"` (lowercase), which is not a registered `MatchGenerator` bean ID (`"roundRobin"`
   is). This was never caught before E05S12 because `participatingTeams` was always empty, so
   `generateMatches()` was never called. Fixed as part of IT remediation; the bug was pre-existing
   and not introduced by E05S12.

3. **Pre-existing IT adaptations**: 7 tests in 4 test classes were updated to reflect the new
   reality that tournaments are created with N seeded teams. All adaptations are minimal (assertion
   value changes, team number range adjustments) — no new test logic for unrelated features was
   introduced.

4. **`TournamentServiceTest.deleteTournament_draftWithNoPhases_deletesSuccessfully`**: Now also
   exercises `teamRepository.deleteByTournamentId()` (void, lenient-stubbed via Mockito no-op
   default). The verify on `tournamentRepository.deleteById(id)` still passes — no regression.
