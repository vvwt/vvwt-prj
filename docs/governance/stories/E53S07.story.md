# Story E53S07: Fix: Laufzettel renders field number as 0-based index (Feld 0/1/2 instead of Feld 1/2/3) for both PLAYING and REFEREEING rows

## User Story

**As a** team member reading the printed Laufzettel,
**I want** the Feld column to show the actual field number as labeled at the venue,
**so that** I can locate my next match without translating "Feld 0" into "Feld 1".

---

## Context

User reported on 2026-05-10 (screenshot `Bildschirmfoto_2026-05-10_18-49-15.png`) that the Laufzettel's Feld column shows values `0`, `1`, `2` for a tournament with 3 fields. Field labels at the venue start at 1 (the operator and signage refer to "Feld 1", "Feld 2", "Feld 3"); the printed Laufzettel showing `0` causes participant confusion.

User-confirmed pre-existing bug: "Bug C war mit Sicherheit schon vorhanden. Vor E53 gab es auch schon ein Feld 0." Predates E53.

### Verifiable expected behavior

For a tournament with 3 fields, the rendered Feld column for both PLAYING rows (where the team is playing) and REFEREEING rows (where the team is the assigned referee) MUST display values from the set `{"1", "2", "3"}` — never `"0"`.

### Root principle (from Brief D-0)

Print is a downstream observer. For Bug C the **DISPLAY layer** is the only legitimate fix surface in this Brief — Discovery does not preselect between (a) a write-side migration making `Match.fieldNumber` 1-based at the storage layer, or (b) a read-side `+1` conversion in the assembler. Both are legitimate; Delivery picks based on blast-radius analysis.

### Codebase entry points (informational only — Delivery picks the implementation shape)

- `DefaultLaufzettelAssembler.java:518` — PLAYING row: `String fieldStr = field != null ? String.valueOf(field) : "";`
- `DefaultLaufzettelAssembler.java:524` — REFEREEING row: same pattern (`String.valueOf(field)`)
- `laufzettel.mustache:68` — PLAYING row: `<td class="laufzettel-col-field">{{fieldNumber}}</td>`
- `laufzettel.mustache:77` — REFEREEING row: same `{{fieldNumber}}` rendering
- `Match.getFieldNumber()` — returns `Integer` directly; storage shape unknown to Discovery (UNVERIFIED H-3 in Brief)
- `activity-schedule.mustache` — verified via grep: does NOT render field numbers (cells show team names). Out of scope.
