# Story E23S03: Q-1b refactor legacy `CertificateAssembler` to inject `PhotoUrlBuilder` (removes hardcoded photo URL at line 377)

## User Story

**As a** maintainer of CertificateAssembler (still at legacy
`de.vvwt.tm.infrastructure.print.*` during E23 parallel phase),
**I want** `buildPhotoUrl(UUID tournamentId, UUID teamId)` to delegate to
the newly-introduced `PhotoUrlBuilder` interface instead of hardcoding the
photo URL schema,
**so that** CertificateAssembler no longer depends on photo's URL format —
enabling the photo atomic cutover (E23S05) to flip the URL in one commit
without affecting certificate's cutover (E23S10).

---

## Context

Per Brief v4 D-17 + T-6, CertificateAssembler.java:377 currently hardcodes:
```java
return "/api/tournaments/" + tournamentId + "/teams/" + teamId + "/photo";
```
This hardcode is the last remaining coupling between certificate and photo
URL schemas. This story replaces it with
`photoUrlBuilder.buildTeamPhotoUrl(tournamentId, teamId)`.

Q-1b refactor per DEC-22 §refactor-clause: behavior-preserving (both code
paths produce the same URL string during parallel phase). Existing
`CertificateAssemblerTest` is the regression gate. No RED-first needed for
the refactor itself.
